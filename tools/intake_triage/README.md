# intake_triage — 取り込めない行は直さずに、機械が決めてよいところまでで仕分ける

取込先の仕様に入るかを行ごとに見たい。ここで機械が「たぶんこう直せばいい」まで踏み込むと、直した跡が
残らないまま元の表と合わなくなる。この部品は **1 件も直さない**。列ごとの違反を 3 値に分け、行の分類は
その最悪値で決め、**どの行のどの列が、どの宣言とどう違うか** だけを返す。

要点は仕分けそのものより、**2 本目と 3 本目の境界が値ではなく宣言の側で決まる** ところにある。同じ違反でも、
それを覆うと宣言された直し方の名前が仕様表に在れば 2 本目に入り、無ければ 3 本目に落ちる。だから
「機械が決めてよい境界」は仕様表を書く人が動かすもので、部品は自分で広げない。

持たせていないものが規律になっている。

- **値を書き換える経路を持たない**(返すのは適用すべき直し方の名前と、対象の列と、現在の値だけ)
- **推測で最も近い値に寄せる経路を持たない**。閾値で自動的に通す引数も持たない
- **既定の型と既定の値域を持たない**(仕様表から取る。空欄の列は評価せずに止まる)
- **部分出力の経路を持たない**(そのまま通る以外の行が残っているあいだ、通る行だけを集めて渡さない)
- **書き出しを持たない**(ファイルはこの部品からは開かない)
- **取り込める率を単独で返さない**(3 分類の件数と、分母に何を含めたかを必ず一緒に返す)
- **取込先の製品や分野の語彙を持たない**(列名・型の名前・値域・直し方の名前は全て仕様表の側にある)

stdlib のみ(csv / json / decimal / hashlib / argparse / datetime)、依存なし。

## 流れ(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | 仕様表を検査する(列の重複・型の名前・値域の宣言・直し方の名前・識別子の列) | 理由コード 6 種(下の表の上 6 つ) |
| 2 | 行と仕様表を突き合わせる | 仕様表に無い列が行に在る / 行の識別子が重複 |
| 3 | 列ごとに 3 値で判定する(そのまま通る / 宣言された直し方で通る / 人が決めるしかない) | — |
| 4 | 行の分類をその行の列の最悪値で決める | — |
| 5 | 3 分類の件数と違反の明細を返す(分母の内訳つき) | — |
| 6 | 全ての行がそのまま通った時だけ、次に渡す行を返す | 1 行でも残っていれば渡さない |

前の段で止まったら次の段には進まない。止まったときは行が 1 つも分類されず、理由コードだけが返る。

## いつも成り立つこと

仕分けの結果は 2 通りしかない。**全ての行がちょうど 1 つの分類に入り、どの行の分類もその行の列の
最悪値と一致する**か、**行は 1 つも分類されず、理由コードが返る**か。どちらの場合も、この部品は値を
1 つも書き換えず、ファイルを 1 つも開かない。

この 1 文は `tests/test_intake_triage_property.py` が性質テスト(hypothesis)で確かめている。宣言どおりの行を
乱数で作り、15 通りから 1 つ引いて 1 か所だけ壊して(「壊さない」も同じ確率で引く)、さらに各列の直し方の
宣言を乱数で付け外しして、毎回この 1 文が成り立つかを見る。乱数は固定で、毎回同じ 300 通り。判定は道具の
関数を使わず、テストの中に別に書いている(型・値域・覆う違反の対応表)。テストの実行には pytest と
hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 仕様表(取込先の宣言)

1 列 = 1 行で、欄は 6 つ。`fixtures/shiyou.csv` が例(8 列)。`init` でひな型が出る。

| 欄 | 意味 |
|---|---|
| `column` | 列名。行の見出しと一致する(重複は止まる) |
| `type` | 型の名前。`文字列` / `整数` / `金額` / `コード` / `日付`。**空欄は許さない** |
| `domain` | 許容する値。**空欄は許さない**(制限を付けないなら `制限なし` と書く) |
| `required` | 埋まっていなければ違反とする列に印を付ける(`○` / `1` / `はい`) |
| `repair` | その列の違反を覆うと宣言する直し方の名前。**空欄なら 3 本目に落ちる** |
| `source` | 出典。報告に載る |

`domain` の書き方は 6 通り。`制限なし` / `集合: 10|20|30` / `範囲: -9999999..0` / `長さ: 6` /
`長さ上限: 40` / `形: YYYYMMDD`。型に書けない種類(日付に `範囲`、金額に `長さ` など)は仕様表の不備として
終了コード 2 で返す。

## 列ごとの違反(`VIOLATIONS`)

| 違反 | 意味 |
|---|---|
| 必要な値が空 | 埋まっていなければ違反と宣言した列が空。空欄で埋めると取込先では別の意味になる |
| 型と違う | 宣言した型の形で読めない(半角の数字以外の字・桁区切りのカンマ・符号以外の記号) |
| 集合の外 | 宣言した集合に無い値 |
| 範囲の外 | 宣言した範囲の外(引く側の列に正の数が入っている場合もここ) |
| 長さが違う | 宣言した長さとちょうど一致しない(先頭のゼロが落ちた場合もここ) |
| 桁あふれ | 宣言した長さの上限を超えている。切り詰めると別の値になる |
| 形が違う | 宣言した形で書かれていない(区切りの有無・暦に無い日) |

## 直し方の名前と、それが覆う違反(`REPAIRS`)

| 直し方の名前 | 覆うと宣言している違反 |
|---|---|
| `半角の数字に直す` | 型と違う |
| `桁区切りのカンマを外す` | 型と違う |
| `括弧は負` | 型と違う / 範囲の外 |
| `印字は符号なし` | 範囲の外 |
| `先頭をゼロで埋める` | 長さが違う |
| `空欄を 0 とみなす` | 必要な値が空 |
| `区切りを外して 8 桁に` | 形が違う |
| `年の表記を宣言した形に直す` | 形が違う |

**部品はこの表で値を直さない**。覆う違反の一覧を持つだけで、実際に直すのは人か後の工程だ。
`桁あふれ` を覆う名前は 1 つも無い(切り詰めると別の値になるので、常に人の判断に落ちる)。
足りない名前があれば、ここに 1 つ登録する。**仕様表の側には名前しか書けない**ので、直し方の中身が
仕様表に散らばることはない。

## 止まる理由コード(`REASONS`)

| 理由コード | 意味 |
|---|---|
| 型の名前が空欄 | 列に型の名前が無い。既定の型は持たない |
| 値域の宣言が空欄 | 列に許容する値の宣言が無い。制限を付けないなら `制限なし` と書く |
| 同じ column が仕様表に 2 行 | どちらの宣言か表から決まらない |
| repair の名前が辞書に無い | 宣言された直し方の名前を部品が知らない。覆う違反が決まらない |
| 必須列が仕様表に無い | 識別子の列が仕様表に無い、または埋まっていなければ違反とする列の宣言が 1 つも無い |
| 仕様表に無い列が行に在る | 仕様表が知らない列が行に在る。どの宣言で判定するか決まらない |
| 行の識別子が重複 | 同じ識別子の行が 2 行ある。どの行の話か報告で決まらない |
| 判定前に出力を要求した | 3 段を通る前に、結果か渡す行を取りに来た |

理由コードは「機械では決まらない理由」の名前になっている。どう直すか(宣言を足すか、原本をもらい直すか)は
人が決める。仕様表そのものが読めない場合(登録していない型の名前、`domain` の書き間違い、型に書けない
値域の種類)は理由コードにせず、終了コード 2 で返す。

## 使い方

```
python intake_triage.py triage <行.csv> --spec <仕様表.csv> --key <識別子の列名>
python intake_triage.py report <行.csv> --spec <仕様表.csv> --key <識別子の列名> --format csv
python intake_triage.py init   <仕様表.csv>
```

終了コードは 0 = 全ての行がそのまま通る / 3 = そのまま通る以外の行が在る、または理由コードで止まった /
2 = 仕様表か引数の不備。バッチの中に置いて 3 で止められる。`--key` は既定を持たない。

```python
from intake_triage import Spec, triage

t = triage(rows, Spec.load("仕様表.csv"), "識別子の列名")
if t.report.ok:
    print(t.report.counts)              # 3 分類の件数
    for v in t.violations():
        print(v.key, v.column, v.value, v.violation, v.judgment, v.repair)
    print(t.share()["分母に含めたもの"])  # 率は分母の内訳と一緒にしか出ない
    rows = t.handoff()                  # 全ての行がそのまま通った時だけ返る
else:
    for p in t.report.pending:
        print(p.reason, p.detail)       # この時点で行は 1 つも分類されていない
```

`violations()` が返すのは「どの行のどの列が、どの宣言とどう違うか」までで、**問い合わせの文面は作らない**。
宛先・依頼の内容・業務上の優先順位は人が決める。

## 前後の工程

前の工程(形の違う表を宣言どおりに読み替える部品 → 2 つの軸から足して止める関所)を通った行をそのまま
受け取り、通った行だけを次の工程(取込用 CSV の書き出し)に渡せる形で返す。この部品自身は読み書きを
持たないので、「仕分けはまだなのに出力はもうできている」という状態が作れない。

## テストと fixture

```
python -m pytest tools/intake_triage -q        # 75 passed
python fixtures/make_fixtures.py               # 合成 fixture を作り直す
```

fixture は全て合成データで、人・金額・取込仕様はすべて架空。`gyou.csv` は 18 行で、6 行は違反なし、
12 行は 1 行につき 1 か所だけ宣言から外した値を置いてある。`shiyou.csv` と `shiyou_fugou_nashi.csv` の差は
1 欄(ある列の `repair`)だけで、そこだけで 2 本目と 3 本目の線が動く。`test_measure_*` が記事に載せた数値の
出どころで、固定の fixture から決定論的に出る値を `assert` で固定している。

## できないこと

- 分類が合っていても、取込先が実際にその行を受け取るとは言えない。見ているのは手元の仕様表の宣言だけで、
  取込先に投げて確かめてはいない
- 値が業務として正しいかは判定しない。「宣言された型と値域に照らしてどこに落ちるか」までが仕分けの範囲
- **宣言が覆うと言った違反は、実際には直せない値でも 2 本目に入る**(暦に無い日に `区切りを外して 8 桁に`
  が宣言されている場合など)。宣言の正しさは判定しない。だから 2 本目は「人が宣言した範囲」であって
  「機械が直せる範囲」ではない
- 違反は 1 列につき 1 つだけ返す(型 → 値域の順で最初に当たったもの)。同じ列に 2 つ重なっている場合、
  2 つめは 1 つめを直した後にもう一度かけて見つける
- 宣言した列が行に無ければ、その列は全行で空として判定される(`required` なら全行が 3 本目に落ちる)。
  黙って通ることはないが、「列が無い」という理由コードは持たない
- 直し方の名前は部品に登録した 8 つだけ。足りない形は名前を 1 つ登録してから宣言する
- 文字コードも区切りも扱わない。この部品は読み込んだ行を受け取る
