# tally_gate — 人ごとと項目ごとに足して、両方が合うまで次に渡さない

支給控除の一覧は「人 × 項目」の表だ。人ごとに横へ足した差引の額、項目ごとに縦へ足した集計行、そして総計の
3 つは、**同じ数字集合**から出てくる。だから「3 つが全部一致するまで取込用の出力を作らない」という関所が作れる。

この部品はその関所だが、要点は検算そのものより **軸を変えると見える壊れ方が変わる** ところにある。1 か所の値が
違えば行と列の両方に出て交点が特定できるが、符号の所属を取り違えた行は人ごとの合計では出ても項目ごとの合計では
出ず、2 か所の差が打ち消し合う形は総計では消える。不一致は「どの軸で見えたか」の分類で返す。

持たせていないものが規律になっている。

- **許容誤差の引数を持たない**(`tolerance` / `atol` / 丸めて吸収する経路が無い)。差が 1 円でも不一致
- **既定の丸めを持たない**(宣言表の `rounding` 列から取る。空欄の項目は評価せずに止める)
- **書き出しを持たない**(全部一致した時に次の工程へ渡す行を返すだけ。ファイルはこの部品からは開かない)
- **業種の語彙を持たない**(`group` の名前・恒等式・集計行の名前・識別子の列名は、全て呼び出し側が宣言する)

stdlib のみ(csv / json / decimal / argparse / hashlib)、依存なし。

## 入力は 2 つ

明細は 1 枚の CSV で、行が人、列が項目、値が金額。1 行だけ集計行で、その識別子は呼び出し側が宣言する。

宣言表は項目 1 つが 1 行。

| 欄 | 意味 |
|---|---|
| `item` | 項目の名前(明細の列の見出しと一致する) |
| `group` | その項目がどの group に属するか。名前は呼び出し側が決める(部品は意味を知らない) |
| `sign` | その項目を group の中で足すときの符号(`+` / `-`)。印字が符号なしの項目に `-` を付ける |
| `rounding` | 丸めの名前。**空欄は許さない** |
| `source` | 出典。差の報告に載る |

恒等式は group の名前だけで書く。`支給 - 控除 = 差引` のように、左辺が ± の並び、右辺が group 1 つ。
項目の名前も業種の語彙も恒等式には出てこない。

## 検査(順序を固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 0 | 宣言表と明細が噛み合うかを見る | 理由コード 7 種(下の表)。1 件でもあれば 3 つの検査に進まない |
| 1 | 行方向。人ごとに group へ足し、恒等式の形で差引の列と突き合わせる | 差があれば `row` の差として残す |
| 2 | 列方向。項目ごとに全員ぶんを足し、集計行と突き合わせる(**印字されたままの値**を足す = 符号は使わない) | 差があれば `column` |
| 3 | 総計。行方向の和(人ごとの左辺を全員ぶん)と、列方向の和(集計行から作った左辺)を 2 経路で突き合わせる | 差があれば `total` |
| 4 | 3 つが全部一致した時だけ、次の工程へ渡す行を返す | 1 つでも差があれば返さない |

3 つの検査は常に全部走る。途中で止めないのは、**どの軸まで見えたか**が壊れ方の形を示すからだ。

## どの軸で見えたか(分類)

| 分類 | 意味 |
|---|---|
| `all_agree` | 3 つ全部一致。この時だけ `handoff()` が行を返す |
| `row_only` | 人ごとの合計だけに出た(符号・group の宣言の取り違えなど) |
| `column_only` | 項目ごとの合計だけに出た |
| `invisible_in_total` | 行と列には出たが総計では消えた(差が打ち消し合う形)。交点は特定できる |
| `row_and_column` | 3 つ全部に出た。交点が特定でき、総計でも消えなかった |
| `column_and_total` | 項目ごとと総計に出たが、人ごとには 1 件も出なかった(人が抜けた形など) |
| `total_only` / `row_and_total` | 名前はあるが到達しない(下記) |
| `not_checked` | 理由コードで止まり、3 つの検査に進まなかった |

`report.crossing()` は、行と列の両方に差が出た時の交点(人 × 項目)の組を返す。行 1 件 × 列 1 件なら 1 組に
決まるが、打ち消し合う形では 2 件 × 2 件 = 4 組になり、**どれが本当の交点かは決まらない**。

**列方向が全部一致すれば総計も必ず一致する**(項目ごとの合計が集計行と全部一致するなら、それを恒等式の形に
並べ直した総計も一致する)。だから `total_only` と `row_and_total` には到達しない。名前だけ置いてある。
`tests/test_tally_gate.py::test_total_is_implied_by_column` がこれを見ている。

## いつも成り立つこと

結果は 2 通りしかない。**3 つの検査が全部一致して、次の工程へ渡す行が返る**か、**行は返らず、理由コードか
「どの軸で見えたか」の分類と差の一覧が返る**か。どちらの場合も、この部品からファイルは 1 つも開かれない。

この 1 文は `tests/test_tally_gate_property.py` が性質テスト(hypothesis)で確かめている。人ごとの差引と
集計行をテストの中の計算でそろえた表を乱数で作り、半分の確率で 1 か所だけ壊して(金額を変える・読めない値に
する・空欄にする・丸めの名前を消す・人を 2 行にする・集計行を消す・集計行の値を変える・宣言表に無い列を足す)、
毎回この 1 文が成り立つかを見る。乱数は固定で、毎回同じ 300 通り。足し直しは道具の関数を使わず、丸めも含めて
テストの中で別に書いている。

## 止まる理由コード(`REASONS`)

| 理由コード | 意味 |
|---|---|
| `rounding 空欄` | 宣言表の項目に丸めの名前が無い。部品は既定の丸めを持たない |
| `group 未宣言` | 宣言表の項目に group の宣言が無い。どの軸にも足せない |
| `項目が宣言表に無い` | 明細に、宣言表に無い列がある。符号も丸めも決まらないので足さない |
| `同じ人が 2 行` | 同じ識別子の行が 2 行ある。その人の横の合計が表から決まらない |
| `集計行が無い` | 宣言された名前の集計行が明細に無い。項目ごとの合計の突き合わせ先が無い |
| `数字として読めない値` | 金額の欄が数として読めない(全角数字・単位つきなど) |
| `検査前に出力を要求した` | `check()` を通る前に、次の工程へ渡す行を取りに来た |

表そのものの不備(恒等式が読めない・`sign` が `+` `-` 以外・登録されていない丸めの名前・同じ項目が 2 行・
恒等式に出てこない group・識別子の列が無い)は理由コードにしない。表を直すべき話なので、例外にして終了コード 2 で返す。

全角数字は `Decimal("８")` がそのまま通ってしまうので、金額の形(半角数字・符号・小数点・桁区切りのカンマだけ)
を先に見ている。空欄は 0 として足す(空欄と 0 は区別しない)。

## 丸めの名前

`formula_table`(数式を表の行に置く部品)と同じ 4 つで、振る舞いもそろえてある。

| 名前 | 振る舞い |
|---|---|
| `50銭以下切捨て` | 50 銭以下を切り捨て、50 銭を超えたら切り上げる |
| `1円未満切捨て` | 1 円未満を切り捨てる |
| `円未満四捨五入` | 円未満を四捨五入する(端数 0.5 は上へ。実行環境の既定の偶数丸めとは違う) |
| `丸めない` | 端数を残したまま足す |

足りなければ `ROUNDINGS` に登録を増やす。増やす場所は 1 か所で、恒等式の側には書けない。

## 使い方

```
python tally_gate.py check  <明細.csv> --spec <宣言表.csv> --identity "支給 - 控除 = 差引" --id-column 識別子 --total-row 合計
python tally_gate.py report <明細.csv> --spec <宣言表.csv> --identity "支給 - 控除 = 差引" --id-column 識別子 --total-row 合計 --format csv
python tally_gate.py init   <宣言表.csv>
```

終了コードは 0 = 3 つ全部一致 / 3 = 理由コードか差で止まった / 2 = 表か引数の不備。バッチの中に置いて 3 で止められる。

```python
from tally_gate import Declaration, Spec, Table, check

decl = Declaration.of("支給 - 控除 = 差引", id_column="識別子", total_row="合計")
gate = check(Table.load("meisai.csv", decl.id_column), Spec.load("koumoku.csv"), decl)
r = gate.report
if r.ok:
    rows = gate.handoff()       # ここで初めて次の工程へ渡す行が手に入る
else:
    print(r.visibility)                      # どの軸で見えたか
    for p in r.pending:
        print(p.reason, p.detail)            # 理由コードで止まった時
    for d in r.diffs:
        print(d.axis, d.who, d.item, d.expected, d.actual, d.delta, d.source)
    print(r.crossing())                      # 行と列の両方に出た時の交点
```

`handoff()` が返すのは行(`list[dict]`)だけで、書き出しはしない。取込用の CSV を書くのは別の部品
(`intake_csv`)の仕事で、その列仕様へそのまま渡せる形にしてある。

## テストと fixture

```
python -m pytest tools/tally_gate -q     # 64 passed
python fixtures/make_fixtures.py         # 合成 fixture を作り直す
```

fixture は全て合成データで、料率も金額も人も架空。実在の保険料率・税率は 1 つも入れていない。`meisai.csv` は
8 人 + 集計行 1 行、`koumoku.csv` は 8 項目で、`保険料の戻し` だけ `sign` が `-`(控除の group の中で引く側。
印字は符号なし)。保険料の列は銭を残したままにしてあり、合成した 8 人のうち 2 人が端数ちょうど 50 銭に当たる。

`test_measure_visibility` が壊れ方 6 通りを 1 つずつ仕込んで、どの軸で見えたかを数える。記事に載せた数値は
このテストが `assert` で固定しているので、値が変われば記事も変える。

## できないこと

- 合計が一致したことは「同じ数字集合を 2 つの軸から足して同じになった」までで、**値そのものが正しいとは言えない**。
  項目の所属や制度上の正しさは判定しない
- 打ち消し合う差は、総計の検査を通ってしまう。行と列には出るので交点の候補は出るが、1 つには決まらない
- 元の数字集合そのものが同じ誤りから作られていれば、どの軸から足しても同じ誤った答えになる(軸を増やしても
  この形は捕まらない)
- 丸めは「足す前に位をそろえる」ためだけに使う。その値が宣言どおりの丸めで計算されたかは確かめない
- 空欄は 0 として足す。空欄と 0 を区別したい仕様には合わない
- 軸は 2 つ(人と項目)だけ。3 軸以上(人 × 項目 × 事業所など)の突き合わせは持たない
- 恒等式は左辺が ± の並び、右辺が group 1 つの形だけ。掛け算や条件分岐を含む式は書けない
- 上の件数は合成データでの測定で、他の人の表で同じ内訳になるとは限らない
