# update_ledger — 数表の更新を「実行 1 回 = 台帳 1 行」で残す

毎年書き換わる数表(料率・限度額・等級表)を更新するとき、**更新そのものの記録が無いと
「いつ何が変わったか」を後から数えられない**。間違いが混ざった回も特定できない。

この部品は、更新 1 回について次を 1 行にして追記専用の台帳(JSONL)へ残す。
検査に落ちた回は**本番ファイルを書き換えない**(前の sha256 がそのまま次の行に繋がる)。

| 台帳の列 | 中身 |
|---|---|
| `run_at` | いつ実行したか。同じ値の行は 2 つ作れない(追記を拒む) |
| `inputs` | 取得したファイルごとの指紋(`name` / `sha256` / `fetched_at`) |
| `counts` | 差分 6 種の件数。**丸めない** |
| `changed` | 何行が動いたか。1 行が 2 つの側面で動くので `counts` の合計とは別に持つ |
| `rows_prev` / `rows_now` | 前回と今回の行数。`rows_prev + 追加 - 削除 = rows_now` が成り立つ |
| `status` / `reason` / `detail` | `ok` / `failed` と、止まった理由コード |
| `findings_total` / `findings` | 表そのものの検査で見つかった不備の数と見本 |
| `samples` | 差分の見本(先頭 3 件) |
| `applied` | 本番ファイルを差し替えたか |
| `sha256` / `prev_sha256` | この回のあと / 前の本番ファイルの sha256(**前の行の `sha256` と繋がる = 鎖**) |

入力の表の形は [asof_table](../asof_table) と同じ(`key` / `basis` / `valid_from` / `valid_to` /
`known_from` / `known_to` / `known_quality` / `priority` / `value` / `source` / `sel_*`)。CSV でも JSON でもよい。

## 差分 6 種

行の識別は `key` + `sel_*`(対象)+ `valid_from` + `known_from` + `priority`。
**順位まで識別に入れてある**のは、同じ有効期間・同じ公表時点で本則と経過措置が並ぶ表が実在するからで、
入れないと 2 行が同じ識別になって、どちらと突き合わせたかで差分の種類が変わってしまう。

| 種 | 何が動いたら数えるか |
|---|---|
| 追加 | 今回だけにある識別 |
| 削除 | 前回だけにある識別 |
| 値の変更 | `value`(および下の 3 種に入らない列。分類の分からない列は引き当てに効きうる側へ数える) |
| 有効期間の変更 | `valid_to`(開いていた行を閉じた / 期限を延ばした) |
| 公表時点の変更 | `known_to` / `known_quality`(差し替えられた・公表日の質が変わった) |
| 出典欄の変更 | `source` / `source_url` / `meta` / `note` |

1 つの行が値と出典の両方で動くことがあるので、**6 種の合計は「動いた行数」を超えることがある**。
だから `changed`(何行動いたか)を別の列に持っている。

## 止まる理由コード(この 8 つで全部)

| 理由コード | 意味 |
|---|---|
| `有効期間の重なり` | 同じ key × 対象 × priority で、有効時間も知識時間も重なる行がある |
| `期間の穴` | 同じ key × 対象 × priority で、前の行の `valid_to` と次の行の `valid_from` が離れている |
| `行数の急変` | 行数が前回から `max_row_change`(既定 0.2)を超えて動いた |
| `指紋が前回と同一なのに差分あり` | 入力の sha256 が前回と同じなのに行の差分が出た |
| `指紋が違うのに差分 0` | 入力の sha256 が前回と違うのに行の差分が 1 件も無い |
| `台帳の鎖が切れている` | 前の行の sha256 と今の本番ファイルが繋がらない / 台帳の中の件数が積み上がらない |
| `run_at の重複` | 同じ `run_at` の行がすでにある。**この 1 つだけは追記せずに拒む**(`LedgerError`) |
| `入力の列が足りない` | 入力が行の表として読めない(必要な列が無い / 日付が読めない) |

判定の順番は固定で、`台帳の鎖` → `入力の列` → `指紋と差分` → `行数の急変` → `重なり` → `穴`。
先に当たった 1 つを `reason` に書く(不備の総数は `findings_total` に別に残る)。
**関所に落ちた回も、何を変えようとした回だったかが分かるように差分の件数は残す。**

## 使い方

```
python update_ledger.py record --ledger 台帳.jsonl --now 今回.csv --prev 前回.csv \
       --output 本番.json --input 料率表=取得した.xlsx --run-at 2026-09-30T09:00:00+00:00 --apply
python update_ledger.py inventory --ledger 台帳.jsonl
python update_ledger.py replay --ledger 台帳.jsonl --at 2026-09-30T00:00:00+00:00
python update_ledger.py validate 今回.csv
```

終了コードは 0 = 通った / 3 = 理由コードで止まった・表に不備があった / 2 = 台帳か引数の誤り。出力は 1 行 JSON。

`--apply` を付けない回は**本番ファイルを触らない**(差分だけ数えて台帳に 1 行残す)。
`record` には「決まらなければ最新へ」に相当する引数が無い。

```python
from update_ledger import record, read_ledger, inventory, replay, Fingerprint

e = record("台帳.jsonl", "今回.csv", "前回.csv", "本番.json",
           (Fingerprint.of_file("料率表", "取得した.xlsx"),),
           run_at="2026-09-30T09:00:00+00:00", apply=True)
print(e.status, e.reason, e.counts, e.changed, e.sha256[:8])

entries = read_ledger("台帳.jsonl")
for row in inventory(entries):        # 1 行 1 件の時系列一覧
    print(row["n"], row["run_at"], row["status"], row["rows_now"], row["sha"])
print(replay(entries).as_dict())      # 台帳そのものの自己検査
```

`replay` は台帳を先頭から辿り、`run_at` の重複と順序、前の行の sha256 との鎖、
`rows_prev + 追加 - 削除 = rows_now` の積み上げ、指紋と差分の食い違いを見る。
`--at` を渡すとその時点までを辿って、当時の行数と本番ファイルの sha256 を再構成する。

## できないこと

- **値そのものの正しさは判定しない。** 改正の解釈もしない。何行がどう動いたかを数えて残すだけ
- **台帳の先頭の行を消されると、台帳の中からは分からない。** 鎖は前の行との繋がりで見ているので、
  先頭を切り落とすと切った跡が残らない。台帳は追記専用の置き場(版管理・追記専用ストレージ)に置く前提
- 差し替えを止めるのは検査に落ちた回だけで、**検査を通った間違った値は止められない**。関所は形しか見ない
- 上流が中身を変えずに書式だけ変えた回は `指紋が違うのに差分 0` で止まる。止まる側に倒してあるので、
  そのまま進めたい時は人が判断して次の回で通す(黙って進む経路は作っていない)
- 行数のしきい値(既定 0.2)は表ごとの事情で決める値で、根拠のある数ではない。呼ぶ側で明示する
- 入力ファイルそのものが開けない場合(取得の失敗)は台帳に行を残さずに終了コード 2 で落ちる。
  「実行 1 回 = 台帳 1 行」が崩れるのはここだけ
- 台帳は 1 つの表につき 1 本の想定。複数の本番ファイルを 1 本の台帳で混ぜると鎖が繋がらない
