# idle_rows — 引ける行をそのまま積んでも答えは変わらないので、どの問いからも参照されない行を先に数える

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [引ける行をそのまま積んでも答えは変わらないので、どの問いからも参照されない行を先に数える](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_28.html)(2026-10-28 公開)
<!-- article-links:end -->

**引ける状態にした行と、どれかの問いが実際に参照する行は別で、参照されない行を塊に積んでも
答えは変わらない。**

[context_pack](../context_pack) の回は、引いた行を AI へ渡す塊に焼く道具だった。あちらは
**積む行が決まった後**の話で、こちらは**積む行をどう選ぶか**の手前を数える。
[answer_check](../answer_check) は返ってきた文章の数値が塊に在るかの突合で、積んだのに
参照されなかった行は数えない。[handoff_edge](../handoff_edge) は求める値から下へ辿って外に
残る一手を数え、[input_chain](../input_chain) は入力の出どころを下まで辿る。どちらも
**問いの側から下へ**辿る向きで、こちらは **行の側から上へ、参照してくる相手が在るかを数える
逆向き**だ。

この部品は、行の台帳・参照の宣言表・問いの一覧の 3 枚(と理由コードの登録表)から、
rule 1 件ごとに 6 値(**参照されている / どの参照元からも参照されない / 参照元は在るが
問いから呼ばれない / 参照の宣言が無い / 照合専用** の 5 値 + 別枠 **基準日より後に有効に
なる行**)を付け、滞留している行数を **一次の空白と二次の空白に分けて** 返す。
**引かない。計算しない。式を評価しない。時計を読まない。数えるだけだ。**

持たせていないものが規律になっている。

- **参照を推測で補わない**(rule 名の文字列が近いから参照と見なす経路が無い。文字列の
  近さを測る呼び出しをこの部品は 1 つも持たない。宣言表に無い組は参照 0 として数え、
  「収録済だから参照されているはず」の既定も無い)
- **滞留の理由を決めない**(理由コードは台帳の列を写して数えるだけで、判定に 1 度も使わない。
  登録表に無いコードは別枠の一覧に出し、未実装か未収録かを当てる経路が無い)
- **照合専用と宣言された行を滞留に数えない**(由来の欄が照合専用の行は別の値に出て、
  滞留している行数に足される経路が無い。引く対象でないと宣言された行を、参照されていない
  行の件数に混ぜない)
- **一次の空白と二次の空白を同じ列に潰さない**(どの参照元からも指されない行と、指す参照元は
  在るがその参照元を呼ぶ問いが無い行を、**別の値と別の行数で返す**。これが骨の物理形)
- **未来有効行を滞留に混ぜない**(基準日は必ず問いの一覧の列で、現在時刻を読む呼び出しが
  1 つも無い。**同じ入力なら何日後に走らせても同じ答えになる** = [env_match](../env_match) の
  回で書いた「判定に入れない欄」をここでも守る。[future_row](../future_row) の回と役割を分ける)
- **大きさを見積もらない**(返るのは rule の数と行数だけ。長さや量を掛ける経路が無く、
  入力が小さくなると主張する欄も無い)
- **参照されない行の是非を判定しない**(出力に順位の欄も勧めの欄も無い。残すかどうかは表を
  持つ人が決める)
- **件数を割合にしない**(件数と行数と 3 つの分母の内訳だけを返す)
- **実際に何回呼ばれたかは数えない**(呼び出しの記録を読む経路が無い。数えるのは宣言の上での
  参照だけで、そのことを入力の形で明示している)
- **参照の仕方は記録するだけ**(`別の式経由` と書いてあっても、2 段目は辿らない。辿るのは
  「その参照元を要る参照元に挙げた問いが在るか」の 1 段だけ)
- **出典の欄が空の行は使わずに止まる**
- **行を引かない・値を計算しない・式を評価しない・原文を取りに行かない**(評価器も
  ネットワーク経路も持たない。塊を組むのは [context_pack](../context_pack)、返りの突合は
  [answer_check](../answer_check) の仕事で、ここに寄せない)
- **この部品自身の「読めない」を、測っている相手の「参照されない」と同じ欄に入れない**
  (4 枚のどれかが 1 行でも壊れていたら 1 件も数えず、理由コードだけを返す。6 値は全て 0 に
  なり、滞留している行数も 0 行になる)
- **入力表を書き換えず、行も宣言も生成しない**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない。行順にも依らない)
- **数は整数だけ**(行数も件数も整数で、float を使う経路が無い)

## 入力 — 3 枚の表 + 理由コードの登録表

行の台帳は 8 列。**1 つの rule が 1 行**で、ここが「引ける状態にした行」の側になる。

| 列 | 意味 |
|---|---|
| `table_id` | 数表 id(空欄・区切り文字入りは「表として読めない」) |
| `rule_id` | rule id(同じ id が 2 行あると**止まる**。同じ id が 2 つの数表に跨っても**止まる**) |
| `rows` | 行数(0 以上の整数)。小数は読めない |
| `origin` | 由来(`自前抽出` / `上流` / `照合専用`。登録外は「表として読めない」) |
| `valid_from` | 有効開始日(空欄可。`YYYY-MM-DD`。基準日より後なら**別枠**) |
| `reason` | 滞留の理由コード(空欄可。登録表に無ければ**別枠の一覧**へ) |
| `reason_source` | 理由の出典(登録表が「要る」と言うコードで空欄なら**止まる**) |
| `source` | 出典(ファイル名 + 行番号)。空欄は**止まる** |

参照の宣言表は 5 列。**1 つの (参照元, rule) の組が 1 行**で、ここが「実際に参照する側」の
宣言になる。

| 列 | 意味 |
|---|---|
| `ref_id` | 参照元 id(式 または 問い の id) |
| `ref_kind` | 参照元の種別(`式` / `問い`。登録外は「表として読めない」) |
| `rule_id` | 参照する rule id(台帳に無い id は**別枠の一覧**へ。止めない) |
| `how` | 参照の仕方(`式の入力` / `問いが直接引く` / `別の式経由`)。**記録するだけで判定に使わない**。種別と食い違えば**止まる** |
| `source` | 出典(空欄は**止まる**) |

問いの一覧は 6 列。**1 つの (問い, 要る参照元) の組が 1 行**。1 つの問いが 2 つの参照元を
要るときは、問い id を分けて 2 行書く(`needs` に区切り文字で並べる経路が無い)。

| 列 | 意味 |
|---|---|
| `question_id` | 問い id(同じ id が 2 行あると「表として読めない」) |
| `wants` | 求める値 |
| `needs` | その値に要る参照元 id。どの宣言にも無い id なら**止まる** |
| `asof` | **基準日**。**1 行だけ埋める**(2 通りあると読めない、1 つも無いと読めない) |
| `swap` | 入れ替え方(`逆順` / `両端入れ替え` / `1 つずらす`)。`verify` が使う宣言 |
| `source` | 出典(空欄は**止まる**) |

理由コードの登録表は 3 列(`code` / `means` / `source_needed`)。**ヘッダだけでも読める**
(= 理由コードを 1 つも登録していない状態は正常で、そのとき全ての理由コードが別枠の一覧へ
出る)。`source_needed` は `要る` / `要らない` で、登録外は「表として読めない」。

## 分け方 — rule 1 件に付く 6 値

| 行の形 | どうするか | 6 値 |
|---|---|---|
| 由来が照合専用 | 引く対象でないと宣言された行なので滞留に数えない | 照合専用 |
| 有効開始日が基準日より後 | 分母から外す | 基準日より後に有効になる行 |
| その数表を指す宣言が 1 行も無い | 調べていないことと、調べて指されていないことを分ける | 参照の宣言が無い |
| 宣言は在るが、この行を指す宣言が無い | **一次の空白** | どの参照元からも参照されない |
| 指す参照元は在るが、その参照元を要る参照元に挙げた問いが無い | **二次の空白** | 参照元は在るが問いから呼ばれない |
| 指す参照元が在り、その参照元が問いから呼ばれている | 滞留に数えない | 参照されている |

上から順に見るので、**「参照の宣言が無い」と「どの参照元からも参照されない」は別の値になる**。
前者は宣言の記録そのものが無い話で、後者は記録の中身の話だ。やることも違う。前者は先に参照の
宣言を書く番で、後者は残すかどうかを決める番になる。

## 一次の空白と二次の空白 — 1 つに潰さない

| 値 | 指している参照元 | 呼ばれている参照元 | 読み方 |
|---|---|---|---|
| どの参照元からも参照されない | 0 件 | 0 件 | 引けるが、引く相手がどこにも宣言されていない |
| 参照元は在るが問いから呼ばれない | 1 件以上 | 0 件 | 参照する式は在るが、その式を呼ぶ問いが無い(上に来る値が立っていない) |

この 2 つを「参照されない行」の 1 つに潰すと、塊に積む行を選ぶときに同じ資格で並ぶ。
けれど二次の空白は、**上に来る値が 1 つ立つだけで参照される行**で、一次の空白は参照の宣言を
書くところから始まる。やることが違うので、値も行数も別にした。

## 件数の検算 — 5 通りの数え方が合う

- **6 値の件数の合計 = rule の数**
- **5 値の合計 = 参照候補の数**(基準日より後に有効になる行は分母の外)
- **数表ごとの内訳の合計 = rule の数**(rule 1 件はちょうど 1 つの数表に入る)
- **由来ごとの行数の合計 = 全体の行数**(由来は 3 通りで、1 行はちょうど 1 つに入る)
- **6 値ごとの行数の合計 = 全体の行数**、かつ **一次の空白 + 二次の空白 = 滞留している行数**

5 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
分母は rule の数 / 参照候補の数 / 別枠の数 の 3 つを必ず付ける。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- rule 1 件ごとに、6 値のどれか 1 つが付き、**6 値の合計が rule の数**に等しく、**5 値の合計が
  参照候補の数**に等しく、**数表ごとの内訳の合計も rule の数**に等しく、**由来ごとの行数の
  合計と 6 値ごとの行数の合計がどちらも全体の行数**に等しく、**一次の空白と二次の空白の
  行数の和が滞留している行数**に等しく、**照合専用の行と基準日より後に有効になる行は滞留の
  行数に入らず**、**一次の空白の行は指している参照元が 0 件**、**二次の空白の行は指している
  参照元が 1 件以上で呼ばれている参照元が 0 件**、**理由コードを全部空にしても 6 値と滞留して
  いる行数が動かず**、判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を
  入れ替えても同じバイト列**になる
- または、1 件も数えずに理由コードが返る(数えた rule や指紋を取りに行くと例外になる)

どちらの場合も、この部品は 4 枚の表を 1 文字も書き換えない。

この 1 文を `tests/test_idle_rows_property.py` の `@given` テストが確かめている(数表を
1〜3 つ、その中の rule を 1〜2 件ずつ、由来を 3 通り、有効開始日を 3 通り、参照の宣言を
0〜3 本ずつ、問いを 1〜2 件、理由コードを 5 通りから引く。3 割くらいの確率でどこか 1 か所を
崩し、崩し方 10 通りが「1 件も数えずに止まる理由コード」10 個に 1 対 1 で対応している。
乱数は固定で毎回同じ 200 通り)。**6 値の分け方はテストの側で別に実装している**(部品の
`judge` / `six` を呼ばない)。同じファイルの 2 本目は「照合専用の行と未来有効行は滞留に
入らない」ことだけを、由来 × 有効開始日 × 指されているか × 呼ばれているか の総当たりで
見ている(上限 300)。

この性質テストは、書いている途中で 1 つ捕まえた。**最初は「照合専用と未来有効行は滞留に
入らない」を、合成した 2 行の表で確かめようとして落ちた**。片方の行を呼ぶ問いを 1 件だけ
置いていたので、その問いの要る参照元を替えたとき、**見ていない方の行が二次の空白に落ちて
いた**。滞留の行数が 0 にならない理由が、測りたかった行とは別のところに在った。問いを 2 件に
分けて、見ていない方の行が常に参照されている形にしてから、測りたい 1 行だけが動くようにした。
**一次と二次を分けて数える道具を、分けずに試そうとして詰まった形**になる。

## 止まる理由コード(13 個)

4 枚の表の側。1 件も数えずに止まるものが 10 個。

`出典の欄が空` / `同じ rule id が台帳に 2 行ある` / `同じ rule id が 2 つの数表に跨っている` /
`同じ参照元 id と rule id の組が宣言表に 2 行ある` /
`登録表が出典を要ると言うコードなのに理由の出典が空` /
`照合専用の行に滞留の理由コードが入っている` / `照合専用の行を指す参照の宣言が在る` /
`問いが要る参照元を指す宣言が 1 行も無い` / `参照元の種別が問いなのに問いの一覧に無い` /
`参照元の種別と参照の仕方が食い違う`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄や区切り文字入り・同じ問い id が 2 行・由来や種別や参照の
仕方が登録外・行数が 0 以上の整数でない・日付の形が違う・その月に無い日付・基準日が 1 つも
無いか 2 通り・登録外の入れ替え方・入れ替え方の宣言が 2 通り・同じ理由コードが登録表に 2 行・
出典が要るかが登録外、は**「表として読めない」**(終了コード 2)で、理由コードには混ぜない。

## 使い方

```
python idle_rows.py init ひな型/
python idle_rows.py check 行の台帳.csv 参照の宣言.csv 問いの一覧.csv 理由コード.csv
python idle_rows.py idle  行の台帳.csv 参照の宣言.csv 問いの一覧.csv 理由コード.csv
python idle_rows.py verify 行の台帳.csv 参照の宣言.csv 問いの一覧.csv 理由コード.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、宣言された入れ替え方で
3 枚の行順を入れ替えても同じ出力になるか、件数の合計が 5 通りとも合うか、そして 2 つの写しだ。
**宣言 1 行を外した写し**では、「参照されている」が 1 減って「どの参照元からも参照されない」が
1 増え、**一次の空白の行数がその rule の行数ちょうどだけ増える**こと(二次の空白は動かない)。
**問い 1 件を外した写し**では、その問いだけが呼んでいた参照元が指す行が「参照元は在るが問いから
呼ばれない」へ移り、**二次の空白の行数だけが増える**こと(一次の空白は動かない)。
1 件の問いは複数の rule に効くので、**動く rule を入力から先に数えておき、外した後の件数が
その数と合うか**を見る。写しはメモリの中だけで、入力の表には 1 文字も書かない。

終了コードは、別枠と止まった行が 0 件のときだけ 0、在れば 3、表として読めなければ 2。
**参照されない行を残すべきかどうかは、この終了コードにも出力にも出さない。**

関数でも呼べる。

```python
import idle_rows as I

t = I.idle_rows(I.Ledger.load("行の台帳.csv"), I.Declarations.load("参照の宣言.csv"),
                I.Questions.load("問いの一覧.csv"), I.Registry.load("理由コード.csv"))
if t.report.ok:
    print(t.counts()["滞留している行数"], t.unreachable_chains())
```

## テストと fixture

```
python -m pytest tools/idle_rows -q
python fixtures/make_fixtures.py     # 合成の 4 枚と、崩した表 39 枚を書き直す
```

`fixtures/` に入っているのは合成した 4 枚(台帳 14 行 = 277 行 / 宣言 9 行 / 問い 3 件 /
登録表 3 行)と、理由コードと「表として読めない」を出すために 1 か所だけ崩した表 39 枚だ。
**実在の料率・金額・取引先名は 1 つも入っていない。** 数表 id も rule id も参照元 id も架空で、
`H1` `K11` `F1` `Q1` のような記号にしてある。**rule の数と行数の桁(14 rule / 277 行、
うち滞留 196 行)だけは手元の記録と同じ形にそろえてある**(値は架空)。

## できないこと

- **数えるのは宣言の上での参照だけで、実際に何回引かれたかは数えない。** 呼び出しの記録を
  読む経路が無いので、「宣言は在るが誰も呼んでいない」状態はこの部品では見えない
- **参照の宣言そのものを書くのは人の仕事。** 式の入力一覧から機械的に起こせる場合もあるが、
  この部品はその変換を持たない(持つと、宣言の無い状態を「参照されない」と区別できなくなる)
- **辿るのは 1 段だけ。** 式が式を呼ぶ連なりを 2 段以上辿らないので、`別の式経由` と書かれた
  参照元が間接的に問いへ繋がっていても、この部品は繋げない。繋げたいときは問いの側で
  その参照元を要る参照元として宣言する
- **滞留の理由は判定しない。** 未実装なのか、未収録なのか、照合専用なのか、未来有効行なのかを
  分けないので、理由は読む人が書くことになる(登録表に無いコードは別枠に出るだけだ)
- **残すかどうかも判定しない。** 参照されない行に順位も勧めも付けないので、残すかどうかは
  表を持つ人が決める
- **入力が小さくなる量は出さない。** 行数は返るが、長さや量に換算する経路は持たない
- **基準日は読む人が与える入力で、この部品は「いま」を知らない。** 未来有効行の切り方も
  基準日に従う([future_row](../future_row) の回と役割を分ける)
- **行を引かない・計算しない。** 塊を組むのは [context_pack](../context_pack)、返りの突合は
  [answer_check](../answer_check) の仕事で、ここは数えるだけになる
- 上の件数は、合成した 4 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
