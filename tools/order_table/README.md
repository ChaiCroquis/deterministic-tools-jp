# order_table — 同じ中身でも行の順は変わるので、並べ方を表に書いてから並べる

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [同じ中身でも行の順は変わるので、並べ方を表に書いてから並べる](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_11.html)(2026-10-12 公開)

**行の並べ方を宣言しないまま並べると、中身が同じでも出力のバイト列が変わる。** 同じ 12 行を同じ
処理に流しても、入力の行順が違えば出力の行順が違い、差分も sha256 も毎回ずれる。
[update_ledger](../update_ledger) の台帳には「差分 0 なのに本番ファイルの sha256 が動いた」行が
実際に 1 行あり、「同じ実行時刻で、どちらが先かが台帳から決まらない」行も 2 行あった。

この部品は並び順を **宣言表からだけ** 取り、宣言された鍵で行の順が一意に決まるかを見て、
決まらなければ **並べずに止まる**(同値の組の件数・関与した行数・分母の内訳を付けて返す)。

持たせていないものが規律になっている。

- **宣言表に無い列で並べない**(鍵を自然文や列名から推測して足す経路が無い。
  [variant_fan](../variant_fan) の「軸を推測して足さない」をそのまま継ぐ)
- **同値の組が残ったら並べずに止まる**(安定ソートの結果を返す経路が無い = 入力順に依存した
  出力を黙って渡さない。これが上の観測を出力の形にしたところ)
- **行番号・連番・ハッシュを振って一意にしない**(鍵が足りないことを隠す経路が無い。足すべき鍵の
  候補も提案しない = 決めるのは宣言を書く人)
- **ロケール依存の照合順を使わない**(文字列はコードポイント列としてだけ比較。NFKC も異体字の
  寄せもしない = [jp_name](../jp_name) / [jp_charset](../jp_charset) の領域に手を出さない)
- **値の種類が宣言されていない列は止まる**(文字列として並べて `10` が `9` の前に来る経路が無い)
- **欠損の置き場所が宣言されていない列は止まる**(空欄を黙って先頭や末尾に寄せない。空欄を 0 や
  直前の行で埋める経路も無い)
- **float が混ざったら止まる**(数は整数か Decimal の宣言どおりにだけ比較。
  [formula_table](../formula_table) / [variant_fan](../variant_fan) の規律を継ぐ)
- **許容誤差・近似一致の引数を持たない**(近い値を同じ値として束ねない。相異なるかはバイト列か
  宣言された種類での一致でだけ決める。[tally_gate](../tally_gate) と同じ)
- **一意になった率を単独で返さない**(同値の組の件数・関与した行数・分母(全行数と鍵の組数)の
  内訳を必ず併記。[check_census](../check_census) / [scope_ledger](../scope_ledger) /
  [variant_fan](../variant_fan) と同じ)
- **入力表も宣言表も書き換えず、列を足さない**(直す・補う経路が無い)
- **出典の欄が空の宣言行は使わずに止まる**(誰の宣言由来かを辿れない鍵で並べない。
  [source_pin](../source_pin) / [reader_registry](../reader_registry) と同じ)

## 入力 — データ表と並び順の宣言表の 2 枚

データ表は普通の CSV(1 行 1 件)。宣言表は 8 列で、業種の語彙を 1 つも持たない。

| 列 | 意味 |
|---|---|
| `rank` | 順位。**鍵の行**はここに 1 以上の整数を書く(空欄の行は候補の並びを書く行) |
| `column` | 列名。データ表のヘッダに無ければ止まる |
| `direction` | 向き。`昇順` / `降順` |
| `kind` | 値の種類。`コードポイント列` / `整数` / `Decimal` / `日付` / `宣言された列挙`。空欄は止まる |
| `missing` | 欠損(空欄)の置き場所。`先` / `後`。空欄は止まる |
| `choices` | 種類が `宣言された列挙` の列について、候補の並びを `\|` で区切って書く行で使う |
| `source` | その宣言の出典(記事か README のファイル名 + 行番号)。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が入力表の行順を入れ替えるときの宣言(全行で同じ値) |

宣言表の行は 2 種類ある。`rank` のある **鍵の行** と、`rank` が空で `choices` のある
**候補の並びの行**(列挙の順序をどこから取るか)だ。候補の並びの行が、鍵の行に無い列名を指していたら
止まる(`宣言表に無い列名`)。

```csv
rank,column,direction,kind,missing,choices,source,swap
1,支給日,昇順,日付,後,,articles/07_asof_table.md L28,逆順
2,区分,昇順,宣言された列挙,後,,articles/09_update_ledger.md L58,
,区分,,,,甲|乙|丙,articles/09_update_ledger.md L58,
3,社員番号,昇順,整数,先,,articles/05_intake_csv.md L24,
```

## 欠損と向きは別のこと

欠損の置き場所は **宣言どおりにだけ** 掛かり、向きには引きずられない。`降順` にしても、
`missing` が `後` の列の空欄は後ろに残る。空欄を 0 として並べたり、直前の行の値で埋めたりする経路は
無い(値そのものを触らない)。

## 値の種類が並び順を決めている

同じ列でも、`整数` と宣言するか `コードポイント列` と宣言するかで並びが変わる。

```
整数            2 / 7 / 8 / 9 / 10 / 12 / 31 / 45 / 60 / 100 / 103
コードポイント列  10 / 100 / 103 / 12 / 2 / 31 / 45 / 60 / 7 / 8 / 9
```

`Decimal` と宣言した列では `829` と `829.0` は **数として等しい = 同値** になり、
`コードポイント列` と宣言した列では別の値のまま残る。どちらが正しいかは部品が決めない。
種類が空欄の列は止まるので、「文字列として並べたら 10 が 9 の前に来た」は起きない。

## いつも成り立つこと

並べた結果は 2 通りしかない。

- 出力は入力の行の並べ替えにちょうどなっていて(1 行も増えず減らず書き換わらず、列も増えない)、
  行の順は宣言された鍵だけで決まり(**入力表の行順を宣言された入れ替え方で入れ替えた表からでも
  同じバイト列**)、判定部分のバイト列に時刻・ホスト名・絶対パスが 1 つも入らない
- または、1 行も並べずに理由コードが返る(並べた表を取りに行くと例外になる)

どちらの場合も、この部品はデータ表も宣言表も 1 文字も書き換えない。

この 1 文を `tests/test_order_table_property.py` の `@given` テストが確かめている(データ表を
2〜8 行、鍵を 1〜3 本、向きと欠損の置き場所を乱数で振り、3 割くらいの確率で表のどこか 1 か所を
崩す。乱数は固定で毎回同じ 120 通り)。**期待する並びは部品の比較を呼ばず、値を順位の整数に直して
から並べ替えるテスト側の別実装で計算している。** 同じファイルの 2 本目は分母の恒等式と束ね方を
300 通りで見ていて、`829` と `829.0` が `Decimal` の宣言では同値になり `コードポイント列` の
宣言では別の値のまま残ることを確かめている。

## 出力 — 一意になった率は単独では返らない

`check` が返すのはデータ表の行数、鍵の列、鍵の組数、同値の組の件数、関与した行数、
順が一意に決まった行数、分母の内訳、それに「鍵は宣言された列だけ」の 1 行だ。
**率だけを返す呼び方も、option も無い。**

```
"データ表の行数": 12, "鍵の組数": 9, "同値の組の件数": 3,
"同値の組に関与した行数": 6, "順が一意に決まった行数": 6
```

同値の組には、鍵の verbatim と **データ表の行番号** が付く(行番号は読むだけで、振らない)。
`sort` は並べた CSV をそのまま標準出力に書く。**絶対パス・読んだ時刻・ホスト名は判定部分に
入れない**(別の欄「読んだ条件」に出し、sha256 の対象から外す)。

`verify` は 2 つ見る。2 回並べて判定部分のバイト列の sha256 を突き合わせ、さらに
**宣言された入れ替え方で入力表の行順を入れ替えた表でも同じ出力になるか** を実測する
(= 入力順に依存していないことを確かめる段)。入れ替え方は宣言から取り、部品は乱数の既定を持たない。
一致しなければ観測としてそのまま返す(平均も多数決も取らない)。

## 止まる理由コード(11 個)

```
宣言表が 0 行 / 順位の重複 / 出典の欄が空 / 値の種類が空欄 or 未登録 / 欠損の置き場所が空欄 /
宣言表に無い列名 / データ表に無い列名 / float の混入 / 同値の組が残る /
2 回目の判定部分がバイト列として不一致 / 行順を入れ替えた表で出力が変わる
```

`値の種類が空欄 or 未登録` は 4 つの形をまとめている(種類の欄が空 / 5 種の外 /
`宣言された列挙` なのに候補の並びの行が無い / 宣言された候補に無い値がデータに在る)。
**その列が宣言された種類として読めない** 形を 1 つの理由コードにした。

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**(表を書く側の話なので
台帳の理由コードに混ぜない)。向き・欠損の置き場所・入れ替え方が **登録の外の語** だったとき、
順位が整数でないとき、宣言表の列そのものが足りないとき、ヘッダに同じ列名が 2 つあるとき、
そして `整数` / `Decimal` / `日付` と宣言した列に **数や日付として読めない値**(`未定` など)が
在ったとき。小数や指数表記は語彙の間違いではなく宣言との食い違いなので、理由コード
`float の混入` に入る。

## 使い方

```bash
python order_table.py init ひな型/            # データ表と並び順のひな型を書く
python order_table.py check データ表.csv 並び順.csv   # 件数と分母の内訳(並べずに見るだけ)
python order_table.py sort  データ表.csv 並び順.csv   # 並べた CSV を標準出力へ
python order_table.py verify データ表.csv 並び順.csv  # 2 回 + 入れ替えた表で突き合わせる
```

終了コードは、**順が一意に決まったときだけ 0**、同値の組が残れば 3、表として読めなければ 2。
まとめて走らせる仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from order_table import Table, Order, sort_table

s = sort_table(Table.load("データ表.csv"), Order.load("並び順.csv"))
print(s.counts() if s.report.ok else [p.reason for p in s.report.pending])
```

CLI は `sort` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。
そのこともテストで固定してある。

## 読み替えた範囲(「建前と実務の乖離」の型)

- 方針側 = 公開済みの道具の README と記事に書いた宣言の verbatim(ファイル名 + 行番号 + 公開 URL)
- 実務側 = [update_ledger](../update_ledger) の台帳 11 行への観測 2 件と、合成表へのその場の実走
- 見えるのは **宣言された鍵で行の順が一意に決まるかまで**。道具の内部の並べ方そのものは見ていない
- 一致しない行に「嘘」「違反」とは書かない(出すのは宣言の verbatim と件数だけ)。宣言が書かれて
  いない理由も推定しない

## できないこと

- 判定したことは「宣言された鍵で行の順が一意に決まるか」までで、**どの並び順が業務として正しいかは
  判定しない**
- **どの列を鍵にすべきかも言わない。** 足すべき鍵の候補も提案しないので、同値の組が残ったときに
  宣言を書き直すのは人の側になる
- **宣言が十分かどうかも分からない。** 鍵が一意でも、その鍵が業務上の並び順と合っているかは別の話
- 行番号・連番を振って一意にする経路が無いので、鍵が足りない表はいつまでも止まる
- ロケールの照合順や辞書順(五十音順)では並べられない。文字列はコードポイント列としてだけ比較する
- 相異なるかは宣言された種類での一致でだけ決める。`Decimal` では `829` と `829.0` が同値になり、
  `コードポイント列` では別の値のまま残る
- 負の数・空欄以外の「欠損らしき値」(`-` や `該当なし`)は欠損として扱わない。空欄だけが欠損
- 上の件数は、合成したデータ表と宣言表に対する測定で、他の人の手元で同じ数字になるとは限らない
