# env_match — 同じ道具でも環境が違えば出力は変わるので、判定に入れない欄を先に表に書く

解説記事: [同じ道具でも環境が違えば出力は変わるので、判定に入れない欄を先に表に書く](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_12.html)(2026-10-13 公開)

**同じ入力・同じ道具でも、判定に入れる欄を宣言しないまま指紋を比べると、環境が違うだけで一致が
崩れる。** この連載の道具は毎回「同じ入力には同じバイト列」と書いていて、
[variant_fan](../variant_fan) と [order_table](../order_table) の記事では
「読んだ表の絶対パスと、読んだ時刻と、ホスト名は、判定とは別の欄に出る。この 3 つを判定部分から
外してあるのが、指紋を比べられる前提になっている」と宣言している。その 3 つで足りているかは、
一度も突き合わせていなかった。

この部品は「判定に入れる欄 / 入れない欄」を **宣言表からだけ** 取り、ラベル(= 変えた環境要素)の
あいだでバイト列を突き合わせ、欄ごとに 4 値(**一致 / 不一致 / 判定部分が取れない / 宣言が無い**)に
分ける。

持たせていないものが規律になっている。

- **宣言表に無い欄を勝手に判定から外さない**(一致させるために黙って除外する経路が無い。宣言に
  無い欄は 4 値の「宣言が無い」に入って数に残る。これが記事の骨を出力の形にしたところ)
- **外した欄の件数と分母(宣言表の行数・出力に現れた欄数)を必ず併記**し、一致率を単独で返さない
  ([check_census](../check_census) / [scope_ledger](../scope_ledger) /
  [variant_fan](../variant_fan) / [order_table](../order_table) と同じ)
- **正規化しない**(改行の揃え・空白の詰め・キーの並べ替え・数の書式の寄せが無い。寄せれば
  一致するのを一致と呼ばない)
- **許容誤差・近似一致の引数を持たない**(相異なるかはバイト列の一致でだけ決める。
  [tally_gate](../tally_gate) / [variant_fan](../variant_fan) / [order_table](../order_table)
  と同じ)
- **自分で走らせない**(子プロセスを起動せず、環境変数も読み書きしない。走らせるのは人で、
  この部品は突き合わせるだけ = [check_census](../check_census) が走らせる側、こちらは
  突き合わせる側で役割が重ならない)
- **現在の環境を既定のラベルとして混ぜない**(今の環境の値を黙って基準にしない。基準にする
  ラベルも宣言から取る)
- **差が出た理由を環境要素に割り当てない**(1 要素だけ違うラベル対でも「その要素のせい」とは
  書かず「その対で差が出た」までで止める)
- **不一致と「判定部分が取れない」を混ぜない**(4 値を潰す引数が無い。
  [answer_check](../answer_check) / [check_census](../check_census) と同じ規律)
- **不一致の行は差が現れた欄名と行番号だけ**(値は判定に入れた欄のものに限り、原因も直し方も
  書かない)
- **出力の束もラベル表も宣言表も書き換えず、欄を足さない**
- **出典の欄が空のラベル行・宣言行は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)

## 入力 — 出力の束とラベル表と宣言表の 3 つ

出力の束は、ラベル 1 つにつき `<ラベル名>.tsv` の 1 ファイル。中身は 1 行 1 欄で、
**欄名 → タブ → 値** とだけ書く(値の中にタブと改行は書けない)。

```
データ表の行数	12
sha256	94feaa4769bb…
読んだ時刻	2026-10-13T09:12:08
ホスト名	合成の端末A
```

**行の終わりは触らない。** だから端末の既定の改行が違えば、値のバイト列も違ったままになる
(CRLF で書き出した束は、どの値も復帰文字で終わっている)。道具の出力が JSON なら、
その中から「欄名と値」をこの形に書き出してから渡す。

ラベル表は 6 列で、業種の語彙を 1 つも持たない。

| 列 | 意味 |
|---|---|
| `label` | ラベル名(= 出力の束のファイル名) |
| `element` | 変えた環境要素。**空欄は止まる** |
| `setting` | 設定した値 |
| `source` | その行の出典(記事か README のファイル名 + 行番号)。**空欄は止まる** |
| `base` | 基準にするラベル名(書く行は 1 行でよい。全行で同じ値) |
| `swap` | 入れ替え方。`verify` がラベル表の行順を入れ替えるときの宣言 |

判定部分の宣言表は 4 列。

| 列 | 意味 |
|---|---|
| `field` | 欄名(出力の束の 1 列目) |
| `judge` | `入れる` / `入れない`。登録の外は「表として読めない」 |
| `reason` | `入れない` 行の理由の分類。`時刻` / `絶対パス` / `ホスト名` / `版` / `乱数の種` |
| `source` | その宣言の出典(ファイル名 + 行番号)。**空欄は止まる** |

```csv
field,judge,reason,source
データ表の行数,入れる,,articles/20_order_table.md L103
sha256,入れる,,articles/19_variant_fan.md L143
読んだデータ表の絶対パス,入れない,絶対パス,articles/20_order_table.md L146
読んだ時刻,入れない,時刻,articles/20_order_table.md L146
ホスト名,入れない,ホスト名,articles/20_order_table.md L146
```

基準は `base` に書いたラベルで、**書かれていなければ止まる**。今の環境を既定の基準として
混ぜる経路は無いし、表の 1 行目を黙って基準にすることもしない。

## 4 値 — 「取れない」と「宣言が無い」を不一致に混ぜない

| 値 | いつ入るか |
|---|---|
| `一致` | 判定に入れた欄が、全ラベルで基準ラベルとバイト列として同じ |
| `不一致` | 判定に入れた欄が、どれかのラベルで違う |
| `判定部分が取れない` | 判定に入れた欄が、どれかのラベルの出力に無い(比べる相手が無い) |
| `宣言が無い` | 出力に在るのに宣言表に無い(判定にも、外す側にも入れられない) |

`宣言が無い` が 1 欄でもあれば止まる。**宣言に無い欄を黙って判定から外せば一致は増えるが、
その経路を持たせていない。** 外せるのは宣言表で `入れない` と書いた欄だけだ。

## いつも成り立つこと

突き合わせの結果は 2 通りしかない。

- 宣言表で `入れる` と書かれた欄だけを基準ラベルのバイト列と突き合わせて 4 値に分け(一致 +
  不一致 + 判定部分が取れない = 判定に入れた欄数、判定に入れた欄数 + 判定から外した欄数 =
  宣言表の行数、宣言が無い = 出力に現れた欄のうち宣言表に無い欄の数)、判定部分に時刻・
  ホスト名・絶対パスの値が 1 つも入らず、**ラベル表の行順を入れ替えても同じバイト列** になる
- または、1 つも結果を返さずに理由コードが返る(結果や指紋を取りに行くと例外になる)

どちらの場合も、この部品は出力の束もラベル表も宣言表も 1 文字も書き換えない。

この 1 文を `tests/test_env_match_property.py` の `@given` テストが確かめている(ラベルを
2〜4 個、宣言を 1〜4 行、判定と理由の分類と値を乱数で振り、3 割くらいの確率でどこか 1 か所を
崩す。乱数は固定で毎回同じ 120 通り)。**期待する 4 値は部品の突き合わせを呼ばず、生成した値の
辞書を基準ラベルと直に比べるテスト側の別実装で数えている。** 同じファイルの 2 本目は
300 通りで「外した欄だけで差を作っても結果は一致のまま、入れた欄を 1 つ動かすと不一致になる」
ことを見ている。

## 出力 — 一致率は単独では返らない

`check` と `match` が返すのは、ラベル数・基準ラベル・対の数・宣言表の行数・判定に入れた欄数・
判定から外した欄数・出力に現れた欄数・4 値の件数・外した欄の内訳(理由の分類ごと)・
外した欄で差が出た欄数、それに分母の内訳と 2 つの固定行だ。**率だけを返す呼び方も、option も
無い。**

```
"判定に入れた欄数": 8, "判定から外した欄数": 4, "出力に現れた欄数": 12,
"4 値": {"一致": 8, "不一致": 0, "判定部分が取れない": 0, "宣言が無い": 0},
"外した欄で差が出た欄数": 4
```

対ごとの差は、ラベル名・変えた環境要素・設定した値の verbatim と、差が出た欄数だけを並べる。
**どの環境要素のせいかは書かない**(固定行「差の原因は書かない」が消せない)。`match` はさらに
不一致の欄(欄名・行番号・判定に入れた欄の値)と、宣言が無い欄を出す。

`verify` は 2 つ見る。2 回突き合わせて判定部分のバイト列の sha256 を突き合わせること、そして
**宣言された入れ替え方でラベル表の行順を入れ替えても同じ出力になるか**(= 比較結果がラベルの
読み込み順に依存していないことの実測)だ。一致しなければ観測としてそのまま返す。

## 止まる理由コード(12 個)

```
宣言表が 0 行 / ラベルが 1 つ / ラベル名の重複 / 環境要素の欄が空 / 出典の欄が空 /
理由の分類が未登録 / 宣言表に無い欄名 / 出力に無い欄名 / 判定部分が取れない /
基準ラベルが表に無い / 2 回目の判定部分がバイト列として不一致 /
ラベル順を入れ替えた表で出力が変わる
```

`判定部分が取れない`(= `入れる` 欄が出力に無い)と `出力に無い欄名`(= `入れない` 欄が出力に
無い)は分けてある。前者は突き合わせが成立しない話で、後者は宣言が出力と噛み合っていない話だ。

**`不一致` は理由コードではない。** 突き合わせは成立しているので、件数と欄名と行番号が返る
(終了コードは 3)。

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。判定・入れ替え方が
登録の外の語だったとき、列そのものが足りないとき、`入れる` 行に理由の分類が書かれているとき、
同じ欄名の宣言が 2 行あるとき、基準や入れ替え方の宣言が 2 通りあるとき、設定した値が空欄の
とき、束のファイルが無い / タブが 1 個でない / 同じ欄名が 2 行ある / 欄名が utf-8 として
読めないとき。

## 使い方

```bash
python env_match.py init ひな型/                  # 束とラベル表と宣言表のひな型を書く
python env_match.py check  束/ ラベル表.csv 判定部分.csv   # 件数と分母の内訳
python env_match.py match  束/ ラベル表.csv 判定部分.csv   # 上 + 不一致の欄と指紋
python env_match.py verify 束/ ラベル表.csv 判定部分.csv   # 2 回 + ラベル順を入れ替えて突合
```

終了コードは、**判定に入れた欄がすべて一致したときだけ 0**、不一致や止まったときは 3、表として
読めなければ 2。まとめて走らせる仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from env_match import Labels, Decl, Outputs, match

labels, decl = Labels.load("ラベル表.csv"), Decl.load("判定部分.csv")
m = match(Outputs.load("束/", labels), labels, decl)
print(m.counts() if m.report.ok else [p.reason for p in m.report.pending])
```

CLI は `match` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。
そのこともテストで固定してある。

## 読み替えた範囲(「定説の訂正」の型)

- 前提側 = **この連載自身の公開宣言の verbatim**(公開記事のファイル名 + 行番号 + 公開 URL)。
  誰も言っていない主張を立ててから崩す形(藁人形)にならないよう、入力をそう決めてある
- 観測側 = 公開済みの道具の出力の形を写した **合成の束** への、その場の実走
- 見えるのは **宣言された判定部分がラベル間で一致するかまで**。道具の内部の非決定性は見ていない
- 差が出た対はそのまま返すが、原因を環境要素に割り当てない。残差(宣言表に無い欄で出た差)は
  解釈で埋めずに「宣言が無い」として置く

## テストと fixture

```bash
python -m pytest tools/env_match -q      # 49 passed(2026-10-13 実走)
```

`fixtures/` に合成の束 4 つ(計 9 ファイル)と宣言表 1 枚・ラベル表 4 枚、それに崩した表 18 枚が
入っている。**値は全て架空で、実在の給与額・取引先名・端末名は 1 つも入れていない。**
宣言表の出典のうち 7 件はこの repo 内の実在の行(`articles/19_variant_fan.md` L143 /
`articles/20_order_table.md` L103・L104・L105・L107・L146 / `public/README.md` L50)を指し、
テストがその行を開いて宣言の語が在ることまで確かめている。残りは合成のメモ(架空)。
`fixtures/make_fixtures.py` を実行すると、崩した表ごと書き直す。

## できないこと

- 判定したことは「宣言された判定部分がラベル間でバイト列として一致するか」までで、
  **どの環境が正しいかは判定しない**
- **差の原因も言わない。** 1 要素だけ違うラベル対でも「その対で差が出た」までで止まる
- **外す欄の一覧が足りているかも判定しない。** 足すべき欄の候補も出さないので、宣言を書き直すのは
  人の側になる
- 比べられるのは **渡された出力** だけで、この部品は走らせない。だから「本当に同じ入力だったか」は
  表の外の話になる
- 寄せれば一致する差(改行・空白・数の書式)も不一致として返る。寄せる引数は無い
- 束のファイルの **末尾の改行の有無** は欄ではないので比べない(比べるのは欄ごとの値のバイト列)
- 上の件数は、合成した束と表に対する測定で、他の人の手元で同じ数字になるとは限らない
