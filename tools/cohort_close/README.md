# cohort_close — 終わると書いた行も日付で閉じるとは限らないので、対象の線で閉じる行を 1 行 1 件で並べる

数表の行の終わり方は 2 通り在る。**有効期間の終わり(日付)で閉じる行**と、**対象の線(生年月日・到達日・年齢・裁定の別)で閉じる行**だ。後者は有効期間が開いたままなので、日付の欄だけを見ると「まだ続いている行」にも「もう要らない行」にも見えてしまう。

この部品は、人が台帳に書いた分だけを使って、rule 1 件ごとに 4 値 + 別枠を付ける。**なぜその線で閉じたかは書かない。行を消してよいかも決めない。**

```
python cohort_close.py check 行.csv 線.csv 記号.csv 収録.csv
```

## 持たせていないもの

- **理由を当てない**。線を引いた理由の欄が無い。線の文字列と含む側の語を写すだけ
- **消してよいかを決めない**。rule を「まだ要る / もう要らない」の 1 値に丸める列が無い
- **対象者がいなくなる時期を当てない**。寿命も人数も推計しない。基準日は出力に写すだけで判定に使わない
- **年齢や年度生まれを日付に直さない**。補助の判定が読むのは `YYYY-MM-DD 以前` と `YYYY-MM-DD 以降` の 2 形だけ
- **語の似かたから記号を当てない**。記号は線の台帳の欄から取るだけで、線の文字列は判定に入らない(文字列を全部入れ替えても判定部分の指紋は変わらない)
- **率や合計の 1 値を返さない**。返すのは区分ごとの件数と、区分 × 収録の状態の内訳だけ
- **取りに行かない**(通信の経路が無い)。**時計を読まない**。**入力を書き換えない**。**float を使わない**

## 入力 — 4 表

どの行にも出典(ファイル名 + 行番号)の欄が要る。

### 行の台帳(4 列)

| 列 | 中身 |
|---|---|
| `rule_id` | rule の id(同じ id が 2 行在ると、その rule は別枠「id の重複」へ) |
| `end_text` | 有効期間の終わりの記載を**原文のまま**(例 `○年○月 廃止` `○年限り`。無ければ空) |
| `none_note` | 読んだ範囲に閉じ方が書かれていないと人が確かめたときだけ `閉じ方の記載なし`(ほかは空。別の語が在ると止まる) |
| `source` | 出典。空欄のとき、その rule は別枠「出典が空」へ |

### 線の台帳(5 列、1 rule に 0〜N 行)

| 列 | 中身 |
|---|---|
| `rule_id` | rule の id(行の台帳に無い id は「台帳に無い rule id を指す線」へ) |
| `line_text` | 線の文字列を**原文のまま**(例 `1970-01-01 以前生まれのみ`) |
| `side_word` | 含む側の語を原文のまま(`以前` `以降` `〜` 等。書かれていなければ空) |
| `symbol` | 線の記号(記号の登録表に在るものだけ) |
| `source` | 出典 |

### 記号の登録表(3 列)

`symbol` / `means` / `source`。ひな型には 6 つ入っている(`生年月日の線` / `到達日の線` / `年齢の線` / `裁定の別` / `文書に閉じると書いてある` / `範囲か閉じる線か書き分けなし`)。**登録表が空か、行の出典が空なら、1 件も数えずに止まる。**

`範囲か閉じる線か書き分けなし` は、その文字列が「対象の範囲」なのか「閉じる線」なのかが文書に書き分けられていないときに人が付ける記号で、付いた rule は区分に入らず別枠へ出る。

### 収録の台帳(3 列、1 rule に 0 か 1 行)

`rule_id` / `state`(`収録` `未収録` `記載なし` の 3 つだけ)/ `source`。行が無い rule には `収録の台帳に行が無い` が入り、書かれた `記載なし` とは別の値になる。**収録の状態は区分に使わない**(別の列に並べるだけ)。

## 分け方 — rule 1 件に付く 4 値と別枠

| 値 | 意味 |
|---|---|
| (A) | 日付で閉じる記載だけ在る(`end_text` が在り、線が無い) |
| (B) | 対象の線で閉じる記載だけ在る(線が在り、`end_text` が空) |
| (C) | 両方在る |
| (D) | 読んだ範囲に閉じ方の記載なし(どちらも無い) |

別枠は上から順に当たり、**4 値より先に当たる**。id の重複 / 出典が空 / 登録表に無い記号 / `範囲か閉じる線か書き分けなし` の記号が付いた線 / 閉じる記載と `閉じ方の記載なし` が同時に書かれた((A) と (D) が同時、線と (D) が同時のどちらも)。この 5 つは rule の単位で数える。6 つめの「台帳に無い rule id を指す線」だけは線の単位で、rule の件数の検算には入らない。

含む側の語が空の線が付いた rule は (B)(C) のままで、`含む側の語なし` の印が別の列に付く(向きを当てない)。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- **4 値を付けた**: rule 1 件ごとに 4 値か別枠 5 のどれか 1 つが付き、**その合計 = rule の件数**、**区分 × 収録の状態の内訳の合計 = 区分の件数**になる。有効期間の終わりの記載が空の rule は (A)(C) に入らず、線が 1 本も無い rule は (B)(C) に入らない。**収録の状態を入れ替えても、線の文字列を入れ替えても、線の台帳の行順を入れ替えても、判定部分は同じバイト列**になる
- **1 件も数えずに理由コードが返る**: 4 値や sha256 を取りに行くと例外

どちらの場合も、この部品は 4 表を 1 文字も書き換えない。

この 1 文を検査にしたのが `tests/test_cohort_close_property.py`(hypothesis、`derandomize=True`)。4 値の決め方はテストの中に別に書いてあり、部品の `judge` / `counts` を使わずに分類し直して突き合わせる。補助の判定についても、境目の日が含む側に入ることと、語が無ければどの日でも止まることを別の性質テストで見ている。

## 補助 — その生年月日は線のどちら側か

```
python cohort_close.py side 行.csv 線.csv 記号.csv 収録.csv <基準日> <生年月日>
```

記号が `生年月日の線` の線について、渡した生年月日が `線の内側` か `線の外側` かを返す。

- 読むのは `YYYY-MM-DD 以前` と `YYYY-MM-DD 以降` の 2 形だけ(後ろに `生まれ` `生まれのみ` が付いていてよい)。ほかは `読めない線`
- 境目ちょうどの日は含む側の語に従う。**`side_word` が空なら、どの日でも `含む側の語なし` で止まる**
- `side_word` が線の文字列の語と違うときも `読めない線`
- 基準日は出力に写すだけで、判定には使わない(時計も読まない)

## 止まる理由コード(4 個)

記号の登録表が空 / 記号の登録表の行の出典が空 / 収録の状態が決めた 3 つの外 / `none_note` が決めた語の外。**止まった表は 4 値を 1 件も返さない。**

表として読めないとき(列が決めた並びでない / rule が 1 件も無い / rule id が空 / 線の文字列が空 / 登録表に同じ記号が 2 行 / 収録の台帳に同じ rule id が 2 行 / 収録の台帳の rule id が行の台帳に無い)は終了コード 2。

## 使い方

```
python cohort_close.py init   ひな型/
python cohort_close.py check  行.csv 線.csv 記号.csv 収録.csv
python cohort_close.py report 行.csv 線.csv 記号.csv 収録.csv
python cohort_close.py verify 行.csv 線.csv 記号.csv 収録.csv
python cohort_close.py side   行.csv 線.csv 記号.csv 収録.csv 2026-11-18 1970-01-01
```

`report` は rule ごとの一覧と判定部分の sha256 を足す。`verify` は 5 つ見る。

- 二度走らせて判定部分の sha256 が同じか
- 線の台帳の行順を入れ替えても同じか
- 4 値 + 別枠 = rule の件数、区分 × 収録の状態の内訳の合計 = 区分の件数か
- 線 1 行を消すと、**その rule だけ**が (B) → (D)、または (C) → (A) へ動くか
- 補助の判定で生年月日を境目の前日・当日・翌日に置くと語のとおりに分かれ、語を空にすると 3 日とも `含む側の語なし` で止まるか

終了コードは、止まらず別枠も台帳に無い rule id も 0 件のときだけ 0、在れば 3、表として読めなければ 2。関数としても呼べる(`judge` / `check` / `report` / `verify` / `side` / `side_of`)。

## テストと fixture

```
python -m pytest tools/cohort_close -q
```

`fixtures/` の 4 表は合成で、**実データ・実在の名前・実在のパスは 1 つも入っていない**(rule id は記号、線の日付は架空、出典は「合成の…(架空)」)。`fixtures/make_fixtures.py` で作り直せる。

## できないこと

- **消してよいかは分からない。** 4 値を付けるところまでで、行を残すか消すかは読む人が決める
- **線が正しいかは分からない。** 線の文字列も含む側の語も台帳に人が書いたものを写すだけで、条文や公表資料と照らしていない
- **対象者がまだいるかは分からない。** 人数も時期も見ない
- **記号の割り振りは台帳を書いた人の判断だ。** 記号が変われば別枠に出る rule も変わる
- **2 形以外の線は補助の判定が読めない。** 年度生まれ・年齢・到達日は `読めない線` のまま返る
- 件数は合成した 4 表に対する測定で、ほかの人の環境で同じ数字になるとは限らない
