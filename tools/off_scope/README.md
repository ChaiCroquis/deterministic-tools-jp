# off_scope — 対象外と書いた項目も表に行が無いとは限らないので、触れている線と在り所を 1 行 1 件で分ける

「ここは別の領域だから対象外」と書いた線のすぐ外側に、**計算には要ると同じ 1 行で宣言された項目**が並んでいることがある。しかも、その領域の行が実際には表の中で動いていることがある。**「対象外」という 1 語は、少なくとも 4 つの別の状態をまとめている。**

この部品は、3 枚の台帳と登録表 3 枚から、線に触れている項目 1 件ごとに 4 値 + 別枠 7 を付ける。**収録すべきかは決めない。必須かどうかも判断しない。線を引き直さない。**

```
python off_scope.py check 項目.csv 領域.csv 在り所.csv 入る形.csv basis.csv payload.csv 2026-09-20
```

## 持たせていないもの

- **収録すべきかを決めない**。推奨・順位・点数・合計の 1 値を出す列が無い。終了コード 0 も「収録しなくてよい」ではなく「別枠と (A)(B) が台帳に無い」の意味
- **必須かどうかを判断しない**。必須の欄は入力の文字列を出典ごと写すだけで、空の行には `必須の記載なし` を入れる。要るかどうかを言い当てる辞書も分類器も持たない
- **領域の線を引き直さない**。`内` / `外` / `境界として明示` の 3 値は領域の登録表から取るだけで、判定の辞書を持たない
- **項目名から領域を推測しない**。項目名の欄は一覧に写すだけで、判定に使う経路が無い(名前を全部入れ替えても判定部分の指紋は変わらない)
- **条文や規約を読まない**。取りに行かない・走らせない・実行しない・import しない・構文解析しない・通信の経路が無い・入力フォルダの外を読まない
- **`0 件` と `欄が無い` を同じ値にしない**。行数を数えない在り所(`第2層` / `case属性` / `無い`)は `数えられない` を返し、台帳に 0 と書かれた行とは別の値になる
- **割合を単独で返さない**。カバー率の 1 値を出す列が無く、必ず 2 通りの分母(項目数と、在り所の台帳が数えた行数)が付く
- **時計を読まない**(基準日は呼び出し側が渡す)。**入力を書き換えない**。**float を使わない**(行数と件数は整数、ほかは文字列)

## 入力 — 3 枚 + 登録表 3 枚

**登録表 3 枚の行に出典が無ければ、1 項目も数えずに止まる。**

### 項目の台帳(6 列)

| 列 | 中身 |
|---|---|
| `item_id` | 項目 id(同じ id が 2 行あると止まる) |
| `name` | 項目名(**判定には使わない**。領域をこの文字から推測する経路が無い) |
| `domain` | 領域の記号(領域の登録表に在る記号だけ。無ければ別枠へ) |
| `required` | 必須の宣言(どの計算が要ると書いているかの文字列を**生のまま**。無ければ `—`) |
| `note` | 備考(原文のまま。無ければ `—`) |
| `source` | 出典(ファイル名 + 行番号)。空欄のとき、その項目は別枠「出典が空」へ入る |

### 領域の登録表(3 列)

| 列 | 中身 |
|---|---|
| `domain` | 領域の記号(同じ記号が 2 行あると読めない) |
| `stance` | この表の内か外かの宣言(`内` / `外` / `境界として明示`。ほかの語が在ると止まる) |
| `source` | 出典。空欄のとき 1 項目も数えずに止まる |

**この表だけが線を引く。** 「線の外」は `外` と `境界として明示` の 2 つで、違うのは入る形まで書かれているかどうかだ。

### 在り所の台帳(5 列、1 項目に 0〜N 行)

| 列 | 中身 |
|---|---|
| `item_id` | 項目 id(項目の台帳に無いと読めない) |
| `place` | 在り所の記号(`収録` / `照合専用` / `第2層` / `case属性` / `無い`) |
| `rows` | 行数(`収録` と `照合専用` のときは 0 以上の整数。ほかの記号で埋まっていると読めない) |
| `origin` | 由来の記号(`自前抽出` / `上流` / `—`) |
| `source` | 出典。空欄のとき、その項目は別枠「出典が空」へ入る |

**同じ項目に別の記号の行が 2 行在ると、別枠「同じ項目が 2 か所で別の行き先を宣言されている」へ出る**(どちらが本当かを決めない)。

### 入る形の宣言表(6 列、1 項目に 0 か 1 行)

| 列 | 中身 |
|---|---|
| `item_id` | 項目 id(同じ項目に 2 行在ると読めない) |
| `basis` | basis の欄名(`—` = 記載なし。登録表に無い欄名は別枠へ) |
| `payload` | payload 種別(空か `—`、または登録表に無い種別なら別枠へ) |
| `selector` | selector 次元の列挙(`/` 区切り。`—` = 記載なし) |
| `period_end` | 期間の終わりの記載(`—` = 記載なし。**何か書かれていれば閉じている**) |
| `source` | 出典。空欄のとき、その項目は別枠「出典が空」へ入る |

`period_end` は**記載の有無だけを見て、文字は読まない**。「2024 年限り」と書いてあるのか「当分の間」と書いてあるのかを道具は区別しない。

### 登録表 2 枚(basis の欄名 / payload 種別、各 3 列)

| 表 | 列 |
|---|---|
| basis の欄名の登録表 | `basis` / `means` / `source` |
| payload 種別の登録表 | `payload` / `means` / `source` |

**登録表に無い欄名は、候補の側にだけ在るものとして別枠へ出す。** 「入る形まで書いたのに、その欄名は登録表にまだ無い」を、書いていないことと同じ値にしない。

## 分け方 — 項目 1 件に付く 4 値(欄は 5 つ)と別枠 7

| 値 | 意味 |
|---|---|
| (A) | 線の外と宣言され、在り所が `無い` で、必須の宣言が在る |
| (B) | 線の外と宣言されたのに `収録` か `照合専用` の行が在る(行数と由来つき) |
| (C) | 線の外と宣言され、行は無いが行き先が宣言されている(`第2層` / `case属性`) |
| (D) | `境界として明示` と宣言され、入る形(basis / payload / selector)まで書かれている |
| (D) | `内` と宣言(この部品の対象の外) |

別枠 7 は上から順に当たり、**4 値より先に当たる**。出典が空 / 領域の記号が登録表に無い / 同じ項目が 2 か所で別の行き先を宣言されている / basis の欄名が登録表に無い / payload 種別が空か登録表に無い / 期間の終わりの記載が在る / 必須の宣言も在り所の宣言も無い。

**(D) の 1 つめに進むのは `境界として明示` の項目だけ**だ。`外` と言い切った項目に入る形が書かれていても (D) にはならず、列に出るだけになる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- **4 値を付けた**: **項目 1 件ごとに 4 値の 5 欄か別枠 7 のどれか 1 つ**が付き、**その合計 = 項目の件数**、**領域の宣言ごとの内訳の合計も在り所ごとの内訳の合計も同じ数**になる。**領域が `内` と宣言された項目は (A)(B)(C) と (D) の 1 つめに入らず**、**登録表に無い記号の項目は 4 値に入らず**、**行数を数えない在り所は `数えられない` を返して 0 件と同じ値にならず**、**必須の欄が空で在り所も `無い` 項目は 4 値に入らず**、**(A) は在り所が `無い` か行が無い項目だけ**になる。2 通りの分母は必ず両方そろって出る。判定部分に項目名も必須の宣言の文字も絶対パスも入らず、**項目名を全部入れ替えても、6 枚の行順を 3 通りに入れ替えても、同じバイト列**になる
- **1 項目も数えずに理由コードが返る**: 4 値や sha256 を取りに行くと例外

どちらの場合も、この部品は 6 枚の表を 1 文字も書き換えない。

この 1 文を検査にしたのが `tests/test_off_scope_property.py`(hypothesis、`derandomize=True`)。4 値の決め方はテストの中に別に書いてあり、部品の `judge` / `five` / `extras` を呼ばない。

## 件数の検算 — 3 通りの数え方が合う

`check` の出力の `件数の合計の検算` が、同じ件数を 3 通りに数えて並べる。

- 4 値 + 別枠 の合計
- 領域の宣言(`内` / `外` / `境界として明示` / 登録表の外)ごとの合計
- 在り所(`収録` / `照合専用` / `第2層` / `case属性` / `無い` / 行が無い / 行き先が 2 つ以上)ごとの合計

**3 つが項目の件数に戻らなければ、どこかの数え方が壊れている。**

## 返す量 — 3 つだけ

- 4 値 + 別枠 の項目数
- (B) の行数の合計(**由来ごとの内訳つき**)
- 必須の宣言が在るのに在り所が `無い` 項目の数(**別枠へ出た項目も数える**)

**順位も点数もカバー率の 1 値も返さない。** 割合を出したい人のために、分母は 2 通り(項目数と、在り所の台帳が数えた行数)を必ず並べて返す。

## 止まる理由コード(7 個)

登録表の行の出典が空 / 項目 id の重複 / 領域の登録表の宣言が決めた 3 つの外 / 在り所の記号が決めた 5 つの外 / `収録`・`照合専用` の行数が整数でない / 基準日が渡されていない / 登録表そのものが空。

**止まった表は 4 値を 1 件も返さない**(4 値も別枠も全て 0 で、理由コードだけが返る)。表として読めないとき(列が足りない / 行が無い / 項目 id が空 / 在り所の項目 id が台帳に無い / 行数の欄が余計 / 入る形が同じ項目に 2 行 / 領域の登録が同じ記号で 2 行)は終了コード 2。

## 使い方

```
python off_scope.py init ひな型/
python off_scope.py check  項目.csv 領域.csv 在り所.csv 入る形.csv basis.csv payload.csv 2026-09-20
python off_scope.py report 項目.csv 領域.csv 在り所.csv 入る形.csv basis.csv payload.csv 2026-09-20
python off_scope.py verify 項目.csv 領域.csv 在り所.csv 入る形.csv basis.csv payload.csv 2026-09-20
```

`report` は項目ごとの一覧と、領域の宣言ごと・在り所ごとの内訳と、判定部分の sha256 を足す。`verify` は 5 つ見る。

- 2 回読んで、行順を 3 通りに入れ替えても判定部分の指紋が同じか
- 3 通りの数え方の合計が項目の件数に戻るか
- (B) の行数の合計が、在り所の台帳の該当行の行数合計と合うか
- 2 通りの分母が両方出ていて、出典が空のまま 4 値に入った項目が 0 件か
- 1 件の在り所を `無い` → `収録`(1 行)にすると、**その項目だけ**が (A) → (B) へ移るか

終了コードは、止まらず・別枠 0 件・(A) と (B) が 0 件のときだけ 0、在れば 3、表として読めなければ 2。

## テストと fixture

```
python -m pytest tools/off_scope -q
```

`fixtures/` の 6 枚は合成で、**実データ・実在の名前・実在のパスは 1 つも入っていない**(項目 id は記号、項目名は「合成の項目 …(架空)」、領域の記号は「領域 1〜4」、出典は「合成の…(架空)」)。`fixtures/kowashita/` に、止まる理由コード 7 個と表として読めない 7 通りへ道を付けた崩した表が入っている。`fixtures/make_fixtures.py` で作り直せる。

## できないこと

- **収録すべきかは分からない。** 4 値を付けるところまでで、どの項目を表に入れるかは読む人が決める。(A) でも「入れるべき」とは言っていない
- **必須かどうかは分からない。** 返るのは入力の文字列の写しだけで、書かれていない項目は `必須の記載なし` になる。本当に要るかは人が書く側に残る
- **線の引き方が妥当かは分からない。** `内` / `外` / `境界として明示` は登録表から取るだけで、その線が正しいかは出力に出ない
- **行数が正しいかは分からない。** 台帳に人が書いた行数をそのまま使う。行数を数えない在り所は `数えられない` で、0 行なのか記録していないのかは言えない
- **行き先の宣言が守られているかは分からない。** `第2層` と書かれていても、その層に行が在るかは見ない(見るのは宣言の数え上げだけ)
- 上の件数は合成した 6 枚に対する測定で、ほかの人の環境で同じ数字になるとは限らない
