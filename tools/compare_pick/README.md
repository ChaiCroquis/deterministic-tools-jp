# compare_pick — 「高い方が適用」は順位では決まらないので、比べる欄と単位と丸めの前後を先に書く

**順位の欄に値が入っていても、その順位では決まらない裁定が実在する。「高い方が適用」は順位の
上下ではなく値の比較で、比較は ① どの欄を比べるか ② 単位 ③ 丸めの前か後か ④ 同値のとき
どちらが勝つか ⑤ 比べる 2 行の有効期間が基準日で重なるか、の 5 つが宣言されていないと、同じ
「高い方」が実装ごとに別の答えを返す。しかも順位の欄は埋まっているので、同順位の重複を見る
検査はこの行を 1 件も止めない。**

[rank_clash](../rank_clash) の回で、絞り終わって 2 本残った行が順位の欄から 1 本に決まるかを
出した。そのとき「高い方を採るという裁定は、順位の上下ではなく値の比較なので、この部品の守備
範囲の外になる」と書いて、外に置いた 1 件がある。この部品はその 1 件を拾う。

この部品は、裁定の宣言表・候補の表・基準日の表の 3 枚から、(組 × 基準日)1 つごとに 4 値
(**順位で決まった / 比較で決まった / 比較では決まらない / 止まった**)を付ける。止まったものは
理由コード別、決まらないものは理由別に分けて数え、分母(組数 × 基準日の数)と内訳を併記して
返す。**式を評価しない。行を引かない。比べるだけだ。**

持たせていないものが規律になっている。

- **裁定の種類が「値の比較」の組は、順位の欄に値が入っていても順位で決めない**(比較の代わりに
  順位で決める経路を持たない。順位を読む経路は 1 つだけで、同値のときの扱いに
  `宣言された順位で裁定` と書いてある組の同値のときに限る。この部品の骨をそのまま入力の形に
  したところ)
- **単位が違う 2 行を比較しない**(換算表も換算の引数も無い。パーセントと金額と千分率を黙って
  揃える経路が無い)
- **丸めを比較の前にするか後にするかが空欄の組は比較しない**(既定を持たない。
  [formula_table](../formula_table) の「丸めの名前は空欄を許さない」を裁定の側にも置いた)
- **丸めの前後は宣言どおりにしか動かさない**(道具の側で有利な方を選ばない)
- **同値は向きで勝たせない**(`大きい方` でも同値なら決まらない。宣言が `宣言された順位で裁定`
  なら順位へ落とすが、順位も同じなら決まらない)
- **float を使わない**(値は文字列から `Decimal` にして比べる。指数表記や `NaN` のように float
  から来た形は、読める形でも使わずに止まる)
- **比べる 2 行の有効期間が基準日で重なっていない組は比較しない**(重なるか否かの 1 段だけを
  持つ。期間を切るのは [span_split](../span_split) の仕事)
- **式を評価しない・値を計算しない**(計算は宣言された丸め 1 段だけ。式を評価するのは
  [formula_table](../formula_table) の仕事で、ここに式を解く経路は無い)
- **行を引かない・期間を切らない・帯に当てない・空欄の意味を決めない・日付の種別を決めない・
  未来の行を分けない**(版を選ぶのは [asof_table](../asof_table)、帯は
  [band_edge](../band_edge)、空欄は [blank_kind](../blank_kind)、日付の種別は
  [basis_map](../basis_map)、順位の裁定は [rank_clash](../rank_clash)、未来の行は
  [future_row](../future_row) の仕事で、役割が重ならない)
- **件数は理由別に、分母(組数 × 基準日の数)と内訳つきで出す**(率を単独で返さない。
  [check_census](../check_census) 以降と同じ)
- **4 つを混ぜない**([rank_clash](../rank_clash) / [future_row](../future_row) と同じ)
- **入力表を書き換えず、行も宣言も生成しない**([intake_triage](../intake_triage) 以降と同じ)
- **出典の欄が空の行は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)

## 入力 — 裁定の宣言表と候補の表と基準日の表の 3 つ

裁定の宣言表は 9 列。**1 rule が 1 行**で、「候補が 2 本以上残ったときに何で決めるか」をここだけ
に書く。

| 列 | 意味 |
|---|---|
| `rule_id` | rule id(空欄は「表として読めない」。2 行あると**止まる**) |
| `kind` | 裁定の種類。登録の 3 種(`宣言された順位` / `値の比較` / `決まらない`) |
| `field` | 比べる欄の名前(`値の比較` のときだけ要る) |
| `direction` | 向き。登録の 2 種(`大きい方` / `小さい方`) |
| `unit` | 単位。**空欄のまま持つ**(比較の段で止まる) |
| `round_when` | 丸めを比較の前にするか後にするか(`前` / `後`)。**空欄のまま持つ** |
| `rounding` | 丸めの名前。登録の 3 種(`丸めない` / `50 の倍数に丸める` / `小数点以下を切り捨てる`) |
| `tie` | 同値のときの扱い。登録の 2 種(`決まらない` / `宣言された順位で裁定`) |
| `source` | その行の出典。**空欄は止まる** |

```csv
rule_id,kind,field,direction,unit,round_when,rounding,tie,source
R01,宣言された順位,,,,,,,articles/27_rank_clash.md L8
R02,値の比較,欄A,大きい方,単位甲,後,50 の倍数に丸める,宣言された順位で裁定,articles/27_rank_clash.md L101
R04,決まらない,,,,,,,articles/27_rank_clash.md L212
```

候補の表は 10 列。絞り終わって残った候補 1 本が 1 行で、同じ `group_id` の行が比較の相手になる。

| 列 | 意味 |
|---|---|
| `group_id` | 組 id。**同じ組の中で rule は 1 つだけ** |
| `rule_id` | その組が従う rule id。**宣言表に無い rule は「表として読めない」** |
| `row_id` | 行 id(組 id との組み合わせが 2 行あると**止まる**) |
| `priority` | 順位。**空欄のまま持つ**(0 と読み替えない) |
| `field` | この行が持っている欄の名前。宣言の比べる欄と違えば**止まる** |
| `value` | 比べる欄の値。**文字列のまま読み、`Decimal` にして比べる** |
| `unit` | この行の単位。宣言の単位と違えば**止まる**(換算しない) |
| `valid_from` / `valid_to` | 有効期間。半開区間で、終わりの日は含まない |
| `source` | その行の出典。**空欄は止まる** |

基準日の表は 4 列。1 基準日が 1 行で、同じ組を基準日ごとに読み直す。

| 列 | 意味 |
|---|---|
| `asof_id` | 基準日 id(空欄も、同じ id が 2 行あるのも「表として読めない」) |
| `asof` | 基準日(ISO の日付) |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 決め方 — 読む順番が答えを決める

裁定の種類で先に分かれる。**`値の比較` の組では、順位の列を読まない。**

| 裁定の種類 | どうなるか |
|---|---|
| `決まらない` | 比べずに **比較では決まらない**(宣言が決まらないと言っている) |
| `宣言された順位` | 順位の最大値が 1 本なら **順位で決まった**。同順位や空欄なら **決まらない** |
| `値の比較` | 宣言が揃っているかを見て、揃っていれば値を比べる |

`値の比較` の組は、この順に見る。**基準日に依る検査だけが最後に来る。**

| 順 | 見るもの | 揃っていなければ |
|---|---|---|
| 1 | 宣言の単位 / 丸めの前後 / 丸めの名前 / 同値の扱い | 止まる(4 つの理由コード) |
| 2 | 行の比べる欄 / 値 / 単位 / 値が数に読めるか | 止まる(5 つの理由コード) |
| 3 | 候補が 2 本以上あるか | 止まる(1 本に比較の宣言が付いている) |
| 4 | 基準日で有効期間が重なるか | 止まる(重ならない) |
| 5 | 宣言どおりの前後で丸めて `Decimal` で比べる | 同値なら宣言のとおりに落とす |

**丸めの前後が答えを動かす。** 丸めは値を下げも上げもするが、同じ丸めを両方に当てるので勝敗が
直接ひっくり返ることはない。ひっくり返るのは**同値になったとき**だ。比較の前に丸めると 2 つの
値が同じ値に落ち、同値の扱いが `宣言された順位で裁定` なら、そこから先は順位の欄が勝敗を決める。
だから「高い方」と書いてあっても、丸めの前後の 1 欄で勝つ行が入れ替わる。

## 件数の検算 — 分母は組数 × 基準日の数

- **4 値の件数の合計 = 組数 × 基準日の数**
- **止まった理由別の件数の合計 = 止まったの件数**
- **決まらない理由別の件数の合計 = 比較では決まらないの件数**

3 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- (組 × 基準日)ごとに 4 値が 1 つだけ付き、**4 値の合計が 組数 × 基準日の数** に等しく、
  **止まった理由別の合計が止まったの件数**、**決まらない理由別の合計が比較では決まらないの
  件数** に等しく、決まった組の勝った行 id は **候補の表にそのまま在る id**、勝った値は
  **同じ組の値のどれかを宣言された丸めに通したもの**(ほかの 2 値には行 id も値も付かない)で、
  判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても同じバイト列**
  になる
- または、1 組も読まずに理由コードが返る(読んだ組や指紋を取りに行くと例外になる)

どちらの場合も、この部品は宣言表も候補の表も基準日の表も 1 文字も書き換えない。

この 1 文を `tests/test_compare_pick_property.py` の `@given` テストが確かめている(rule を
1〜3 本作って裁定の種類を振り、比較の宣言を引く。組を 1〜3 組、各組の候補を 1〜3 本、値を合成の
値と読めない形から、単位を 2 種から、順位を 0 / 10 / 20 / 空欄から、有効期間を 2 種から引く。
基準日は 1〜2 件。3 割くらいの確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。
**丸めはテストの側で別に実装している**(部品の `round_value` を呼ばない)。同じファイルの 2 本目
は 300 通りで、「値が違う 2 行の勝敗は、順位の欄をどう書いても向きと値だけで決まる」ことを見て
いる。

## 出力 — 決まった率は単独では返らない

`check` と `pick` が返るのは、3 枚それぞれの行数、組数、基準日の数、分母(組数 × 基準日の数)、
4 値の件数、止まった理由別と決まらない理由別の件数、それに分母の内訳と検算と 5 つの固定行だ。
**率だけを返す呼び方も、option も無い。**

```
"分母(組数 × 基準日の数)": 22,
"4 値": {"順位で決まった": 2, "比較で決まった": 3, "比較では決まらない": 6, "止まった": 11},
"止まった理由別": {"比べる欄が候補の表に無い": 2, "単位の不一致": 2, "値が数に読めない": 2,
                   "float 混入": 2, "基準日で有効期間が重ならない": 1,
                   "候補が 1 本しかない組に比較の宣言が付いている": 2}
```

固定行は 5 つとも消せない。「順位の列で比較を代えない」「単位を揃えない」「丸めの前後に既定を
当てない」「同値を向きで勝たせない」「式を評価しない」だ。`pick` はさらに組ごとの内訳(結果・
理由・勝った行 id・勝った値・経路・候補の本数)と、決まった組だけを並べた一覧を出す。一覧の
並びは組 id と基準日 id の順で、**どれから手を付けるかの順位は付かない。**

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の sha256 を突き合わせること、**宣言された
入れ替え方で 3 枚の行順を入れ替えても同じ出力になるか**、**件数の合計が合うか**、それに
**単位を 1 欄書き換えた写し**(止まったの増えと比較で決まったの減りが一致するか)と
**丸めの前後を入れ替えた写し**(勝者が入れ替わる組が何件あるか)だ。写しはメモリの中だけで、
入力の表には 1 文字も書かない。

## 止まる理由コード(18 個)

```
出典の欄が空 / 組 id と行 id の重複 / 宣言に無い裁定の種類 / 同じ rule に宣言が 2 行 /
比べる欄が候補の表に無い / 比べる欄の値が空 / 単位の不一致 / 単位の欄が空 / 丸めの前後が空 /
登録されていない丸めの名前 / 同値のときの扱いが空 / 値が数に読めない / float 混入 /
基準日で有効期間が重ならない / 候補が 1 本しかない組に比較の宣言が付いている /
件数の合計が合わない / 2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる
```

先の 4 個は 1 組も読まずに止まる。次の 11 個は組ごとに止まる(ほかの組は読む)。後の 3 個は
`verify` が見つける。

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。向きが登録の外
(空欄も)だったとき、比べる欄の名前が空欄のとき、丸めの前後や同値の扱いに登録外の語を書いた
とき、入れ替え方が登録の外のとき、列そのものが足りないとき、行が 0 行のとき、id が空欄のとき、
順位が整数でないとき、日付が ISO でないか暦に無いとき、有効期間が逆順か 0 日のとき、同じ組に
2 通りの rule を書いたとき、候補の表が宣言表に無い rule を名乗ったとき、同じ基準日 id を 2 行
書いたとき、そして入れ替え方の宣言が 2 通りあるときだ。

## 使い方

```bash
python compare_pick.py init ひな型/                                         # 3 枚のひな型を書く
python compare_pick.py check  裁定の宣言表.csv 候補の表.csv 基準日の表.csv   # 件数と分母の内訳
python compare_pick.py pick   裁定の宣言表.csv 候補の表.csv 基準日の表.csv   # 上 + 組ごとと指紋
python compare_pick.py verify 裁定の宣言表.csv 候補の表.csv 基準日の表.csv   # 2 回 + 行順 + 写し
```

終了コードは、**止まった組も決まらない組も 1 つも無いときだけ 0**、どちらかがあるときは 3、表と
して読めなければ 2。まとめて走らせる仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from compare_pick import Declared, Candidates, Asofs, compare_pick

t = compare_pick(Declared.load("裁定の宣言表.csv"), Candidates.load("候補の表.csv"),
                 Asofs.load("基準日の表.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `pick` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。そのこと
もテストで固定してある。

## テストと fixture

```bash
python -m pytest tools/compare_pick -q      # 26 passed(2026-10-21 実走)
```

`fixtures/` に宣言表 3 枚・候補の表 1 枚・基準日の表 1 枚と、崩した表 39 枚が入っている。
**実在の料率・金額・取引先名は 1 つも入っていない**(値も単位の名前も架空で、単位としての金額や
パーセントの記号は 1 文字も無い)。写したのは形だけ、つまり「順位の欄に値が入っているのに、その
順位では決まらない裁定が宣言に書いてある」「単位が違う 2 行が同じ組に入っている」「丸めの前後で
勝者が入れ替わる」「比べる 2 行の有効期間が基準日によって重ならない」という 4 つで、これは私の
棚卸し記録に残っている形だ。出典のうち 4 件はこの repo 内の実在の行
(`articles/27_rank_clash.md` L8 / L101 / L212、`articles/08_formula_table.md` L61)を指し、
テストがその行を開いて語が在ることまで確かめている。`fixtures/make_fixtures.py` を実行すると、
崩した表ごと書き直す。

## できないこと

- 判定したことは「順位で決まらない裁定が、宣言なしに黙って決まらないか」と「同じ値の組で宣言を
  入れ替えると勝者が変わるか」までで、**どちらを採るのが正しい裁定かは判定しない**
- **実在の料率や金額がいくらかも言わない。** 返るのは勝った行の id と、入力に在った値を宣言された
  丸めに通した値だけだ
- **宣言の中身が妥当かも判定しない。** 向きも単位も丸めの前後も、書いてあるとおりに使うだけで、
  どれを選ぶべきかは人の側に返る
- **足すべき宣言も提案しない。** 空欄も登録外の語も件数として残るだけで、埋め方を出す経路が無い
- **式を評価しない。** 2 つの数式を引いて比べる形(新旧比較のような)は、式を引く側の仕事で、
  ここに渡すのは引き終わった値だ
- **期間を切らない。** 基準日で重なるかを見るだけで、重なり方を切り分ける段は持たない
- 単位は文字列として突き合わせる。同じ単位を違う表記で書けば別の単位になる
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
