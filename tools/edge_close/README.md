# edge_close — 足す行ごとに「前の行のどの端を閉じることになるか」を仕分ける

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [新しい行を足しても前の行は閉じないので、閉じる端を足す前に一覧にする](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_30.html)(2026-10-31 公開)
<!-- article-links:end -->

**行を足す操作と、前の行の端を閉じる操作は別だ。足す側の 1 行だけを見ていると閉じ忘れが見えない。
閉じ忘れた表は同じ日に 2 つの答えを返し、閉じすぎた表は答えの無い日を作る。**

有効期間つきの表に新しい行を足すとき、差分として出てくるのは「追加 1 行」だけだ。けれど実際に
起きているのは 2 つの操作で、もう一方(前の行の終了を閉じる)は差分の外にある。この部品は、
既存の行の表・足す行の表・閉じ方の宣言表の 3 枚を読んで、足す行 1 件ごとに次の 6 値か別枠の
どれか 1 つを付ける。

- ① 閉じる端がある(閉じることになる行 id と、閉じる端の日付を併記)
- ② 閉じ忘れると重なる(既存の終了の次の単位が、足す行の開始より後 = 同じ日に 2 つ)
- ③ 閉じると隙間ができる(既存の終了の次の単位が、足す行の開始より前 = 答えの無い日)
- ④ 閉じる端が無い(同じ鍵の既存の行が無い、または終了が書かれていない)
- ⑤ 有効期間は閉じたが知識期間の端が開いたまま
- ⑥ 同じ日に 2 つ開く(既存の行と足す行の開始が同じ日で、どちらも終了が開いている)
- 別枠(鍵が宣言表に無い / 出典が空 / 終了が開始より前 / 順位が登録外 / 提案 id の重複 /
  日付の書式が宣言と違う / 施行日未定の印が立っているのに開始が入っている)

**閉じない。足さない。直さない。引かない。** 出るのは端の一覧と件数だけだ。

## いつも成り立つこと

**足す行 1 件には 6 値 + 別枠のどれか 1 つだけが付き、7 値の合計は足す行の件数に等しく、6 値の
合計は 6 値が付いた件の数に等しく、rule ごと・次元の値ごと・① の言い方ごと・別枠の理由ごとの
内訳の合計もそれぞれ元の数に等しい。閉じる端として指す行は必ず同じ鍵(rule + 次元 + 順位 +
知識期間の重なり)の行で、終了が書かれていない行は指されない。⑤ が出るのは知識期間も閉じる対象
だと宣言された rule だけだ。3 枚のどれかが 1 行でも壊れていれば 1 件も仕分けず、6 値は全て 0 で
理由コードだけが返る。どちらの場合も入力の 3 枚は 1 文字も書き換わらない。**

この 1 文は `tests/test_edge_close_property.py` の 2 本の `@given` テストで検査している。
1 本目は 3 枚の表を乱数で組み立てて(3 割くらいの確率でどこか 1 か所を崩して)上の不変式を見る。
2 本目は「①・②・③ の分かれ目は端の 1 単位だけで、その 1 単位は区間の閉じ方と端の単位の宣言から
決まる」ことを、閉じ方 × 単位 × 終了の位置 × 開始の位置 の総当たりで見る。**6 値の分け方は
テストの側で別に実装してある**(部品の `judge` / `candidate` / `seven` を呼ばない)。

## 使い方

```
python edge_close.py init ひな型/
python edge_close.py check 既存の行.csv 足す行.csv 閉じ方の宣言.csv
python edge_close.py edges 既存の行.csv 足す行.csv 閉じ方の宣言.csv
python edge_close.py verify 既存の行.csv 足す行.csv 閉じ方の宣言.csv
```

`check` は件数と内訳だけ、`edges` はそれに判定ごとの一覧・閉じる端の一覧・重なる一覧・隙間の
一覧・知識期間の端が開いたままの一覧・二重開始の一覧・別枠の一覧・どの足す行からも指されなかった
既存の行の一覧・次元の値ごとの内訳・`sha256` を足す。`verify` は下の 5 つを見る。

終了コードは、別枠・重なり・隙間・二重開始・知識期間の開き・止まった行が 0 件のときだけ 0、在れば
3、表として読めなければ 2。**0 は「表が正しい」ではなく「閉じ忘れと閉じすぎが見つからなかった」の
意味で、良し悪しはこの部品の終了コードにも出力にも出ない。**

## 入力の 3 枚

既存の行の表(11 列)。

| 列 | 意味 |
|---|---|
| `row_id` | 行 id(同じ id が 2 行あると止まる) |
| `rule_id` | どの数表の rule か |
| `dims` | 各次元の値。`名前=値` を `;` でつないで書く(未指定は宣言された記号) |
| `priority` | 順位(宣言表の「許す順位の値」に無ければ止まる) |
| `valid_from` / `valid_to` | 有効期間の 2 端 |
| `valid_open` | 終了が開いているかの印(`開` / 空) |
| `known_from` / `known_to` | 知識期間の 2 端 |
| `known_open` | 知識終了が開いているかの印 |
| `source` | 出典。空欄は止まる |

終了の欄と印の組み合わせは 3 通りだけを受け取る。**印あり + 終了が空 = 開いている**、
**印なし + 終了が埋まっている = 閉じている**、**印なし + 終了も空 = 終了が書かれていない**
(閉じる端として指さない = ④ 側へ落ちる)。印あり + 終了が埋まっている は止まる。**空欄を
「たぶん開いている」と読み替える経路を持たない。**

足す行の表(12 列)は既存の行の表と同じ並びに、`add_id`(提案 id)と `pending_order`(施行日
未定の印 `政令待ち`)が入る。**印が立っている行は有効開始が空でよい**。印が立っているのに開始が
入っている行は別枠へ出る。

閉じ方の宣言表(10 列)。

| 列 | 意味 |
|---|---|
| `rule_id` | どの数表の rule か(同じ id が 2 行あると止まる) |
| `end_included` | 区間の閉じ方 = 終了を含むか(`含む` / `含まない`) |
| `edge_unit` | 端の単位(`日` / `月`) |
| `gap_allowed` | 隙間を許すか(`許す` / `許さない`)。**記録するだけで判定に使わない** |
| `reason_code` | 隙間を許す場合は必須の理由コード |
| `unspecified_mark` | 未指定次元の記号(この記号は**記号のまま鍵に入る**) |
| `close_known` | 知識期間も閉じる対象か(`閉じる` / `閉じない`) |
| `priorities` | 許す順位の値(`0;10;20`) |
| `new_label` | ④ の行に写してよい語(空なら何も写さない) |
| `source` | 出典。空欄は止まる |

**この表を読まずに隣接を判定する経路が無い。** 同じ表でも、区間の閉じ方と端の単位の宣言が違えば
1 日ずれて重なりと隙間が入れ替わる。

## 鍵の作り方

鍵は **rule id + 次元の値 + 順位 + 知識期間の重なり**。同じ鍵の行のうち、**有効開始が足す行の
開始以前で最も後ろの行**が閉じる端になる。施行日未定の行は開始が無いので、同じ鍵のうち最も後ろの
行を指し、閉じる日付の欄は空のままにする。

**鍵の作り方を道具が決めない。** 次元を文字列の似かたで寄せる経路が無く、未指定の記号を展開して
当てる経路も無い(記号は記号のまま鍵に入る)。順位は同じ値どうしを突き合わせるだけで、**勝ち負けを
決める経路は無い**。

## verify が見る 5 つ

1. 2 回読んで判定部分のバイト列の `sha256` が同じか
2. 3 枚の行順を 3 通りに入れ替えても同じ出力になるか
3. 7 値の合計 = 足す行の件数、6 値の合計 = 6 値が付いた件の数、rule ごと・次元の値ごと・
   ① の言い方ごと・別枠の理由ごとの内訳の合計も合うか
4. **既存の行の「終了が開いている」印を 1 件外すと、その足す行だけが ① から ③ か ④ へ移り、
   ほかの件が 1 つも動かないか**
5. **足す行の開始を既存の終了の次の単位にすると ② が ① になり、さらに 1 単位後ろにすると
   ③ になるか**(区間の閉じ方と端の単位の宣言を 1 単位で確かめる)

4 と 5 の写しは**メモリの中だけ**で、入力の CSV には 1 文字も書かない。

## 持たせていないもの

- **閉じる操作をしない**(閉じた後の表を返す関数も、閉じる日付を既存の行へ書き込む関数も無い)
- **どちらの期間が正しいかを決めない**(重なりを片方に寄せる引数が無い)
- **重なりを誤り・違反・事故と呼ばない**(語彙を持たない)
- **④ を新設と名乗らない**(宣言表の `new_label` が埋まっているときだけ、その語をそのまま写す)
- **隙間を埋めない・前の行を延ばさない**
- **順位で裁定しない**(勝ち負けは別の部品の領分)
- **期間を切らない**(料率が変わる日で分割するのは別の部品の領分)
- **値を開かない・計算しない**(`payload` の列が無い)
- **時計を読まない**(現在時刻を読む呼び出しを持たない。基準は入力の日付の欄だけ)
- **割合も点数も順位も出さない**(返るのは件数と内訳と一覧だけ)

## できないこと

- 閉じるべき日付が正しいかは分からない。出すのは「宣言どおりに閉じるならこの日付」までで、
  その日付が制度として正しいかは人が決める
- 施行日未定の行については、重なるか隙間になるかを言わない(開始が無いので端を比べられない)
- 未指定の記号を展開しないので、ワイルドカード行と具体値の行の重なりは見つけられない
- 出典の欄が埋まっているかまでしか見ない。出典が本当にその行を指しているかは分からない
- 知識期間の重なりの判定は、有効期間と同じ「区間の閉じ方」の宣言を使う。知識期間だけ別の
  閉じ方にしたい表は、いまの宣言表では書き分けられない
