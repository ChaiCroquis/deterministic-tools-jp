# cover_stock — 引ける年は数表ごとに違うので、計算に要る行がそろう期間を先に年表にする

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [引ける年は数表ごとに違うので、計算に要る行がそろう期間を先に年表にする](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_21.html)(2026-10-22 公開)
<!-- article-links:end -->

**同じ基準日を渡しても、引ける年は数表ごとに別で、ある年は料率が引けて別の表は収録の外にある。
しかも引けない理由は「収録を始める前」「収録の中の穴」「収録の終わりより後」「収録の端が仮置き」
の 4 つに分かれるのに、引いた側に返るのは 1 つの終了コードだけで、どれだったかが残らない。
だから引く前に、数表ごとの収録の端と穴を 1 行 1 件の年表にして、計算 1 件に要る行がそろう期間を
数える。**

[asof_table](../asof_table) の回で、引き当て 1 件ごとに「収録範囲の外」を返す段までは作った。
ただしあれは 1 件ずつ引いて初めて分かる形で、**引く前に収録の端を数える段は無い**。この部品は
その前段に立つ。[span_split](../span_split) は 1 つの rule の期間を改定日で切る道具で数表を
またがず、[future_row](../future_row) は表に先に入った未来の行を予定に分ける道具で端の確度の欄
を持たない。ここは在庫の側を数える。

この部品は、収録の在庫表・計算のレシピ表・数える年の一覧の 3 枚から、(レシピ × 年)1 つごとに
5 値(**レシピの要る数表が全部そろう / 一部だけそろう / 1 つもそろわない / 止まった / 端が
仮置きの行に依存している**)を付ける。引けない数表は 4 つの理由に分け、止まったものは理由コード
別に数え、2 つの分母(レシピ数 × 年の数 / 数表の延べ数 × 年の数)と内訳を併記して返す。
**行を引かない。期間を切らない。穴を埋めない。数えるだけだ。**

持たせていないものが規律になっている。

- **年の数え方が宣言されていない行は数えない**(暦年を既定として当てる経路が無い。年度の
  開始月が 3 月の表と 4 月の表と 8 月の表が同じ在庫に並ぶ、という事実を機械側に写した)
- **年の数え方が違う数表を、換算せずに同じ年として突き合わせない**(換算表も換算の引数も無い。
  「そろう」は日付が覆われていることではなく**その年の行が在ること**を言うので、数え方が違えば
  どの行をその年の行と見るかは表を書く人が決める)
- **端が `仮置き` の行は確定として数えない**(別枠の 5 値目に出す。4 値に混ぜない)
- **穴を埋めない・直近の端で代用しない**([asof_table](../asof_table) の「直近の行を返さない」を
  在庫の側へ置いた)
- **「今日」を使わない**(未来かどうかは入力の年の一覧と在庫表の端だけで決まる。
  [env_match](../env_match) と同じで、判定部分に環境を入れない)
- **引けない理由を 1 つに潰さない**(4 つの理由コードを別の欄に分けて数える = この部品の骨の
  物理形)
- **行を引かない・版を選ばない・期間を境界で切らない・帯に当てない・空欄の意味を決めない・
  日付の種別を決めない・順位で裁定しない・未来の行を予定に分けない・値を比べない**(版は
  [asof_table](../asof_table)、期間は [span_split](../span_split)、帯は [band_edge](../band_edge)、
  空欄は [blank_kind](../blank_kind)、日付の種別は [basis_map](../basis_map)、順位は
  [rank_clash](../rank_clash)、未来の行は [future_row](../future_row)、値の比較は
  [compare_pick](../compare_pick) の仕事で、役割が重ならない)
- **足すべき年も、取りに行く先も提案しない**(取得の地図は [source_pin](../source_pin) の道具。
  ここは在庫を数えるところで止める)
- **網羅率を出さない**(在庫表に書かれた数表の範囲までしか言わない)
- **件数は丸めず、理由別に分母と内訳つきで出す**(率を単独で返さない)
- **入力表を書き換えず、行も在庫も生成しない**
- **出典の欄が空の行は使わずに止まる**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない)

## 入力 — 収録の在庫表と計算のレシピ表と数える年の一覧

収録の在庫表は 9 列。**1 数表が 1 行**で、その数表がどこからどこまで在るかをここだけに書く。

| 列 | 意味 |
|---|---|
| `table_id` | 数表 id(空欄は「表として読めない」。2 行あると**止まる**) |
| `area` | 領域(空欄は「表として読めない」) |
| `covered_from` | 収録開始(ISO の日付)。**読めないまま持つ**(数える段で止まる) |
| `covered_to` | 収録終了(ISO の日付。半開区間で、終わりの日は含まない) |
| `open_end` | 終了が開いているか。登録の 2 種(`開いている` / `閉じている`) |
| `year_kind` | 年の数え方。登録の 4 種。**空欄のまま持つ** |
| `edge_confidence` | 収録開始の端の確度。登録の 2 種(`実値` / `仮置き`)。**空欄のまま持つ** |
| `holes` | 穴の一覧。`開始/終了` を `;` でつなぐ(半開区間)。空欄は穴なし |
| `source` | その行の出典。**空欄は止まる** |

```csv
table_id,area,covered_from,covered_to,open_end,year_kind,edge_confidence,holes,source
T01,合成の領域甲(架空),1989-01-01,,開いている,暦年,実値,,articles/07_asof_table.md L185
T05,合成の領域戊(架空),2017-04-01,,開いている,年度(4 月開始),仮置き,,articles/28_future_row.md L14
T06,合成の領域己(架空),2002-01-01,2026-01-01,閉じている,暦年,実値,2010-01-01/2011-01-01,私の棚卸し記録(非公開)
```

年の数え方として登録してあるのは `暦年` / `年度(3 月開始)` / `年度(4 月開始)` /
`年度(8 月開始)` の 4 つだけだ。**ここに無い数え方は、勝手に足さずに止まる。**

計算のレシピ表は 3 列。計算 1 件に要る数表を縦棒でつないで書く。

| 列 | 意味 |
|---|---|
| `recipe_id` | レシピ id(空欄も、同じ id が 2 行あるのも「表として読めない」) |
| `table_ids` | 要る数表 id を縦棒でつなぐ。**空欄のまま持つ**(数える段で止まる) |
| `source` | その行の出典。**空欄は止まる** |

数える年の一覧は 5 列。**年の数え方をここでも宣言する**(在庫表の側と食い違えば止まる)。

| 列 | 意味 |
|---|---|
| `year_id` | 年 id(空欄も、同じ id が 2 行あるのも「表として読めない」) |
| `year` | 年(4 桁。それ以外は「表として読めない」) |
| `year_kind` | その年の数え方。登録の 4 種(空欄も登録外も「表として読めない」) |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 数え方 — 見る順番が理由を決める

数表 1 枚について、その年の全部が収録の中に入っているかを、この順に見る。

| 順 | 見るもの | 入っていなければ |
|---|---|---|
| 1 | その年の始まりが収録開始より前か | **収録を始める前** |
| 2 | その年が穴と重なるか | **収録の中の穴** |
| 3 | 終了が閉じていて、その年の終わりが収録終了より後か | **収録の終わりより後** |
| 4 | 端が仮置きで、その年が仮置きの端で決まる最初の年か | **端が仮置きで確定できない** |
| 5 | どれにも当たらない | そろう |

**順番を入れ替えない。** 収録を始める前の年は、穴が在っても端が仮置きでも、いつも 1 の理由で
返る。ここを入れ替えると、同じ年が表の書き方で別の理由を返してしまう。

レシピ 1 件は、要る数表の読みをまとめて 5 値になる。

| 読み | どうなるか |
|---|---|
| 全部そろう | **レシピの要る数表が全部そろう** |
| 引けない理由が「端が仮置き」だけ | **端が仮置きの行に依存している**(別枠。確定として数えない) |
| 1 枚でもそろう | **一部だけそろう** |
| 1 枚もそろわない | **1 つもそろわない** |
| 表そのものの不備 | **止まった**(理由コード 16 個のどれか) |

## 件数の検算 — 分母は 2 つある

- **5 値の件数の合計 = レシピ数 × 年の数**
- **止まった理由別の件数の合計 = 止まったの件数**
- **そろった数表 + 引けない理由別の件数の合計 = 読んだ数表の延べ数**(止まった件の数表は
  数えない。数表ごとの分母は別に出す)

3 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- (レシピ × 年)ごとに 5 値が 1 つだけ付き、**5 値の合計が レシピ数 × 年の数** に等しく、
  **止まった理由別の合計が止まったの件数**、**そろった数表 + 引けない理由別の合計が読んだ数表
  の延べ数** に等しく、そろわない年に挙がる理由は **4 つのうちのどれか**で、**収録開始を 1 年
  後ろへずらしても「全部そろう」へ入ってくる年は 1 件も無く**、判定部分に時刻・ホスト名・絶対
  パスが 1 つも入らず、**3 枚の行順を入れ替えても同じバイト列**になる
- または、1 件も読まずに理由コードが返る(読んだ年や指紋を取りに行くと例外になる)

どちらの場合も、この部品は在庫表もレシピ表も年の一覧も 1 文字も書き換えない。

この 1 文を `tests/test_cover_stock_property.py` の `@given` テストが確かめている(数表を
1〜3 枚作って年の数え方・端の確度・終了の開き・穴を振り、レシピを 1〜3 本、要る数表を 1〜3 枚
引く。年を 1〜2 件。3 割くらいの確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。
**年の覆いの判定はテストの側で別に実装している**(部品の `look` を呼ばない)。同じファイルの
2 本目は 300 通りで、「収録の外の年には、近くの年の行を当てない」ことを見ている。

## 出力 — そろった率は単独では返らない

`check` と `stock` が返るのは、3 枚それぞれの行数、分母(レシピ数 × 年の数)、5 値の件数、
引けない理由別と止まった理由別の件数、分母の内訳と検算、それに 7 つの固定行だ。
**率だけを返す呼び方も、option も無い。**

```
"分母(レシピ数 × 年の数)": 77,
"5 値": {"レシピの要る数表が全部そろう": 12, "一部だけそろう": 2, "1 つもそろわない": 4,
         "止まった": 57, "端が仮置きの行に依存している": 2},
"引けない理由別(数表の延べ数)": {"収録を始める前": 4, "収録の中の穴": 2,
                                 "収録の終わりより後": 1, "端が仮置きで確定できない": 3}
```

固定行は 7 つとも消せない。「網羅率を出さない」「年の数え方に既定を当てない」「年の数え方を
換算しない」「穴を埋めない・直近の端で代用しない」「仮置きの端を確定として数えない」
「システム日付を読まない」「行を引かない・足すべき年も取りに行く先も提案しない」だ。

`stock` はさらに、レシピと年ごとの内訳と、**在庫の年表(1 行 1 件)**を出す。年表の列は
日付 / 領域 / 数表 / 出来事 / 端の確度 / 出典で、出来事は `収録の開始` / `収録の終わり` /
`穴の開始` / `穴の終わり` の 4 つに分けてある(1 つの欄に混ぜない)。並びは日付の順で、
**どこから埋めるべきかの順位は付かない。**

`verify` は 4 つ見る。2 回読んで判定部分の sha256 を突き合わせること、**宣言された入れ替え方で
3 枚の行順を入れ替えても同じ出力になるか**、**件数の合計が合うか**、それに 2 つの写し
(**収録開始を 1 年後ろへずらした写し** = 全部そろうへ入ってくる年が 1 件も無いか、
**端の確度を実値に替えた写し** = 別枠の年が全部そろうへいくつ移るか)だ。写しはメモリの中だけ
で、入力の表には 1 文字も書かない。

## 止まる理由コード(16 個)

```
出典の欄が空 / 数表 id の重複 /
レシピが参照する数表 id が在庫表に無い / レシピに数表 id が 1 つも無い / 年の数え方が空 /
登録されていない年の数え方 / 年の数え方が違う / 端の確度が空 / 収録開始が収録終了より後 /
穴が収録範囲の外にある / 穴どうしが重なる / 日付が暦として読めない /
開いている終了に日付が入っている /
件数の合計が合わない / 2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる
```

先の 2 個は 1 件も読まずに止まる。次の 11 個はレシピと年ごとに止まる(ほかの年は読む)。後の
3 個は `verify` が見つける。

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。列が足りない、
行が 0 行、id が空欄、同じレシピ id や年 id を 2 行書いた、同じレシピが同じ数表を 2 回参照して
いる、終了の開きや端の確度に登録外の語を書いた、穴の形が `開始/終了` でない、穴の開始が終了
以降、年が 4 桁でない、数える年の数え方が空欄か登録外、入れ替え方が登録外か 2 通りある、だ。

## 使い方

```bash
python cover_stock.py init ひな型/
python cover_stock.py check  収録の在庫表.csv 計算のレシピ表.csv 数える年の一覧.csv
python cover_stock.py stock  収録の在庫表.csv 計算のレシピ表.csv 数える年の一覧.csv
python cover_stock.py verify 収録の在庫表.csv 計算のレシピ表.csv 数える年の一覧.csv
```

`check` が件数と内訳、`stock` が上にレシピと年ごとの内訳と在庫の年表を足したもの、`verify` が
2 回読みと 2 つの写しだ。終了コードは、**全部そろう年しか無いときだけ 0**、そろわない年か
止まった年があるときは 3、表として読めなければ 2。まとめて走らせる仕組みの中に置いて、3 で
止められる。

関数としても同じ形で呼べる。

```python
from cover_stock import Stock, Recipes, Years, cover_stock

t = cover_stock(Stock.load("収録の在庫表.csv"), Recipes.load("計算のレシピ表.csv"),
                Years.load("数える年の一覧.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `stock` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。その
こともテストで固定してある。

## テストと fixture

```bash
python -m pytest tools/cover_stock -q      # 17 passed(2026-10-22 実走)
```

`fixtures/` に在庫表 1 枚・レシピ表 1 枚・年の一覧 1 枚と、崩した表 33 枚が入っている。
**実在の料率・金額・取引先名は 1 つも入っていない**(数表 id も領域の名前も架空で、入っている
のは日付と年と件数だけだ)。写したのは形だけ、つまり「収録の端が領域ごとに 36 年ずれている」
「同じ『3 年分』でも年の数え始めが 4 通りある」「収録の端が仮置きの行が在る」「収録の中に穴が
在る」の 4 つで、これは私の棚卸し記録に残っている形だ。出典のうち 2 件はこの repo 内の実在の行
(`articles/07_asof_table.md` L185、`articles/28_future_row.md` L14)を指し、テストがその行を
開いて語が在ることまで確かめている。`fixtures/make_fixtures.py` を実行すると、崩した表ごと
書き直す。

## できないこと

- 判定したことは「要る行がそろう期間がどこか」と「仮置きの端をどう読むかで在庫がどれだけ動くか」
  までで、**どの年まで収録すべきかは判定しない**
- **制度が実際に何年分あるかも言わない。** 言えるのは在庫表に書かれた数表の範囲までだ
- **実在の料率や金額がいくらかも言わない。** 値の欄を持っていない
- **足すべき年も、取りに行く先も提案しない。** 引けない件数が残るだけで、埋め方を出す経路が無い
- **穴を埋めない。** 穴の在る年は引けない年として数えるだけで、近くの年の行を当てない
- **年の数え方を揃えない。** 数え方が違う組は止まるだけで、どちらに揃えるべきかは人の側に返る
- 端の確度は収録開始の端についてだけ見る。収録終了の端が仮置きである場合の欄は持っていない
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
