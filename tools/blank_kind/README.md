# blank_kind — 空欄は 0 とも全部とも読めるので、欠けている意味を列ごとに書いてから引く

**同じ空欄が、列によって「全部に当たる」とも「まだ取っていない」とも「制度として該当なし」
とも読める。どれかを書いていないと、空欄は黙って 0 か現行値になる。**
[asof_table](../asof_table) の回で基準日と公表時点、[span_split](../span_split) の回で期間、
[band_edge](../band_edge) の回で帯の等号まで、宣言の形を決めてきた。けれど宣言された列に
**値が入っていない** ときの扱いは、どの回でも手つかずだった。

この部品は、空欄の意味を **値の表の理由コードと列の宣言からだけ** 取り、マスごとに 4 値
(**値が在る / 空欄(宣言された意味つき)/ 決まらない / 止まった**)に分ける。欠けている
件数は理由コード別に数え、分母(対象 × 項目の総数)と内訳を併記して返す。

持たせていないものが規律になっている。

- **空欄に理由コードが無ければ止まる**(空欄の既定の意味を持たない。この部品の骨をそのまま
  入力の形にしたところ)
- **同じ空欄記号を列ごとに別の意味で読む**(「全部に当たる」列の空欄と、値の列の空欄を同じ
  経路に流さない。列の宣言が無ければ止まる)
- **0 と空欄をどちらにも寄せない**(0 が正規の値になりうる項目で空欄を 0 にしない、0 を
  空欄として落とさない)
- **仮置きの値を黙って値として返さない**(理由コードの付いた行は、値を持っていても仮置きの
  欄で返す。仮置きを外す提案もしない)
- **空欄を前の行・前の期間・前の版の値で埋めない**(引き継ぎの引数が無い。
  [span_split](../span_split) / [band_edge](../band_edge) と同じ)
- **欠けている件数を理由コード別に数え、分母と内訳を必ず併記する**(率を単独で返さない。
  [check_census](../check_census) 以降と同じ)
- **「値が在る」と「空欄」と「止まった」を混ぜない**([answer_check](../answer_check) /
  [scope_ledger](../scope_ledger) / [env_match](../env_match) / [span_split](../span_split) /
  [band_edge](../band_edge) と同じ)
- **入力表を書き換えず、値も理由コードも生成しない**([intake_triage](../intake_triage)
  以降と同じ)
- **出典の欄が空の行・宣言は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)
- **float を使わない**(値は Decimal、件数は整数)
- **空欄の理由を推定して埋めない、足すべき理由コードも提案しない**
- **形容の語を出力に持たない**(返すのは件数と分母と内訳だけ。数が無いなら多寡を書かない)
- **日付で表の版を選ばない / 期間を切らない / 値を帯に当てない**(版を選ぶのは
  [asof_table](../asof_table)、期間を切るのは [span_split](../span_split)、帯で引くのは
  [band_edge](../band_edge) の仕事で、役割が重ならない)

## 入力 — 値の表と項目の宣言と理由コードの宣言の 3 つ

値の表は 6 列。対象 × 項目 のマスが 1 行ずつ並ぶ。

| 列 | 意味 |
|---|---|
| `target` | 対象(空欄は「表として読めない」) |
| `item` | 項目。項目の宣言に無い項目は**止まる** |
| `value` | 値(Decimal。指数表記は受けない)。空欄なら理由コードが要る |
| `reason` | 空欄の理由コード。**値も理由コードも空なら止まる** |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が値の表の行順を入れ替えるときの宣言 |

項目の宣言は 6 列で、業種の語彙を 1 つも持たない。

| 列 | 意味 |
|---|---|
| `item` | 項目(2 行書くと「表として読めない」) |
| `kind` | 値の種類。登録の 6 種(`金額` / `日数` / `月数` / `年数` / `時間` / `人数`)。**空欄は止まる** |
| `reasons` | 空欄に許す理由コードの一覧(縦棒で区切る。空欄 = 空欄を 1 つも許さない) |
| `zero_ok` | 0 が正規の値になりうるか(`はい` / `いいえ`)。**空欄は止まる** |
| `all_match` | 空欄が「全部に当たる」を意味する列か(`はい` / `いいえ`)。**空欄は止まる** |
| `source` | その行の出典。**空欄は止まる** |

理由コードの宣言は 4 列。

| 列 | 意味 |
|---|---|
| `code` | コード(2 行書くと「表として読めない」) |
| `meaning` | 意味 |
| `how` | 返し方。`値として返さない` / `全部に当たるとして扱う` / `該当なしとして返す` |
| `source` | その行の出典。**空欄は止まる** |

```csv
item,kind,reasons,zero_ok,all_match,source
合成の金額の列(架空),金額,値が未取得|要照合|仮置き,はい,いいえ,協会けんぽ / 私の棚卸し記録(非公開)
合成の年齢の列(架空),年数,全部に当たる,はい,はい,articles/07_asof_table.md L15
```

## 列の 1 欄 — 同じ空欄記号が意味を持ったり決まらなくなったりする

同じ理由コードを書いた空欄でも、その列が「全部に当たる」列かどうかで結果が変わる。

| 列の種類 | 空欄に書いた理由コードの返し方 | 結果 |
|---|---|---|
| 値の列 | 値として返さない | `空欄(宣言された意味つき)` |
| 値の列 | 全部に当たるとして扱う | **`決まらない`**(値が無いのか、全部に当たるのか) |
| 全部に当たる列 | 全部に当たるとして扱う | `空欄(宣言された意味つき)` |
| 全部に当たる列 | 値として返さない も許している | **`同じ列に 2 つの意味` で止まる** |

既定は持たせていない。理由コードの無い空欄が 1 マスでもあれば、1 マスも読まずに止まる。

## 4 値 — 「空欄」と「決まらない」と「止まった」を混ぜない

| 値 | いつ入るか |
|---|---|
| `値が在る` | 値が書かれていて、理由コードが付いていない |
| `空欄(宣言された意味つき)` | 理由コードが付いていて、その返し方が列の種類と合っている |
| `決まらない` | 返し方と列の種類が食い違う、または 0 が正規の値でない項目に 0 が書かれている |
| `止まった` | 理由コードが返ったマス(理由コードが空、宣言に無いコード など) |

`空欄` と `決まらない` は止まる理由コードではない。読む手続きは成立しているので、どのマスが
そうなったかが返る(終了コードは 3)。

## 件数の検算 — 対象 × 項目 を、値を 1 つも読む前に突き合わせる

項目の宣言に並んだ項目と、値の表に出てくる対象から、マスの総数(対象 × 項目)を先に出す。
そのうえで次の 2 つを見る。

- **足りないマス**(対象 × 項目 の組が値の表に無い)→ **止まる**
- **2 行あるマス**(同じ組が 2 行書いてある)→ **止まる**

読んだ後には、**理由コード別の件数の合計 + 理由コードの無い行の件数 = 対象 × 項目 の総数**
を突き合わせる。4 値の合計も同じ総数になる。2 つの数え方は別の経路で出しているので、
片方だけ数え方を差し替えると、この検算が自分で見つけて止まる。

## いつも成り立つこと

読んだ結果は 2 通りしかない。

- マスごとに 4 値が 1 つだけ付き、4 値の合計が **対象 × 項目 の総数** に等しく、空欄の意味と
  返し方は **宣言された理由コードからだけ** 付き(決まらないマスには意味も返し方も付かない)、
  **理由コード別の件数の合計 + 理由コードの無い行の件数** が総数に等しく、判定部分に時刻・
  ホスト名・絶対パスが 1 つも入らず、**値の表の行順を入れ替えても同じバイト列** になる
- または、1 マスも読まずに理由コードが返る(結果や指紋を取りに行くと例外になる)

どちらの場合も、この部品は値の表も項目の宣言も理由コードの宣言も 1 文字も書き換えない。

この 1 文を `tests/test_blank_kind_property.py` の `@given` テストが確かめている(対象を
1〜3、項目を 1〜3、各マスを値か空欄で振り、3 割くらいの確率でどこか 1 か所を崩す。乱数は
固定で毎回同じ 150 通り)。**4 値は部品の分類を呼ばず、行と宣言からテスト側の別実装で
組み立てている。** 同じファイルの 2 本目は 300 通りで、「列の種類の 1 欄を書き換えると、同じ
理由コードの空欄だけが `空欄` と `決まらない` のあいだで入れ替わり、値の側のマスは動かない」
ことを見ている。

## 出力 — 欠けている率は単独では返らない

`check` と `read` が返すのは、値の表の行数・項目の宣言の行数・理由コードの宣言の行数・
対象の数・項目の数・対象 × 項目 の総数・4 値の件数・理由コード別の件数・仮置きの件数、
それに分母の内訳と検算と 3 つの固定行だ。**率だけを返す呼び方も、option も無い。**

```
"4 値": {"値が在る": 4, "空欄(宣言された意味つき)": 8,
         "決まらない": 0, "止まった": 0},
"理由コード別": {"値が未取得": 1, "仮置き": 1, "未収録": 1, "施行日待ち": 1,
                 "該当なし": 1, "手で追加": 1, "全部に当たる": 2},
"理由コードの付いた行に値も在った件数(仮置き)": 1
```

固定行は 3 つとも消せない。「空欄の意味は宣言から取る」(既定も推定も提案も無いこと)、
「0 と空欄を寄せない」、「前の値で埋めない」(引き継ぎも版選びも帯当てもしないこと)だ。
`read` はさらにマスごとの内訳(値・結果・理由コード・空欄の意味・返し方・仮置きの値・出典)と、
理由コードの付いたマスだけを並べた表を出す。

`verify` は 3 つ見る。2 回読んで判定部分のバイト列の sha256 を突き合わせること、**宣言された
入れ替え方で値の表の行順を入れ替えても同じ出力になるか**、そして **理由コード別の件数の合計と
理由コードの無い行の件数が、対象 × 項目 の総数に合うか** だ。合わなければ観測としてそのまま
返す。

## 止まる理由コード(11 個)

```
理由コードが空 / 宣言に無いコード / 項目が宣言に無い / 同じ列に 2 つの意味 /
0 の扱いが未宣言 / 列の種類が未宣言 / 出典の欄が空 / 値の種類が空 /
件数の合計が合わない / 2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる
```

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。値の種類・
返し方・入れ替え方が登録の外の語だったとき、`はい` / `いいえ` 以外を書いたとき、列そのものが
足りないとき、対象・項目・コード・意味が空欄のとき、数として読めないとき、指数表記で書いた
とき、同じ項目または同じコードの宣言が 2 行あるとき、許す理由コードの一覧に同じコードを 2 つ
書いたとき、入れ替え方の宣言が 2 通りあるとき。

## 使い方

```bash
python blank_kind.py init ひな型/                                  # 3 枚の表のひな型を書く
python blank_kind.py check  値の表.csv 項目の宣言.csv 理由コードの宣言.csv   # 件数と分母の内訳
python blank_kind.py read   値の表.csv 項目の宣言.csv 理由コードの宣言.csv   # 上 + マスごとと指紋
python blank_kind.py verify 値の表.csv 項目の宣言.csv 理由コードの宣言.csv   # 2 回 + 行順 + 件数
```

終了コードは、**全てのマスに値が在るときだけ 0**、空欄や決まらないマスがあるときや止まった
ときは 3、表として読めなければ 2。まとめて走らせる仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from blank_kind import Sheet, Columns, Reasons, read

t = read(Sheet.load("値の表.csv"), Columns.load("項目の宣言.csv"),
         Reasons.load("理由コードの宣言.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `read` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。
そのこともテストで固定してある。

## テストと fixture

```bash
python -m pytest tools/blank_kind -q      # 28 passed(2026-10-16 実走)
```

`fixtures/` に値の表 3 枚・項目の宣言 2 枚・理由コードの宣言 1 枚と、崩した表 33 枚が入って
いる。**値も対象も項目も全て架空で、実在の金額や率や取引先名は 1 つも入れていない。** 空欄の
類型の名前(値が未取得・要照合・仮置き・未収録・施行日待ち・該当なし・手で追加・全部に当たる)
だけは、私の棚卸し記録(非公開)に文言として残っている区別を写した。**値そのものは写して
いない**(その記録自身が「値は未取得」「要照合」「未実施」と書いているため)。出典のうち 4 件
はこの repo 内の実在の行(`articles/07_asof_table.md` L15 / `articles/08_formula_table.md` L42 /
`articles/22_span_split.md` L16 / `articles/23_band_edge.md` L16)を指し、テストがその行を開いて
語が在ることまで確かめている。`fixtures/make_fixtures.py` を実行すると、崩した表ごと書き直す。

## できないこと

- 判定したことは「空欄の意味が宣言から 1 つに決まるか」までで、**どの意味が制度として正しい
  かは判定しない**
- **値がいくらかも言わない。** 値は入力の表から来るので、拾ってくるのは人の側になる
- **理由コードの一覧が足りているかも判定しない。** 宣言に無い意味は、書かれていない以上
  検出できない
- **空欄の理由を推定しない。足すべき理由コードも提案しない。** 理由コードの無い空欄は止まる
  だけで、埋める候補を出す経路が無い
- 仮置きを外す判断もしない。仮置きの値は仮置きの欄に出るだけで、採否は人の側に返る
- 日付で表の版を選ばない。期間も切らない。値を帯にも当てない
- 対象(`target`)は結果に添えるだけで、意味の決め分けには使わない。対象ごとに空欄の意味が
  違う表は、項目を分けて渡すことになる
- 上の件数は、合成した表に対する測定で、他の人の環境で同じ数字になるとは限らない
