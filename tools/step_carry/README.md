# step_carry — 宣言した「次の一歩」を約束に割って、後の文書のどこに記載が在るかを並べる

「次にやること」を書いたメモの 1 項目には、たいてい 2 つ以上の約束が入っている。後日の進捗の 1 枚では、その半分だけが
済みとして現れ、残りの半分は次の作業候補にも判断待ちにも出てこない、ということが起きる。項目のまま「済み / 未」で見ると、
半分済んだ項目が済みに見える。この部品は、**人が台帳に書いた約束の割り方と記載だけ**を使って、約束ごとに
後の文書のどこに記載が在るかを 4 つに分け、項目ごとに約束の内訳を並べる。

**文を約束に割らない。** 句読点や矢印で割る経路は無く、1 項目を何個の約束に割るかは人が台帳に書く。
**語の似かたから記載を当てない。** 類似度・部分一致の経路は無い。項目を「済み / 未」の 1 値に丸めない。
完了率・進み具合の率・合計の 1 値を出さない。なぜ記載が無いかの理由を当てない。どちらの文書が正しいかを決めない。
記載なしを「やっていない」「放置」と言い換えない。ネットワークに出ない、渡されたファイルの外を読まない、時計を読まない、
入力を書き換えない、float を使わない。標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 4 枚(どの行にも出典の欄が要る)

| 表 | 列 |
|---|---|
| 文書の登録表 | 文書 id / 時点(文字列のまま)/ 次の候補の行(`137-143` の形、無ければ空)/ 出典 |
| 約束の台帳 | 約束 id / 項目 id / 宣言の文字列(verbatim)/ 宣言側の出典 |
| 記載の台帳 | 約束 id / 後の文書 id / 記号 / 後の側の行 / 後の側の出典 / 後の側の文字列(verbatim) |
| 記号の登録表 | 記号 / 意味 / 要求する欄(後の側の欄の名前を `/` で区切る)/ 出典 |

記号は 6 つ: `済みの記載` / `次の候補に在る` / `判断待ちに在る` / `別の欄に在る` / `読んだ範囲に記載なし` / `近い語のみ`。
どの行がどの記号かは**台帳を書く人が決める**。道具は文字を読んで記号を当てない。

## 4 値(約束の行 1 つに 1 つ)

| 4 値 | 条件 |
|---|---|
| (A) 後の文書に済みの記載が在る | `済みの記載` の行が在る |
| (B) 後の文書の次の候補か判断待ちに在る | (A) でなく、`次の候補に在る` か `判断待ちに在る` の行が在る |
| (C) 後の文書の別の欄に在る | (A)(B) でなく、`別の欄に在る` の行が在る(例: 対象外の欄。宣言と違う置き場) |
| (D) 読んだ範囲に記載なし | 上のどれも無い。「やっていない」とは言わない |

`近い語のみ` は (A)〜(C) に数えず、別の列に並べる(寄せない)。`読んだ範囲に記載なし` は人が明示に書ける (D) の行で、
どこまで読んだかを出典の欄に書く。

別枠の理由は 6 つで、手前が勝つ: 出典が空 / 宣言の文字列が空 / 台帳に無い id を指す記載 / 登録表に無い記号 / id の重複 /
同じ約束に (A) と (D) が同時に書かれた。約束の行は、自分の行か、自分を指す記載の行に理由が 1 つでも在れば別枠になる。
記号が要求する欄が空のときも「出典が空」に入れる。

ほかに返すもの:

- 項目ごとに 1 行 = 約束の数と、4 値 + 別枠の内訳。**項目を 1 値の「済み / 未」に丸めない**
- 後の文書の次の候補の行のうち、どの約束の記載(近い語のみ・記載なしを除く)にも使われていない行の番号と数。
  新しく足された候補か、対応を書いていない候補かは決めない
- どの約束にも付かない記載(台帳に無い約束 id を指す記載)の数

補助として `words` が、指定した語が後の文書の何行目に何回出るかを literal 一致で数える。この件数は判定に使わない。
0 件でも (D) に自動では入れない(人が台帳に書いた分だけが判定に使われる)。

## いつも成り立つこと

約束の行 1 つには 4 値か別枠の理由 6 つのうち 1 つだけが付き、その合計は約束の行数に、項目ごとの内訳の合計はその項目の約束の数に等しく、記載の台帳の行順を入れ替えても答えは変わらず、渡した表は 1 文字も書き換わらない。

この 1 文は `tests/test_step_carry_property.py` が性質テスト(hypothesis)で確かめている。4 枚の表を乱数で作り
(空の出典、空の宣言、台帳に無い約束 id と文書 id、登録表に無い記号、重複した id、済みと記載なしの同居、近い語のみを混ぜる)、
4 値と別枠はテストの中で別の書き方で引き直して比べる(道具の判定は呼ばない)。乱数は固定で、毎回同じ 300 通り。

## 使い方

```
python step_carry.py check  bunsho.csv yakusoku.csv kisai.csv kigou.csv
python step_carry.py rows   bunsho.csv yakusoku.csv kisai.csv kigou.csv   # 約束 1 行の CSV
python step_carry.py verify bunsho.csv yakusoku.csv kisai.csv kigou.csv   # 5 つの検算
python step_carry.py words  later.txt freee 育休免除                       # 補助の語数え(判定に使わない)
```

終了コードは 0 = 判定した / 3 = verify のどれかが合わない / 2 = 表の形の誤り(1 件も判定しない)。
表の形の誤り = 列が無い、記号の登録表の空・重複、道具が意味を持たない記号の登録、要求する欄に後の側以外の欄の名前、
文書 id の空・重複、次の候補の行が `137-143` の形でない、約束 id・項目 id の空、後の側の行に数字以外。

`verify` が見る 5 つ: 二度走って同じ指紋(sha256)か / 記載の台帳の行順を入れ替えても同じ出力か /
4 値 + 別枠 = 約束の件数で、項目ごとの内訳の合計 = その項目の約束の数か /
記載がちょうど 1 行の約束からその 1 行を消すと、その約束だけが (D) へ動くか /
1 約束を 2 つに割り直すと、その親の項目の内訳だけが動くか。写しはメモリの中だけで作る。

```python
import step_carry as M
tables = M.read_all(["bunsho.csv", "yakusoku.csv", "kisai.csv", "kigou.csv"])
result = M.judge(tables)   # 4 値 / 別枠 / 約束ごと / 項目ごと / 後の文書の次の候補 / 判定部分の sha256
```

`fixtures/gousei/` は合成した 4 枚(架空の店の月次の締めメモと翌月の進捗表)。`examples/jokyo/` は、
私の手元の 2 文書(数表の棚卸しの記録の「次の一歩」と、翌日の作業状況の記録)から、宣言 3 項目を私が 5 つの約束に割り、
私が読んで書いた記載 10 行を写した 4 枚。

テストの実行には別に pytest と hypothesis が要る。ライセンスは MIT。
