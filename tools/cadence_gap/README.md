# cadence_gap — 自動で更新すると書いた表も最後に動いた日は別なので、宣言した周期と実行の履歴を突き合わせる

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [自動で更新すると書いた表も最後に動いた日は別なので、宣言した周期と実行の履歴を突き合わせる](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_26.html)(2026-10-27 公開)
<!-- article-links:end -->

**「自動で週 1 回更新する」と書いてある数表でも、履歴に残っている実行は別の話で、
最後に中身が動いた日を見ないと古い行をそのまま引く。**

[update_ledger](../update_ledger) の回は、更新 1 回を台帳の 1 行にして差分を 6 種に分ける道具
だった。あちらは**行の中**を数え、こちらは**行と行の間隔**を数える。[check_census](../check_census)
は宣言された実行コマンドをその場で走らせる道具で、こちらは走らせず履歴を読むだけだ。
[recalc_scope](../recalc_scope) は差し替えた後にどれを出し直すかの回で、差し替えがまだ来ていない
場合は扱わない。[cover_stock](../cover_stock) は年ごとに行がそろうかの在庫で、そろっている行が
いつ更新されたかは見ない。

この部品は、周期の宣言表・実行の履歴表・問いの一覧の 3 枚から、問い 1 件ごとに 6 値
(**宣言どおり / 遅れている / 一度も動いていない / 履歴が無い / 宣言が無い** の 5 値 +
別枠 **基準日より前の実行が無い**)を付け、問いごとに 3 つの日付(**走った最後の日 /
中身が動いた最後の日 / 落ちた回を除いた最後の日**)を別の列で返す。**走らせない。
時計を読まない。値を引かない。原文を取りに行かない。数えるだけだ。**

持たせていないものが規律になっている。

- **基準日を時計から取らない**(現在時刻を読む呼び出しが 1 つも無い。基準日は必ず問いの
  一覧の列で、日付は文字列から整数の通算日に直すだけ。**同じ入力なら何日後に走らせても同じ
  答えになる** = [env_match](../env_match) の回で書いた「判定に入れない欄」をここでも守る)
- **落ちた回を最後の更新に数えない**(結果が `failed` の行は「走った最後の日」にだけ入り、
  「中身が動いた最後の日」と「落ちた回を除いた最後の日」に入る経路が無い)
- **中身が動いた件数が 0 の実行を更新に数えない**(走った最後の日と中身が動いた最後の日を
  別の列で返し、**1 つの「最終実行」に潰す経路が無い**。これが骨の物理形)
- **周期の宣言が無い数表に既定の周期を当てない**(週 1 を既定にする引数も、ほかの数表の周期を
  借りる経路も無い。別の値「宣言が無い」に出す)
- **遅れの理由を決めない**(登録がまだ / 資料がまだ公表されていない / 改定が無かった を区別
  せず「遅れている」の 1 値 + 空き日数 + 超過日数で返し、理由は読む人に戻す。自動で走る宣言の
  有無で判定を変える経路も無い)
- **評価の語を出力に持たない**(出すのは日数と件数だけ。評価の語は文字列としてもコードに無い)
- **鮮度を点数や割合にしない**(件数と日数と 3 つの分母の内訳だけを返す)
- **次回改定の近さを鮮度と同じ列に入れない**(予定を受け取っても別の一覧で返す。鮮度と改定の
  近さは別の問いだから、同じ列で足さない)
- **件数と指紋の食い違いを、どちらが正しいとも決めない**(2 種類に分けて並べるだけで、どちらを
  直すべきかを返す欄が無い)
- **出典の欄が空の行は使わずに止まる**
- **走らせない・値を引かない・計算しない・原文を取りに行かない**(実行経路もネットワーク経路も
  持たない。走らせるのは [check_census](../check_census) の仕事で、ここに寄せない)
- **この部品自身の「読めない」を、測っている相手の「履歴が無い」と同じ欄に入れない**(3 枚の
  どれかが 1 行でも壊れていたら 1 件も数えず、理由コードだけを返す。6 値は全て 0 になる)
- **入力表を書き換えず、行も実行も生成しない**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない。行順にも依らない)
- **数は整数だけ**(日数も件数も整数で、float を使う経路が無い)

## 入力 — 3 枚の表

周期の宣言表は 7 列。**1 つの数表が 1 行**で、ここが建前の側になる。

| 列 | 意味 |
|---|---|
| `table_id` | 数表 id(空欄・区切り文字入りは「表として読めない」。同じ id が 2 行あると**止まる**) |
| `cycle_days` | 宣言された周期(日数、整数)。小数は読めない。1 日より短いと**止まる** |
| `auto` | 自動で走る宣言の有無(`在る` / `無い`。登録外は「表として読めない」) |
| `auto_source` | 自動で走る宣言の出典(空欄は**止まる**) |
| `cycle_source` | 周期の出典(空欄は**止まる**) |
| `next_change` | 次回改定の予定日(空欄可。在れば**別枠**で返す) |
| `next_change_source` | 次回改定の出典(予定が在るのに空欄なら**止まる**) |

実行の履歴表は 7 列。**1 回の実行が 1 行**で、ここが実務の側になる。

| 列 | 意味 |
|---|---|
| `run_id` | 実行 id(空欄・区切り文字入り・重複は「表として読めない」) |
| `table_id` | 数表 id |
| `ran_on` | 実行日(`YYYY-MM-DD`。形が違う・その月に無い日付は「表として読めない」) |
| `result` | 結果(`ok` / `failed`。登録外は「表として読めない」) |
| `moved` | 中身が動いた件数(0 以上の整数)。落ちた回に 1 以上が入っていると**止まる** |
| `fingerprint` | 出力の指紋。動いた件数が 1 以上で空欄なら**止まる**、落ちた回に入っていても**止まる** |
| `source` | 出典(空欄は**止まる**) |

同じ日に同じ数表が 2 回走っていても構わない(実行 id が違えば別の行として数える)。

問いの一覧は 4 列。**1 つの問いが 1 行**。

| 列 | 意味 |
|---|---|
| `table_id` | 数表 id(宣言表にも履歴表にも無いと**止まる**) |
| `asof` | **基準日**。いつ時点の鮮度を見るかを人が決める(同じ数表を違う基準日できいてよい) |
| `source` | 出典(空欄は**止まる**) |
| `swap` | 入れ替え方(`逆順` / `両端入れ替え` / `1 つずらす`)。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 分け方 — 問い 1 件に付く 6 値

| 問いの形 | どうするか | 6 値 |
|---|---|---|
| 周期の宣言が無い数表 | 既定の周期を当てない | 宣言が無い |
| 履歴が 1 行も無い数表 | 走ったことが無いのか記録が無いのかを決めない | 履歴が無い |
| 履歴は在るが基準日より後の実行だけ | 分母から外す | 基準日より前の実行が無い |
| 走った履歴は在るが、中身が動いた回が無い | 空き日数を出せない | 一度も動いていない |
| 空き日数が宣言された周期を超えた | 超過日数を添える | 遅れている |
| 空き日数が宣言された周期の内側 | 超過日数は 0 | 宣言どおり |

上から順に見るので、**「履歴が無い」と「一度も動いていない」は別の値になる**。前者は記録の
話で、後者は記録の中身の話だ。また **「宣言が無い」数表にも 3 つの日付は出る**(履歴さえ在れば
出る)。出ないのは空き日数と超過日数で、周期を当てないからそこは空のまま返る。

## 3 つの日付 — 1 つに潰さない

| 列 | 何を拾うか | 何を拾わないか |
|---|---|---|
| 走った最後の日 | 基準日までの全ての実行 | 基準日より後の実行 |
| 中身が動いた最後の日 | 結果が `ok` で、動いた件数が 1 以上の実行 | 落ちた回と、動いた件数 0 の回 |
| 落ちた回を除いた最後の日 | 結果が `ok` の実行 | 落ちた回 |

鮮度の答えに使うのは真ん中の列だけだ。上の 2 つは**走ったことの記録**で、更新されたことの
記録ではない。この 3 つを 1 つの「最終実行」に潰すと、走っただけの回や落ちた回が鮮度の答えに
なり、しかもどれも「最終実行」の名前で返る。

## 件数の検算 — 4 通りの数え方が合う

- **6 値の件数の合計 = 問いの数**
- **5 値の合計 = 鮮度候補の数**(基準日より前の実行が無い問いは分母の外)
- **数表ごとの内訳の合計 = 問いの数**(問い 1 件はちょうど 1 つの数表に入る)
- **日数まで出せた件数 = 日数を出せる条件がそろった問いの数**(中身が動いた最後の日も周期の
  宣言も在る問い)

4 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
分母は 問いの数 / 鮮度候補の数 / 別枠の数 の 3 つを必ず付ける。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- 問い 1 件ごとに、6 値のどれか 1 つが付き、**6 値の合計が問いの数**に等しく、**5 値の合計が
  鮮度候補の数**に等しく、**数表ごとの内訳の合計も問いの数**に等しく、**日数まで出せた件数が
  日数を出せる条件がそろった問いの数**に等しく、**落ちた回と中身が動いた件数 0 の回は「中身が
  動いた最後の日」に出ず**、**基準日より後の実行は 3 つの日付のどれにも入らず**、**中身が
  動いた最後の日は走った最後の日より後にならず**、**周期の宣言が無い数表には既定の周期を
  当てず**、判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても
  同じバイト列**になる
- または、1 件も数えずに理由コードが返る(数えた問いや指紋を取りに行くと例外になる)

どちらの場合も、この部品は 3 枚の表を 1 文字も書き換えない。

この 1 文を `tests/test_cadence_gap_property.py` の `@given` テストが確かめている(数表を
1〜3 つ、周期を 3 通り、実行を 0〜2 回ずつ、問いを 1〜3 件引く。実行の結果と動いた件数と指紋を
引くので宣言どおり・遅れている・一度も動いていないが混ざり、宣言表と履歴表の載せ方を引くので
「宣言が無い」と「履歴が無い」も混ざる。基準日は 5 通りから引くので「基準日より前の実行が無い」
も出る。3 割くらいの確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。**6 値の分け方
はテストの側で別に実装している**(部品の `judge` / `six` を呼ばない)。同じファイルの 2 本目は
「落ちた回と差分 0 の回は中身が動いた最後の日に出ない」ことだけを総当たりで見ている(上限 300)。

この性質テストは、書いている途中で 1 つ捕まえた。**「日数まで出せた件数 = 中身が動いた最後の日
が在る問いの数」という検算を置いていたが、これは常には成り立たない**。周期の宣言が無い数表にも
履歴さえ在れば「中身が動いた最後の日」は出て、しかし周期を当てないので日数は出ない。合成した
表ではその数表の実行が差分 0 だったので偶然どちらも同じ数になっていた。検算の側を「日数を
出せる条件がそろった問い」に直した。

## 出力 — 点数も割合も返らない

`check` と `cadence` が返るのは、3 枚それぞれの行数、3 つの分母、6 値の件数、日数まで出せた
件数、走ったが中身は動いていない実行の数、件数と指紋が食い違う実行の数、数表ごとの内訳、
理由別の止まった件数、分母の内訳と検算、それに 10 個の固定行だ。**達成の度合いだけを返す
呼び方も、option も無い。**

```
"分母(問いの数)": 9,
"分母(鮮度候補の数)": 8,
"分母(別枠の数)": 1,
"6 値": {"宣言どおり": 3, "遅れている": 2, "一度も動いていない": 1,
         "履歴が無い": 1, "宣言が無い": 1, "基準日より前の実行が無い": 1},
"日数まで出せた件数": 5,
"日数を出せる条件がそろった問い": 5,
"走ったが中身は動いていない実行": 4,
"件数と指紋が食い違う実行": 2,
"理由別の止まった件数": {},
"件数の合計の検算": "6 値の合計 9 / 問いの数 9(5 値 8 = 鮮度候補 8 も同じ、…",
"基準日を時計から取らない": "…",
"落ちた回を最後の更新に数えない": "…",
"差分 0 の実行を更新に数えない": "…",
"既定の周期を当てない": "…",
"遅れの理由を決めない": "…",
"点数も割合も返さない": "…",
"次回改定の近さは別枠": "…",
"食い違いをどちらが正とも決めない": "…",
"走らせない・取りに行かない": "…",

```

`cadence` にすると、判定ごとの一覧、**問いごとの 3 つの日付**(空き日数と超過日数つき)、
**走ったが中身は動いていない実行だけの一覧**(その数表の最後の実行かどうかの印つき)、
**件数と指紋が食い違う実行**(2 種類)、**次回改定の近さ**(別の問い)が出る。
**名前は入力に書かれたものがそのまま出る**(部品が書き足すことはしない)。

## 止まる理由コード(11 個)

3 枚の表の側。1 件も数えずに止まるものが 8 個。

`出典の欄が空` / `同じ数表 id が宣言表に 2 行ある` / `宣言された周期が 1 日より短い` /
`落ちた回に中身が動いた件数が入っている` / `中身が動いた回に指紋が無い` /
`落ちた回に指紋が入っている` / `問いの数表 id が宣言表にも履歴表にも無い` /
`次回改定の予定が在るのに出典が空`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄や区切り文字入り・同じ実行 id や同じ問いが 2 行・結果や自動の
宣言が登録外・周期や件数が 0 以上の整数でない・日付の形が違う・その月に無い日付・登録外の
入れ替え方・入れ替え方の宣言が 2 通り、は**「表として読めない」**(終了コード 2)で、理由
コードには混ぜない。

## 使い方

```
python cadence_gap.py init ひな型/
python cadence_gap.py check   周期の宣言.csv 実行の履歴.csv 問いの一覧.csv
python cadence_gap.py cadence 周期の宣言.csv 実行の履歴.csv 問いの一覧.csv
python cadence_gap.py verify  周期の宣言.csv 実行の履歴.csv 問いの一覧.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、宣言された入れ替え方で 3 枚の
行順を入れ替えても同じ出力になるか、件数の合計が 4 通りとも合うか、そして 2 つの写しだ。
**最後の実行を落ちた回に替えた写し**では、宣言どおりが動く問いの数だけ減って遅れているが同じ数
だけ増え、超過日数が 1 つ前に動いた実行から数え直されること。**中身が動いた件数を 0 に替えた
写し**では、中身が動いた最後の日だけが 1 つ前に戻り、走った最後の日と落ちた回を除いた最後の日は
動かないこと。1 回の実行は基準日の違う複数の問いに効くので、**動く問いの数を入力から先に数えて
おき、替えた後の件数がその数と合うか**を見る。写しはメモリの中だけで、入力の表には 1 文字も
書かない。

終了コードは、別枠と止まった行が 0 件のときだけ 0、在れば 3、表として読めなければ 2。
**遅れていることの是非は、この終了コードにも出力にも出さない。**

関数でも呼べる。

```python
import cadence_gap as C

t = C.cadence_gap(C.Declarations.load("周期の宣言.csv"), C.Runs.load("実行の履歴.csv"),
                  C.Questions.load("問いの一覧.csv"))
if t.report.ok:
    print(t.counts()["6 値"], t.ran_but_not_moved())
```

```
python -m pytest tools/cadence_gap -q
python fixtures/make_fixtures.py     # 合成の 3 枚と、崩した表 33 枚を書き直す
```

`fixtures/` に入っているのは合成した 3 枚(宣言 5 行 / 履歴 11 行 / 問い 9 件)と、理由コードと
「表として読めない」を出すために 1 か所だけ崩した表 33 枚だ。**実在の料率・金額・取引先名は
1 つも入っていない。** 数表 id も実行 id も指紋も日付も架空で、指紋は `fp11` のような記号にして
ある。**履歴の行数と結果の内訳(11 行 / `ok` 9 / 落ちた回 2)だけは手元の記録と同じ形にそろえて
ある**(値は架空)。

## できないこと

- **基準日は読む人が与える入力で、この部品は「いま」を知らない。** だから「いま何日空いて
  いるか」はこの部品だけでは出ない。時計から取る引数を増やすつもりも無い
- **遅れの理由は判定しない。** 登録がまだなのか、資料がまだ公表されていないのか、改定が無かった
  のかを分けないので、理由は読む人が確かめることになる
- **周期そのものが妥当かも判定しない。** 週 1 が適切かどうかは人が決める
- **止まっていたことの影響の大きさも出さない。** どの結果が古い行で出たかは
  [recalc_scope](../recalc_scope) の範囲で、ここは日数までだ
- **走らせない。** 宣言された実行をその場で走らせるのは [check_census](../check_census) の仕事で、
  ここは履歴を読むだけになる
- **件数と指紋のどちらが正しいかも決めない。** 食い違う実行は 2 種類に分けて並べるだけだ
- **「中身が動いた件数」の正しさは測れない。** 履歴に書かれた数をそのまま信じるので、差分の
  数え方そのものが壊れていればこの部品も一緒に間違える
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
