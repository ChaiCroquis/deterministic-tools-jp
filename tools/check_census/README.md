# check_census — 検証は在るかを数えず、走らせた結果だけを台帳に残す

棚卸しの記録に「テストが在る」と数えられた本数が並んでいても、その件数は **走らせた結果を 1 件も
言っていない**。在ることと通ったことは別の事実で、数えた件数は前者しか言わない。

この部品は宣言表に書かれた runner **だけ** を実際に走らせ、**通った / 落ちた / 走らなかった /
テストが無い** の 4 値を、分母の内訳つきで台帳に残す。走らなかったものを通ったに混ぜない。

持たせていないものが規律になっている。

- **宣言に無いコマンドを実行しない**(フォルダを見て runner を推測で組み立てる経路が無い)
- **シェルを経由しない**(argv は配列のまま渡す。文字列を結合してコマンドを作る経路が無い。
  `shell=True` がソースのどこにも無いことをテストで固定してある)
- **ネットワークを既定で許さない**(`allow_network` が空の行は、外向きの既定を環境変数で落として走らせ、
  落ちたら落ちたと書く)
- **走らなかったものを通ったにも落ちたにも混ぜない**(4 値を 3 値に潰す引数が無い。
  [intake_triage](../intake_triage) の 3 分類、[answer_check](../answer_check) の 4 値と同じ規律)
- **合格率を単独で返さない**(4 値の件数と分母の内訳を必ず併記する。[tally_gate](../tally_gate) /
  [cross_route](../cross_route) / [answer_check](../answer_check) と同じ)
- **テストもコードも書き換えない**(直す・生成する・再試行する経路が無い。返すのは台帳と理由コードだけ)
- **timeout を既定値で黙って延ばさない**(宣言表から取る。超えたら「走らなかった」に落ちて理由が付く)
- **判定部分に所要時間・時刻・ホスト名を入れない**(非決定な値を一致判定に混ぜない)
- **カバレッジを測らない**(テストの中身が妥当か・網羅しているかは部品の外)

stdlib のみ(subprocess / csv / json / hashlib / pathlib / datetime / platform / os / argparse)、依存なし。

## 流れ(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | 宣言表の列が揃っているかを見る | name / path / declared / runner / timeout / required / source のどれかが無い |
| 2 | argv と出典を見る(runner が JSON の配列か、出典が書かれているか) | argv が配列でない、出典の列が空欄 |
| 3 | timeout と name を見る(timeout が数か、同じ name の行が 1 件か) | timeout が空欄か数でない、同じ name の行が 2 件以上 |
| 4 | 宣言された argv だけを配列のまま走らせる | — |
| 5 | 終了コードと理由コードを 4 値に分け、件数と分母の内訳を出す | — |
| 6 | `verify` で 2 回目の判定部分と sha256 を突き合わせる | 2 回目の判定部分がバイト列として不一致 |

前の段で止まったら **1 行も走らせない**。止まったときは台帳が 1 行も返らず、理由コードだけが返る。

## いつも成り立つこと

台帳の結果は 2 通りしかない。**宣言表の行のひとつひとつがちょうど 1 つの判定(通った / 落ちた /
走らなかった / テストが無い)に入り、その合計が宣言の行数に等しく、走らなかった行とテストが無い行には
終了コードが無く、通った行の終了コードは 0、落ちた行は 0 以外で、判定部分のバイト列に所要時間・時刻・
ホスト名が 1 つも入らない**か、**判定が 1 件も返らず、理由コードが返る**か。どちらの場合も、この部品は
宣言表もテストもコードも 1 文字も書き換えない。

この 1 文は `tests/test_check_census_property.py` が性質テスト(hypothesis)で確かめている。宣言表を
乱数で 1〜2 行作り、1 行ごとに 8 とおりの在り方(通る / 落ちる / timeout を超える / runner が無い /
実行ファイルが無い / path が無い / 宣言の列が空欄 / テストが無い)から引く。さらに 4 割くらいの確率で
宣言表そのものを 1 か所だけ崩す(runner を文字列にする / timeout を空にする / 出典を空にする / 同じ
name を 2 行にする)。乱数は固定で、毎回同じ 50 通り。**期待する判定は道具の関数を使わず、テストの側で
持っている**(走らせる argv をテストが決めているので、その行が通るはずか落ちるはずか走らないはずかは
テストの側で分かる)。同じファイルの 2 本目は **分母の恒等式** を見る(4 値の合計が宣言の行数に等しく、
走らせた行だけを分母にした合格率は、宣言の行すべてを分母にした合格率を下回らない = 狭い分母だけを
引用すると必ず上振れする側に出る)。テストの実行には pytest と hypothesis が要る(道具そのものは
標準ライブラリだけで動く)。

## 入力 — 宣言表 1 枚だけ

`fixtures/sengen.csv` が例、`init` でひな型が出る。1 行が 1 つの検証対象。

| 欄 | 意味 |
|---|---|
| `name` | 行を指す名前。**空欄も重複も止まる**(どの行の結果かが決まらない) |
| `path` | runner を走らせるフォルダ。宣言表のある場所からの相対パス、または絶対パス |
| `declared` | 「テストが在るか」の grep 相当の宣言。`在る` / `無い` / `不明`。**結果列と必ず並べて出す** |
| `runner` | 実行する argv を **JSON の配列** で明示(`["python", "-m", "pytest", "-q"]`) |
| `timeout` | 秒。**宣言表から取る**(既定値で黙って延ばさない) |
| `required` | `はい` / `いいえ`。`はい` の行が通らなければ終了コード 3 |
| `allow_network` | `はい` / `いいえ` / 空欄。列そのものが無くてもよい。空欄は外向きの既定を落として走らせる |
| `source` | その行の出典(どの記録から持ってきた宣言か)。**空欄は止まる** |

`declared` が `無い` の行の `runner` 欄は読まない(走らせない)。`在る` と `不明` の行は走らせる
(**不明を「無い」に寄せない**)。

## 判定は 4 値

| 判定 | 何が起きたか |
|---|---|
| `通った` | 宣言された argv が終了コード 0 を返した |
| `落ちた` | 終了コード 0 以外を返した(試験が 1 件も無くて 5 を返す場合もここ) |
| `走らなかった` | 走らせる前に止まった。理由コードが付く |
| `テストが無い` | 宣言で `無い` と書かれている |

`走らなかった` に付く理由コードは 4 個。

```
runner が無い(runner 欄が空、または実行ファイルが見つからない) / timeout /
宣言の列が空欄(name か path が空) / path が無い
```

**走らなかったものを通ったにも落ちたにも混ぜない。** 3 値に潰す引数は関数にも CLI にも無い。

## 合格率は分子分母だけでは返らない

`rate()` は 4 値の件数と、分母に何を含めたかの文字列を必ず同時に返す。

```
{"宣言で在る": 8, "宣言で無い": 1, "宣言で不明": 1,
 "通った": 3, "落ちた": 3, "走らなかった": 3, "テストが無い": 1,
 "宣言の行数": 10, "走らせた数": 6, "走らなかった数": 3, "テストが無い数": 1,
 "合格率_走らせた行のみ": "0.5000", "合格率_宣言の行すべて": "0.3000",
 "分母に含めたもの": "走らせた行のみ = 通った 3 + 落ちた 3 = 6(走らなかった 3 + テストが無い 1 を
                   除いた分母) / 宣言の行すべて = 10(走らなかった行とテストが無い行を含む分母)",
 "在ると数えた数は結果を 1 件も言わない": "宣言では在る 8 / 走らせて通った 3"}
```

走らなかった行を分母から落とすと、同じ入力で `0.3000` が `0.5000` になる。だから片方だけを引用できない
形にしてある。最後の 1 行はこの部品の骨をそのまま出力にしたもので、報告から外せない。

## 台帳の判定部分は決定論

判定部分に入るのは 6 欄だけで、行の順は宣言表の順、キーの順・区切り・改行は固定。

```
{"name": "道具A_通る", "宣言": "在る", "判定": "通った", "理由コード": "",
 "終了コード": 0, "出力の末尾の指紋": "61affed0…(末尾 10 行の sha256)"}
```

所要秒・始めた時刻・ホスト名は **別の欄**(`timing()`)に出し、sha256 の対象から外す。非決定な値を
一致判定に混ぜないため。

`verify` は 2 回走らせて判定部分の sha256 を突き合わせる。**一致しなかったら、走らせた対象が同じ入力に
同じ結果を返していないという観測としてそのまま返す**(平均も多数決もしない)。どの欄で違ったかも出る。

```
{"ok": false, "一致": false, "判定した回数": 2,
 "観測": "走らせた対象が同じ入力に同じ結果を返していない(平均も多数決もしない)",
 "不一致の内訳": [{"name": "道具I_揺れる", "違った欄": {"出力の末尾の指紋": ["252b06…", "d6715a…"]}}],
 "pending": [{"reason": "2 回目の判定部分がバイト列として不一致", "detail": "不一致の行 1 件"}]}
```

所要時間を出力に書く runner(`N passed in 0.03s` のような行を出すもの)は、終了コードが一致していても
**出力の指紋だけが毎回変わる**。その場合もこの形で返る。吸収する経路は持たせていない。

## 止まる理由コード(6 個)

| 理由コード | 何が起きたか |
|---|---|
| 宣言表に必要な列が無い | `name` / `path` / `declared` / `runner` / `timeout` / `required` / `source` のどれかが無い |
| argv が配列でない | `runner` 欄が JSON の配列でない(文字列を結合してコマンドを作らせない) |
| timeout が空欄か数でない | 既定値で黙って延ばさないので、空欄なら止まる |
| 出典の列が空欄 | その宣言がどこから来たかが辿れない |
| 同じ name の行が 2 件以上 | どの行の結果かが決まらない |
| 2 回目の判定部分がバイト列として不一致 | 同じ宣言表から 2 回走らせて、判定部分が違った |

`declared` が `在る` / `無い` / `不明` 以外、`required` / `allow_network` が `はい` / `いいえ` 以外の
ときは、理由コードにせず終了コード 2 で返す(宣言表として読めない = 書く側の話)。

## 使い方

```
python check_census.py census <宣言表.csv>
python check_census.py verify <宣言表.csv>
python check_census.py init   <宣言表.csv>
```

終了コードは 0 = 止まらず、`required` が `はい` の行が全部通った / 3 = `required` の行に通っていない
ものがある、または理由コードで止まった / 2 = 宣言表として読めない。バッチの中に置いて 3 で止められる。
**option は `-h` 以外に 1 つも無い**(テストで固定してある)。

```python
from check_census import Declaration, census, verify

c = census(Declaration.load("sengen.csv"))
if c.report.ok:
    print(c.rate())      # 4 値 + 分母の内訳 + 2 つの合格率
    print(c.table())     # 判定部分(宣言の列と結果の列が並ぶ)
    print(c.timing())    # 所要秒 / 時刻 / ホスト名(判定部分の外)
    print(c.sha256())    # 同じ入力なら同じバイト列
else:
    for x in c.report.pending:
        print(x.reason, x.detail)
```

## 読み替えた範囲(「許可はあるが使われていない」の型)

「許可はあるが使われていない」滞留の型を、ここでは **許可の根拠 = テストファイルが在ること(走らせて
よい形になっている)/ 滞留している量 = 本数** と読み替えている。**滞留の理由は書かない**(なぜ走って
いないのかは出典が無いので、この部品も記事も言わない)。言うのは「在ると数えた数」と「走らせた結果」の
2 つを並べることまでで、差の原因は人が調べる。

## テストと fixture

```
python -m pytest tools/check_census -q      # 25 passed
python fixtures/make_fixtures.py            # 合成 fixture を作り直す
```

fixture は全て合成データで、プロジェクト名・runner・出典はすべて架空。実在のツール名もパスも入って
いない。合成 runner は外へ 1 バイトも出ない(`run_net.py` は「外向きを使う検証」に見立てて、外向きの
既定が落ちていることを見て落ちるだけで、通信はしない)。`sengen.csv` は 10 行で、4 値と「走らなかった」
の理由コード 3 つが出そろう形にしてある。`test_measure_*` が記事に載せた数値の出どころで、固定の
合成プロジェクトから決定論的に出る値を `assert` で固定している。

repo に入れてある `sengen.csv` の `runner` は `["python", "run_ok.py"]` のように PATH 上の `python` を
指す。テストは `make_fixtures.build(dest, sys.executable)` で宣言表を作り直すので、PATH には依存しない。

## できないこと

- 判定したことは「宣言された runner が終了コード 0 を返したか」までで、**テストが正しいことは判定
  しない**。通っても、そのテストが見るべきものを見ているとは言えない
- **対象が仕様どおり動くことも判定しない**。見ているのは終了コードだけ
- **カバレッジを測らない**。網羅しているか、どの行が通ったかは部品の外
- **なぜ走っていなかったのかは分からない**。在ると数えた数と走らせた結果の差は出るが、理由は出ない
  (上の「読み替えた範囲」)
- 外向きの既定を落とすのは **環境変数だけ**。ソケットを塞ぐわけではないので、環境変数を見ない通信は
  通る。確実に塞ぎたいなら、この部品の外(OS やコンテナの側)でやる
- 出力の指紋は末尾 10 行だけで、途中の行は見ていない。末尾に時刻や所要時間を書く runner は、結果が
  同じでも指紋が毎回変わる(`verify` が不一致として返す。吸収しない)
- timeout で止めた行の部分出力は捨てる。**「途中まで通っていた」は残らない**
- 宣言表の正しさは判定しない。走らせる argv が本当にその対象のテストなのか、`declared` の `在る` が
  合っているかは、宣言を書く人の側になる
- 上の件数は合成プロジェクトでの測定で、他の人の手元で同じ数字になるとは限らない
