# asof_table — 毎年変わる数表を「基準日・対象・公表時点」で引く

料率・最低賃金・等級表・限度額のような毎年変わる数表を「適用開始日つきの履歴」で持つと、
**適用開始日という日付 1 軸では足りない**。足りないのは次の 4 か所で、どれも誤った値を静かに返す。

| 日付 1 軸で壊れる点 | 何が起きるか | この部品で潰す列 |
|---|---|---|
| 基準日がルールごとに違う | 同じ月の給与でも、社会保険は対象月の初日、雇用保険は賃金の締切日で引く。呼ぶ側が 1 つの日付を渡すと片方が年度をまたぐ | `basis`(どの日付で引くかを行の側が宣言する) |
| 数式そのものが改正される | 値だけを履歴にしても、計算の仕方が変わった改正を表せない | `value` に数式 id を置ける形にはなっているが、**評価はこの部品の外**(未実装) |
| 公表日と施行日がずれる | 2 月に公表されて 3 月分から適用される表を、2 月上旬の時点で引くと未来の知識を使ってしまう | `known_from` / `known_to`(知識時間) |
| 経過措置が対象を限定する | 本則が改定されても、ある帯の人だけ旧い値が続く | `sel_*`(対象セグメント)と `priority` |

引いた結果には**使った行の出典・有効開始日・行番号が必ず付く**。決まらないときは理由コードで止まり、
**黙って現行値や直近値へ落ちる経路は無い**(`resolve` に fallback の引数も持たせていない)。
標準ライブラリのみ(csv / json / datetime / argparse)、依存なし。

## 表の形(1 行 = 1 条項の適用単位)

| 列 | 意味 |
|---|---|
| `key` | 何を求めるか。同じ key の行は同じ `basis` を持つ(食い違うと表の不備として止まる) |
| `basis` | case のどの日付で有効期間を引くかの名前(対象月初日 / 賃金締切日 / 請求日 / 離職日 …) |
| `valid_from` / `valid_to` | 有効時間。半開区間 `[valid_from, valid_to)`。`valid_to` 空 = 開いたまま。`valid_from` 空 = 施行日未定(決して当たらない) |
| `known_from` / `known_to` | 知識時間(公表側)。`as_of` を渡すと「その時点の知識」で引ける。空は許さない |
| `known_quality` | `known_from` の質。`実値` / `仮置き`(空欄は仮置き扱い) |
| `priority` | `0` 本則 / `10` 経過措置 / `20` 特例 |
| `value` | 値。**文字列のまま返す**(型変換・端数処理・数式評価はしない) |
| `source` | 出典。返り値に必ず付く |
| `sel_*` | 対象セグメントの次元。列名は呼ぶ側が決める。**空欄 = ワイルドカード**なので、次元を後から足しても既存行は無修正 |

業種や制度の意味は部品の中に持たない。`basis` の名前も `sel_` の次元名も、呼ぶ側の表で決める。

## 引き方(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | key の行を集め、`basis` を決める | key が表に無い / 同じ key に basis が 2 種類 |
| 2 | case から `basis` の日付を取る | case にその名前の日付が無い |
| 3 | 知識時間で絞る(`as_of` 省略 = 差し替えられていない行 = いまの知識) | as_of 時点で未公表 / 公表日が仮置き |
| 4 | 有効時間で絞る(`case[basis]` が半開区間に入るか) | 収録範囲の外(前後の外・期間の穴) |
| 5 | 対象(`sel_*`)で絞る | 同上 |
| 6 | 最高 `priority` の 1 行 | 同順位で複数該当 |

## 決まらないときの理由コード(`REASONS`、この 5 つで全部)

| 理由コード | 意味 |
|---|---|
| `基準日が case に無い` | この key は `basis` で宣言した日付で引く。case にその名前が無いので、どの日付で引くかを機械では選べない |
| `as_of 時点で未公表` | 有効時間では当たる行があるが、その行は `as_of` の時点ではまだ公表されていない |
| `収録範囲の外` | key が表に無いか、基準日が表の期間のどれにも入らない(前後の外か、期間の穴) |
| `同順位で複数該当` | 同じ `priority` の行が 2 つ以上当たった。どちらを採るかは表の外の判断になる |
| `公表日が仮置き` | 当たるはずの行の `known_from` が仮置きなので、`as_of` 時点で公表済みだったかを機械では決められない |

理由コードは「機械では決まらない理由」の名前になっている。どう直すかは人が決める。
**対象を細かく指定しない側が勝つ、といった優先順位は持たない。**
ワイルドカードの行と具体的な行が同じ `priority` で当たれば `同順位で複数該当` で止まる(優先は `priority` に書く)。

## 表そのものの検査(`validate`、直さない)

| 不備 | 中身 |
|---|---|
| `期間の逆転` | `valid_from >= valid_to` |
| `知識期間の逆転` | `known_from >= known_to` |
| `基準日の不一致` | 同じ key に `basis` が 2 種類以上 |
| `priority が登録外` | 0 / 10 / 20 のどれでもない |
| `有効期間の重なり` | 同じ key × 対象 × priority で、知識時間も有効時間も重なる行 |
| `期間の穴` | 同じ key × 対象 × priority で、前の行の `valid_to` と次の行の `valid_from` が離れている |

施行日未定の行(`valid_from` 空)は期間を持たないので、重なりにも穴にも数えない。

## 使い方

```
python asof_table.py resolve <表.csv> --key <key> --case 名前=値 [--case ...] [--as-of YYYY-MM-DD]
python asof_table.py validate <表.csv>
```

終了コードは 0 = 引けた / 3 = 理由コードで止まった・表に不備があった / 2 = 表か引数の誤り。出力は 1 行 JSON。

```
$ python asof_table.py resolve fixtures/ryouritsu.csv --key 保険料率_甲 --case 対象月初日=2025-06-01 --case sel_地域=地域A
{"ok": true, "key": "保険料率_甲", "basis": "対象月初日", "value": "9.60", "source": "合成の料率表 2025 年度版(架空)", "valid_from": "2025-03-01", "priority": 0, "priority_name": "本則", "row": 13}
```

関数として呼ぶなら次のとおり。

```python
from datetime import date
from asof_table import Table, resolve, validate, naive_lookup

table = Table.load("ryouritsu.csv")          # .json でも同じ形
r = resolve(table, "保険料率_甲",
            {"対象月初日": "2026-03-01", "sel_地域": "地域A"},
            as_of=date(2026, 2, 5))
if r.ok:
    print(r.value, r.source, r.valid_from, r.row)
else:
    print(r.reason, r.detail, r.rows)        # 値は返らない
```

`naive_lookup` は比較用に入れてある(key と 1 つの日付だけで、その日以前の最新の行を返す
= 適用開始日つきの履歴の引き方)。自分の環境で同じ比較ができる。

## できないこと

- **数式を評価しない。** 値は文字列のまま返す。型変換も端数処理もしない
- 収録されていない期間は引けない。表の外の日付に対して直近の行を返すことは決してしない
- `known_from` が仮置きの行は、`as_of` を渡した引き当てで止まる。仮置きを実値に直すのは表を作る側の作業
- 対象の指定が細かい行を自動で優先しない。優先順位は `priority` に明示する
- 3 次元以上の表(帯 × 帯 × 帯)は `sel_*` の次元に分解するか、値の側に持つ。表そのものは 1 段しかない
- 表の意味は検査しない。`validate` が見るのは期間・priority・basis の形だけ
