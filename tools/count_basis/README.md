# count_basis — 一致した件数は確かめた行数とは限らないので、件数の単位と掛けた次元を先に分ける

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [一致した件数は確かめた行数とは限らないので、件数の単位と掛けた次元を先に分ける](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post_02.html)(2026-11-03 公開)
<!-- article-links:end -->

検証の報告に並ぶ「N 件一致」の N を、**元の行 × 掛けた次元 × 確かめ方** の 3 層へ分けて返す
部品です。**N 行を独立に確かめたという意味ではない**ことを、出力の形で見せます。

骨は 1 行で言えます。**多くの N は「元の行 × 掛けた次元」の積で、単位も確かめ方も検証ごとに
別なのに、同じ 1 つの列に並ぶと足し合わせて読める。**

標準ライブラリだけで動きます(テストの実行には pytest と hypothesis が要ります)。

## 持たせていないもの

ここが規律です。

- **出力に「検証の総件数」の欄が無い**。内訳は検証ごと・単位ごと・由来ごとに分けて出します。
  **単位の違う件数を足す関数そのものを置いていません**
- **確かめ方の強さを点数や順位にしない**。確かめ方コードに付くのは意味と、要求する欄だけです
- **独立かどうかを名前の近さで推測しない**。宣言表に無い次元は「宣言なし」のままです
- **割合・カバー率・%を出さない**
- **原文の「通過」から件数を補完しない**
- **検証を走らせない**(宣言された検証を実走する経路も、通信の経路もありません)
- **検証が十分かを判定しない**
- **計算の分岐数を数えない**
- **2 経路の値そのものを突き合わせない**
- **実在の料率・金額を読まない**(値の列がありません)
- **現在時刻を読まない**(日付の列も時刻の列もありません)
- **入力を書き換えない**
- **float を使わない**

## 入力 — 4 種 5 枚

どの行にも出典の欄が要ります。

検証の台帳(6 列)。検証 1 件が 1 行です。

```csv
check_id,declared_count,unit,tables,method,source
K01,"7,050",cell,T1,M1,合成の作業状況のメモ(架空)L84
K02,通過,,T2,M1,合成の作業状況のメモ(架空)L85
K03,47,shibu,T3;T8,M2,合成の作業状況のメモ(架空)L86
```

`declared_count` は**原文の表記のまま**書きます(「7,050」「通過」「1.251」)。`tables` は
対象の数表 id を `;` で並べます。`source` が空の行は別枠へ出します。

元の行の台帳(5 列)。数表 1 枚が 1 行です。

```csv
table_id,rule_id,rows,origin,source
T1,合成の料率表_甲,141,自前抽出,合成の収録範囲のメモ(架空)L10
T2,合成の等級表_甲,3,自前抽出,合成の収録範囲のメモ(架空)L11
T3,合成の料率表_乙,47,上流,合成の収録範囲のメモ(架空)L12
T8,合成の照合用の料率表,47,照合専用,合成の収録範囲のメモ(架空)L17
```

掛けた次元の宣言表(5 列)。1 つの次元が 1 行です。

```csv
check_id,dim_name,factor,place,source
K01,等級,50,1 行が持つ表の中に在る,合成の次元のメモ(架空)L4
K02,年,3,行として在る,合成の次元のメモ(架空)L5
```

`place` が**この部品のいちばん大事な欄**です。`行として在る` / `1 行が持つ表の中に在る` /
`計算で広げた` の 3 つだけを受け取ります。2 つめは「行は増えていない」という意味です。

確かめ方コードの登録表(4 列)と単位記号の登録表(3 列)。

```csv
method,meaning,requires,source
M1,機械の再計算,次元の宣言,合成の登録のメモ(架空)L1
M2,独立 2 経路,2 系統の由来,合成の登録のメモ(架空)L1
M5,人の目視,件数と単位,合成の登録のメモ(架空)L1
```

```csv
unit,meaning,source
cell,セル,合成の登録のメモ(架空)L1
shibu,支部,合成の登録のメモ(架空)L1
row,行,合成の登録のメモ(架空)L1
```

`meaning` が登録の集合の外なら読めずに止まります(確かめ方は 5 つ、単位は 6 つ)。**記号の
綴りから意味を当てる経路はありません。** `requires` はその確かめ方が要求する欄で、埋まって
いなければ 1 件も数えずに止まります。

## 分け方 — 検証 1 件に付く 7 値 + 別枠 4 種

上から順に見て、どれか 1 つだけが付きます。

| 値 | 付く条件 |
|---|---|
| 分解できた | 元の行数 × 倍率の積 = 宣言件数(在り所に「1 行が持つ表の中」が無い) |
| 分解が合わない | 積が宣言件数と違う(**差の値だけを出し、どちらが正しいかは言わない**) |
| 件数が書かれていない | 単位記号が空で、件数も整数として読めない(「通過」だけの行) |
| 次元の宣言が無い | 宣言表にその検証の行が無い |
| 倍率が 1 行の持つ表の中に在る | 在り所がそれを 1 つでも持つ(= 行は増えていない) |
| 他の検証と元の行を共有している | 自分より前の検証と数表 id が交わる |
| 元の行の台帳に無い数表を指している | 指している id が台帳に無い |
| 別枠(出典が空) | 検証の台帳の `source` が空 |
| 別枠(登録表に無いコード) | 確かめ方コードか単位記号が登録表に無い |
| 別枠(単位記号が無い) | 単位記号が空で、件数は整数として読める |
| 別枠(件数が整数でない) | 単位記号は登録表に在るが、件数が整数として読めない |

**重なりの印が付くのは後ろの検証だけ**です(前の検証の区分は動かしません)。共有している
数表 id の集合は、そのまま一覧に出します。

## 積が合っていても「分解できた」に入らない場合

倍率の在り所が `1 行が持つ表の中に在る` なら、積が宣言件数と合っていても別の値に落ちます。
行として 50 本あるのでなく、1 行が持つ表の中に 50 の帯があるだけ、という場合です。

合成した表の K01 がその形です。宣言件数は 7,050、元の行は 141 行、倍率は 50 で、141 × 50 は
7,050 と合います。それでも **7,050 行を持つ数表は台帳に 1 枚もありません**(最大は 1,681 行)。
ここを「積が合ったから分解できた」と書くと、読む側はその数を行数として受け取ります。

## 件数の検算 — 4 通りの数え方が合う

- 7 値 + 別枠の合計 = 検証の数
- 7 値の合計 = 7 値が付いた検証の数
- 単位ごとの内訳の合計 = 検証の数(値ごとの内訳の合計も一致)
- 由来ごとの内訳の合計 = 元の行の台帳の行数

4 通りを別の経路で持っているので、どれか 1 つを差し替えると合わなくなります。**単位をまたいで
件数を足した値は、どこにも現れません。**

## いつも成り立つこと

読んだ範囲は 2 通りしかありません。

- 検証 1 件ごとに、7 値 + 別枠 4 種のどれか 1 つが付き、**11 値の合計が検証の数**に等しく、
  **7 値の合計が 7 値が付いた検証の数**に等しく、**単位ごとの内訳の合計も検証の数**に等しく、
  **由来ごとの内訳の合計が元の行の台帳の行数**に等しく、**別枠の検証には元の行も倍率も付かず**、
  **「分解できた」の検証は必ず 元の行数 × 倍率の積 = 宣言件数 かつ在り所に「1 行が持つ表の中に
  在る」を持たず**、**「倍率が 1 行の持つ表の中に在る」の検証はその在り所を必ず持ち**、
  **「他の検証と元の行を共有している」の検証は共有している数表 id を必ず 1 つ以上持ち**、
  **出力に「検証の総件数」の欄が無く**、判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、
  **5 枚の行順を 3 通りに入れ替えても同じバイト列**になる
- または、1 件も数えずに理由コードが返る(分けた検証や sha256 を取りに行くと例外になる)

どちらの場合も、この部品は 4 種 5 枚の表を 1 文字も書き換えません。

この 1 文を `tests/test_count_basis_property.py` の `@given` テストが確かめています(検証を
1〜4 件、宣言件数を 6 通り、単位記号を 4 通り、指す数表を 1〜3 枚の部分集合、確かめ方を
3 通り、次元を 0〜2 本から引く。4 回に 1 回くらいどこか 1 か所を崩し、崩し方 8 通りが「1 件も
数えずに止まる理由コード」8 個すべてに道を付ける。乱数は固定で毎回同じ 200 通り)。**7 値 +
別枠の分け方はテストの側で別に実装しています**(部品の `judge` / `eleven` を呼びません)。
同じファイルの 2 本目は「倍率の在り所だけが『分解できた』と『1 行が持つ表の中に在る』を
分ける」ことを、在り所 × 倍率 × 元の行数 × 宣言件数 の総当たりで見ています(上限 300)。

`layers` にすると、判定ごとの一覧、**重なりの一覧**(共有している数表 id つき)、**倍率が

## 止まる理由コード(11 個)

表の側 8 個は、1 件も数えずに止まります。

- 出典の欄が空
- 同じ検証 id が検証の台帳に 2 行ある
- 同じ数表 id が元の行の台帳に 2 行ある
- 同じ検証 id と次元名の組が 2 行ある
- 確かめ方が要求する欄が埋まっていない
- 指している数表 id の欄が空
- 同じ数表 id を 1 つの検証が 2 度指している
- 次元名が空

verify が見つける 3 個は、件数の合計が合わない / 2 回目の判定部分が不一致 / 行順を入れ替えた
表で出力が変わる、です。

列が無い・行が無い・行数や倍率が整数でない・在り所や由来や意味が登録の集合の外・id に区切り
文字が入る、は「表として読めない」(終了コード 2)で、こちらも 1 件も数えません。

## 使い方

ひな型を出します。

```
python count_basis.py init ひな型/
```

数えます。

```
python count_basis.py layers 検証の台帳.csv 元の行の台帳.csv 掛けた次元の宣言表.csv 確かめ方の登録表.csv 単位記号の登録表.csv
```

この手続き自体が決定論かどうかを実測します。

```
python count_basis.py verify 検証の台帳.csv 元の行の台帳.csv 掛けた次元の宣言表.csv 確かめ方の登録表.csv 単位記号の登録表.csv
```

`verify` は 5 つ見ます。2 回読んで判定部分のバイト列の指紋が同じか、3 通りの入れ替え方で
5 枚の行順を入れ替えても同じ出力になるか、4 通りの数え方の合計が合うか、そして 2 つの写しです。
**次元を 1 つ外した写し**では、その検証の積が外した倍率の分だけ減って「分解が合わない」へ移り、
ほかの検証の区分と単位ごと・由来ごとの内訳が 1 つも動かないこと。**ある検証が別の検証と同じ
数表 id を指すようにした写し**では、重なりが 1 増え、それでも出力に総件数の欄が現れないこと。
写しはメモリの中だけで、入力の表には 1 文字も書きません。

終了コードは、別枠・分解が合わない検証・重なり・台帳に無い数表・逆向きの欠け・止まった行が
0 件のときだけ 0 です。**0 は「検証が厚い」ではなく「4 種 5 枚に欠けが無い」の意味**で、
厚みはこの部品の終了コードにも出力にも出ません。

```
python -m pytest tools/count_basis -q
```

`fixtures/` に合成の 4 種 5 枚(検証 16 行 / 元の行 9 行 / 次元 16 行 / 確かめ方 5 行 /
単位 6 行)と、崩した表 33 枚が入っています。**実データ・実在の料率・実在の金額は 1 つも
入れていません**(数表 id は記号、rule id は架空の名前、出典は「合成の…(架空)」)。
`fixtures/make_fixtures.py` で書き直せます。

## できないこと

- **検証が厚いかは分からない。** 返るのは検証ごとの値と件数と分母の内訳だけで、何を分母に
  するかは読む人が決めます。終了コード 0 も「4 種 5 枚に欠けが無い」であって、十分に確かめた
  という意味ではありません
- **宣言された次元が本当かは分からない。** 「3 年 × 47 支部 × 50 等級」と書かれた欄が本当に
  その積なのかは、この部品には確かめようがありません。**欄が埋まっていることまでしか見ません**
- **確かめ方の強さは分からない。** 人の目視と機械の再計算のどちらが確かかは、点数にも順位にも
  しません。登録表の意味を記録するだけです
- **宣言件数と積のどちらが正しいかは分からない。** 合わない検証は差の値を出すだけです
- **重なりをどう扱うかは決めない。** 共有している数表 id を出すだけで、どちらを捨てるかは
  人が決めます
- **検証を走らせない。** 宣言された検証が実際に通るかは、この部品の外の仕事です
