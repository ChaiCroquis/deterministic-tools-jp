# run_kinds — 落ちた回が障害とは限らないので、実行の記録を成功率にせず回ごとに分ける

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [落ちた回が障害とは限らないので、実行の記録を成功率にせず回ごとに分ける](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_29.html)(2026-10-30 公開)
<!-- article-links:end -->

**「ジョブが通ったか」と「本番の中身が入れ替わったか」は別の軸で、通った / 落ちたの 2 値だけを
数えると、どちらも読めない数字が出る。**

[update_ledger](../update_ledger) の回は、実行 1 回を台帳 1 行として書く側の道具だった。あちらは
**記録をどう残すか**の話で、こちらは**残った記録をどう数えるか**になる。
[check_census](../check_census) は宣言された検証が走ったかを数える道具、
[recalc_scope](../recalc_scope) は版の指紋で出し直す対象を出す道具、
[cadence_gap](../cadence_gap) は更新の間隔と鮮度を見る道具で、この部品は鮮度も次回も出さない
(時刻の欄を入力に持たない)。

この部品は、実行の台帳・意図の宣言表・語の登録表の 3 枚から、実行 1 回ごとに 6 値か別枠 2 種の
どれか 1 つを付ける。**成功率も稼働率も出さない。失敗の原因も分類しない。良し悪しも判定しない。**

持たせていないものが規律になっている。

- **成功率・稼働率・失敗率を出さない**(返るのは件数と内訳だけ。割合にする経路も option も無く、
  分母をこの部品が決めない。通ったと宣言された回の中に、初回と、何も変わらなかった回が混ざるので、
  割ると何を言っている数字か分からなくなる)
- **失敗の原因を分類しない**(入力に `error` の列が無く、本文を読む経路も無い。落ちたと宣言された
  回に付くのは、据え置きの有無と、事前の宣言が在るかだけ)
- **事後の申告を試験として数えない**(宣言が実行より後の行は、宣言が無い回と同じ値へ落ちる。
  後から「あれは試験だった」と言える経路を道具に作らない。**これが骨の物理形**)
- **足りないのと、決めていないのを同じ列に潰さない**(事前に試験と宣言された据え置きと、宣言が
  無い据え置きは別の値で返る。前者は意図どおりで、後者はまだ誰も書いていない)
- **実行を障害と呼ばない**(件数と一覧に障害・異常・事故の語が無い。落ちた回は「落ちたと宣言され、
  据え置きになった回」としか書かない)
- **鮮度・最終更新日・次に動く日を出さない**(入力に日付の列も時刻の列も無い。現在時刻を読む
  呼び出しも 1 つも無く、順は並び順の番号だけで決まる)
- **差分の中身を見ない**(どの行がどう変わったかの列が無い。読むのは件数 3 つと指紋だけ)
- **再実行しない・取りに行かない**(走らせる経路も、通信の経路も無い)
- **良し悪し・順位・推奨・次にすべきことを出さない**(点数欄も順位欄も無い。どの回を調べるかは
  台帳を持つ人が決める)
- **判断がつかない回は誰がどこに書いたかを必ず併記する**(別枠と一覧の各行に出典が付き、出典の欄が
  空の行は入口で止まる)
- **この部品自身の「読めない」を、測っている相手の「欠け」と同じ欄に入れない**(3 枚のどれかが
  1 行でも壊れていたら 1 回も数えず、理由コードだけを返す。6 値は全て 0 になる)
- **入力表を書き換えず、行も宣言も生成しない**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない。行順にも依らない)
- **数は整数だけ**(件数も差分も整数で、float を使う経路が無い)

## 入力 — 3 枚の表

実行の台帳は 9 列。**1 回の実行が 1 行**。

| 列 | 意味 |
|---|---|
| `run_id` | 実行 id(同じ id が 2 行あると**止まる**) |
| `seq` | 並び順の番号(1 から連続する整数)。**時刻でなく、この欄で順を決める** |
| `status` | 宣言された status の語(登録表に status の語として無ければ**別枠**) |
| `added` | 差分の件数・追加(0 以上の整数)。小数は読めない |
| `removed` | 差分の件数・削除(同上) |
| `changed` | 差分の件数・変更(同上) |
| `first_run` | 初回の印(`初回` / 空欄)。**先頭の行以外に付いていたら止まる** |
| `fingerprint` | 出力の指紋(空欄可)。据え置きを伴う語の回に埋まっていれば**別枠** |
| `source` | 出典(ファイル名 + 行番号)。空欄は**止まる** |

意図の宣言表は 4 列。**1 回の実行が 1 行**で、ここが「その回を試験として数えてよいか」の側になる。
**ヘッダだけでも読める**(= 1 つも宣言していない状態は正常で、そのとき据え置きの回が全部 ② に出る)。

| 列 | 意味 |
|---|---|
| `run_id` | 実行 id(台帳に無い id は**一覧へ出すだけ**で止めない) |
| `intent` | 意図コード(登録表に意図コードとして無ければ**止まる**) |
| `declared_before` | 宣言された時点が実行より前かどうかの印(`実行より前` / `実行より後`) |
| `source` | 宣言の出典(空欄は**止まる**) |

語の登録表は 4 列。**1 つの語が 1 行**。status の語と意図コードを同じ表に書く。

| 列 | 意味 |
|---|---|
| `word` | 語(`ok` / `failed` / `失敗試験` など) |
| `meaning` | 意味(`通った` / `落ちた` = status の語、`試験` / `試験でない` = 意図コード) |
| `holds` | 据え置きを伴うか(`据え置き` / `据え置かない`)。**意図コードの行のこの欄は記録するだけで判定に使わない** |
| `declared_in` | 登録の出典(空欄は**止まる**) |

`status` の語に当てるのは `meaning` が `通った` / `落ちた` の行だけで、`intent` に当てるのは
`試験` / `試験でない` の行だけだ。**語の形から意味を当てる経路は無い**(`failed` という綴りを
見て「落ちた」と決めることはしない)。

## 分け方 — 実行 1 回に付く 6 値 + 別枠 2 種

| 回の形 | どうするか | 値 |
|---|---|---|
| status の語が登録表に無い | 意味が分からないので、差分も指紋も見に行かない | 別枠(登録表に無い status 語) |
| 据え置きを伴う語で、指紋が埋まっている | 据え置きのはずが動いている | 別枠(落ちたのに指紋が動いた) |
| 据え置きを伴う語で、意味が `試験` の意図コードが `実行より前` と宣言されている | 事前に宣言された試験 | ① 据え置き・試験と事前に宣言されている |
| 据え置きを伴う語で、その宣言が無い | 宣言が事後・試験でない・そもそも無いを、言い方として残す | ② 据え置き・試験の事前の宣言が無い |
| 初回の印が付いている | 比べる相手が無い(差分は収録の全件) | ③ 初回(比べる相手が無い) |
| 差分 0 かつ指紋が直前と同じ | 走ったが何も変わらない | ④ 差分 0 かつ指紋が直前と同じ |
| 差分ありかつ指紋が直前と違う | 入れ替わった | ⑤ 差分ありかつ指紋が直前と違う |
| 差分 0 なのに指紋が動いた / 差分ありなのに指紋が同じ | どちらが正しいかは書かない | ⑥ 差分の件数と指紋の動きが噛み合わない |

**直前の指紋**は、並び順を遡って最初に見つかる空でない指紋だ(据え置きの回は本番を触っていない
ので、指紋の欄が空のまま飛ばされる)。指紋の欄が埋まっている回は、判定がどの値であっても履歴に
入る(欄を無視しない)。**初回の印が無い回の前に指紋が 1 つも無ければ止まる**(比べる相手が無い
のに比べようとする状態を、黙って ③ にしない)。

**⑤ と ⑥ のうち、指紋が履歴の前の回の値へ戻ったものには「戻り」の印が付く**(前に出た指紋と同じ
値になった回)。④ には付かない(直前と同じなので、動いていない)。

## 事後の申告を試験として数えない

| 言い方 | どこで分かるか | 入る値 |
|---|---|---|
| 意味が `試験` の意図コードが `実行より前` | 意図の宣言表 | ① |
| 同じ意図コードだが `実行より後` | 同上(`declared_before` の欄) | ② (言い方 = 宣言が実行より後) |
| 意味が `試験でない` 意図コード | 語の登録表の `meaning` | ② (言い方 = 宣言された意図が試験でない) |
| 宣言そのものが無い | 意図の宣言表に行が無い | ② (言い方 = 宣言そのものが無い) |

この 4 つを「意図的な失敗」の 1 語に潰すと、記録は検証の役に立たなくなる。**落ちた後からでも
「あれは試験だった」と書けてしまうので、事前に書かれていたことだけを ① に入れている。** ② の
3 通りは値としては同じで、一覧の中で言い方の違いとして残る(どれが悪いとは書かない)。

## 件数の検算 — 3 通りの数え方が合う

- **6 値 + 別枠の件数の合計 = 実行の件数**
- **6 値の合計 = 6 値が付いた回の数**(別枠は分母の外)
- **status 語ごとの内訳の合計 = 実行の件数**(**登録表に無い語も 1 行として並べる**。外すと合計が
  合わなくなるので、欠けを黙って落とせない)。値ごとの内訳の合計も、それぞれの件数に戻る

3 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
分母は 実行の件数 / 6 値が付いた回の数 / 別枠の数 / 台帳に出てくる status 語の数 の 4 つを必ず付ける。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- 実行 1 回ごとに、6 値 + 別枠 2 種のどれか 1 つが付き、**8 値の合計が実行の件数**に等しく、
  **6 値の合計が 6 値が付いた回の数**に等しく、**status 語ごとの内訳の合計も実行の件数**に等しく、
  **据え置きを伴う語の回には差分と指紋の判定が付かず**(直前の指紋も戻りの印も空)、
  **① に入るのは意味が `試験` として登録された意図コードが `実行より前` と宣言された回だけ**で、
  **② の回は言い方の違いを必ず 1 つ持ち**、**差分 0 かつ指紋が直前と同じ回に戻りの印が付かず**、
  **指紋の欄が空の回は履歴に入らず**、判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、
  **3 枚の行順を 3 通りに入れ替えても同じバイト列**になる
- または、1 回も数えずに理由コードが返る(仕分けた回や指紋を取りに行くと例外になる)

どちらの場合も、この部品は 3 枚の表を 1 文字も書き換えない。

この 1 文を `tests/test_run_kinds_property.py` の `@given` テストが確かめている(実行を 1〜5 回、
status の語を 3 通り、差分の件数を 0〜2 から 3 欄ぶん、指紋を 3 通りと空欄から、意図の宣言を
4 通りから引く。3 割くらいの確率でどこか 1 か所を崩し、崩し方 9 通りが「1 回も数えずに止まる理由
コード」9 個すべてに道を付ける。乱数は固定で毎回同じ 200 通り)。**6 値 + 別枠の分け方はテストの
側で別に実装している**(部品の `judge` / `six` を呼ばない)。同じファイルの 2 本目は「① と ② の
分かれ目は事前の宣言だけ」を、status × 差分 × 指紋 × 宣言 の総当たりで見ている(上限 300)。

書いている途中で 1 つ捕まえたのは、`verify` の「指紋を 1 つ書き換えた写し」の側だ。**最初は、
④ の回の指紋を書き換えたら動くのはその回だけ、と書いていた。** 実際には、その指紋を直前として
見ていた後ろの回も比べる相手が変わる。**④ が 2 回続く台帳では次の回も ④ から ⑥ へ動く**ので、
計画からその場合を外し、「動いた回」を数える単位を指紋の値でなく判定(値・戻りの印・言い方)に
変えてから測り直した。**1 つ前の回を書き換える道具を、1 つ前を見ずに試そうとして詰まった形**になる。

## 出力 — 点数も割合も返らない

`check` と `kinds` が返るのは、3 枚それぞれの行数、4 つの分母、6 値 + 別枠の件数、戻った回の数、
事前の宣言が無い据え置きの回の数、噛み合わない回の数、別枠 2 種の数、台帳に無い実行 id を指す
宣言の数、据え置きでない回に付いた宣言の数、status 語ごとの内訳、理由別の止まった件数、分母の
内訳と検算、それに 9 個の固定行だ。**稼働率だけを返す呼び方も、option も無い。**

```

"分母(別枠の数)": 2,
```

`kinds` にすると、判定ごとの一覧、**履歴の前の回の値へ戻った回の一覧**(同じ指紋が前に出た回の

**どの一覧にも、原因も良し悪しも書かない。** 書くのは形と出典だけだ。

## 止まる理由コード(12 個)

3 枚の表の側。1 回も数えずに止まるものが 9 個。

`出典の欄が空` / `同じ実行 id が台帳に 2 行ある` / `並び順の番号が 1 から連続していない` /
`初回の印が並び順の先頭の行以外に付いている` / `据え置きを伴う語の回に差分の件数が書かれている` /
`据え置きを伴わない語の回に指紋が無い` / `同じ実行 id に 2 通りの意図コードが宣言されている` /
`意図コードとして登録されていない語が宣言されている` / `初回の印が無い回の前に指紋が 1 つも無い`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄や区切り文字入り・並び順や差分の件数が整数でない・並び順が 0・
初回の印が登録外・意味が登録の 4 つでない・据え置きを伴うかが登録の 2 つでない・同じ語が 2 行・
同じ実行 id と意図コードの組が 2 行・宣言の前後の印が登録外、は**「表として読めない」**
(終了コード 2)で、理由コードには混ぜない。

## 使い方

```
python run_kinds.py init ひな型/
python run_kinds.py check 実行の台帳.csv 意図の宣言表.csv 語の登録表.csv
python run_kinds.py kinds 実行の台帳.csv 意図の宣言表.csv 語の登録表.csv
python run_kinds.py verify 実行の台帳.csv 意図の宣言表.csv 語の登録表.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、3 通りの入れ替え方で 3 枚の
行順を入れ替えても同じ出力になるか、件数の合計が 3 通りとも合うか、そして 2 つの写しだ。
**試験の宣言を 1 件外した写し**では、その回だけが ① から ② へ移り(言い方は「宣言そのものが
無い」)、ほかの回の判定が 1 つも動かないこと。**④ の回の指紋を履歴に無い値へ書き換えた写し**
では、その回が ④ から ⑥ へ移り、**戻りの印が付かず、戻った回の数も増えず、合計が変わらない**
こと。写しはメモリの中だけで、入力の表には 1 文字も書かない。

終了コードは、別枠・噛み合わない回・事前の宣言が無い据え置き・逆向きの欠け・止まった行が 0 件の
ときだけ 0、在れば 3、表として読めなければ 2。**0 は「稼働率が高い」ではなく「台帳と宣言に欠けが
無い」の意味で、良し悪しはこの終了コードにも出力にも出ない。**

関数でも呼べる。

```python
import run_kinds as R

t = R.run_kinds(R.Runs.load("実行の台帳.csv"), R.Intents.load("意図の宣言表.csv"),
                R.Words.load("語の登録表.csv"))
if t.report.ok:
    print(t.counts()["6 値 + 別枠"], t.returns(), t.no_declaration())
```

## テストと fixture

```
python -m pytest tools/run_kinds -q
python fixtures/make_fixtures.py     # 合成の 3 枚と、崩した表 30 枚を書き直す
```

`fixtures/` に入っているのは合成した 3 枚(実行の台帳 17 行 / 意図の宣言表 5 行 / 語の登録表
5 行)と、理由コードと「表として読めない」を出すために 1 か所だけ崩した表 30 枚だ。
**実在の指紋も実在の実行 id も 1 つも入っていない。** 指紋は架空の 12 桁で、実行 id は `R01` の
ような記号にしてある。status の語だけは、語の形が分からないと読めないので `ok` と `failed` を
置き、3 つ目は架空の語にした。**差分の件数は桁だけ手元の記録と同じ形にそろえてある**(値は架空)。
手元の台帳は 11 回ぶんだが、fixture は 17 回にしてある(手元に出てこない形 = 事前の宣言・別枠
2 種も 1 回ずつ入れて数えるため)。

## できないこと

- **稼働率も成功率も分からない。** この部品が返すのは件数と内訳だけで、どれを分母にするかは
  読む人が決める。終了コード 0 も「欠けが無い」であって、よく動いているという意味ではない
- **落ちた理由は分からない。** `error` の列を持たないので、上流の値が変わったのか、こちらの
  実装が壊れたのかは分けない。理由は読む人が書く
- **宣言が本当かは分からない。** 意図の宣言表に書かれた「実行より前」が本当に実行より前かは、
  この部品には確かめようがない(確かめるには実行より前に書いた記録そのものが要る)。
  **この部品は欄が埋まっていることまでしか見ない**
- **差分の件数と指紋のどちらが正しいかは分からない。** ⑥ は食い違いの形を出すだけで、
  どちらを直すかは人が決める
- **鮮度も次に動く日も出さない。** 時刻の欄を持たないので、最後に動いたのがいつかは
  [cadence_gap](../cadence_gap) の領分になる
- **差分の中身は見ない。** どの行がどう変わったかは [update_ledger](../update_ledger) や
  [recalc_scope](../recalc_scope) の領分で、ここに寄せていない
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
