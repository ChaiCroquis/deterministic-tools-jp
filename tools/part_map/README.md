# part_map — 部品と詰まり方の対応を、書かれた記載だけで線の内・外・記載なしの 1 枚に並べる

「共通部品にまとめれば、詰まり方とそれぞれ 1 対 1 で片づく」と書いた計画は多い。けれど、どの部品がどの詰まり方に
当たるかを書いた行は、たいてい一部にしか無い。この部品は、**人が台帳に書いた対応の記載だけ**を使って、
詰まり方ごとに「線の内の部品に記載が在る / 線の外の部品にだけ記載が在る / 読んだ範囲に記載なし」の 3 つに分け、
部品ごとに記載の件数を並べる。

**名前や語の似かたから対応を当てない。** 文字列を比べる経路も、類似度の経路も無い。どの部品を線の内に入れるべきかも
決めない。1 対 1 の宣言に対して返すのは**件数だけ**で、成り立つ / 成り立たないの欄、一致率、順位、合計の 1 値は無い。
該当本数は文字列のまま写し、足さない(1 本の道具が複数の詰まり方に数えられていることがあるので)。
ネットワークに出ない、原本やソースを取りに行かない、ディスクを歩かない、時計を読まない、入力を書き換えない、
float を使わない。標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 4 枚(どの行にも出典の欄が要る)

| 表 | 列 |
|---|---|
| 詰まり方の台帳 | 詰まり方 id / 説明 / 該当本数(文字列のまま)/ 出典 |
| 部品の台帳 | 部品 id / 内容 / 線の記号(`線の内と宣言` か `線の外`)/ 業種依存(文字列のまま)/ 出典 |
| 対応の台帳 | 詰まり方 id / 部品 id / 記載の種類 / 対応を書いた側の出典 / 部品の側の出典 |
| 記号の登録表 | 記号 / 意味 / 要求する欄(出典の欄の名前を `/` で区切る)/ 出典 |

記載の種類は 3 つ: `同じ数が両側に在る` / `内容の語が代表例に在る` / `近い語のみ`。
どの行がどの種類かは**台帳を書く人が決める**。道具は文字を読んで種類を当てない。

## 3 値(詰まり方の行 1 つに 1 つ)

| 3 値 | 条件 |
|---|---|
| (A) 線の内の部品に対応の記載が在る | `近い語のみ` 以外の対応のうち、1 つ以上が線の内の部品を指す |
| (B) 線の外の部品にだけ記載が在る | `近い語のみ` 以外の対応が在り、全部が線の外の部品を指す |
| (C) 読んだ範囲に記載なし | `近い語のみ` 以外の対応が無い。「対応する部品が存在しない」とは言わない |

`近い語のみ` は (A)(B) に数えず、別の列に並べる(寄せない)。

別枠の理由は 5 つで、手前が勝つ: 出典が空 / 対応の片側の出典が空 / 台帳に無い id を指す対応 / 登録表に無い記号 /
id の重複。詰まり方の行は、自分の行か、自分を指す対応の行(とその先の部品の行)に理由が 1 つでも在れば別枠になる。
壊れた記載が在るのに「記載なし」と出さないためだ。

ほかに返すもの:

- 部品ごとに 1 行 = 対応の記載の件数(`近い語のみ` を除く)と段(0 / 1 / 2 以上)、`近い語のみ` の件数、別枠の対応の件数
- 宣言の検算(件数だけ)= 線の内と宣言された部品の数、そのうち記載がちょうど 1 件 / 0 件 / 2 件以上の数、
  線の内の部品がちょうど 1 つの詰まり方の数、(C) の数

## いつも成り立つこと

詰まり方の行 1 つには 3 値か別枠の理由 5 つのうち 1 つだけが付き、その合計は詰まり方の行数に、部品ごとの件数の合計は対応の行数に等しく、表の行順を入れ替えても答えは変わらず、渡した表は 1 文字も書き換わらない。

この 1 文は `tests/test_part_map_property.py` が性質テスト(hypothesis)で確かめている。4 枚の表を乱数で作り
(空の出典、片側が空の対応の出典、台帳に無い id、登録表に無い記号、重複した id、近い語のみ、線の内と外を混ぜる)、
3 値と別枠はテストの中で別の書き方で引き直して比べる(道具の判定は呼ばない)。乱数は固定で、毎回同じ 300 通り。

## 使い方

```
python part_map.py check  kadai.csv buhin.csv taiou.csv kigou.csv
python part_map.py rows   kadai.csv buhin.csv taiou.csv kigou.csv   # 詰まり方 1 行の CSV
python part_map.py verify kadai.csv buhin.csv taiou.csv kigou.csv   # 5 つの検算
```

終了コードは 0 = 判定した / 3 = verify のどれかが合わない / 2 = 表の形の誤り(1 件も判定しない)。
表の形の誤り = 列が無い、詰まり方 id・部品 id の空、記号の登録表の空・重複、道具が意味を持たない記号の登録、
要求する欄に出典以外の欄の名前。

`verify` が見る 5 つ: 二度走って同じ指紋(sha256)か / 4 枚の行順を入れ替えても同じ出力か /
3 値 + 別枠 = 詰まり方の件数で、部品ごとの合計 = 対応の行数か / 対応 1 行を消すと、その詰まり方と部品の行だけが動くか /
線の内の部品 1 つを線の外にすると、つながる詰まり方だけが (A)(B) の間で動き、検算が 1 部品分だけ変わるか。
写しはメモリの中だけで作る。

```python
import part_map as M
tables = M.read_all(["kadai.csv", "buhin.csv", "taiou.csv", "kigou.csv"])
result = M.judge(tables)   # 3 値 / 別枠 / 詰まり方ごと / 部品ごと / 宣言の検算 / 判定部分の sha256
```

`fixtures/gousei/` は合成した 4 枚(架空の通販の受注まわりの部品化計画)。`examples/shiwake/` は
私の手元の記録(道具の棚卸しを仕分けた文書)から、詰まり方 6 行・部品 10 行と、私が読んで書いた対応 6 行を写した 4 枚。

テストの実行には別に pytest と hypothesis が要る。
