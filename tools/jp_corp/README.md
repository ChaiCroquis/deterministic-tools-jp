# jp_corp — 会社名を法人格を捨てずに寄せ、法人番号があれば番号で突き合わせる

会社名の突合を「法人格を取ってから似ている順」で寄せると、別法人が静かに 1 件に畳まれる。
「山田商事株式会社」と「山田商事有限会社」は、法人格を外すとどちらも「山田商事」になる。
この道具は法人格を除去ではなく分離して保持し、照合キーの一部として使う。そのうえで、
公表されている 13 桁の法人番号が列にあれば、名前より先に番号で突き合わせる。
**類似度のしきい値を一切持たない。** stdlib のみ(unicodedata / re)、依存なし。

## 流れ(固定)

| 段 | すること | 判断待ちに落ちる条件 |
|---|---|---|
| 1 | 表記の正規化(NFKC で合字・全角英数・全角カナ、空白と区切りを除く) | 空の会社名(法人格だけ、記号だけ) |
| 2 | 法人格の分離(前株・後株・中間のどこでも。除去しない) | — |
| 3 | 番号の経路(13 桁の検査数字を確かめ、通った番号で突合) | 番号の検査に落ちる |
| 4 | 名前の経路(照合キー = 法人格の種類 + 屋号 + 事業所の印) | 相手なし / 相手が複数 / 法人格が違う |
| 5 | 自分側の索引も引く | 自分側が重複 / 番号が食い違う |

番号が無い行は名前の経路に回る。名前でも決まらなければ判断待ちになる。
判断待ちの理由コードは 7 つ(`REASONS`)。どれも「機械では決まらない理由」を名前にしてある。

## 法人格の表(`LEGAL_FORMS`)

各行の先頭が種類の名前。丸括弧に入った合字は NFKC で `(株)` `(有)` の形になるので、合字そのものは表に無い。

```
株式会社 / 有限会社 / 合同会社 / 合資会社 / 合名会社 / 特定非営利活動法人(NPO法人)/
一般社団法人 / 一般財団法人 / 公益社団法人 / 公益財団法人 / 医療法人社団 / 医療法人財団 /
医療法人 / 社会福祉法人 / 学校法人 / 宗教法人 / 独立行政法人 / 社会保険労務士法人 /
税理士法人 / 弁護士法人 / 司法書士法人 / 行政書士法人 / 事業協同組合 / 協同組合
```

長い表記から先に当てるので、`医療法人社団` が `医療法人` に食われない。
表に無い法人格は種類が空のまま屋号に残るので、別のキーになる(黙って畳まれることはない)。

支店・支社・営業所・事業所・出張所・支部で終わる行は、**事業所の印だけを別の欄に立てる**。
支店名そのものは屋号から切り離さない(区切りの無い表記では、地名がどこまでかが機械では決まらないため)。

## 法人番号の検査数字

`check_digit(下 12 桁)` が先頭 1 桁を作る。算式は「9 -(下 12 桁を右から数え、奇数番目は 1 倍・
偶数番目は 2 倍して合計した値)を 9 で割った余り」。

**限界**: この算式はこの道具が持っている実装で、公表されている仕様と一致することを確かめてはいない。
テストは同じ算式で作った合成番号でしか通っていない。実際の番号で使う前に、算式が公表値と合うかを
自分で確かめること。もう 1 つの限界として、9 と 0 の取り違えはこの算式では検出できない
(`test_check_digit_cannot_see_zero_nine_swap` で固定してある)。

## 使い方

```
python jp_corp.py --key 山田商事株式会社 東海運輸株式会社大阪支店   # 表記 TAB 法人格 TAB 屋号 TAB 事業所 TAB 照合キー
python jp_corp.py --check 5835678256246                          # 番号 TAB OK / NG(理由)
python jp_corp.py A.csv B.csv --column 取引先名 --number-column 法人番号   # 判断待ちが 1 件でもあれば exit 3
```

```python
from jp_corp import Row, parse, to_key, number_reason, build_index, match, match_all

parse("㈱山田商事")          # kind='株式会社' yago='山田商事' branch='' position='前'
to_key("山田商事有限会社")   # '有限会社|山田商事|'  ← 法人格を捨てないので株式会社とは別のキー

for d in match_all(左の台帳, 右の台帳):
    if d.status == "判断待ち":
        print(d.row.name, d.reason, d.note, [c.name for c in d.candidates])
    else:
        print(d.row.name, d.by, d.candidates[0].name)     # by は 番号 / 名前
```

出力は「照合(番号 or 名前)」か「判断待ち + 理由コード + 候補」のどちらかで、確率やスコアは返さない。

## テスト

```
python -m pytest tools/jp_corp -q      # fixture は全て合成データ(fixtures/make_fixtures.py で再生成可)
```

`tests/test_jp_corp.py` の `test_measure_*` が、合成 1,000 行の取引先台帳 2 つで
「完全一致だけの突合」「法人格を除去して類似度 0.8 以上を自動採用する突合」「この道具」を比べている。
記事に載せる数値はそこから取り、`assert 変数 == 値` で固定してある。

## できないこと

- 同じ法人かどうかは決めない。決めるのは「番号が一致するか」「照合キーが一致するか」だけ
- 法人番号の算式が公表値と一致するかは確かめていない(上記)。9 と 0 の取り違えは検出できない
- 表に無い法人格(外国の法人格、組合の細かい種類)は種類が空のまま屋号に残る。足すときはテストを足す
- 支店名は屋号から切り離さないので、本社の行と支店の行は別のキーになる。まとめたい台帳では別の扱いが要る
- ローマ字の大文字小文字は畳むが、カナと漢字は畳まない(読みを持っていないため)
- 旧商号・合併後の名称は追えない。名前が変わって番号も無い行は「相手なし」として人に返る
- 屋号の中の表記ゆれ(「あおば」と「アオバ」)は畳まない。畳むこと自体が判断になる
