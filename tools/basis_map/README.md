# basis_map — 手元にある日付が引ける日付とは限らないので、日付の種別を先に台帳にする

**日付は 1 種類ではない。手元にあるのが支払日でも、行が求めているのは対象月初日や離職日や
請求日で、どの種別を渡すかを台帳に書いていないと、似た名前の日付が黙って代入される。**
[asof_table](../asof_table) の回で「同じ日付で引いても公表時点で答えが変わる」ところ、
[span_split](../span_split) の回で「期間を境界で切る」ところまでは決めた。けれどどちらも
**渡す日付の種別が既に決まっている前提** で、種別そのものが決まるかの段は、どの回でも
手つかずだった。

この部品は、日付の種別の台帳・rule ごとの要求表・手元の表の 3 枚から、(rule × 対象)の組
1 つごとに 4 値(**決まった / 手元に無い / 決まらない / 止まった**)を付ける。決まらない
ものは理由別(**候補どまり / 宣言外の表記 / 同じ種別に 2 つ**)に分けて数え、分母
(rule 数 × 対象数)と内訳を併記して返す。**引かない。決まるかを出すだけだ。**

持たせていないものが規律になっている。

- **別名は台帳に宣言された分だけ写す**(「賃金締切日」と「賃金締め日」を寄せるのは台帳に
  そう書いてある時だけ。文字列が似ていることを理由に寄せる経路を持たない)
- **手元に無い種別を別の日付で代用しない**(支払日から対象月初日を作らない。月初・月末へ
  丸める引数も、前営業日へずらす引数も、今日やシステム日付を使う経路も無い)
- **要求する種別が台帳に登録されていなければ「決まらない」に落ちる**(候補の但し書きが
  付いた種別を登録済み扱いにしない。この部品の骨をそのまま入力の形にしたところ)
- **同じ種別に日付が 2 つあれば「決まらない」**(新しい方も先に出てきた方も採らない)
- **同じ別名が 2 つの種別に宣言されていれば止まる**(どちらかに寄せない)
- **日付の書式を推測して読まない**(台帳に宣言された書式だけ。書式を直すのは
  [wareki](../wareki) の仕事で、役割が重ならない)
- **日付の値を作らない・ずらさない・比べない**(引く段には入らない。版を選ぶのは
  [asof_table](../asof_table)、期間を切るのは [span_split](../span_split)、帯に当てるのは
  [band_edge](../band_edge) の仕事)
- **空欄の意味は決めない**(欠けている理由を読むのは [blank_kind](../blank_kind) の仕事で、
  ここでは「手元に無い」で止める)
- **足すべき種別も別名も提案しない**(決めるのは台帳を書く人)
- **件数は理由別に、分母(rule 数 × 対象数)と内訳つきで出す**(率を単独で返さない。
  [check_census](../check_census) 以降と同じ)
- **4 つを混ぜない**([answer_check](../answer_check) / [span_split](../span_split) /
  [band_edge](../band_edge) / [blank_kind](../blank_kind) / [recalc_scope](../recalc_scope)
  と同じ)
- **入力表を書き換えず、種別も別名も生成しない**([intake_triage](../intake_triage) 以降と同じ)
- **出典の欄が空の行は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)
- **float を使わない**(件数は整数。日付は文字列のまま持つ)

## 入力 — 種別の台帳と要求表と手元の表の 3 つ

種別の台帳は 7 列。日付の種別 1 つが 1 行になる。

| 列 | 意味 |
|---|---|
| `kind_id` | 種別 id(空欄は「表として読めない」。2 行あると**止まる**) |
| `name` | 正式な表記(空欄は「表として読めない」) |
| `aliases` | **宣言された別名**(縦棒で区切る。0 件以上)。寄せてよい表記はここに書いた分だけ |
| `meaning` | 意味の 1 行(空欄は「表として読めない」) |
| `format` | 日付の書式。登録の 2 種(`YYYY-MM-DD` / `YYYY-MM`)。外は読めない表 |
| `status` | 状態。登録の 2 種(`登録済` / `候補`)。**外は止まる** |
| `source` | その行の出典。**空欄は止まる** |

```csv
kind_id,name,aliases,meaning,format,status,source
K01,対象月初日,対象月の初日,その月の 1 日,YYYY-MM-DD,登録済,articles/07_asof_table.md L13
K02,賃金締切日,賃金締め日,賃金を締める日,YYYY-MM-DD,登録済,articles/02_wareki.md L15
K05,資格取得日,,被保険者の資格を取る日,YYYY-MM-DD,候補,私の棚卸し記録(非公開)
```

要求表は 3 列。「その rule はどの種別の日付を要求するか」を 1 行で書く。

| 列 | 意味 |
|---|---|
| `rule_id` | rule id(空欄は「表として読めない」。2 行あると**止まる**) |
| `kind_id` | 要求する種別 id。**台帳に無い id は止まる**(似た表記で探し直す経路は無い) |
| `source` | その行の出典。**空欄は止まる** |

手元の表は 5 列。**1 対象 × 1 表記で 1 行** になる。

| 列 | 意味 |
|---|---|
| `target_id` | 対象 id(空欄は「表として読めない」) |
| `kind_label` | **手元に書かれている表記**。正式な表記か、宣言された別名 |
| `date` | 日付。**文字列のまま持つ**。宣言された書式に合わなければ止まる |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 写し方 — 宣言された表記だけが橋になる

手元の `kind_label` を種別へ写せるのは、台帳の `name` に一致したときと、`aliases` に宣言
された表記に一致したときの 2 通りだけだ。**似ている / 2 文字しか違わない / 片方が片方を
含む、のどれも寄せる理由にしない。**

| 手元の表記 | 台帳 | どうなるか |
|---|---|---|
| `対象月初日` | `name` と一致 | `K01` に写る |
| `対象月の初日` | `aliases` に宣言あり | `K01` に写る |
| `賃金締め日` | `aliases` の宣言を外すと | **写らない**(宣言外の表記) |
| `支払日` | どの行にも宣言が無い | **写らない**(宣言外の表記) |

写せない表記が 1 行でも残っている対象では、**「手元に無い」と言い切らない**。その表記が
探している種別かもしれないからで、そこは `決まらない` に落とす。

## 4 値 — 「手元に無い」と「決まらない」を混ぜない

| 値 | いつ入るか |
|---|---|
| `決まった` | 要求する種別に写る手元の行がちょうど 1 行あり、日付が宣言された書式に合う |
| `手元に無い` | 要求する種別に写る行が 0 行で、**写せない表記も 0 行** |
| `決まらない` | 候補どまり / 宣言外の表記 / 同じ種別に 2 つ のどれか |
| `止まった` | 理由コードが返った(表が揃う前に止まるので、このとき 4 値は全て 0) |

判定の順は **候補どまり → 同じ種別に 2 つ → 写る 1 行 → 写せない表記の有無** だ。だから
手元にその日付が在っても、要求する種別の状態が `候補` なら `決まらない` に入る。
**候補の但し書きが付いた種別を登録済み扱いにしない** ほうを採った。

## 件数の検算 — 分母は rule 数 × 対象数

- **4 値の件数の合計 = rule 数 × 対象数**
- **決まらない理由別の件数の合計 = 決まらないの件数**

2 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
同じ rule id が 2 行あると件数を rule 1 件ずつに割り当てられないので、そこでも止まる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- (rule × 対象)の組ごとに 4 値が 1 つだけ付き、**4 値の合計が rule 数 × 対象数** に等しく、
  **決まらない理由別の合計が決まらないの件数** に等しく、`決まった` 組の渡す日付は
  **手元の表にそのまま在る文字列**(ほかの 3 値には日付も表記も付かない)で、判定部分に
  時刻・ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても同じバイト列** になる
- または、1 組も読まずに理由コードが返る(読んだ組や指紋を取りに行くと例外になる)

どちらの場合も、この部品は種別の台帳も要求表も手元の表も 1 文字も書き換えない。

この 1 文を `tests/test_basis_map_property.py` の `@given` テストが確かめている(種別を
2〜4 個作って別名の宣言と状態を振り、rule を 1〜3 本、対象を 1〜3 件作り、手元の表記を
宣言された表記とどこにも宣言されていない表記から引く。3 割くらいの確率でどこか 1 か所を
崩す。乱数は固定で毎回同じ 150 通り)。**4 値は部品の判定を呼ばず、3 枚の表の行から
テスト側の別実装で組み立てている。** 同じファイルの 2 本目は 300 通りで、「宣言されて
いない表記は、どれだけ正式な表記に似ていても寄らない」ことを見ている。

## 出力 — 決まった率は単独では返らない

`check` と `map` が返るのは、3 枚それぞれの行数、対象数、分母(rule 数 × 対象数)、4 値の
件数、決まらない理由別の件数、それに分母の内訳と検算と 3 つの固定行だ。**率だけを返す
呼び方も、option も無い。**

```
"分母(rule 数 × 対象数)": 20,
"4 値": {"決まった": 6, "手元に無い": 7, "決まらない": 7, "止まった": 0},
"決まらない理由別": {"候補どまり": 4, "宣言外の表記": 2, "同じ種別に 2 つ": 1}
```

固定行は 3 つとも消せない。「似た表記を自分で寄せない」「手元に無い種別を代用しない」
「日付を作らない・ずらさない・比べない」だ。`map` はさらに組ごとの内訳(結果・決まらない
理由・手元の表記・渡す日付・写せなかった行の件数)と、`決まった` 組だけを並べた一覧を出す。
一覧の並びは rule id と対象 id の順で、**どれから手を付けるかの順位は付かない。**

`verify` は 3 つ見る。2 回読んで判定部分のバイト列の sha256 を突き合わせること、**宣言された
入れ替え方で 3 枚の行順を入れ替えても同じ出力になるか**、そして **4 値の件数の合計が
rule 数 × 対象数に合うか** だ。合わなければ観測としてそのまま返す。

## 止まる理由コード(9 個)

```
出典の欄が空 / 種別 id が台帳に無い / 同じ別名が 2 種別に宣言 / 台帳に同じ種別 id が 2 行 /
書式が宣言外 / 状態が宣言外 / 件数の合計が合わない / 2 回目の判定部分が不一致 /
行順を入れ替えた表で出力が変わる
```

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。書式・
入れ替え方が登録の外の語だったとき、列そのものが足りないとき、行が 0 行のとき、
種別 id・正式な表記・意味・rule id・要求する種別 id・対象 id・表記・日付が空欄のとき、
別名の一覧に同じ表記を 2 つ書いたとき、同じ対象に同じ表記を 2 行書いたとき、そして
入れ替え方の宣言が 2 通りあるとき。

## 使い方

```bash
python basis_map.py init ひな型/                             # 3 枚の表のひな型を書く
python basis_map.py check  種別の台帳.csv 要求表.csv 手元の表.csv   # 件数と分母の内訳
python basis_map.py map    種別の台帳.csv 要求表.csv 手元の表.csv   # 上 + 組ごとと指紋
python basis_map.py verify 種別の台帳.csv 要求表.csv 手元の表.csv   # 2 回 + 行順 + 検算
```

終了コードは、**決まらない組が 1 つも無いときだけ 0**(手元に無いが何件あっても 0)、
決まらない組があるときや止まったときは 3、表として読めなければ 2。まとめて走らせる
仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from basis_map import Registry, Demands, Hand, basis_map

t = basis_map(Registry.load("種別の台帳.csv"), Demands.load("要求表.csv"),
              Hand.load("手元の表.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `map` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。
そのこともテストで固定してある。

## テストと fixture

```bash
python -m pytest tools/basis_map -q      # 24 passed(2026-10-18 実走)
```

`fixtures/` に種別の台帳 3 枚・要求表 1 枚・手元の表 1 枚と、崩した表 28 枚が入っている。
**値(料率・金額)は 1 つも入っていない**(この部品は値を持たない)。対象 id・rule id・
日付は全て架空で、実在の料率や金額や取引先名は 1 つも無い。写したのは形だけ、つまり
「同じ種別が 2 通りの書かれ方で並ぶ」「候補の但し書きが付いた種別を rule が要求している」
「方針の例示に出てくる種別が手元に 1 行も無い」という 3 つで、これは私の棚卸し記録に残って
いる形だ。出典のうち 5 件はこの repo 内の実在の行(`articles/07_asof_table.md` L13 / L16、
`articles/02_wareki.md` L15、`articles/22_span_split.md` L13 / L14)を指し、テストがその行を
開いて語が在ることまで確かめている。`fixtures/make_fixtures.py` を実行すると、崩した表ごと
書き直す。

## できないこと

- 判定したことは「渡す日付が台帳から 1 つに決まるか」までで、**どの種別が制度として正しいかは
  判定しない**
- **日付がいつかも言わない。** 返るのは手元の表にそのまま在る文字列で、作った日付は 1 つも無い
- **台帳が足りているかも判定しない。** 候補どまりの種別も宣言外の表記も件数として残るだけで、
  足すべき種別や別名を提案する経路が無い
- **引かない。** 行を実際に引く経路も、他の部品を呼ぶ経路も持たない
- **順位を付けない。** 決まった組の一覧は rule id と対象 id の順で、どれから手を付けるかは
  人の側に返る
- 表記は文字列として突き合わせる。全角と半角、送り仮名の違いは別の表記になる(寄せたければ
  台帳に別名として宣言する)
- 書式は登録の 2 種だけで、和暦や区切りの違う表記はそのままでは読まない
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
