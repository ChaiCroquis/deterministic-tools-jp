# arrow_split — 改定の記載の矢印を、登録した意味の記号で分けてから、前後の値の行だけを前と後に割る

改定のメモには `0.5%→0.4%` のように、線が動いた前と後が矢印で書かれている行がある。ところが同じ矢印の字は、
同じ文書の中で「対応(帯→等級)」「公表と適用(1 月公表→4 月分)」「日付から出来事へ」「行き先」「式の版」にも使われる。
この部品は、**矢印の意味を人が登録した記号で分けてから、割る印の付いた記号の行だけを矢印の字 1 つで前と後に切り、
1 行 1 件で並べる**。後の文書に書かれた収録の記載は、人が対の登録表に書いた分だけ横に置く。
**矢印の意味を字面から当てない。前後を数に直さない。名前の似かたで収録の記載と結び付けない。**
標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 4 表(どの行にも出典の欄が要る)

| 表 | 列 | 書くこと |
|---|---|---|
| 記載の台帳 | `entry_id, rule, field, text, symbol, date_text, source` | 矢印(または線が動いた記載)を原文のまま `text` に写す。`symbol` は意味の記号。`date_text` は原文に在る日付の記載だけ(無ければ空) |
| 記号の登録表 | `symbol, split, source` | 意味の記号を人が登録する。前と後に割る記号だけ `split` に `割る` と書く |
| 収録の台帳 | `cov_id, rule, state, source` | 後の文書から写した収録の記載。`state` は `収録` か `未収録` |
| 対の登録表 | `entry_id, cov_id, side, source` | 記載と収録の記載の対応。`side` は `前` `後` か空(前後の別が書かれていないとき) |

`source` を `<文書の名前> L<行番号>` の形にしておくと、`--doc` で文書の行の写しと突き合わせられる。

## 出力

記載ごとに、意味の記号 / 前の文字列 / 後の文字列 / 日付の記載 / 区分 / 印 / 横に置いた収録の記載 が返る。

| 区分 | 意味 |
|---|---|
| (A) 前と後の両方に収録の記載が在る | `前` の側と `後` の側の両方に `収録` の対が在る |
| (B) 収録の記載が在るが前と後の両方にはそろわない | `収録` の対が片側だけ、または前後の別が書かれていない |
| (C) 未収録の記載が在る | `未収録` の対が 1 つでも在る |
| (D) 読んだ範囲に記載なし | 対が 1 行も無い |
| 割らない記号 | 割る印の無い記号の行。割らずに件数だけ数える(対が在れば収録の記載は横に置く) |
| 別枠(6 つ) | 同じ記載 id が 2 回 / 出典が空 / 登録表に無い記号 / 割る記号なのに矢印の字が無い / 矢印の字が 2 つ以上 / 対の登録表が収録の台帳に無い行を指す |

印は区分に使わない。文字列の側が 2 つ(前と後で単位の字が片側にしか無い / 後ろに「等」が付く)、
収録の側が 2 つ(収録の記載に前後の別が書かれていない / 収録と未収録の記載が両方在る)。

登録表・収録の台帳・対の登録表そのものが崩れているとき(出典が空、同じ記号が 2 回、状態が 2 語以外、側が 3 値以外など)は、
区分を 1 行も返さずに理由コードで止まる。

## いつも成り立つこと

結果は 2 通りしかない。**記載 1 行ごとに、4 値・割らない記号・別枠のどれか 1 つだけが付き、その合計が記載の台帳の行数に等しく、割る印の無い記号の行は前と後に割られず、割られた行の前と後は記載の文字列を矢印の字 1 つで切った左右そのままで、4 表の行順を入れ替えても判定部分が同じバイト列になる**か、**1 行も数えずに理由コードが 1 つ返る**か。どちらの場合も 4 表は書き換わらない。

この 1 文は `tests/test_arrow_split_property.py` が性質テスト(hypothesis)で確かめている。4 表を小さな語彙から乱数で作り
(id の重複・空の出典・登録表に無い記号・矢印の無い文字列・矢印 2 つ・収録の台帳に無い行を指す対が、どれも出る)、
毎回この 1 文が成り立つかを見る(乱数は固定で、毎回同じ 300 通り)。区分の決め方は道具の関数を使わず、テストの中で別に書いている。
テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python arrow_split.py init ひな型/
python arrow_split.py check 記載.csv 記号.csv 収録.csv 対.csv
python arrow_split.py check 記載.csv 記号.csv 収録.csv 対.csv --doc 文書.md --label 文書の名前
python arrow_split.py verify 記載.csv 記号.csv 収録.csv 対.csv
```

終了コードは 0 = 並べた / 3 = 理由コードで止まった / 2 = 表として読めない。

`--doc` を付けると、文書の行のうち矢印の字(`→`)を literal に含む行を数え、台帳の出典が指していない行番号を返す。
台帳の文字列が出典の行にそのまま在るかも見る(写し間違いの検出)。

`verify` は 5 つ見る。二度走らせて sha256 が同じか / 4 表の行順を逆にしても同じか / 4 値 + 割らない記号 + 別枠の合計が行数に戻るか /
記号を割らない記号に替えるとその 1 行だけが割られなくなるか / 対を 1 行抜くとその記載だけが (D) へ動くか。

```python
import arrow_split as M

tables = [M.read_table(p, k) for p, k in (("記載.csv", "entries"), ("記号.csv", "symbols"),
                                           ("収録.csv", "coverage"), ("対.csv", "pairs"))]
out = M.check(*tables)
for row in out["記載"]:
    print(row["記載 id"], row["意味の記号"], row["前"], row["後"], row["日付の記載"], row["区分"])
```

## 持たせていないもの

- 矢印の意味を字面から当てる経路(記号は人が登録した分だけ)
- 前後の値を数に直して差や倍率を出す経路、単位を補う経路、日付の年月に日を補う経路
- 名前の似かたで収録の記載と結び付ける経路(対の登録表に書かれた行だけを使う)
- 前後の値が正しいか、動いた方向が良いか悪いかを返す経路
- 値を引きに行く経路、通信、現在時刻、浮動小数点、入力を書き換える経路

## 試験

```
python -m pytest tools/arrow_split -q -s
```

`fixtures/` は合成した 4 表と合成の文書で、実在の制度・名前は入っていない。
