# source_shift — 主の出どころが替わった瞬間を 1 行 1 件の一覧にする

同じ名前の表の値を取る先を別の出どころへ入れ替えると、表の行は同じ名前のまま、中身の由来だけが替わる。
実行の記録に残るのは増えた・減った・替わった行の件数で、どの rule の主の出どころがいつ替わったか、
替わった後に古い側が何の役で残ったか、入れ替えの時に前後を比べたかは、件数からは読めない。

この部品は、入れ替えを 1 行 1 件の台帳に書いてもらい、それを順に歩いて、rule(または領域)ごとに
**主が替わったか・古い側の役が書かれているか・引き継ぎの突合が在るか** を 4 つの区分に分ける。
**値は比べない。取りに行かない。どちらの出どころがよいかを決めない。実行の記録の件数を rule に割り振らない。**
標準ライブラリのみ(argparse / csv / hashlib / json / pathlib / sys)、依存なし。

## 入力(5 枚の表。どの行にも出典の欄が要る)

| 表 | 列 | 書くこと |
|---|---|---|
| 動きの台帳 `moves.csv` | `move_id` / `seq` / `date_text` / `rule` / `from_source` / `to_source` / `old_role` / `actor` / `scope` / `source` | 出どころの線が動いた 1 件を 1 行。`seq` は呼ぶ側が渡す整数で、並べる鍵はこれだけ。`date_text` は写すだけ。`from_source` が空 = 前は無かった(最初に置いた動き)。`old_role` は動いた後の古い側の役。`scope` は入れ替えた範囲の文字列 |
| 出どころの登録表 `sources.csv` | `source_id` / `name` / `kind` / `covers` / `source` | `kind` は種別の記号(`原本` / `上流の写し` など。写すだけ)。`covers` は、その出どころから取れる rule を `;` で並べる |
| 役の記号の登録表 `roles.csv` | `role` / `meaning` / `source` | `主` / `照合専用` / `退いた` / `併用` など。記号は登録表に在るものだけ |
| 引き継ぎの突合の台帳 `checks.csv` | `check_id` / `move_id` / `scope` / `compared` / `matched` / `source` | 入れ替えの時に前後を比べた記録。比べた範囲の文字列、比べた件数、一致した件数 |
| いまの由来の台帳 `current.csv` | `rule` / `current_source` / `source` | いまの主の出どころだと文書に書いてあるもの |

## 出力

rule ごとに 1 行。区分は 4 値と別枠のどれか 1 つ。

| 区分 | 意味 |
|---|---|
| (A) | 主が替わり、古い側の役が書かれ、**主の入れ替えのすべて**に引き継ぎの突合が 1 件以上在る |
| (B) | 主が替わったが、突合の記載が無い入れ替えが 1 件以上在る(0 件とは書かず、その動きの id を並べる) |
| (C) | 主が替わっていない。入れ替える相手(その rule を `covers` に持つ別の出どころ)は登録表に在る |
| (D) | 出どころが 1 つだけ。入れ替える相手が登録表に無い |
| 別枠 | 区分を付けずに止めた。理由コードが 1 つ以上付く |

「主が替わった」は、`from_source` が空でない動きのこと。最初に置いた動き(`from_source` が空)は動きの回数には
数えるが、主の入れ替えには数えない。最初に置いた動きに付いた突合は動きの行に写すだけで、区分には使わない。

(A) は「突合が在る」であって「合っていた」ではない。一致した件数が比べた件数より少なくても (A) のままになる。
合ったかどうかで分けるのは読む人の仕事で、道具は 2 つの件数を並べるだけにしている。

(C) と (D) の分かれ目は登録表だけで決まる。(D) は「世の中に相手が無い」ではなく「登録表に相手を書いていない」。

動きごとに 1 行(別枠の rule の動きは歩かないので出ない)。順の番号 / 日付の文字列(空は `日付の記載なし`)/
前 → 後(と種別の写し)/ 古い側の役 / 動かした主体(空は `記載なし`)/ 入れ替えた範囲 / 引き継ぎの突合
(比べた範囲・比べた件数・一致した件数。無ければ `突合の記載なし`)。比べた範囲と入れ替えた範囲は
**同じ文字列かどうかだけ**を見て、違えば `範囲が違う` の印を付ける。どちらが広いかは判定しない。

ほかに 2 つの一覧が出る。

- **歩いた最後の主といまの由来の台帳が食い違う rule**。動きの台帳を順に歩いた最後の `to_source` と、
  いまの由来の台帳の `current_source` が違うもの。どちらが正しいかは決めない
- **動きに結び付かない突合**。`move_id` が動きの台帳に無い突合。止めずに並べる

## 別枠の理由コード(`REASONS`、rule ごとに付く)

| 理由コード | 意味 |
|---|---|
| 出典が空 | その rule に触れる行(動き・突合・いまの由来)か、参照している登録表の行の出典が空 |
| 記号か出どころ id が登録表に無い | 前・後・いまの主の出どころ id、古い側の役の記号のどれかが登録表に無い |
| 順の番号が重複か整数でない | `seq` が整数として読めない、または台帳の中で同じ整数が 2 行以上在る(重複した両方の rule が別枠になる) |
| 線がつながらない | 動く前の出どころが、その rule の直前の動きの後と合わない |
| 古い側の役が空 | 前の出どころが在るのに `old_role` が空(`役の記載なし` を道具の側で補わない) |
| 件数が読めない | 比べた件数・一致した件数が整数でない、負、または一致した件数が比べた件数を超える |

理由は rule ごとに付く。崩れている rule だけ区分を付けず、ほかの rule は歩く。
列が無い・id が空か重複、のように表として読めないときは、区分を付ける前に止まる(終了コード 2)。

## いつも成り立つこと

どの rule にも区分 (A)(B)(C)(D) か別枠のどれか 1 つが付き、5 つの件数の合計は rule の件数に等しい。**(A) の rule は主の入れ替えのすべてに突合が 1 件以上在り、(B) の rule には突合の無い主の入れ替えが 1 件以上在り、(C)(D) の rule には主の入れ替えが 1 件も無く、別枠の rule には理由コードが 1 つ以上付く。** 動きの台帳の行順を入れ替えても出力は同じで、入力は 1 文字も書き換わらない。

この 1 文は `tests/test_source_shift_property.py` が性質テスト(hypothesis)で確かめている。rule を 1 件から 5 件、
rule ごとに動きを 0 行から 3 行つなげた表を乱数で作り、4 割ほどの表で 1 か所だけ崩して、毎回この 1 文が成り立つかを見る
(乱数は固定で、毎回同じ 200 通り)。区分の数え直しは道具の関数を使わず、テストの中で別に書いている。
テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python source_shift.py init ひな型/                                              # 見出しだけの 5 枚を書く
python source_shift.py check  moves.csv sources.csv roles.csv checks.csv current.csv   # 区分の件数と 2 つの一覧
python source_shift.py rows   moves.csv sources.csv roles.csv checks.csv current.csv   # rule ごと・動きごとの 1 行
python source_shift.py verify moves.csv sources.csv roles.csv checks.csv current.csv   # 決定論かを 5 つ見る
```

終了コードは 0 = 別枠が 0 件で、歩いた最後の主といまの由来の台帳の食い違いも 0 件 / 3 = 別枠か食い違いが在る /
2 = 表として読めない。(B) が在っても 0 のままになる(突合が無いことを誤りとは扱わない)。

```python
import source_shift as SS

t = SS.load(["moves.csv", "sources.csv", "roles.csv", "checks.csv", "current.csv"])
res = SS.judge(t)
for row in res["rule ごとの行"]:
    print(row["rule"], row["区分"])
for row in res["動きごとの行"]:
    print(row["順の番号"], row["前"], "→", row["後"], row["古い側の役"], row["引き継ぎの突合"])
```

`verify` が見る 5 つ。

- 二度走って判定部分の sha256 が同じ
- 動きの台帳の行順を入れ替えても同じ出力(鍵は順の番号)
- 区分 4 値 + 別枠の合計 = rule の件数
- 主の入れ替えに 1 件だけ付いている突合を外した写しでは、その rule だけ (A) → (B) へ移り、ほかは変わらない
- 主を元の出どころへ戻す動きを 1 行足した写しでは、その rule だけ動きの回数が 1 増え、食い違いの一覧に 1 件載る

写しはメモリの中だけに作る。入力のファイルには書かない。

## テストと fixture

```
python -m pytest tools/source_shift -q        # 36 passed
```

fixture は全て合成データで、rule は `K01`〜`K10`、出どころは `S1`〜`S4`、日付は `T01` のような記号、出典は
「合成の…(架空)」。実在の記録の写しではない。10 rule を (A) 2 / (B) 2 / (C) 2 / (D) 2 / 別枠 2 に分かれるように
作ってあり、`test_measure_*` がその数を `assert` で固定している。

## できないこと

- 値は比べない。2 つの出どころの値が合うかどうかは、値を読む別の部品の仕事になる
- 台帳に書かれなかった入れ替えは分からない。動きの台帳は人が書くもので、書き漏らした動きを道具は見つけられない
- 突合の中身は見ない。比べた件数と一致した件数は渡された整数を写すだけで、数え直さない
- 範囲は文字列が同じかどうかしか見ない。言い回しが違うだけで同じ範囲のものも `範囲が違う` になる
- どちらの出どころがよいかは決めない。種別(原本 / 上流の写し)は写すだけで、順位も点数も付けない
- 日付は読まない。順は呼ぶ側が渡した整数で決まり、日付の文字列と順が食い違っていても気づかない
- 実行の記録の増えた・減った件数とは結び付けない。同じ数字が在っても、同じ行を指すとは言えないため
