# change_slot — 数表の「改定」の記載を、確認をどこに置くかの枠に割り振って 1 行 1 件の一覧にする

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [数表が動く時期は行ごとに別なので、改定の記載を一覧にしてから確認の枠を決める](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post.html)(2026-11-02 公開)
<!-- article-links:end -->

「毎年どこかで値が変わる表」と一口に言っても、動く時期の記載は rule ごとに別だ。定例でも時期の書き方が
割れるうえ、そこに不定期・通達・通知・済んだ一回限りの改正・新設・廃止・将来施行・施行日未定・そもそも
動かない行が混ざる。これを「年 1 回の更新作業」1 本に潰すと、年度途中に動く行を取りこぼし、動かない行を
毎年確認し、まだ施行日が無い行を確認の枠に入れて空振りする。

この部品は、**宣言された種別記号を置き場の登録表に当てて、確認の枠に割り振るだけ** をやる。
次にいつ動くかを計算しない。日付を補完しない。今日を読まない。要照合を確定として扱わない。
値を引かない。改定の中身を要約しない。優先度を付けない。行を足さない・閉じない。
stdlib のみ(csv / hashlib / json / argparse)、依存なし。

## 入力の 3 枚

| 表 | 欄 |
|---|---|
| 改定の台帳 | rule id / 領域 / 改定の記載(原文の文字列をそのまま写す)/ 種別記号 / 時期の欄 / 地域で発効日が違うか / 対象記号 / 照合の印 / 公表する側 / 置き所が要求する欄の値 / 出典(ファイル名 + 行番号) |
| 置き場の登録表 | 種別記号 / 次に動く時期が言えるか / 確認の置き所の記号 / 要求する欄の名前 / 登録の出典 |
| 変わる対象の登録表 | 対象記号 / 直す場所の記号 / 再検証の範囲の記号 / 出典 |

宣言の語彙はこれだけで、ここに無い語を書くと止まるか別枠に出る。

| 欄 | 値 |
|---|---|
| 時期の欄 | `YYYY-MM`(年月)/ `MM-DD`(月日)/ `記載なし` の 3 形。原文に在る分だけ |
| 地域で発効日が違うか | `はい` / `いいえ` / `宣言なし` |
| 照合の印 | `照合済` / `要照合` |
| 対象記号 | `率` / `表` / `式` / `要件` / `給付の有無` |
| 次に動く時期が言えるか | `言える` / `言えない` / `動かない` / `済み` |
| 確認の置き所の記号 | `定例の枠` / `随時の枠` / `置かない` / `施行日が決まるまで保留` |
| 直す場所の記号 | `行の値` / `行の形` / `式の実装` / `行の追加` / `行の閉じ` |

**種別記号は台帳に宣言された記号だけを読む。** 改定の記載の文字列から種別を当てる辞書も regex も
持たない(「不定期」「通達」「固定」のような語を見て推測する経路が無い)。登録表に無い種別記号は別枠。

## 出力の 9 値と別枠

| 枠 | 意味 |
|---|---|
| ① | 定例の枠に置く(時期が月日まで書かれている) |
| ② | 定例の枠に置くが時期は年月までで日は書かれていない |
| ③ | 定例だが発効日が地域ごとに違うので枠を地域ごとに割る(割った先の値は入れない) |
| ④ | 随時の枠(時期を書かない) |
| ⑤ | 済んだ一回限りの改正(記載は過去の時期。確認の枠に置かない) |
| ⑥ | 新設・廃止・期間限定(行の追加または行の閉じが要る側へ渡す) |
| ⑦ | 将来の施行日が書かれている(確認の枠だけ置いて値は入れない) |
| ⑧ | 施行日未定(枠に置けない) |
| ⑨ | 動かない(固定・法定。確認の枠に置かない) |

枠は 2 段で決まる。1 段目は **登録表** で、種別記号から(次に動く時期が言えるか × 確認の置き所の記号)の
対を引く。2 段目は公表している割り振りの表で、その対を 6 つの枠組みに写す。

| 次に動く時期が言えるか | 確認の置き所の記号 | 枠組み | 9 値への分かれ方 |
|---|---|---|---|
| 言える | 定例の枠 | 定例 | 地域の印が `はい` なら ③、時期が月日なら ①、年月なら ②、記載なしなら別枠 |
| 言えない | 随時の枠 | 随時 | ④ |
| 済み | 置かない | 済み | 直す場所が `行の追加` / `行の閉じ` なら ⑥、それ以外は ⑤ |
| 動かない | 置かない | 動かない | ⑨ |
| 言える | 施行日が決まるまで保留 | 将来 | ⑦ |
| 言えない | 施行日が決まるまで保留 | 未定 | ⑧ |

**この表の鍵は 2 つとも登録表の欄で、改定の記載の文字列は入らない。** 登録表の 1 行を差し替えれば、
同じ種別の rule が別の枠へ動く。登録表に無い対(例 `言える` × `随時の枠`)が書かれていたら、
読み込みの段で止まる(1 件も割り振らない)。

止まる理由コードは 14 個。表の側 5 つ(`表が読めない` / `登録表の鍵が壊れている` /
`登録表の欄が壊れている` / `枠の組み合わせが登録外` / `対象の登録表が壊れている`)はどれか 1 つでも
起きると **1 件も割り振らない**(9 値は全て 0)。rule ごとの別枠 9 つは、手前が勝つ順で
`rule id の重複` → `出典が空` → `時期の欄が 3 形でない` → `地域の印が宣言なし` →
`種別記号が登録外` → `対象記号が登録外` → `照合の印が要照合` → `置き所が要求する欄が空` →
`定例の枠なのに時期が記載なし`。**この順そのものが仕様** で、同じ rule に 2 つの理由は付かない。

一覧の並びは **時期の欄の文字列だけ** で決まる。年月の群は文字列の昇順、月日の群は別の表として
月日の昇順で、年月と月日を同じ並びに混ぜない。年度の開始月を補わない。「10 月頃」を日に直さない。

## いつも成り立つこと

rule ごとに付く答えは 1 つだけで、9 値か別枠の理由のどちらか一方に入る。
**9 値に入った rule の枠は、置き場の登録表のその種別行が指す確認の置き所と、台帳に宣言された
時期の形・地域の印・直す場所の記号だけから決まる**(改定の記載の文字列は一切使わない)。
9 値と別枠の件数の合計、および種別ごとの内訳の合計は、どちらも rule の件数に等しい。
年月の一覧と月日の一覧は交わらず、4 つの群の行数の合計も rule の件数に等しい。
どの場合も入力の表は 1 文字も書き換わらない。

この 1 文は `tests/test_change_slot_property.py` が性質テスト(hypothesis)で確かめている。
登録表の「種別記号 → (言えるか × 置き所)」の対応を乱数で割り当て、さらに **改定の記載には
宣言された種別と矛盾する語を乱数で入れる**(「固定」と書いてある行の種別が `定例`、など)。
枠の引き当てをテストの中で別に書いて突き合わせるので、道具が種別記号や記載の文字列から枠を導く規則を
内側に持っていれば、乱数の対応と食い違って落ちる。乱数は固定で、毎回同じ 300 通り + 200 通り + 200 通りに
なる。テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python change_slot.py init   <置き場ディレクトリ>                      # 合成のひな型 3 枚
python change_slot.py check  <改定の台帳> <置き場の登録表> <変わる対象の登録表>   # 件数の内訳
python change_slot.py rows   <改定の台帳> <置き場の登録表> <変わる対象の登録表>   # 1 行 1 件の一覧
python change_slot.py verify <改定の台帳> <置き場の登録表> <変わる対象の登録表>   # 決定論かどうか 5 つ
```

終了コードは 0 = 割り振れた / 3 = 表の側が壊れていて 1 件も割り振らない / 2 = 引数・読み書きの誤り。

```python
from change_slot import read_table, load_okiba, load_taishou, judge, slot_rows, lists, verify
from change_slot import KAITEI_COLS, OKIBA_COLS, TAISHOU_COLS

kaitei = read_table("kaitei_daichou.csv", KAITEI_COLS)
okiba = load_okiba(read_table("okiba_touroku.csv", OKIBA_COLS))
taishou = load_taishou(read_table("taishou_touroku.csv", TAISHOU_COLS))
got = judge(kaitei, okiba, taishou)        # 9 値 / 別枠 / 種別ごとの内訳 / 直す場所ごと / sha256
grouped = lists(slot_rows(kaitei, okiba, taishou))   # 年月の一覧 / 月日の一覧 / 記載なし / 形が登録外
```

## verify が見る 5 つ

| # | 見るもの |
|---|---|
| 1 | 2 回読んで判定部分の sha256 が同じか |
| 2 | 3 枚の行順を入れ替えても同じ出力になるか(順は rule id と登録表の鍵、および時期の欄の文字列だけで決まる) |
| 3 | 9 値 + 別枠の合計 = rule の件数、種別ごとの内訳の合計 = rule の件数 |
| 4 | 照合の印を 1 件だけ `要照合` → `照合済` に替えると、その rule だけが別枠から登録表の種別行が指す枠へ移り、**登録表のその 1 行だけを差し替えると同じ印で別の枠になる**(= 移り先を道具が決めていない)。合計は変わらない |
| 5 | 時期の欄を `記載なし` から年月に替えると、その rule だけが別枠から ② へ移り、年月の一覧が 1 行増える。**替える年月は作らず、台帳に在る年月を借りる** |

4 と 5 の写しはメモリの中だけで、入力の表には 1 文字も書かない。

## テストと fixture

```
python -m pytest tools/change_slot -q           # 38 passed
python fixtures/make_fixtures.py fixtures       # 合成 fixture を作り直す
```

fixture は全て合成で、rule 名も領域も機関名も架空、年月・月日も架空。実在の料率も金額も人名も
1 つも入っていない。写したのは形だけで、定例でも時期の書き方が割れること、同じ列に済んだ改正と
新設・廃止と将来施行と施行日未定と動かない行が混ざること、照合前の行が混ざること、1 つの種別が
複数の枠に割れ 1 つの枠が複数の種別から集まることの 4 つ。
記事に載せた数値は `tests/test_change_slot.py` が `assert` で固定している。

## できないこと

- **次にいつ動くかを計算しない。** 今日を読まないので、次の改定までの残りも、過去か未来かも出ない
- **日付を計算しない。** 暦も休日表も年度表も持たない。「年度」から年度初めの日を作る経路が無く、「10 月頃」を日に直す経路も無い
- **時期の欄の値が暦として正しいかは見ない。** 見るのは 3 つの形だけなので、月の位置に `13` と書いてあっても形が合えば通る(暦を持たないため)
- **要照合を確定として扱わない。** 照合の印が `要照合` の行は 9 値に入れず別枠に出す。印を替えるのは人の仕事
- **記載の無い時期を埋めない。** `記載なし` を既定値で補う経路が無い
- **値を引かない・計算しない。** 値(料率・金額)の欄そのものを持たない
- **改定の内容を要約しない。** 改定の記載は写すだけで、中身を解釈する経路が無い
- **優先度・重要度・手間の見積りを付けない。** 「大事な改定」「軽い改定」の語彙を持っていない
- **網羅と言わない。** 件数は入力の件数だけを返し、割合にしない
- **実行の履歴を読まない。** 道具が何回動いたかは読まない。読むのは制度側の記載だけ
- **行を足さない・閉じない。** ⑥ は渡す先の記号(行の追加 / 行の閉じ)を返すだけ
- **枠の良し悪しを判定しない。** 種別記号と枠の対応は登録表の側にあり、その対応が正しいかは人が決める
- **台帳の記載が原文のとおりかは確かめない。** 出典としてファイル名 + 行番号を要求するところまでで、その行に本当にそう書いてあるかは読まない
