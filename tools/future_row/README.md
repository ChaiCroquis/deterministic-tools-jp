# future_row — 公布された改正は表に先に入るので、効き始める日が来るまでは予定として別に返す

**公布された改正は、効き始める前に表へ入る。だから同じ表の中に「もう知っているが、まだ
効き始めていない行」が並ぶ。基準日の答えに混ぜれば早すぎる値が返り、入れずに捨てれば「次に
いつ変わるか」を答えられない。さらに施行日が政令にゆだねられた改正は効き始める日の欄が空で、
空を基準日や年度初めや公布日で埋めると、まだ効き始めていない改正が効いてしまう。**

[asof_table](../asof_table) の回で、行に「知った日」と「効き始める日」の 2 列を立てた。けれど
あの回の向きは過去向きで、見ていたのは「あの時点ではどう計算していたか」を再現する側だった。
**同じ 2 列の反対向き、つまり 知った日 ≦ 基準日 < 効き始める日 の行をどう扱うかは、どの回でも
本題にしていない。** [span_split](../span_split) で「施行日が決まっていない行は、知識として
読むが切るのには使わない」と 1 行だけ宣言したが、あれは期間を切る側の話で、予定を返す口は
作っていない。

この部品は、行の表・状態の宣言・基準日の表の 3 枚から、(行 × 基準日)1 組ごとに 5 値
(**もう効き終わった / 基準日に効いている / これから効き始める / 効き始める日が未定 /
止まった**)を付ける。そのうえで rule ごとに「次にいつ変わるか」を、基準日より後でいちばん
早い効き始める日 1 件だけ、出典つきで返す。**引かない。分けるだけだ。**

持たせていないものが規律になっている。

- **効き始める日が空の行に日付を推定して入れない**(基準日・年度初め・公布日・次の月初へ
  丸める引数が 1 つも無い。空の行は予定に置き、日付を返さない。この部品の骨をそのまま
  入力の形にしたところ)
- **知った日を効き始める日として代用しない**(公布日で引く経路が無い)
- **判定にシステム日付を使わない**(基準日は表から受け取る。システムの日付と時刻は「読んだ
  条件」の欄に書き出すだけで、判定部分には入れない。[env_match](../env_match) /
  [basis_map](../basis_map) と同じ向き)
- **まだ効き始めていない行を基準日の答えに混ぜない**(答えの口と予定の口は別の配列で返る。
  1 つにまとめる関数も option も無い)
- **段階施行を 1 行にまとめない**(効き始める日ごとに別の行として数える。まとめる引数が無い)
- **前の行を閉じていない重なりは止まる**(同じ rule・同じ対象・同じ順位で効いている期間が
  重なったら、1 組も読まずに止まる)
- **知った日が基準日より後の行は扱わずに止まる**(当時の知識を再現するのは
  [asof_table](../asof_table) の仕事で、この部品は「もう知っている行」だけを分ける)
- **「次にいつ変わるか」は 1 件だけ返す**(近い日を探して代用しない。効き始める日が空の行を
  混ぜない。無ければ「無い」と返す)
- **値を返さない**(行の表に値の列が無い。[rank_clash](../rank_clash) と同じ)
- **順位で裁定しない・期間を切らない・帯にも当てない・空欄の意味も読まない・日付の種別も
  決めない**(順位は [rank_clash](../rank_clash)、期間は [span_split](../span_split)、帯は
  [band_edge](../band_edge)、空欄は [blank_kind](../blank_kind)、日付の種別は
  [basis_map](../basis_map) の仕事で、役割が重ならない。この部品が持つのは基準日に対する
  効き始めの前後 1 段だけだ)
- **件数は分母(行数 × 基準日の数)と内訳つきで出す**(率を単独で返さない。
  [check_census](../check_census) 以降と同じ)
- **5 つを混ぜない**([answer_check](../answer_check) / [span_split](../span_split) /
  [band_edge](../band_edge) / [blank_kind](../blank_kind) / [recalc_scope](../recalc_scope) /
  [basis_map](../basis_map) / [rank_clash](../rank_clash) と同じ)
- **入力表を書き換えず、行も日付も生成しない**([intake_triage](../intake_triage) 以降と同じ)
- **出典の欄が空の行は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)
- **float を使わない**(件数は整数、日付は年月日の文字列のまま比べる)

## 入力 — 行の表と状態の宣言と基準日の表の 3 つ

行の表は 9 列。1 条項適用単位が 1 行になる。

| 列 | 意味 |
|---|---|
| `row_id` | 行 id(空欄は「表として読めない」。2 行あると**止まる**) |
| `rule_id` | その行が属する rule id。**宣言表に無い rule は「表として読めない」** |
| `known_from` | 知った日(公表日)。年月日。**基準日より後なら止まる** |
| `valid_from` | 効き始める日。年月日、または**宣言された空の記号** |
| `valid_to` | 効き終わる日。年月日、または**宣言された空の記号**(= まだ閉じていない) |
| `seg` | 対象セグメント。`名前=値` を縦棒で区切る。**未指定に見える記号は書けない** |
| `priority` | 順位。**空欄のまま持つ**(0 と読み替えない)。整数でなければ読めない表 |
| `announcer` | 公表元。**判定には使わず素通しする** |
| `source` | その行の出典。**空欄は止まる** |

```csv
row_id,rule_id,known_from,valid_from,valid_to,seg,priority,announcer,source
G01,R01,2001-04-01,2001-04-01,2007-10-01,次元A=a1,0,公表元甲(架空),articles/07_asof_table.md L32
G02,R01,2004-06-01,2007-10-01,政令待ち,次元A=a1,0,公表元甲(架空),私の棚卸し記録(非公開)
G07,R03,2004-06-01,政令待ち,政令待ち,次元A=a3,,公表元丙(架空),articles/22_span_split.md L46
```

`G01` と `G02` が「前の行を閉じたうえで未来の行が並ぶ」形だ。`G02` は **もう表に入っているが、
2007-10-01 まで答えには出てこない。** `G07` は効き始める日の欄が空で、宣言された記号で書いて
ある。有効期間は半開区間で読むので、効き始める日は含み、効き終わる日は含まない。

状態の宣言は 6 列。**1 rule が 1 行**で、「どの状態を使うか」「欄が空のときどうするか」を
ここだけに書く。

| 列 | 意味 |
|---|---|
| `rule_id` | rule id(空欄は「表として読めない」。2 行あると**止まる**) |
| `states` | 使う状態の名前と意味。`名前=意味` を縦棒で区切る。**名前は登録の 4 つと同一** |
| `blank_rule` | 効き始める日が空のときの扱い。登録の 1 種(`予定に置き、日付は返さない`) |
| `open_rule` | 効き終わる日が空のときの扱い。登録の 1 種(`まだ閉じていないものとして扱う`) |
| `blank_mark` | 空欄の記号。**この記号だけが「欄が空」になる** |
| `source` | その行の出典。**空欄は止まる** |

同じ記号が 2 つの列で「空」を表すが、**意味は列ごとに宣言で分かれている。** 効き始める日の空は
「予定に置き、日付は返さない」、効き終わる日の空は「まだ閉じていない」だ。記号は「この欄は
わざと空だ」という宣言で、空の読み方そのものは別の欄に書く。

基準日の表は 4 列。1 基準日が 1 行で、引く時点を外から渡す。

| 列 | 意味 |
|---|---|
| `asof_id` | 基準日 id(空欄も、同じ id が 2 行あるのも「表として読めない」) |
| `asof` | 基準日。年月日 |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 分け方 — 見るのは効き始める日と効き終わる日と基準日だけ

| 行の書き方 | 基準日との関係 | 状態 |
|---|---|---|
| 効き始める日が宣言された空の記号 | 基準日に関わらず | **効き始める日が未定** |
| 効き始める日が年月日 | 効き始める日 > 基準日 | **これから効き始める** |
| 効き始める日が年月日 | 効き始める日 ≦ 基準日 < 効き終わる日 | **基準日に効いている** |
| 効き始める日が年月日 | 効き終わる日 ≦ 基準日 | **もう効き終わった** |

似た記号(`-` `未定` `なし` `TBD` など)が欄に書かれていたら、宣言された記号と一致しない限り
**寄せずに止まる**。効き始める日が空の行は、どこへ寄せても意味が変わるので、記号の揺れを
推測しない。

「次にいつ変わるか」は rule ごと・基準日ごとに 1 件だけ返る。**基準日より後でいちばん早い
効き始める日の行** で、その行の id と出典が付く。無ければ `無い` とだけ返り、近い日も空の行も
代わりに使わない。

## 件数の検算 — 分母は行数 × 基準日の数

- **5 値の件数の合計 = 行数 × 基準日の数**
- **「次にいつ変わるか」の件数 ≦ rule 数(基準日ごとに数えて)**
- **基準日を次に変わる日まで進めると、`これから効き始める` が減った分だけ効き始めた側が増える**

3 つめは効き始めの 1 日ずれを測るところだ。ここで 1 つ分かったことがある。**進めた先の日は、
その日に前の行が閉じる日でもある。** 段階施行の表では、新しい行が効き始めるのと同時に前の行が
終わるので、減った 1 件がそのまま `基準日に効いている` に入るとは限らず、`もう効き終わった` に
入ることがある。だから検算は「減った分 = 効き始めた側(2 つの合計)の増えた分」で見て、内訳は
別に数えている。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- (行 × 基準日)の組ごとに 4 つの状態が 1 つだけ付き、**5 値の合計が 行数 × 基準日の数** に
  等しく、「次にいつ変わるか」は **rule ごと・基準日ごとに 1 件以下** で、返る日付は
  **行の表にそのまま在る効き始める日で、しかも基準日より後** であり、効き始める日が未定の行は
  1 件も混ざらず、判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても
  同じバイト列** になる
- または、1 組も読まずに理由コードが返る(読んだ組や指紋を取りに行くと例外になる)

どちらの場合も、この部品は行の表も状態の宣言も基準日の表も 1 文字も書き換えない。

この 1 文を `tests/test_future_row_property.py` の `@given` テストが確かめている(rule を
1〜3 本作り、rule ごとに行を 1〜3 本、効き始める日を日付の候補から引いて **前の行を閉じながら**
並べる。3 割くらいの確率で効き始める日が空の行を 1 本足す。基準日は 1〜3 件。3 割くらいの
確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。**5 値は部品の判定を呼ばず、2 枚の
表の行からテスト側の別実装で組み立てている。** 同じファイルの 2 本目は 300 通りで、「効き始める
日の前日と当日で状態が 1 日だけずれる」ことと「空の記号の行はどの基準日でも未定のまま」を
見ている。

## 出力 — 答えの口と予定の口は別の配列

`check` が返るのは、3 枚それぞれの行数、分母(行数 × 基準日の数)、5 値の件数、基準日ごとの
内訳、「次にいつ変わるか」の件数、それに分母の内訳と検算と 6 つの固定行だ。**率だけを返す
呼び方も、option も無い。**

```
"分母(行数 × 基準日の数)": 30,
"5 値": {"もう効き終わった": 7, "基準日に効いている": 13, "これから効き始める": 7,
         "効き始める日が未定": 3, "止まった": 0},
"次に変わる日の件数": 6,
"基準日ごとの次に変わる日の件数": {"A01": 3, "A02": 3, "A03": 0}
```

固定行は 6 つとも消せない。「空の効き始める日を埋めない」「知った日で引かない」「判定に
システム日付を使わない」「まだ効き始めていない行を答えに混ぜない」「段階施行を 1 行に
まとめない」「値を返さない」だ。

`split` はさらに **4 つの別の配列** を出す。答えの口(基準日に効いている)、予定の口(これから
効き始める)、予定の口(効き始める日が未定)、もう効き終わった、の 4 つで、**1 つにまとめた
配列は出ない。** `next` は rule ごと・基準日ごとの「次に変わる日」を、日付・行 id・出典つきで
出す(無い組は `無い` とだけ)。

`verify` は 3 つ見る。2 回読んで判定部分のバイト列の sha256 を突き合わせること、**宣言された
入れ替え方で 3 枚の行順を入れ替えても同じ出力になるか**、そして **件数の 3 つの検算** だ。

## 止まる理由コード(11 個)

```
出典の欄が空 / 行 id の重複 / 知った日が基準日より後 / 知った日より前に効き始める日がある /
効き終わる日が効き始める日より前か同じ / 状態の宣言に無い記号 /
同じ rule に状態の宣言が 2 行 / 効いている期間の重なり / 件数の合計が合わない /
2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる
```

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。列そのものが
足りないとき、行が 0 行のとき、行 id・rule id・知った日・対象・基準日 id が空欄のとき、
効き始める日・効き終わる日の欄が(記号も書かず)空のとき、日付が `1999-12-31` の形でないか
暦に無い日のとき、対象を `名前=値` で書いていないとき、同じ次元の名前を 2 つ書いたとき、対象に
未指定に見える記号を書いたとき、順位が整数でないとき、行が宣言表に無い rule を名乗ったとき、
状態の名前が登録の 4 つと違うとき、空のときの扱いが登録の外の語だったとき、空欄の記号が
空欄のとき、同じ基準日 id を 2 行書いたとき、入れ替え方が登録の外のときと 2 通りあるときだ。

## 使い方

```bash
python future_row.py init ひな型/                                    # 3 枚の表のひな型を書く
python future_row.py check  行の表.csv 状態の宣言.csv 基準日の表.csv   # 件数と分母の内訳
python future_row.py split  行の表.csv 状態の宣言.csv 基準日の表.csv   # 上 + 4 つの口と指紋
python future_row.py next   行の表.csv 状態の宣言.csv 基準日の表.csv   # 次に変わる日
python future_row.py verify 行の表.csv 状態の宣言.csv 基準日の表.csv   # 2 回 + 行順 + 検算
```

終了コードは、**止まる理由が 1 件も無いときだけ 0**(効き始める日が未定の行が何件あっても 0)、
止まったときは 3、表として読めなければ 2。未定は「待っている状態」であって作業の残りではない
ので、ここでは 0 を返している。まとめて走らせる仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from future_row import Sheet, Declared, Asofs, future_row

d = Declared.load("状態の宣言.csv")
t = future_row(Sheet.load("行の表.csv", d), d, Asofs.load("基準日の表.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `split` / `next` / `check` / `verify` / `init` の 5 つで、option は `-h` 以外に 1 つも
無い。そのこともテストで固定してある。

## テストと fixture

```bash
python -m pytest tools/future_row -q      # 27 passed(2026-10-20 実走)
```

`fixtures/` に行の表 4 枚・状態の宣言 1 枚・基準日の表 1 枚と、崩した表 42 枚が入っている。
**値(料率・金額)は 1 つも入っていない**(この部品は値の列を持たない)。行 id・rule id・
基準日 id・対象の名前と値・公表元・日付は全て架空で、実在の料率や金額や取引先名は 1 つも無い。
写したのは形だけ、つまり「前の行を閉じたうえで未来の行が並ぶ」「同じ rule に効き始める日の
違う行が 3 本並ぶ(段階施行)」「効き始める日の欄が空のまま持つ行がある」「もう効き終わった
行が残っている」という 4 つで、これは私の棚卸し記録に残っている形だ。出典のうち 5 件はこの
repo 内の実在の行(`articles/07_asof_table.md` L32、`articles/09_update_ledger.md` L13、
`articles/22_span_split.md` L15 / L46、`articles/27_rank_clash.md` L15)を指し、テストが
その行を開いて語が在ることまで確かめている。`fixtures/make_fixtures.py` を実行すると、崩した
表ごと書き直す。

## できないこと

- 判定したことは「まだ効き始めていない行が基準日の答えから外れるか」と「次にいつ変わるかが
  表から 1 件に決まるか」までで、**改正の中身が正しいかは判定しない**
- **値がいくらになるかも言わない。** 行の表に値の列が無い
- **その日に本当に施行されるかも判定しない。** 表に書かれた日付をそのまま前後に分けるだけだ
- **なぜ施行日が決まっていないかも言わない。** 未定の行は未定のまま予定の口に置くだけで、
  見込みの日付を埋める経路が無い
- **遡及して適用される行は扱えない。** 効き始める日が知った日より前の行は止まるので、遡及の
  ある表はこの部品に渡せない(分けているのは「もう知っているが、まだ効き始めていない」側だけだ)
- **重なりを見る鍵は rule・対象・順位の 3 つだけ。** 知識期間は「知った日が基準日以前の行は
  全部もう知っている」として扱っているので、知った日が違っても同じ鍵なら重なりとして止まる
- **引かない。** 行を実際に引く経路も、他の部品を呼ぶ経路も持っていない
- 対象の値は文字列として突き合わせる。全角と半角、表記の揺れは別の値になる
- 日付は `1999-12-31` の形だけを読む。和暦も、年度も、年月だけの表記も読めない
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
