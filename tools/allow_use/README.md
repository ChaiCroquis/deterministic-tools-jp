# allow_use — 許した語の一覧と、式に実際に出てくる語を、1 語 1 行で並べる

計算の仕方を式として data に持つと、「式に書いてよい語はこれだけ」という閉じた一覧(許可の一覧)ができる。
ただし一覧に載っている語と、手元の式が実際に使っている語は、同じ集合とは限らない。
この部品は、許した語を 1 語 1 行にして、束ごとに「その語が出てくる式の本数」を横に置く。
**式は評価しない。使われていない語を削れとも不要とも言わない。並べたところで止まる。**
標準ライブラリのみ(ast / csv / json / hashlib / argparse / re)。

## 入力は 4 表(CSV、UTF-8)

どの行にも出典(ファイル名 + 行番号、または JSON のキー)の欄が要る。

| 表 | 列 | 中身 |
|---|---|---|
| ① 許可の台帳 | `word, kind, origin, source` | 語 / 語の種別(`名前` か `構文の種類`)/ 一覧の出どころ id(`文書` `コード` など人が決めた id)/ 出典 |
| ② 式の台帳 | `expr_id, bundle, expr, source` | 式 id / 束の id(`式の一覧` `行に埋まった式` など人が決めた id)/ 式の文字列(原文のまま)/ 出典 |
| ③ 数え方の登録 | `mode, main_bundle, pattern, repl, source` | 1 行だけ。数え方(`書かれた字のまま` か `書き換えの後`)/ 主の束の id / 書き換えの規則(正規表現と置き換えの字)/ 出典 |
| ④ 別の在り所 | `word, note, source` | 0 行でもよい。一覧を通らずにその語が呼ばれている場所を、人が書く欄 |

一覧も式も、人が写して台帳にする。**部品はコードのファイルを開いて一覧を抜かないし、JSON を探して式を抜かない。**
書き換えの規則も部品は持たない。式を評価する仕組みが、読む前に式の字を書き換えている場合(数字を別の書き方に直すなど)、
その規則を ③ に登録すると、書き換えた後の字で数える。どちらで数えたかは出力に残る。

## 式の読み方

標準ライブラリの `ast.parse(mode="eval")` で式を木にする。

- **構文の種類** = 木の節の型の名前(`BinOp` `Call` `Sub` など)
- **名前** = 呼び出しの先の名前だけ(`f(x)` の `f`)。変数の名前は拾わない

読めない式は別枠に置き、本数に入れない。

## 区分は 4 値

| 区分 | 意味 |
|---|---|
| (A) 主の束に出てくる | 登録した主の束の式に、その語が 1 本以上出てくる |
| (B) 主の束には出ず他の束にだけ出てくる | 主の束には無いが、他の束の式に出てくる |
| (C) どの束にも出てこない | 許可の台帳には在るが、読めた式のどれにも出てこない |
| (D) 式には出てくるが許可の台帳に無い | 線の外。一覧に無い語が式に書かれている |

並びは 種別 → 語の昇順で固定。補助の印は 2 つで、区分には使わない。

- `一覧の出どころの片方にしか無い` … 同じ種別の語を載せた出どころが 2 つ以上あり、その語が全部には載っていない
- `(C) の語に別の在り所の登録が在る` … 式には出てこないが、④ に人が書いた在り所が在る

別枠は 6 つ。式として読めない / 出典が空 / 種別が 2 つの値以外 / 数え方が 2 つの値以外 /
同じ (語, 種別, 出どころ) が 2 行 / 主の束の id が式の台帳に無い。
数え方と主の束は全体に掛かるので、崩れていると語は 1 つも数えずに全部が別枠へ落ちる。

## いつも成り立つこと

許可の台帳の語の種類((語, 種別) の組)は、**区分 (A) (B) (C) か別枠のどれか 1 つにだけ入り、その合計は語の種類数に等しい**。(D) に並ぶのは、読めた式に出てきて許可の台帳に無い語だけになる。式の台帳の行順を入れ替えても判定部分は同じバイト列になり、どの場合も 4 表は書き換わらない。

この 1 文は `tests/test_allow_use_property.py` が性質テスト(hypothesis)で確かめている。4 表を乱数で作り(架空の語、読めない式、出典の空、2 つの値以外の種別と数え方、式の台帳に無い主の束を混ぜる)、毎回この 1 文が成り立つかを見る(乱数は固定で、毎回同じ 300 通り)。式から語を拾う処理と区分の決め方は、部品の関数を使わずテストの中で別に書いてある。テストの実行には pytest と hypothesis が要る(部品そのものは標準ライブラリだけで動く)。

## 使い方

```
python allow_use.py init ひな型/
python allow_use.py check 許可.csv 式.csv 数え方.csv 在り所.csv            # JSON で全部
python allow_use.py check 許可.csv 式.csv 数え方.csv 在り所.csv --lines    # 1 語 1 行
python allow_use.py verify 許可.csv 式.csv 数え方.csv 在り所.csv
```

終了コードは 0 = 並べた / 2 = 表として読めない(列が足りない、数え方の登録が 1 行でない、書き換えの規則が読めない)。

```python
import allow_use as U

allow = U.read_table("許可.csv", "allow")
exprs = U.read_table("式.csv", "exprs")
counting = U.read_table("数え方.csv", "counting")
elsewhere = U.read_table("在り所.csv", "elsewhere")
r = U.judge(allow, exprs, counting, elsewhere)
for row in r["語ごとの行"]:
    print(row["種別"], row["語"], row["区分"], row["束ごとの式の本数"], row["印"])
print(r["区分ごとの語数"], r["語数の検算"])
```

`verify` は 5 つ見る。① 二度走らせて判定部分の sha256 が同じ ② 式の台帳の行順を逆にしても同じ
③ 区分 (A)+(B)+(C) の語数 + 別枠に落ちた語数 = 語の種類数 ④ (C) の語 1 つだけを持つ式 1 本ぶんを主の束に足すと、
その語だけが (A) へ動き他は変わらない ⑤ この部品のソースを `ast` で読んで `eval` / `exec` / `compile` の呼び出しが 0。

④ は式の文字列を作って足すのではなく、木にした後の語の集合を 1 本ぶん足して確かめる。構文の種類は、
1 つだけを使う式が書けないため(`a < b` と書けば `Compare` と `Lt` が同時に出る)。

## テストと fixture

```
python -m pytest tools/allow_use -q -s      # 13 passed
python fixtures/make_fixtures.py            # 合成 fixture を作り直す
```

fixture は全て合成で、語(`tier` `cut0` `half_up` など)も式も架空。主の束に出る語・他の束にだけ出る語・
どこにも出ない語・一覧に無い語・読めない式・出どころ 2 つの片方にしか無い語・別枠に落ちる行を含む。
`test_measure_*` が出す `[measure]` の値は `assert` で固定してあり、解説記事に載せた合成の数字はここから取っている。

## できないこと

- **式を評価しない。** 値が合っているか、式が動くかは分からない。`ast.parse` は木を作るだけで、式を走らせない
  (Python の内部では構文解析に組み込みの仕組みが使われるが、この部品のソースから `eval` / `exec` / `compile` は呼ばない)
- **(C) の語が要るか要らないかは返さない。** 先の式のために置いてあるのかもしれないし、そうでないのかもしれない。
  理由が文書に書かれていなければ、部品にも人にも分からない
- **構文の種類の名前は Python の版に依る。** 節の型の名前は版で増減する(古い版には添字に `Index` が在った)。
  一覧を作った版と、数える版が違うと、本数が変わりうる。手元の試験は Python 3.13.9
- **名前は「呼び出しの先がそのままの名前」のときだけ拾う。** `a.f(x)` の `f` は拾わない(`Attribute` として数える)
- **一覧を通らない呼び出しは見えない。** 関数の中で別の関数が呼ばれていても、部品はコードを読まない。
  人が ④ に書いた分だけが横に置かれる
- **書き換えの規則は登録された正規表現をそのまま使う。** 規則が元の仕組みと同じかどうかは確かめない
- 式 id の重複は見ない。式の台帳の 1 行を式 1 本として数える
- 本数は「その語が出てくる式の本数」で、1 本の式に何回出てくるかは数えない
