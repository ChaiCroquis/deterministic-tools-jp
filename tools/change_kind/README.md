# change_kind — 差分に「替わった」と出た行の見本を、前と後で欄ごとに見比べる

差分の記録の `changed`(替わった行の件数)は、値が替わった行の数として読まれやすい。けれど記録に残っている見本を
前(old)と後(new)で欄ごとに見比べると、**見本に写っている欄がすべて同じもの**や、**文言の欄だけが違うもの**が混ざっていることがある。
この部品は、種別が `changed` の見本を 1 本ずつ欄ごとに比べて 5 つの区分のどれかを付け、回ごとに「件数の合計」と「見本の本数」を横に並べる。
**見本の外は読まない。何が違ったかを当てない。「実質の変更は N 件」のような 1 値に丸めない。**
標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力(3 表)

| 表 | 形 | 列 |
|---|---|---|
| ① 回の台帳 | CSV | `run_id,added,removed,changed,source`(件数が記録されていない回は 3 欄を空にする) |
| ② 見本の台帳 | JSONL(1 行 1 本) | `run_id` / `kind`(`added` `removed` `changed`)/ `key` / `old` / `new` / `source`。`old` と `new` は欄と値の対か `null` |
| ③ 欄の登録表 | CSV | `field,symbol,source`。`symbol` は `数値の欄` `文言の欄` `種別の欄` `識別子の欄` の 4 つ。人が登録した分だけ |

値は**書かれた文字列として等しいか**だけを見る。`5000` と `5000.0`、`1226` と `"1226"` は等しくない。数として近いかは見ない(float を使わない)。
対の中の欄の順は見ない。並び(配列)の順は見る。

## 出力

種別が `changed` の見本 1 本ごとに、区分か別枠のどれか 1 つ。

| 区分 | 意味 |
|---|---|
| (A) 見本に写っている欄がすべて同じ | old と new で欄の名前の集まりが同じで、全部の欄の値が同じ。**「変更なし」ではない**(見本に写っていない所は比べていない) |
| (B) 違うのは文言の欄だけ | 違った欄がすべて登録表で `文言の欄` |
| (C) 数値の欄が違う | 違った欄がすべて登録表に在り、その中に `数値の欄` が在る |
| (D) 違う欄に登録表に無い欄が含まれる | 欄の名前から記号を当てないので、ここで止める。登録表に足せば別の区分へ動く |
| (E) 数値の欄は同じで、種別か識別子の欄が違う | 違った欄がすべて登録表に在り、`数値の欄` は無く、`種別の欄` か `識別子の欄` が在る |

片側にだけ在る欄(old にだけ / new にだけ)は「違った欄」に入れて印を別の列に付け、その欄の記号で区分する。
見る順は (A) → (D) → (C) → (B) → (E)。

| 別枠 | 意味 |
|---|---|
| 出典が空 | 見本の `source` が空 |
| 回の台帳に無い回を指す見本 | `run_id` が回の台帳に無い |
| 件数の欄が空の回の見本 | 件数が記録されていない回(失敗の回など)を指している。区分に入れない |
| 見本の本数が件数を超える回の見本 | 種別ごとの見本の本数が、その種別の件数を超えている回 |
| 同じ回に同じ key の見本が 2 本以上 | どちらを比べるかを決めない |
| changed なのに old か new が無い | 比べる相手が無い |

回ごとには、件数の合計と見本の本数を並べて `見本が全件` / `見本が一部` / `見本なし` / `件数が 0` / `件数の欄が空` / `見本の本数が件数を超える` を返す。
件数は在るのに見本が 1 本も無い種別(例: 減った行)は別の列に出す。

表として読めないとき(見出しが違う / 回の id が重複 / 回の出典が空 / 件数が整数でない / 欄の名前が重複 / 欄の記号が登録の外 /
欄の出典が空 / 見本の行が読めない / 見本の欄が足りない / 見本の種別が登録の外 / old か new が欄と値の対でない)は、**1 本も区分せずに**理由を返す。

## 使い方

```
python change_kind.py check  fixtures/runs_a.csv fixtures/samples_a.jsonl fixtures/fields_a.csv   # 区分ごとの件数
python change_kind.py rows   fixtures/runs_a.csv fixtures/samples_a.jsonl fixtures/fields_a.csv   # 回ごと・見本ごとの一覧も出す
python change_kind.py verify fixtures/runs_a.csv fixtures/samples_a.jsonl fixtures/fields_a.csv   # 手続きが決定論かを 5 つ見る
```

終了コードは 0 = 読めて別枠が 0 本 / 3 = 読めたが別枠が 1 本以上在る / 2 = 表として読めない(または verify が合わない)。
0 は「値が替わっていない」という意味ではない。

```python
import change_kind as K

tables = (K.read_runs("runs.csv"), K.read_samples("samples.jsonl"), K.read_fields("fields.csv"))
out = K.check(*tables, detail=True)
for row in out["見本ごと"]:
    print(row["run_id"], row["key"], row["区分"] or row["別枠"], [d["欄"] for d in row["違った欄"]])
```

`verify` が見る 5 つ: ① 判定部分の sha256 が二度走って同じ ② 3 表の行順と old / new の欄の順を入れ替えても同じ
③ 区分 + 別枠 = `changed` の見本の本数、回ごとの見本の本数の合計(+ 回の台帳に無い回を指す見本)= 見本の台帳の行数
④ (A) の見本の new の数値の欄を 1 文字変えた写しでは、その 1 本だけが (C) へ動く ⑤ 欄の登録表から 1 欄を消した写しでは、その欄が違う見本だけが (D) になる。
写しはメモリの中だけで、入力には 1 文字も書かない。

## いつも成り立つこと

読んだ結果は 2 通りしかない。**種別が changed の見本 1 本ごとに 5 つの区分か 6 つの別枠のどれか 1 つだけが付き、その合計が changed の見本の本数に等しく、(A) が付くのは old と new で欄の名前の集まりが同じで全部の欄の値が書かれたとおりに等しい見本だけで、(C) が付く見本には数値の欄の違いが必ず在り、3 表の行順と欄の順を入れ替えても同じバイト列になる**か、**1 本も区分せず、止まった理由が 1 つ返る**か。どちらの場合も入力の 3 表は 1 文字も書き換わらない。

この 1 文は `tests/test_change_kind_property.py` が性質テスト(hypothesis)で確かめている。3 表を乱数で作って一時フォルダに書き、道具の読み方で読む。
区分と別枠の照合は道具の関数を使わず、テストの中で別に書いている(乱数は固定で、毎回同じ 200 通り)。テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 持たせていないもの

- (A) の行で何が違ったかを当てる経路(見本の外を読まない)
- 同じ回に足された行・減った行と結び付ける経路
- 替わった理由の欄
- 見本から全件の内訳を推計する経路(割合を掛けない)
- 欄の名前から記号を当てる経路
- 数として丸めて比べる経路、float
- 「変更なし」と言い換える経路、「実質の変更は N 件」の 1 値
- 通信、時計を読む経路、入力を書き換える経路

## 置いてある表

`fixtures/` の 3 表は合成で、回 9 行 / 見本 19 行 / 欄 6 行。規則の名前・値・出典はすべて架空で、実在の料率も金額も入っていない。
5 つの区分と 6 つの別枠が少なくとも 1 本ずつ出るように作ってある。
