# reader_registry — 形の癖は読み取り係の宣言に置き、核には宣言どおり読めた行しか渡さない

解説記事: [帳票の形が相手先ごとに違っても、核は太らせず読み取り係を足す](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_03.html)(2026-10-04 公開)
<!-- article-links:end -->

同じ内容の表が、相手先ごとに別の形で出てくる。行と列が入れ替わっている、時間が 60 進の表記になっている、
引く側の値に符号が付いていない、語が年で改名された、という具合だ。ここで核(計算と検査)の側に
「この形も読む」を足していくと核が太り、どの形のために入れた分岐か誰も言えなくなる。

この部品は読み取りの層だけを担う。**核は形の癖を 1 つも知らない**。癖の名前(値の形)は呼べる名前の
一覧としてここに登録してあるが、**どの列にどの癖があるかは宣言表の側だけ**にある。
stdlib のみ(csv / json / decimal / hashlib / argparse)、依存なし。

## 流れ(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | 宣言表を検査する(係の名前・列の対応・値の形の名前) | 同じ reader_id が 2 行 / column_map が 1 対 1 でない / value_form 空欄 |
| 2 | 係を選ぶ(match を全部評価する) | 一致が 0 件 / 2 件以上(最も近い係を推測で選ぶ経路は無い) |
| 3 | 見出しの軸を特定する | 宣言した見出しが全部そろう行(列)が無い / 並びの長さが宣言と違う |
| 4 | 値の形の名前で読み替える | 宣言した形で読めない値(別の形として読み直さない) |
| 5 | required の列が埋まったか見る | 1 つでも空なら行を返さない |
| 6 | 通ったものだけ、核の列仕様の行と読み替え台帳を返す | — |

前の段で止まったら次の段には進まない。止まったときに返るのは理由コードで、行は 1 行も返らない。

## いつも成り立つこと

読み取りの結果は 2 通りしかない。**宣言どおりに読めた行(核の列が宣言ぶんそろい、required の列が全部
埋まっている)が返る**か、**行は返らず、理由コードが返る**か。どちらの場合も、この部品からファイルは
1 つも開かれない。

この 1 文は `tests/test_reader_registry_property.py` が性質テスト(hypothesis)で確かめている。宣言どおり
の形の表を乱数で作り(行がレコードと列がレコードの両方)、9 通りから 1 つ引いて 1 か所だけ壊して
(「壊さない」も同じ確率で引く)、毎回この 1 文が成り立つかを見る。乱数は固定で、毎回同じ 300 通り。
読み替えは道具の関数を使わず、テストの中で別に書いている(文字列 / 整数 / 60 進の時間)。テストの実行には
pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 宣言表(読み取り係の一覧)

1 係 = 1 行で、列は 7 つ。`fixtures/registry.json` が例(4 係)。`init` でひな型が出る。

| 列 | 意味 |
|---|---|
| `reader_id` | 係の名前。報告と台帳に出る |
| `match` | 選定の手がかり。`headers` = 見出しの軸に literal で在る語、`columns` = 見出しの軸に並ぶ語の数 |
| `orientation` | レコードの並び。`行がレコード` / `列がレコード` |
| `column_map` | 核の列名 ← 原本の見出し。**1 対 1**(1 つの見出しを 2 つの核の列へは書けない) |
| `value_form` | 核の列ごとの値の形の名前。**空欄は許さない** |
| `required` | 埋まっていなければ行を返さない核の列 |
| `source` | 出典。台帳に載る |

`match.columns` は、行がレコードなら見出し行の列数、列がレコードなら見出し列の行数を書く。
選定はこの 2 つ(語の集合と軸の長さ)だけで行い、**似ている度合いでは選ばない**。

## 値の形(`VALUE_FORMS`)

| 名前 | すること |
|---|---|
| `文字列` | 前後の空白だけ落とす |
| `整数` | 桁区切りのカンマを外し、整数として読む(全角数字は読まない) |
| `金額そのまま` | 数として読み、丸めない |
| `金額を50銭以下切捨て` | 50 銭以下を切り捨て、超えたら切り上げる |
| `金額を1円未満切捨て` | 1 円未満を切り捨てる |
| `金額を円未満四捨五入` | 円未満を四捨五入する(端数 0.5 は上へ) |
| `60進の時間` | `7:30` を `7.50` にする。分は 60 で割って 2 桁に丸める |
| `印字は符号なし` | 符号なしで印字される引く側の値にマイナスを付ける |
| `括弧は負` | `(1,200)` を `-1200` にする |

丸めの名前と振る舞いは、同じシリーズの他の部品(数式を表の行に置くもの・2 つの軸から足すもの)と
そろえてある。足りない形があれば、ここに名前を 1 つ登録する。**宣言表の側には名前しか書けない**ので、
癖の中身が宣言表に散らばることはない。

空欄は形にかけず、空欄のまま渡す(埋まっていなければ `required` が止める)。

## 止まる理由コード(`REASONS`)

| 理由コード | 意味 |
|---|---|
| 同じ reader_id が 2 行 | どちらの宣言か表から決まらない |
| column_map が 1 対 1 でない | 1 つの見出しを 2 つの核の列へ割り当てている。移し先が決まらない |
| value_form 空欄 | 核の列に形の名前が無い。既定の形は持たない |
| 係が 0 件 | match に一致した係が無い。最も近い係を推測で選ぶ経路は持たない |
| 係が 2 件以上 | 優先順位で 1 つに絞る経路は持たない |
| 見出し行が見つからない | 宣言した見出しが全部そろう行(列)が無い(2 段見出しはここで止まる) |
| 列数が宣言と違う | データの並びの長さが見出しの軸と合わない |
| 宣言した形で読めない値 | 宣言した形で読めない。別の形としては読み直さない |
| required の列が埋まらない | 埋まっていなければ行を返さないと宣言した列が空のまま |
| 選定前に読み取りを要求した | 宣言表と選定を通る前に、行か台帳を取りに来た |

理由コードは「機械では決まらない理由」の名前になっている。どう直すか(宣言を足すか、原本をもらい直すか)は
人が決める。宣言表そのものが読めない場合(登録していない形の名前、`orientation` の書き間違い、
`required` が `column_map` に無い列を指している等)は理由コードにせず、終了コード 2 で返す。

## 使い方

```
python reader_registry.py select <表> --registry <宣言表.json> --delimiter カンマ
python reader_registry.py read   <表> --registry <宣言表.json> --delimiter カンマ
python reader_registry.py ledger <表> --registry <宣言表.json> --delimiter カンマ --format csv
python reader_registry.py init   <宣言表.json>
```

終了コードは 0 = 読めた / 3 = 理由コードで止まった / 2 = 宣言表か引数の不備。バッチの中に置いて 3 で
止められる。`--delimiter` は既定を持たない(カンマかタブを毎回宣言する)。

```python
from reader_registry import Registry, Sheet, read

reading = read(Sheet.load("原本.csv", "カンマ"), Registry.load("宣言表.json"))
if reading.report.ok:
    rows = reading.rows()          # 核の列仕様に合う行(次の工程へ渡す)
    led = reading.ledger()         # 原本の見出し → 核の列名 / 形の名前 / unmapped / sha256
else:
    for p in reading.report.pending:
        print(p.reason, p.detail)  # この時点で行は 1 行も返らない
```

`rows()` が返すのは行だけで、ファイルは書かない。次の工程(2 つの軸から足す関所 → 取込用 CSV の
書き出し)にそのまま渡せる形にしてある。

## 宣言表に無い見出しは捨てない

`column_map` に無い見出しは、黙って無視せず `unmapped` として台帳に残す(見出しの語と、レコードごとの値)。
核の列には入れない。「増えた列に気づかないまま渡す」ことを防ぐためで、入れるかどうかは人が宣言で決める。

## テストと fixture

```
python -m pytest tools/reader_registry -q        # 81 passed
python fixtures/make_fixtures.py                 # 合成 fixture を作り直す
```

fixture は全て合成データで、人・相手先・金額はすべて架空。宣言表は 4 係(横並び / 転置 / 括弧 / 改名)、
表は 13 枚で、読めるものと止まるものを両方そろえてある。`test_measure_*` が記事に載せた数値の出どころで、
固定の fixture から決定論的に出る値を `assert` で固定している。

## できないこと

- 形の名前は 1 列に 1 つ。2 つの癖が同じ列に重なる場合(符号なしで印字され、かつ銭がある等)は、
  組み合わせた名前を 1 つ登録する。自動で合成はしない
- 宣言した対応が意図どおりかは判定しない。「その列をその名前に移せた」までで、移し先が正しいかは人が決める
- 値が制度として正しいかも判定しない(合計が合うかは次の工程の仕事)
- 見出しが 2 段に分かれている形は読めない。1 行(1 列)に全部そろっていることが前提
- 列が増減した表は、宣言した軸の長さと違うので「係が 0 件」になる。係を足すか宣言を直すのは人の仕事
- 文字コードは扱わない。この部品はテキストを受け取る(どの文字コードで読むかは前の層で決める)
- 区切りはカンマとタブだけ。固定長や Excel の形は読まない
- `60進の時間` は分を 60 で割って 2 桁に丸めるので、割り切れない分では 1/300 時間ぶんの差が落ちる
