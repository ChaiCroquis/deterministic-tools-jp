# recall_tally — 取る前に書いた数と取った後の数を、単位をそろえてから横に並べる

値を取りに行く前に知識で書いた棚卸しにも、数は書いてある(区分の数・等級の数・行の本数・rule の数)。取ってきた後の
記録にも、同じ項目の数が在る。2 つは別の経路で出た数なので、この部品は項目ごとに横に並べ、**単位の記号が同じものだけを
文字列で比べ、単位が違うものは比べずに並べ、概数の印が付いたものは比べず、片側にしか無いものは無いと書く。**

**どちらが正しいかは決めない。** 正しい側の欄も、順位も、点数も、一致率の 1 値も無い。違いの原因も言い当てない。
読むのは渡された 4 枚の表だけで、ネットワークに出ない、値を取りに行かない、ディスクを歩かない、数の文字列から単位を
読み取らない、単位を換算しない(行を年度の数で割る、のような経路が無い)、概数の印を落として比べない、時計を読まない。
float を使わない。標準ライブラリのみ(csv / json / hashlib / argparse / re)、依存なし。

## 入力の 4 枚(どの行にも出典の欄が要る)

| 表 | 列 |
|---|---|
| 経路の登録表 | 経路 id / 経路の素性(原文をそのまま写す)/ 出典 |
| 数の台帳 | 数 id / 経路 id / 項目 id / 数の文字列 / 単位の記号 / 概数の印 / 数え方の記載 / 出典 |
| 単位の記号の登録表 | 記号 / 意味 / 出典 |
| 対の台帳 | 項目 id / 経路 1 の数 id / 経路 2 の数 id / 根拠 / 出典 |

数の文字列は渡されたまま写す(`54`、`67% / 50%`、`≈50`、`一般 / 農林水産・清酒 / 建設` のような列挙でもよい)。
単位の記号は人が欄で宣言する。**道具は数の文字列の中の「等級」や「%」を読まない。** 概数の印は `在る` か `無い` の
2 値で、文字列に `≈` や「約」が在るかは道具が読まない。数え方の記載が空なら `数え方の記載なし` と出す。
対の台帳は、片側の数 id が空でもよい(両側とも空は表の形の誤り)。

## 区分(対 1 件に 1 つ)

| 区分 | 条件 |
|---|---|
| (A) 単位が同じで、数の文字列が一致 | 単位の記号が同じで、空白(半角・全角・タブ)だけを除いた文字列が 1 文字も違わない |
| (B) 単位が同じで、整数の形で、一致しない | 単位の記号が同じで、両方が半角の数字だけでできていて、一致しない。差を整数で返す(符号は「経路 2 − 経路 1」と決めてあるだけ) |
| (C) 単位の記号が違う | 比べない。差を返さない。両側の単位を並べる |
| (D) 片側にしか数が無い | 対の片側の数 id が空、または数の文字列が空。無い側は `数の記載なし` と出す(0 と書かない) |
| (E) どちらかに概数の印が在る | 比べない。差を返さない(印を落として引き算に入れない) |

判定の順は、別枠 5 つ → (D) → (E) → (C) → (A) → (B) / 別枠 6。概数の印は単位より先に見る。

別枠の理由は 6 つで、手前が勝つ: 出典が空 / 単位の記号が登録表に無い / 数 id が重複 / 対の台帳の数 id が数の台帳に無い /
対の両側が同じ経路 / (B) に入るはずの数の文字列が整数の形でない(小数・分数・範囲・桁区切り・全角はそのまま並べ、差を返さない)。

ほかに返すもの:

- 項目ごとに 1 行 = その項目の数を全部並べる。対に入らなかった数は `対の外` として並べる(捨てない)
- 経路ごとに 1 行 = 数の件数、単位の記号ごとの内訳、数え方の記載が空の件数
- `table-rows` = 表の行を節ごとに数える補助。区切りの文字と見出しの行数を引数で受け、`#` で始まる行で節を切り、
  区切りの文字で始まる連続した行を 1 つの表として、表ごとに見出しの行を除いた行を数える。行の中身は読まない、
  重複を除かない。**rule の数だとは言わず `表の行の数` と出す**(1 行に 2 つの rule が書かれていても 1 と数える)

## いつも成り立つこと

対 1 件には、区分 5 つか別枠の理由 6 つのうち 1 つだけが付き、その合計は対の件数に等しく、表の行順を入れ替えても答えは変わらず、差は (B) の対にだけ返り、渡した表は 1 文字も書き換わらない。

この 1 文は `tests/test_recall_tally_property.py` が性質テスト(hypothesis)で確かめている。4 枚の表を乱数で作り
(空の出典、登録に無い単位、重複した数 id、台帳に無い数 id、同じ経路どうしの対、概数の印、空の数、整数の形でない数、
空白の混じった数を混ぜる)、区分はテストの中で別の書き方で引き直して比べる(道具の判定は呼ばない)。乱数は固定で、
毎回同じ 300 通り。

## 使い方

```
python recall_tally.py check  routes.csv counts.csv units.csv pairs.csv
python recall_tally.py rows   routes.csv counts.csv units.csv pairs.csv   # 対 1 件 1 行の CSV
python recall_tally.py verify routes.csv counts.csv units.csv pairs.csv   # 5 つの検算
python recall_tally.py table-rows notes.md --sep "|" --head 2             # 表の行を節ごとに数える
```

終了コードは 0 = 判定した / 3 = verify のどれかが合わない / 2 = 表の形の誤り(1 件も判定しない)。
表の形の誤り = 列が無い、経路 id や単位の記号の空・重複、数の台帳の経路 id が登録表に無い、概数の印が 2 値でない、
対の両側の数 id が空。

`verify` が見る 5 つ: 二度走って同じ指紋(sha256)か / 4 枚の行順を入れ替えても同じ出力か /
区分 + 別枠 = 対の件数か / (A) の対の片側の数を 1 だけ増やすと、その対だけ (B) に動き差が 1 になるか /
(B) の対の片側の単位の記号を替えると、その対だけ (C) に動き差の欄が消えるか。写しはメモリの中だけで作る。

```python
import recall_tally as R
tables = R.read_all(["routes.csv", "counts.csv", "units.csv", "pairs.csv"])
result = R.judge(tables)   # 区分 / 別枠 / 対ごと / 項目ごと / 経路ごと / 判定部分の sha256
```

`fixtures/gousei/` は合成した 4 枚(店の設計メモと書き出したマスタの、架空の数)。`examples/temoto_no_nibunsho/` は
私の手元の 2 つの文書(値を取る前に書いた棚卸しと、取った後の作業状況の記録)から数を写した 4 枚と、棚卸しの A 章の写し。

テストの実行には別に pytest と hypothesis が要る。
