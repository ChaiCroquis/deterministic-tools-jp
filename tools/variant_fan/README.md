# variant_fan — 同じ式でも、選び方を並べて答えが何通り出るかを先に数える

解説記事: [同じ式でも、選び方を並べて答えが何通り出るかを先に数える](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_10.html)(2026-10-11 公開)
<!-- article-links:end -->

同じ式・同じ金額でも、**書かれていない選び方が 1 つ増えるごとに、どれももっともらしい答えの組み合わせが
掛け算で増える**。丸めの名前、丸めを掛ける段、基準日の取り方、区分の選び方、期間の切り方、入力の桁の扱い。
[formula_table](../formula_table) は丸めの軸 1 本を「書かせて止める」側だったが、こちらは
**軸が何本あるときに答えが何通りになるかを先に数える** 側になる。

この部品は **宣言された軸の候補だけ** を組み合わせて全通り評価し、相異なる値ごとに「その値を出した軸の
組み合わせ」を verbatim で並べ、件数と分母の内訳(軸ごとの候補数と組み合わせ総数)を必ず一緒に出す。
**どれが正しいかは選ばない。**

持たせていないものが規律になっている。

- **軸を自然文から推測して足さない**(軸表に無い軸は扇に入らない。出力には「扇は宣言された軸の範囲内」と
  分母の内訳が必ず付く。[scope_ledger](../scope_ledger) の「機械では読めない」と同じ落とし方)
- **正解を選ぶ引数を持たない**(どの組み合わせが正しいかを返す経路が無い。[cross_route](../cross_route) /
  [answer_check](../answer_check) と同じ規律)
- **平均・中央値・最頻値を返さない。多数決で 1 点に潰さない**(集約で扇を代表値にする経路が無い)。
  扇の幅は観測された最小値と最大値をそのまま併記する
- **許容誤差の引数を持たない**([tally_gate](../tally_gate) と同じ。値が近いことを同じことにしない。
  相異なる値はバイト列の一致でだけ束ねる)
- **宣言された既定の組み合わせには「宣言された既定」の印だけを付ける**(正しい・推奨と書く経路が無い)
- **どの軸がどれだけ効いたかの寄与率・重要度・感度を出さない**(軸ごとの分解の経路が無い)
- **扇の通り数を単独で返さない**(相異なる値の件数・組み合わせ総数・軸ごとの候補数を必ず併記。
  [check_census](../check_census) / [scope_ledger](../scope_ledger) と同じ)
- **既定の丸めを持たない**(丸めは式表の `rounding` 列と軸表の候補からだけ掛かる。formula_table の規律を継ぐ)
- **入力表を書き換えず、式も軸も生成しない**(直す・補う経路が無い)
- **出典の欄が空の候補がある軸は、扇に入れずに止まる**(誰の宣言由来かを辿れない候補を台帳に入れない)
- **組み合わせ数が軸表の宣言上限を超えたら止まる**(黙って間引いたり標本にしたりしない)

## 入力 — 式表と軸表の 2 枚

式表は [formula_table](../formula_table) と同じ形。

| 列 | 意味 |
|---|---|
| `id` | 何を計算するか。別の行の `id` を式の中から名前で呼べる |
| `expr` | 式の文字列。`ast` の allowlist で構文を絞る |
| `rounding` | 丸めの名前。registry の名前か、**軸の名前**。空欄は止まる |
| `valid_from` / `valid_to` | 有効時間。半開区間 `[valid_from, valid_to)` |
| `known_from` / `known_to` | 知識時間(公表側)。`known_from` の空欄は許さない |
| `source` | 出典 |

軸表は 5 列だけで、業種の語彙を持たない。

| 列 | 意味 |
|---|---|
| `axis` | 軸の名前。**式表のどこにこの名前を書いたかで、どの位置に効くかが決まる** |
| `choice` | 候補の値(1 行 1 候補) |
| `source` | その候補の出典(記事か README のファイル名 + 行番号)。**空欄は止まる** |
| `default` | 宣言された既定の候補なら印を書く(軸ごとに 1 つまで) |
| `limit` | 組み合わせ数の上限(全行で同じ値) |

## 軸が効く位置は 3 つ(名前をどこに書いたかだけで決まる)

| 位置 | 書き方 | 候補が何になるか |
|---|---|---|
| 式の中の名前 | `expr` の中にその軸の名前が現れる | 数 |
| 丸めの列 | `rounding` の欄がその軸の名前と一致 | 丸めの名前(registry の 4 つのどれか) |
| 基準日の引数 | `on` / `as_of` にその軸の名前を渡す | 日付(式の版の引き当てに効く) |

**軸の意味からは決めない。** 「基準日」という名前だからといって日付として扱うことはなく、
`on` に渡していなければその軸は日付として効かない。逆に、どこにも書いていない軸は扇の通り数だけを
増やして値は動かさない。軸を宣言から外すときは、**その軸の既定を式表の同じ場所に literal で書き切る**
(= 選び方を書き切った状態)。

## 丸めの registry(この 4 つで全部)

`50銭以下切捨て` / `1円未満切捨て` / `円未満四捨五入` / `丸めない`。
名前が registry に無ければ止まる。丸めの関数は式の中から呼べない。

## いつも成り立つこと

扇の結果は 2 通りしかない。

- 宣言された軸の候補の組み合わせひとつひとつがちょうど 1 つの相異なる値に属し、各値の件数の合計が
  組み合わせ総数(= 軸ごとの候補数の積)に等しく、相異なる値は昇順で重複せず、どの値にもその値を出した
  組み合わせが verbatim で 1 つ以上付き、最小と最大は観測された値そのもので、印が付くのは宣言された
  既定の組み合わせを含む値だけ(多くて 1 つ)、判定部分のバイト列に時刻・ホスト名・絶対パスが 1 つも入らない
- または、値が 1 件も返らず理由コードが返る(扇を取りに行くと例外になる)

どちらの場合も、この部品は式表も軸表も 1 文字も書き換えない。

この 1 文を `tests/test_variant_fan_property.py` の `@given` テストが確かめている(軸表を毎回乱数で
作り直し、軸 1〜3 本をそれぞれ「式の中の名前になる軸」か「丸めの列になる軸」から引き、候補は 2〜3 件、
3 割くらいの確率で表のどこか 1 か所を崩す。乱数は固定で毎回同じ 80 通り)。**期待する値は部品の評価を
呼ばずにテストの側で別に計算している。** 同じファイルの 2 本目は件数の恒等式と束ね方を 300 通りで見ていて、
数として等しい `829` と `829.0` が別の値のまま残ることを確かめている。

## 出力 — 扇の通り数は単独では返らない

`counts()` が返すのは相異なる値の件数、組み合わせ総数、軸ごとの候補数、分母の内訳、
そして「扇は宣言された軸の範囲内」の 1 行だ。**通り数だけを返す呼び方も、option も無い。**

```
"相異なる値の件数": 13, "組み合わせ総数": 96,
"軸ごとの候補数": {"丸めの名前": 3, "丸めを掛ける段": 2, "基準日の取り方": 2, ...}
```

値の行は 4 欄だけで、この順に固定されている。

```
値 / 件数 / 印 / 出した組み合わせ
```

**絶対パス・読んだ時刻・ホスト名は判定部分に入れない**(別の欄「読んだ条件」に出し、sha256 の対象から
外す)。`verify` は 2 回数えて判定部分のバイト列の sha256 を突き合わせ、一致しなければ
**どの値のどの欄が違ったかを観測としてそのまま返す**(平均も多数決もしない)。

## 止まる理由コード(9 個)

```
出典の欄が空 / 候補が 1 件以下 / 軸名の重複 / 丸めの名前が空欄 or 未登録 /
式の id が式表に無い or 2 件以上 / 有効期間が基準日の候補を含まない / float の混入 /
組み合わせ数が上限超え / 2 回目の判定部分がバイト列として不一致
```

「軸名の重複」は、同じ軸名 + 同じ候補の行が 2 件以上あることを指す(1 行 1 候補なので、同じ軸名の行が
複数あるのは普通の形)。列そのものが足りない表、名前が軸・式の `id`・入力のどれにも無い式、依存が循環して
いる式は理由コードにせず、**「表として読めない」として終了コード 2 で返す**(表を書く側の話なので、
台帳の理由コードに混ぜない)。

## 使い方

```bash
python variant_fan.py init ひな型/           # 式表と軸表のひな型を書く
python variant_fan.py fan 式表.csv 軸表.csv --id 負担額 \
    --input 報酬月額=310000 --input 出勤日数=21 --on 基準日の取り方 --as-of 2026-05-01
python variant_fan.py verify 式表.csv 軸表.csv --id 負担額 ... --on 基準日の取り方 --as-of 2026-05-01
```

終了コードは、**扇が 1 通りに決まったときだけ 0**、2 通り以上あれば 3、表として読めなければ 2。
まとめて走らせる仕組みの中に置いて、3 で止められる。

関数としても同じ形で呼べる。

```python
from variant_fan import Spec, fan

f = fan(Spec.load("式表.csv", "軸表.csv"), "負担額",
        {"報酬月額": "310000", "出勤日数": "21"}, on="基準日の取り方", as_of="2026-05-01")
print({**f.counts(), **f.width()} if f.report.ok else [p.reason for p in f.report.pending])
```

`--id` / `--input` / `--on` / `--as-of` のほかに option は無く、そのこともテストで固定してある。

## 読み替えた範囲(「裏方の層に降りる」の型)

- 完成品 = 記事や画面に出る 1 つの数値
- 下位層 = その数値を決めている選択の層(軸 6 本)
- 各供給者の一次出典 = 公開済み記事と README に書いた宣言の verbatim(ファイル名 + 行番号)
- 押さえた量 = その軸が扇に足す候補数

層として見えるのは **宣言された軸までで、宣言されていない軸は数の外** になる。
どの軸がどれだけ値を動かしたかの寄与率は出さない。

## テストと fixture

```bash
python -m pytest tools/variant_fan -q      # 38 passed(2026-10-11 実走)
```

`fixtures/shikihyou.csv`(式表 4 行)と `fixtures/jikuhyou.csv`(軸表 13 行 = 6 軸)が repo に入っている。
**率も日数も金額も架空で、実在の料率・給付額・端数処理の規定値は 1 つも入れていない。** 軸表の出典 13 行の
うち 9 行はこの repo 内の実在の行(`tools/formula_table/README.md` の丸めの registry の 4 行と
`articles/07_asof_table.md` の基準日の宣言)を指し、テストがその行に宣言の語が在ることまで確かめている。
残り 4 行は合成のメモ(架空)。`fixtures/make_fixtures.py` を実行すると、軸を 1 本ずつ宣言に戻す 6 段の表と、
崩した表(止まる理由コードを出すため)が出る。

## できないこと

- 数えたことは「宣言された軸の組み合わせから出る値が何通りあるか」までで、**どの値が制度として
  正しいかは判定しない**
- **宣言されていない軸がほかに無いかは数えていない。** 軸表に無い軸を自然文から足す経路が無いので、
  扇はいつも「宣言された軸の範囲内」の下限になる
- **実務でどの選び方が多数派かも分からない。** 印が付くのは宣言された既定の組み合わせだけで、
  それが正しいとも推奨とも書かない
- どの軸がどれだけ効いたかは出さない。軸を 1 本ずつ宣言に戻して数え直すのは **表を作り分ける人の側**で、
  部品の中に軸ごとの分解は無い
- 相異なる値はバイト列の一致でだけ束ねる。数として等しくても表記が違えば別の値のまま残る
- 丸めの名前は 4 つしか持たない。別の丸め方が要るなら registry に足す(式の側には書けない)
- 負の金額の端数をどちらへ寄せるかは決めていない(測ったのは 0 以上の金額だけ)
- 状態を持つ計算(履歴を走査する判定)はできない。式は 1 回の評価で閉じる
- 上の件数は、合成した式表と軸表に対する測定で、他の人の手元で同じ数字になるとは限らない
