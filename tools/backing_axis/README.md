# backing_axis — 埋まっている欄でも裏付けは同じでないので、行を由来の軸で並べ直す

**欄が埋まっていることと、その値が原文で確かめられたことは別。引けば値は返るし、空欄でも
ないので誰も止まらない。だから普段「制度の領域」で並べている一覧を、「その欄の値はどこから
来たか」という軸に差し替えて数え直す。**

[blank_kind](../blank_kind) の回は空欄の意味を列ごとに分ける道具だった。あちらは**値が入って
いないマス**を見るので、埋まっている欄には何も言わない。ここは逆で、**埋まっている欄だけ**を
見る。[check_census](../check_census) は検証が走ったかを台帳で数える道具で、行ごとの裏付けの型は
見ない。[source_pin](../source_pin) は取りに行く前の地図で、取った後の行には付かない。
[cover_stock](../cover_stock) は年の在庫で、在る年の行がどう裏付けられたかは数えない。

この部品は、行の台帳・由来の登録表・問いの一覧の 3 枚から、行 1 件ごとに 7 値(**機械の再計算 /
2 経路の一致 / 目視 / 写した仮置き / 取れない** の 5 値 + 別枠 **宣言が無い / 旧軸が無い**)を
付ける。新軸で並べ直した一覧、旧軸 × 新軸 の対応表、写した仮置きだけの一覧も返す。
**値を計算しない。行を引かない。原文を取りに行かない。数えるだけだ。**

持たせていないものが規律になっている。

- **同じ軸で並べ直す指定を受け付けない**(問いの新軸が旧軸の欄名と同じなら、その問いは
  止まる。同じ軸で再掲する経路が無い)
- **旧軸を指さない問いは判定しない**(別枠「旧軸が無い」に出す。差し替え前の軸が無いまま
  並べ直す経路が無い)
- **由来の記号を推測しない**(登録表に無い記号は別枠「宣言が無い」に出す。既定の記号を当てる
  経路が無い。旧軸の欄が空の行も別枠に出し、領域を推測して埋めない)
- **宣言と証跡の型が合わない行は止まる**(件数を要求する由来で件数の欄が空、件数の欄に整数で
  ない文字、写した仮置きなのに写し元の欄名が空、写し元がその行自身の欄名、取れないのに理由が空)
- **写した仮置きを実値と同じ列に数えない**(写し元の欄名が在る行が、確かめた件数の 3 列に入る
  経路が無い。仮置きだけの一覧も別に返す)
- **由来に点数・順位・良し悪しを付けない**(5 値の件数と分母の内訳だけを返す。確度のスコアを
  出す経路が無い)
- **件数を割合にしない**(何割が確かめ済かを返す呼び方も option も無い)
- **出典の欄が空の行は使わずに止まる**
- **値を計算しない・行を引かない・原文を取りに行かない**(式は [formula_table](../formula_table)、
  引けるかは [cover_stock](../cover_stock)、返ってから残る一手は [handoff_edge](../handoff_edge)、
  呼ぶ前の入力は [input_chain](../input_chain) の仕事で、役割が重ならない)
- **この部品自身の「読めない」を、測っている相手の「宣言が無い」と同じ欄に入れない**(台帳か
  登録表が 1 行でも壊れていたら 1 行も数えず、理由コードだけを返す。7 値は全て 0 になる)
- **入力表を書き換えず、行も記号も生成しない**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない。行順にも依らない)
- **数は整数だけ**(float を使う経路が無い)

## 入力 — 行の台帳と由来の登録表と問いの一覧

行の台帳は 7 列。**1 つの欄の値の裏付けが 1 行**で、その値がどこから来たのかをここだけに書く。

| 列 | 意味 |
|---|---|
| `row_id` | 行 id(空欄と、区切り文字を含む id と、同じ id が 2 行あるのは「表として読めない」) |
| `rule_id` | その行がどの rule のものか(同上) |
| `old_axis` | 旧軸の値(= これまで並べていた軸)。空欄は別枠「旧軸が無い」 |
| `field` | 値を持つ欄名(空欄と区切り文字入りは「表として読めない」) |
| `origin` | 由来の記号。登録表に無い記号は別枠「宣言が無い」 |
| `evidence` | 証跡。由来が要求する型で書く(件数 / 写し元の欄名 / 取れない理由) |
| `source` | 出典(空欄は**止まる**) |

同じ `rule_id` と `field` の組が 2 行あると**止まる**(同じ欄の裏付けを 2 通り宣言している)。

由来の登録表は 3 列。**1 つの記号が 1 行**。

| 列 | 意味 |
|---|---|
| `origin` | 由来の記号(空欄・区切り文字入り・重複は「表として読めない」) |
| `meaning` | 意味(空欄は**止まる**) |
| `evidence_type` | その記号が要求する証跡の型。登録の 5 種(空欄も登録外も**止まる**) |

証跡の型は 5 種しかない(`機械の再計算の件数` / `2 経路の一致件数` / `目視の件数` /
`写した元の欄名` / `取れない理由`)。**記号は何個でも登録できるが、型は 5 種のまま**なので、
違う記号が同じ型を使うことはある(例: 「原文が取れていない」と「照合する相手が無い」は
どちらも理由を書く)。

問いの一覧は 4 列。**1 つの並べ直しが 1 行**。

| 列 | 意味 |
|---|---|
| `old_list_id` | 旧軸の一覧 id(= 旧軸の値)。空欄と、台帳に無い値は別枠「旧軸が無い」 |
| `new_axis` | 新軸の定義(欄名)。登録の 2 つ(`旧軸` / `由来`)。`旧軸` ならその問いは**止まる** |
| `source` | 出典(空欄は**止まる**) |
| `swap` | 入れ替え方(`逆順` / `両端入れ替え` / `1 つずらす`)。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 分け方 — 行 1 件に付く 7 値

| 行の形 | どうするか | 7 値 |
|---|---|---|
| 旧軸の欄が空 | 並べ直せないので別枠へ | 旧軸が無い |
| 由来の記号が登録表に無い(空欄も) | 推測しないので別枠へ | 宣言が無い |
| 記号が登録されている | その記号が要求する証跡の型の列に入れる | 機械の再計算 / 2 経路の一致 / 目視 / 写した仮置き / 取れない |

旧軸の欄が空で、かつ記号も登録表に無い行は、**旧軸が無い**に入る(差し替え前の軸が無い行は、
由来を書いても対応表の中に置き場が無い)。

問いは 3 つの状態しかない。**判定した**(旧軸を指し、新軸が由来)/ **旧軸が無い**(別枠)/
**止まった**(新軸が旧軸と同じ)。問いは 1 件ずつ判定するので、1 件が止まってもほかの問いの
一覧は動かない。**台帳か登録表の側が壊れていたときだけ、1 行も数えない。**

## 件数の検算 — 3 通りの数え方が合う

- **7 値の件数の合計 = 行数**
- **記号別の件数の合計 + 別枠 2 種 = 行数**
- **旧軸 × 新軸 の対応表のセルの合計 = 行数**(行 1 件はちょうど 1 つのセルに入る)

3 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
分母は 行数 / 問いの数 / 別枠の数 の 3 つを必ず付ける。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- 行 1 件ごとに 7 値のどれか 1 つが付き、**7 値の合計が行数**に等しく、**記号別の合計 + 別枠が
  行数**に等しく、**旧軸 × 新軸 の対応表のセルの合計も行数**に等しく、**写し元の欄名が在る行は
  確かめた 3 列に 1 件も入らず**、**登録表に無い記号は別枠「宣言が無い」に出て**(既定の記号を
  当てない)、**旧軸を指さない問いは別枠に出て**、**新軸が旧軸と同じ問いはその問いだけが止まり**、
  判定部分に時刻・ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても同じバイト列**に
  なる
- または、1 行も数えずに理由コードが返る(数えた行や指紋を取りに行くと例外になる)

どちらの場合も、この部品は行の台帳も由来の登録表も問いの一覧も 1 文字も書き換えない。

この 1 文を `tests/test_backing_axis_property.py` の `@given` テストが確かめている(記号を
1〜3 つ登録して証跡の型を 5 種から引き、行を 1〜4 件、問いを 1〜2 件引く。行の由来は登録した
記号と登録表に無い記号から引き、旧軸は 2 つの値と空欄から引くので別枠 2 種も混ざる。3 割くらい
の確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。**7 値の分け方はテストの側で別に
実装している**(部品の `judge` / `seven` を呼ばない)。同じファイルの 2 本目は「登録表に無い
記号に既定を当てない」ことを見ている(組み合わせは 30 通りしかないので、上限 300 の下で全部を
尽くす)。

## 出力 — 確かめ済の割合は返らない

`check` と `axis` が返るのは、3 枚それぞれの行数、3 つの分母、7 値の件数、記号別と旧軸別の件数、
問いの状態、理由別の止まった件数、分母の内訳と検算、それに 7 つの固定行だ。**割合だけを返す
呼び方も、option も無い。**

```
"分母(行数)": 22,
"分母(問いの数)": 7,
"分母(別枠の数)": 5,
"7 値": {"機械の再計算": 3, "2 経路の一致": 4, "目視": 1, "写した仮置き": 5,
         "取れない": 6, "宣言が無い": 2, "旧軸が無い": 1},
"記号別の件数": {"Y1": 3, "Y2": 4, "Y3": 1, "Y4": 5, "Y5": 2, "Y6": 4},
"旧軸別の件数": {"D1": 4, "D2": 3, "D3": 4, "D4": 3, "D5": 3, "D6": 4, "旧軸が無い": 1},
"問いの状態": {"判定した": 5, "旧軸が無い": 2, "止まった": 0},
"件数の合計の検算": "7 値の合計 22 / 行数 22(記号別の合計 19 + 別枠 3 も同じ、…)",
"由来に点数を付けない": "…",
"件数を割合にしない": "…",
"由来の記号を推測しない": "…",
"写した仮置きを実値と同じ列に数えない": "…",
"同じ軸で並べ直さない": "…",
"値を計算しない・行を引かない・原文を取りに行かない": "…",
"入力を書き換えない": "…"
```

`axis` にすると、問いごとの結果に加えて、**新軸で並べ直した一覧**(7 値ごとに行 id / 欄名 /
証跡 / 出典)、**旧軸 × 新軸 の対応表**、**写した仮置きだけの一覧**(欄名と写し元の欄名)が出る。
**名前は宣言に書かれたものがそのまま出る**(道具が書き足すことはしない)。写し元の欄の由来を
さらに辿ることもしない(辿るのは読む人の仕事で、一覧には写し元の欄名だけを残す)。

## 止まる理由コード(14 個)

台帳と登録表の側。1 行も数えずに止まるものが 10 個。

`出典の欄が空` / `件数の欄が空` / `件数の欄に整数でない文字がある` / `写し元の欄名が空` /
`写し元の欄名がその行の欄名と同じ` / `取れない理由が空` /
`同じ rule id と欄名の組が 2 行ある` / `証跡の型が空` / `登録されていない証跡の型` /
`意味の欄が空`

問い 1 件の側。その問いだけ止まるものが 1 個。

`旧軸と同じ軸で並べ直す指定`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄や区切り文字入り・同じ行 id が 2 行・同じ記号が 2 行・
新軸の欄名が空欄や登録外・同じ問いが 2 行・登録外の入れ替え方、は**「表として読めない」**
(終了コード 2)で、理由コードには混ぜない。

## 使い方

```
python backing_axis.py init ひな型/
python backing_axis.py check  行の台帳.csv 由来の登録表.csv 問いの一覧.csv
python backing_axis.py axis   行の台帳.csv 由来の登録表.csv 問いの一覧.csv
python backing_axis.py verify 行の台帳.csv 由来の登録表.csv 問いの一覧.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、宣言された入れ替え方で 3 枚の
行順を入れ替えても同じ出力になるか、件数の合計が 3 通りとも合うか、そして 2 つの写しだ。
**行 1 件の由来を `写した仮置き` から `2 経路の一致` に替えた写し**では、仮置きの一覧からその
欄名が消えて 2 経路の一致が 1 増え、写した仮置きが 1 減ること、そして**証跡の欄を直さないまま
なら代わりに止まる**ことを見る。**問い 1 件の新軸を旧軸に替えた写し**では、その問いだけが
「同じ軸」で止まり、ほかの問いの一覧と行の 7 値が 1 件も動かないことを見る。写しはメモリの
中だけで、入力の表には 1 文字も書かない。

終了コードは、別枠と止まった問いが 0 件のときだけ 0、在れば 3、表として読めなければ 2。
**裏付けの良し悪しはこの終了コードにも出力にも出さない。**

関数でも呼べる。

```python
import backing_axis as H

t = H.backing_axis(H.Ledger.load("行の台帳.csv"), H.Registry.load("由来の登録表.csv"),
                   H.Questions.load("問いの一覧.csv"))
if t.report.ok:
    print(t.counts()["7 値"], t.placeholders())
```

## テストと fixture

```
python -m pytest tools/backing_axis -q
python fixtures/make_fixtures.py     # 合成の 3 枚と、崩した表 32 枚を書き直す
```

`fixtures/` に入っているのは合成した 3 枚(行 22 / 記号 6 / 問い 7)と、理由コードを出すために
1 か所だけ崩した表 32 枚だ。**実在の料率・金額・取引先名は 1 つも入っていない。** 行 id も
rule id も欄名も由来の記号も架空で、値も日付も 1 つも入っていない。

## できないこと

- 判定したことは「宣言と証跡の型が合うか」までで、**その証跡が本当かどうかは判定しない**。
  件数を 1 つ書けばそう数えるので、件数そのものの裏取りは別の仕事になる
- **由来に点数も順位も付けない。** どの由来が良いかは言わない(件数と分母だけが残る)
- **何割が確かめ済かを出さない。** 言えるのは宣言に書かれた範囲までで、割合を返す経路が無い
- **写し元の欄をさらに辿らない。** 一覧に写し元の欄名は残るが、その欄の由来を引き直すのは
  読む人の仕事になる
- **空欄かどうかは見ない**(空欄の意味を列ごとに分けるのは [blank_kind](../blank_kind))
- **値も日付も持たない。** 実在の料率や金額がいくらかも、その欄がいつの日付かも言わない
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
