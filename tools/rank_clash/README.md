# rank_clash — 本則と経過措置が同時に当たるので、どちらが勝つかを順位の欄に書いてから引く

解説記事: [本則と経過措置が同時に当たるので、どちらが勝つかを順位の欄に書いてから引く](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_18.html)(2026-10-19 公開)

**絞り終わって行が 2 本残ることは実際に起きる(本則と経過措置、地域別と産業別、公的な行と
事業所ごとの行)。そのとき勝つ行は、より具体的に書かれている方でも、後から書かれた方でも、
値の大きい方でもなく、順位の欄に宣言された方だけである。欄が無ければ黙ってどちらかが勝つ。**

[asof_table](../asof_table) の回で、引く手続きの順番までは宣言した。日付で絞り、期間で絞り、
対象で絞り、残った中でいちばん高い順位の 1 行を返す、という順番だ。けれど **最後の「いちばん
高い 1 行を返す」が宣言から決まるかを確かめる段** は、どの回でも手つかずだった。同じ記事の中
で「同じ順位の行が 2 本以上当たったとき、どちらを採るかは表の外の判断になる」と、出口が開いて
いることを自分で書いている。

この部品は、行の表・裁定の宣言・対象の表の 3 枚から、(rule × 対象)の組 1 つごとに 4 値
(**1 本に決まった / 当たらない / 決まらない / 止まった**)を付ける。決まらないものは理由別
(**同順位で 2 本以上 / 順位の欄が空 / 宣言に無い裁定が要る**)に分けて数え、分母(rule 数 ×
対象数)と内訳を併記して返す。**引かない。決まるかを出すだけだ。**

持たせていないものが規律になっている。

- **具体さで勝たせない**(未指定次元が少ない行を勝たせる経路を持たない。宣言された記号で
  書かれた行と、具体的に書かれた行は、順位が同じなら同じ強さのまま並ぶ。この部品の骨を
  そのまま入力の形にしたところ)
- **行の並び順・後から書かれた順で勝たせない**(先頭・末尾・新しい方を採る引数が無い)
- **値の大小で勝たせない**(高い方・低い方で勝たせる経路が無い。行の表にそもそも値の列が
  無いので、値で決まる裁定は「決まらない」に落ちる)
- **順位の欄が空なら補わない**(空欄を 0 = 本則として扱わない。[blank_kind](../blank_kind) の
  「空欄の意味を決めない」と同じ向き)
- **宣言に無い順位の値は使わずに止まる**(宣言された値の外が来たら、順位の意味を推測しない)
- **同順位で 2 本以上なら「決まらない」に落ちる**(どちらでもよいにしない。先に出てきた方も
  採らない)
- **未指定の記号を推測しない**(宣言された記号だけ。空欄と「未指定」の宣言を区別する)
- **次元の優先順位を自分で決めない**(ある次元が別の次元より強い、を内蔵しない。足すべき
  優先順位も提案しない)
- **日付で絞らない・期間も切らない・帯にも当てない・空欄の意味も読まない・日付の種別も
  決めない**(版を選ぶのは [asof_table](../asof_table)、期間は [span_split](../span_split)、
  帯は [band_edge](../band_edge)、空欄は [blank_kind](../blank_kind)、日付の種別は
  [basis_map](../basis_map) の仕事で、役割が重ならない。この部品は絞り終わった後の 1 段だけ
  を持つ)
- **件数は理由別に、分母(rule 数 × 対象数)と内訳つきで出す**(率を単独で返さない。
  [check_census](../check_census) 以降と同じ)
- **4 つを混ぜない**([answer_check](../answer_check) / [span_split](../span_split) /
  [band_edge](../band_edge) / [blank_kind](../blank_kind) / [recalc_scope](../recalc_scope) /
  [basis_map](../basis_map) と同じ)
- **入力表を書き換えず、行も順位も生成しない**([intake_triage](../intake_triage) 以降と同じ)
- **出典の欄が空の行は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)
- **float を使わない**(件数と順位は整数。ほかは文字列のまま持つ)

## 入力 — 行の表と裁定の宣言と対象の表の 3 つ

行の表は 5 列。絞り終わって残りうる行 1 本が 1 行になる。

| 列 | 意味 |
|---|---|
| `row_id` | 行 id(空欄は「表として読めない」。2 行あると**止まる**) |
| `rule_id` | その行が属する rule id。**宣言表に無い rule は止まる** |
| `seg` | 各次元の値。`名前=値` を縦棒で区切る。**未指定は宣言された記号を書く** |
| `priority` | 順位。**空欄のまま持つ**(0 と読み替えない)。整数でなければ読めない表 |
| `source` | その行の出典。**空欄は止まる** |

```csv
row_id,rule_id,seg,priority,source
G01,R01,次元A=*|次元B=*,0,articles/07_asof_table.md L73
G02,R01,次元A=a1|次元B=*,10,厚生労働省 / 私の棚卸し記録(非公開)
G06,R03,次元A=*|次元B=b1,,私の棚卸し記録(非公開)
```

裁定の宣言は 6 列。**1 rule が 1 行**で、「2 本以上当たったときに何で絞るか」をここだけに書く。

| 列 | 意味 |
|---|---|
| `rule_id` | rule id(空欄は「表として読めない」。2 行あると**止まる**) |
| `kind` | 使う裁定の種類。登録の 2 種(`宣言された順位` / `宣言された順位では決まらない`) |
| `priorities` | 許す順位の値と意味。`値=意味` を縦棒で区切る(例 `0=本則|10=経過措置`) |
| `wildcard` | 未指定次元の記号。**この記号だけが「未指定」になる** |
| `tie` | 同順位のときの扱い。登録の 1 種(`例外にする`) |
| `source` | その行の出典。**空欄は止まる** |

対象の表は 4 列。1 対象が 1 行で、各次元に具体的な値だけを書く。

| 列 | 意味 |
|---|---|
| `target_id` | 対象 id(空欄も、同じ id が 2 行あるのも「表として読めない」) |
| `seg` | 各次元の値。**未指定に見える記号は書けない**(対象は具体でしか書けない) |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 当たり方 — 宣言された記号だけが「どの値でもよい」になる

行の `seg` のある次元が宣言された記号と一致していれば、その次元は見ない。一致していなければ、
対象の同じ次元の値と文字列として突き合わせる。**似ている / 片方が片方を含む / 空欄、のどれも
「どの値でもよい」の理由にしない。**

| 行の `seg` | 対象 `次元A=a1 次元B=b1` | どうなるか |
|---|---|---|
| `次元A=*|次元B=*` | 両方とも宣言された記号 | 当たる |
| `次元A=a1|次元B=*` | 次元A が一致、次元B は記号 | 当たる |
| `次元A=a2|次元B=*` | 次元A が不一致 | 当たらない |
| `次元A=-|次元B=*` | 記号が宣言(`*`)と違う | **止まる**(宣言外の記号) |

3 枚で使っている次元の名前が揃っていないときは、突き合わせる土台が無いので「表として読めない」
で返す。

## 絞り方 — 見るのは順位の欄だけ

当たった本数で分かれる。**0 本なら当たらない、1 本ならそのまま決まった** で、裁定は要らない
(1 本しか当たっていない組は、順位の欄が空でも決まる)。2 本以上のときだけ裁定に入る。

| 当たった本数 | 宣言 | どうなるか |
|---|---|---|
| 2 本以上 | `宣言された順位では決まらない` | **決まらない**(順位を比べない) |
| 2 本以上 | `宣言された順位`、空欄の順位が混じる | **決まらない**(空欄を 0 と読まない) |
| 2 本以上 | `宣言された順位`、いちばん高い順位が 1 本 | その 1 本が決まる |
| 2 本以上 | `宣言された順位`、いちばん高い順位が 2 本以上 | **決まらない**(同順位) |

判定の順は **宣言の種類 → 順位の欄が空か → いちばん高い順位が 1 本か** だ。だから行が具体的に
書かれていても、順位が同じなら勝たない。**具体さは強さではない。**

## 件数の検算 — 分母は rule 数 × 対象数

- **4 値の件数の合計 = rule 数 × 対象数**
- **決まらない理由別の件数の合計 = 決まらないの件数**

2 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
同じ rule に裁定の宣言が 2 行あると、件数を rule 1 件ずつに割り当てられないので、そこでも止まる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- (rule × 対象)の組ごとに 4 値が 1 つだけ付き、**4 値の合計が rule 数 × 対象数** に等しく、
  **決まらない理由別の合計が決まらないの件数** に等しく、`1 本に決まった` 組の勝った行 id は
  **行の表にそのまま在る id**(ほかの 3 値には行 id も順位も付かない)で、判定部分に時刻・
  ホスト名・絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても同じバイト列** になる
- または、1 組も読まずに理由コードが返る(読んだ組や指紋を取りに行くと例外になる)

どちらの場合も、この部品は行の表も裁定の宣言も対象の表も 1 文字も書き換えない。

この 1 文を `tests/test_rank_clash_property.py` の `@given` テストが確かめている(rule を
1〜3 本作って裁定の種類を振り、行を rule ごとに 1〜3 本、各次元の値を宣言された記号と具体的な
値から引き、順位を 0 / 10 / 20 / 空欄から引く。対象は 1〜3 件。3 割くらいの確率でどこか 1 か所
を崩す。乱数は固定で毎回同じ 200 通り)。**4 値は部品の判定を呼ばず、3 枚の表の行からテスト側
の別実装で組み立てている。** 同じファイルの 2 本目は 300 通りで、「具体的に書かれた行は、順位
が同じなら勝たない」ことを見ている。

## 出力 — 決まった率は単独では返らない

`check` と `resolve` が返るのは、3 枚それぞれの行数、分母(rule 数 × 対象数)、4 値の件数、
決まらない理由別の件数、それに分母の内訳と検算と 4 つの固定行だ。**率だけを返す呼び方も、
option も無い。**

```
"分母(rule 数 × 対象数)": 20,
"4 値": {"1 本に決まった": 11, "当たらない": 3, "決まらない": 6, "止まった": 0},
"決まらない理由別": {"同順位で 2 本以上": 2, "順位の欄が空": 2, "宣言に無い裁定が要る": 2}
```

固定行は 4 つとも消せない。「具体さで勝たせない」「並び順で勝たせない」「値の大小で勝たせない」
「順位の欄が空なら補わない」だ。`resolve` はさらに組ごとの内訳(結果・決まらない理由・勝った
行 id・その行の順位・当たった本数)と、`1 本に決まった` 組だけを並べた一覧を出す。一覧の並びは
rule id と対象 id の順で、**どれから手を付けるかの順位は付かない。**

`verify` は 3 つ見る。2 回読んで判定部分のバイト列の sha256 を突き合わせること、**宣言された
入れ替え方で 3 枚の行順を入れ替えても同じ出力になるか**、そして **4 値の件数の合計が rule 数 ×
対象数に合うか** だ。合わなければ観測としてそのまま返す。

## 止まる理由コード(9 個)

```
出典の欄が空 / 行 id の重複 / 宣言に無い順位の値 / 未指定の記号が宣言外 /
rule が宣言表に無い / 同じ rule に裁定の宣言が 2 行 / 件数の合計が合わない /
2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる
```

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。裁定の種類・
同順位のときの扱い・入れ替え方が登録の外の語だったとき、列そのものが足りないとき、行が 0 行の
とき、行 id・rule id・次元の欄・対象 id が空欄のとき、次元を `名前=値` で書いていないとき、
同じ次元の名前を 2 つ書いたとき、順位が整数でないとき、許す順位の書き方が壊れているとき、
対象の表に未指定に見える記号を書いたとき、同じ対象 id を 2 行書いたとき、3 枚で使っている次元
の名前が揃っていないとき、そして入れ替え方の宣言が 2 通りあるとき。

## 使い方

```bash
python rank_clash.py init ひな型/                                 # 3 枚の表のひな型を書く
python rank_clash.py check   行の表.csv 裁定の宣言.csv 対象の表.csv   # 件数と分母の内訳
python rank_clash.py resolve 行の表.csv 裁定の宣言.csv 対象の表.csv   # 上 + 組ごとと指紋
python rank_clash.py verify  行の表.csv 裁定の宣言.csv 対象の表.csv   # 2 回 + 行順 + 検算
```

終了コードは、**決まらない組が 1 つも無いときだけ 0**(当たらないが何件あっても 0)、決まらない
組があるときや止まったときは 3、表として読めなければ 2。まとめて走らせる仕組みの中に置いて、
3 で止められる。

関数としても同じ形で呼べる。

```python
from rank_clash import Sheet, Declared, Targets, rank_clash

t = rank_clash(Sheet.load("行の表.csv"), Declared.load("裁定の宣言.csv"),
               Targets.load("対象の表.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `resolve` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。
そのこともテストで固定してある。

## テストと fixture

```bash
python -m pytest tools/rank_clash -q      # 24 passed(2026-10-19 実走)
```

`fixtures/` に行の表 3 枚・裁定の宣言 2 枚・対象の表 1 枚と、崩した表 36 枚が入っている。
**値(料率・金額)は 1 つも入っていない**(この部品は値の列を持たない)。行 id・rule id・
対象 id・次元の名前と値は全て架空で、実在の料率や金額や取引先名は 1 つも無い。写したのは形
だけ、つまり「宣言された記号で書かれた行と具体的に書かれた行が同じ対象に当たる」「同じ順位の
行が 2 本当たる」「順位の欄が空のまま 2 本当たる」「順位では表せない裁定が要ると宣言に書いて
ある」という 4 つで、これは私の棚卸し記録に残っている形だ。出典のうち 5 件はこの repo 内の実在
の行(`articles/07_asof_table.md` L73 / L108、`articles/23_band_edge.md` L13 / L14、
`articles/26_basis_map.md` L15)を指し、テストがその行を開いて語が在ることまで確かめている。
`fixtures/make_fixtures.py` を実行すると、崩した表ごと書き直す。

## できないこと

- 判定したことは「残った行が宣言から 1 本に決まるか」までで、**どの行が制度として正しいかは
  判定しない**
- **値がいくらかも言わない。** 行の表に値の列が無く、返るのは勝った行の id と順位だけだ
- **順位の付け方が妥当かも判定しない。** 宣言された値をそのまま使うだけで、0 と 10 のどちらを
  本則にすべきかは人の側に返る
- **足すべき順位も提案しない。** 空欄の順位も宣言外の記号も件数として残るだけで、埋め方を
  出す経路が無い
- **引かない。** 行を実際に引く経路も、他の部品を呼ぶ経路も持たない
- **絞る段は持たない。** 日付でも期間でも帯でも絞らないので、ここに渡すのは絞り終わった行だ
- 次元の値は文字列として突き合わせる。全角と半角、表記の揺れは別の値になる
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
