# fill_owner — 表の外に置いた項目を「誰が値を決めるか」「どの層の行になるか」の軸で並べ直す

「表に入らない」は 1 つの状態ではない。外し方が 7 通りあって、外した先で誰が値を決めるか・どの層の行になるかが
それぞれ違う。1 つの「対象外」に潰すと、実は表に入るもの(期限)と、同じ行形式の第 2 層で持つもの(主体ごとに
違う値)と、人が起票して渡すもの(事実認定)が同じ袋に入り、問いが来たときどこへ返すかが決まらない。

この部品は、**宣言された印の組み合わせを置き場の登録表に当てて並べ直すだけ**をやる。
分類の規則を自分で持たない(印から置き場を導く if 文が無い)。自然文を読まない。期限を計算しない。
判断を起票しない。履歴を舐めない。値を引かない。順位も良し悪しも付けない。時計を読まない。
stdlib のみ(csv / hashlib / json / argparse)、依存なし。

## 入力の 3 枚

| 表 | 欄 |
|---|---|
| 問いの台帳 | 問い id / 求める値の名前 / 旧軸の値 / 旧軸の一覧 id / 外し方の記号 / 印 7 つ / 要求する欄の値 / 出典 |
| 置き場の登録表 | 印の組み合わせ(7 つを `|` で並べる)/ 置き場の記号 / 外し方の記号 / 誰が決めるか / 要求する欄の名前 / 出典 |
| 新軸の定義 | 新軸の欄名 / 旧軸の欄名 / 出典(1 行だけ) |

印は 7 つで、値は `はい` / `いいえ` / `宣言なし` の 3 つだけ。

| 印の欄 | 読み |
|---|---|
| `印_行政一意` | 行政が誰でも同じ答えを出すか |
| `印_主体内一意` | 主体内では一意か |
| `印_履歴依存` | 履歴を舐めないと決まらないか |
| `印_人が読む` | 人が読んで決めるか |
| `印_起算日加算` | 起算日 + N 日で書けるか |
| `印_施行日確定` | 施行日が決まっているか |
| `印_法が決める` | 法が値を決めているか |

旧軸の一覧 id は `一覧 id#行#一覧に書かれた旧軸の値` の 3 つ組で書く(一覧の側から写す)。
3 つ組になっていない問いは判定しない。写した値が台帳の旧軸の値と違う問いも判定しない。

## 出力の 8 値と別枠

| 置き場 | 意味 |
|---|---|
| ① | 公的層の行で埋まる |
| ② | 起算日 + N 日の式として公的層の行に入る(準整理可) |
| ③ | 第 2 層(主体ごと)の行で埋まる |
| ④ | case の属性として人が起票してから渡す |
| ⑤ | 数式側の状態機械へ閾値だけ供給する |
| ⑥ | 解釈メモ層から参照し、特例の順位の行として計算に入る場合だけ表に入る |
| ⑦ | 施行日が決まるまで登録だけして計算に使わない行 |
| ⑧ | 置き場なし |

止まる理由コードは 12 個。表の側 4 つ(`表が読めない` / `軸が同じ` / `登録表の鍵が壊れている` /
`登録表の欄が壊れている`)はどれか 1 つでも起きると **1 件も判定しない**(8 値は全て 0)。
問いごとの別枠 8 つは、手前が勝つ順で `問い id の重複` → `出典が空` → `一覧 id が無い` →
`一覧の記載と違う` → `宣言なしを含む` → `組み合わせが登録外` → `外し方の記号が登録外` →
`要求する欄が空`。**この順そのものが仕様**で、同じ問いに 2 つの理由は付かない。

## いつも成り立つこと

問いごとに付く答えは 1 つだけで、置き場 8 値か別枠の理由のどちらか一方に入る。
**置き場に入った問いの置き場は、必ず登録表のその行が指す先と同じ**(道具が印から導いた先ではない)。
8 値と別枠の件数の合計、および旧軸の値ごとの内訳の合計は、どちらも問いの件数に等しい。
どの場合も入力の表は 1 文字も書き換わらない。

この 1 文は `tests/test_fill_owner_property.py` が性質テスト(hypothesis)で確かめている。
登録表の「印の組み合わせ → 置き場の記号」の対応を乱数で割り当てたうえで、置き場の引き当てを
テストの中で別に書いて突き合わせる(= 道具が印から置き場を導く規則を内側に持っていれば、
乱数の対応と食い違って落ちる)。問いは半分の確率でどこか 1 か所を崩す。乱数は固定で、毎回同じ
300 通り + 200 通りになる。テストの実行には pytest と hypothesis が要る(道具そのものは標準
ライブラリだけで動く)。

## 使い方

```
python fill_owner.py init   <置き場ディレクトリ>                       # 合成のひな型 3 枚
python fill_owner.py check  <問いの台帳> <置き場の登録表> <新軸の定義>   # 件数の内訳
python fill_owner.py rows   <問いの台帳> <置き場の登録表> <新軸の定義>   # 並べ直した一覧
python fill_owner.py verify <問いの台帳> <置き場の登録表> <新軸の定義>   # 決定論かどうか 5 つ
```

終了コードは 0 = 判定できた / 3 = 表の側が壊れていて 1 件も判定しない / 2 = 引数・読み書きの誤り。

```python
from fill_owner import read_table, load_okiba, load_jiku, judge, sort_rows, verify
from fill_owner import TOI_COLS, OKIBA_COLS, JIKU_COLS

toi = read_table("toi_daichou.csv", TOI_COLS)
okiba = load_okiba(read_table("okiba_touroku.csv", OKIBA_COLS))
jiku = load_jiku(read_table("jiku_teigi.csv", JIKU_COLS))
got = judge(toi, okiba, jiku)         # 8 値 / 別枠 / 旧軸の値ごとの内訳 / sha256
rows = sort_rows(toi, okiba, jiku)    # 問い 1 件 1 行の並べ直した一覧
```

## verify が見る 5 つ

| # | 見るもの |
|---|---|
| 1 | 2 回読んで判定部分の sha256 が同じか |
| 2 | 3 枚の行順を入れ替えても同じ出力になるか(順は問い id と登録表の鍵だけで決まる) |
| 3 | 8 値 + 別枠の合計 = 問いの件数、旧軸の値ごとの内訳の合計 = 問いの件数 |
| 4 | `印_行政一意` を 1 件だけ `はい` → `いいえ` に替えると ① から登録表の組み合わせ行が指す先へ移り、**登録表のその 1 行だけを差し替えると同じ印で別の置き場になる**(= 移り先を道具が決めていない)。動くのはその問いだけ |
| 5 | `印_施行日確定` を `いいえ` → `はい` に替えると、その問いだけが ⑦ から ① へ移る |

4 と 5 の写しはメモリの中だけで、入力の表には 1 文字も書かない。

## テストと fixture

```
python -m pytest tools/fill_owner -q        # 32 passed
python fixtures/make_fixtures.py fixtures   # 合成 fixture を作り直す
```

fixture は全て合成で、求める値の名前は架空(甲乙丙…)。実在の料率も金額も人名も 1 つも入っていない。
写したのは形だけで、外し方が 7 通りあること、置き場が 8 値に分かれること、1 つの旧軸の列が複数の
置き場に割れること、原文の記号と登録表の記号が食い違う行が在ることの 4 つ。
記事に載せた数値は `tests/test_fill_owner.py` が `assert` で固定している。

## できないこと

- **分類の規則を判定しない。** 印から置き場を導く規則は登録表の側にあり、その規則が正しいかは人が決める
- **自然文を読まない。** 求める値の名前や例示の文から印を推測する経路が無い(事実認定を道具がやらない形)
- **期限を計算しない。** ② は置き場を仕分けるだけで、起算日に N 日を足す経路も暦も休日表も持たない
- **判断を起票しない。** ④ は受け取る属性の名前を返すだけで、値を作る経路も既定値も無い
- **履歴を舐めない。** ⑤ は供給する閾値の名前を返すだけで、通算も待期も実装しない
- **施行日が決まっている行は扱わない。** ⑦ は決まっていない行だけで、分かれ目は印 1 つ
- **順位・良し悪し・難易度・優先度を付けない。** 「自動化しやすい」「あきらめる」のような語彙を持たない
- **原文の記号と登録表の記号が違っても、どちらが正しいとも言わない。** 両方を並べて件数を数えるだけ
- **一覧の側を読まない。** 旧軸の一覧 id に写した値と台帳の値が合うかまでで、一覧が本当にそう書いて
  あるかは確かめない(写し間違いまでしか拾えない)
- **値を引かない・計算しない。** 値の欄そのものを持たない
- 上の件数は合成した 3 枚に対する測定で、他の人の環境で同じ数字になるとは限らない
