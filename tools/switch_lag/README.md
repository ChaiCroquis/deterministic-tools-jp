# switch_lag — 回が替わる窓と、登録した日ごとの「新しい回の行に当たる地域 / 前の回の行に当たる地域」を並べる

地域(セグメント)ごとに開始日が違う数表は、年度の回が替わるとき、最初の地域が新しい行へ移った日から最後の地域が移った日までの窓を持つ。
窓の中の日に引くと、同じ日・同じ rule でも、新しい回の行に当たる地域と前の回の行に当たる地域が混ざる。
この部品は、**人が書いた 3 つの表**を読み、回ごとの窓と、登録した日ごとのセグメントの区分を並べたところで止まる。
**値を計算しない。開始日を推さない。今日の日付を読まない。遅い・早いを返さない。** 標準ライブラリのみ、依存なし。

## 入力(3 表、UTF-8 の CSV)

| 表 | 列 |
|---|---|
| 行の表 | rule / セグメント / 回 / 開始日 / 終了日 / 出典 |
| 見る日の登録表 | 見る日 / 理由 / 出典(空の表でもよい = 窓の表だけ返す) |
| 比べ方の登録 | 種類 / 値 / 出典 |

- `回` は人が写した回の id(道具は開始日から回を作らない)。`終了日` は `YYYY-MM-DD` か `INF`(空も閉じていない行として読む)
- 額や率の列は受け取らない(行の表に列が在っても読まない)
- 比べ方の登録の `種類` は 3 つ。`回`(書いた順が回の順)/ `区間の端`(1 行だけ。`半開` = 終了日を含まない、`両閉` = 終了日を含む)/ `セグメント`(全体の一覧。道具は行から全体を作らない)
- 出典はどの行にも要る(ファイル名 + 行番号、または JSON のキー)

## 出力

**回ごとの窓**(rule × 回): 行数 / 最初の開始日 / 最後の開始日 / その間の日数(引き算)/ 開始日の種類の数 / 全体の一覧のうち行の無いセグメント。

**日ごとの区分**(見る日 × rule × 回の対「前の回 → 新しい回」× セグメント 1 つ 1 行):

| 区分 | 意味 |
|---|---|
| A | その日すでに新しい回(かそれより後ろの回)の行に当たる |
| B | その日は前の回かそれより前の行に当たり、新しい回の行が後の日に在る。新しい回の開始日と、見る日からその日までの日数(引き算)を横に置く |
| C | その日は前の回かそれより前の行に当たり、後の日に始まる新しい回の行が無い |
| D | その日に当たる行が 1 つも無い |

並びは 見る日 → rule → 回の対(回の順)→ 区分 → セグメントの昇順で固定。回の対は、回の順で隣り合う全ての対を出す(どの対を見るかを道具は選ばない)。
文字の出力では、全てのセグメントが A の対は件数の 1 行だけにしている(1 行ずつは `--json` に在る)。
その日に当たる行が 2 つ以上在るときは、回の順で後ろの行を採り、当たった行の数を横に置く。

補助の印は 2 つ。窓が暦の年をまたぐ(最初の開始日と最後の開始日の年が違う)/ 前の回の行の終わりと新しい回の行の始まりがつながらない(`半開` なら終了日と開始日が同じ日でない、`両閉` なら終了日の翌日が開始日でない)。どちらも区分を動かさない。

別枠は 6 つ(区分に使わず理由を返す): 日付として読めない / 出典が空 / 区間の端が 2 つの値以外 / 同じ (rule, セグメント, 回) が 2 行 / 回の id が回の順に無い / セグメントが全体の一覧に無い。
区間の端が別枠のときは、日ごとの区分は出さず、窓の表だけ返す。

列が無い、rule が空、同じ見る日が 2 行、区間の端の行が 1 行でない、回やセグメントの登録に同じ値が 2 行、出典の付いた回・セグメントが 1 つも無いときは、1 行も並べずに止まる。

## いつも成り立つこと

登録した見る日と回の対のどれについても、全体の一覧のセグメントは区分 A〜D のどれか 1 つにだけ入り(件数の合計は全体の数と同じ)、**その区分は、そのセグメントの行と、見る日と、登録した回の順・区間の端だけで決まる**(行の表の行順を入れ替えても、ほかのセグメントの行を除いても、区分は動かない)。

この 1 文は `tests/test_switch_lag_property.py` が性質テスト(hypothesis)で確かめている(乱数は固定で毎回同じ 300 通り)。区分の決め方は道具の関数を使わず、テストの中で別に書いている。

## 使い方

```
python switch_lag.py --rows fixtures/suuhyo/rows.csv --days fixtures/suuhyo/days.csv --setup fixtures/suuhyo/setup.csv --verify
```

`--days` を省くと窓の表だけ。`--json` で JSON。終了コードは 0 = 区分が全て A で、印も別枠も行の無いセグメントも無い / 3 = 人が見る行がある / 2 = 表が読めない / 4 = `--verify` が合わない。
0 は「登録した日には全てのセグメントが新しい回の行に当たった」であって、「行の中身が合っている」という意味ではない。

`--verify` は検算を 5 つ走らせる: 二度走りの sha256 / 行の表の行順を逆にしても同じ / 見る日ごとに A+B+C+D = セグメントの全体の数 / 新しい回より後ろの回の行を除いた表で、見る日を窓の最後の開始日に置くと B が 0、最初の開始日の前日に置くと A が 0 / 道具自身のソースを `ast` で読んで `now`・`today` の呼び出しが 0。


| `fixtures/utsusu.py` | 数表の JSON から行の表と比べ方の登録を写す手伝い(道具の本体は JSON を読まない) |

## できないこと

- 開始日が後ろのセグメントについて、遅い・早いを言わない。理由も返さない
- B や C のセグメントについて、額が足りているか・何かに反しているかを見ない(額を受け取らない)
- 行の無いセグメントについて、改定が無かったのか、収録が無いのかを区別しない
- 「その日に新しい行を知り得たか」は見ない(公表時点の欄を受け取らない)
- 見る日を選ばない。今日の日付を読まない
- セグメントの名前を訳さない・寄せない(字が違えば別のセグメント)
