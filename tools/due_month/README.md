# due_month — 行に付いた次回改定の予定と、行が動いてきた開始日の月日を rule ごとに並べる

数表の行に付いている「次回改定の予定」は、数表ごとの台帳から行へ写された 1 つの日付で、その行自身が過去に動いてきた月日と同じとは限らない。
この部品は、**人が書いた 4 つの表**を読み、rule ごとに開始日の並びと予定を横に置いて、4 つの区分に分けたところで止まる。
**予定を予測しない。周期を数えない。どちらの日付が正しいかを返さない。今日の日付を読まない。** 標準ライブラリのみ、依存なし。

## 入力(4 表、UTF-8 の CSV)

| 表 | 列 |
|---|---|
| 行の表 | rule / valid_from / 予定 / 出どころ / 元の行数 / 出典 |
| 台帳の表 | 台帳id / 種別 / 数表id / 予定 / 出典 |
| 対応の登録表 | 出どころ / 台帳id / 出典(空の表でもよい = 対応なし) |
| 比べ方の登録 | 比べ方 / 出典(1 行だけ。`最後の行` か `どれかの行`) |

- `予定` は `YYYY-MM-DD` か空。`出どころ` は、その行の予定がどこから写されたかを人が引けるようにする id(空でもよい)
- `元の行数` は、同じ rule・開始日・予定・出どころの行を 1 行にまとめたときの元の数(空なら 1)
- `種別` は自前の台帳と上流の台帳を区別する欄(字は自由)
- 出典はどの行にも要る(ファイル名 + 行番号、または JSON のキー)

## 出力

| 区分 | 意味 |
|---|---|
| A | 予定が最後の開始日より後で、月日が登録した比べ方どおりに行の月日と同じ |
| B | 予定が最後の開始日より後で、月日が違う |
| C | 予定が最後の開始日以前(既に持っている行の開始日と同じ日付なら印) |
| D | 予定が空 |

rule 名の昇順で、開始日の一覧・月日の集合・行に付いた予定・区分・結んだ台帳の予定を返す。区分ごとの rule 数と行数も返す。

補助の印は 2 つ。対応の登録表で結んだ台帳の予定と行に付いた予定が違う(両方の日付をそのまま返す。どちらにも寄せない)/ 同じ rule の中で行に付いた予定が 2 通り以上。どちらも区分を動かさない。
予定が 2 通り以上の rule は、最も早い日付で区分を決めて印を付ける(空と日付が混ざるときは日付の側)。

別枠は 6 つ(区分に入れず理由を返す): 日付の形でない予定 / 行の表に rule が空 / 対応の登録表が指す台帳 id が台帳の表に無い / 出典が空 / 比べ方が 2 つの値以外 / 同じ (rule, valid_from, 出どころ) が 2 行。
行が 1 つでも別枠に当たった rule は、rule ごと別枠に出す。比べ方が別枠のときは、C と D だけ区分に置き、A か B になるはずの rule を別枠に出す。
台帳の行が別枠に出たときは、その台帳を無いものとして扱う。

列が無い、valid_from が日付の形でない、元の行数が 1 以上の整数でない、台帳id が空・重複、同じ対応が 2 行、比べ方の登録が 1 行でないときは、1 rule も並べずに止まる。

## いつも成り立つこと

行の表の rule は区分 A〜D か別枠のどれか 1 か所にだけ入り、**区分は、その rule の行の開始日と行に付いた予定と、登録した比べ方だけで決まる**(行順を入れ替えても、台帳の表と対応の登録表を空にしても、区分は動かない)。

この 1 文は `tests/test_due_month_property.py` が性質テスト(hypothesis)で確かめている(乱数は固定で毎回同じ 300 通り)。区分の決め方は道具の関数を使わず、テストの中で別に書いている。

## 使い方

```
python due_month.py --rows fixtures/suuhyo/rows.csv --ledgers fixtures/suuhyo/ledgers.csv --links fixtures/suuhyo/links.csv --compare fixtures/suuhyo/compare.csv --verify
```

`--json` で JSON。終了コードは 0 = 全ての rule が A で、印も別枠も無い / 3 = 人が見る行がある / 2 = 表が読めない / 4 = `--verify` が合わない。
0 は「予定の月日が行の月日と同じだった」であって、「その日に改定される」という意味ではない。

`--verify` は検算を 5 つ走らせる: 二度走りの sha256 / 行順を逆にしても同じ / 区分 4 値 + 別枠 = rule の種類数 / 比べ方を `最後の行` に替えると A から B へだけ動く / D の 1 rule に予定を入れるとその rule だけ D から出る。

## できないこと

- 次にいつ改定されるかは言わない。B は誤りという意味ではない。A は予定が合っているという証拠ではない
- どの出どころをどの台帳に結ぶかは決めない(人の登録)
- 予定が過ぎているかどうかは見ない(今日の日付を読まない)
- 比べ方で件数が動く。件数は登録した比べ方とセットで読む
