# stamp_day — 時刻の欄を、書かれたままの日付と、登録した時差での日付に分けて並べる

道具が書き出す時刻は `2031-04-01T22:48:48+00:00` のように時差の印(`+00:00`)を持っていることが多い。
頭の 10 文字を日付として切り出すと、それは「記録に書かれた時差での日付」になる。
この部品は、時刻の台帳を 1 行 1 件で読み、**書かれたままの日付**と、**人が登録した換算先の時差での日付**を横に並べ、
日ごとの回数を 2 つの読みで返す。**どちらの日付を採るかは決めない。** 標準ライブラリのみ(csv / json / datetime / hashlib / argparse / re)、依存なし。

## 入力(2 表、UTF-8 の CSV)

| 表 | 列 | 中身 |
|---|---|---|
| 時刻の台帳 | `row_id,stamp,source` | 行の番号 / 時刻の文字列そのまま / 出典(ファイル名 + 行番号) |
| 換算先の登録表 | `name,offset` | 名前 / 時差の文字列 `+HH:MM` か `-HH:MM`。人が登録した分だけ |

1 回の実行で使う換算先は 1 行だけ。登録表が 2 行以上のときは `--zone 名前` で 1 行を指す。
名前はただの呼び名で、道具は名前から時差を引かない(地名の辞書も夏時間の表も持っていない)。

## 出力

行ごとに、書かれたままの日付(頭の 10 文字)/ 書かれている時差の印 / 換算後の日付と時刻 / 日付の差(日)/ 区分。

| 区分 | 意味 |
|---|---|
| (A) 日付が同じ | 換算後の日付が、頭の 10 文字と同じ |
| (B) 後の日付に替わる | 換算後の日付が、頭の 10 文字より後(多くは翌日。差は「日付の差(日)」に日数で出る) |
| (C) 前の日付に替わる | 換算後の日付が、頭の 10 文字より前 |

行は換算後の時刻の順に並べ、同じ時刻の行は行の番号の順にする(数字だけの番号は数として比べる。並べ方は出力に書く)。
日ごとの回数は「書かれたままの読み」と「換算後の読み」の 2 列で返し、1 列に丸めない。
最初と最後の時刻、日付が替わった行の番号も返す。

区分に入れずに分けておくもの:

| 分け方 | 中身 |
|---|---|
| 別枠: 出典が空 | 出典の欄が空の行 |
| 別枠: 同じ行の番号が 2 回以上 | 同じ番号の行はどれも区分しない |
| 別枠: 形が読めない時刻 | 日付だけ / 区切りが空白 / 暦に無い日付 / 全角数字 / 前後の空白 など |
| 別枠: 時差の印が無い時刻 | 時差を当てずに別枠へ。日ごとの回数に入れない |
| 印: `Z` で終わる時刻 | `+00:00` と同じに読み、「Z を +00:00 と読んだ」を別の列に付ける(区分には入る) |
| 止まる: 換算先が 1 行に決まらない | 登録表が空 / 2 行以上で指定なし / 指定した名前が無い など。1 行も区分しない |

読める時刻の形は `YYYY-MM-DDTHH:MM:SS` + 任意の小数秒(1〜6 桁)+ 時差の印(`Z` / `+HH:MM` / `-HH:MM`)だけ。

## いつも成り立つこと

読んだ結果は 2 通りしかない。**時刻の台帳の 1 行ごとに 3 つの区分か 4 つの別枠のどれか 1 つだけが付き、その合計が台帳の行数に等しく、区分が付いた行では換算後の日付と時刻が書かれた時刻と同じ瞬間を指し、日ごとの回数は 2 列とも合計が区分の付いた行数に等しく、台帳の行順を入れ替えても同じバイト列になる**か、**1 行も区分せず、止まった理由が 1 つ返る**か。どちらの場合も入力の 2 表は書き換わらない。

この 1 文は `tests/test_stamp_day_property.py` が性質テスト(hypothesis)で確かめている。2 表を乱数で作り(読める時刻・困る時刻・崩れた登録表を混ぜる)、毎回この 1 文が成り立つかを見る(乱数は固定で、毎回同じ 300 通り)。換算の照合は道具の関数を使わず、テストの中で別の道筋(時差つきの時刻を作って換算先へ移す)で書いている。テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python stamp_day.py check  <時刻の台帳.csv> <換算先の登録表.csv> [--zone 名前]   # 区分・別枠・日ごとの回数
python stamp_day.py rows   <時刻の台帳.csv> <換算先の登録表.csv> [--zone 名前]   # 1 行 1 件の一覧(JSON Lines)
python stamp_day.py verify <時刻の台帳.csv> <換算先の登録表.csv> [--zone 名前]   # 決定論の確認 5 つ
```

終了コードは 0 = 読めて別枠が無い / 3 = 読めたが別枠が在る / 2 = 表として読めず 1 行も区分していない / 4 = verify が合わない。
**0 は「読めて別枠が無い」という意味で、「日付が合っている」という意味ではない。**

```python
import stamp_day as T

stamps, zones = T.load("stamps.csv", "zones.csv")
r = T.judge(stamps, zones, "換算先A")
for d in r["日ごとの回数"]:
    print(d["日付"], d["書かれたままの読み"], d["換算後の読み"])
print(r["日付が替わった行の番号"])
```

## verify が見る 5 つ

| 番号 | 見ること |
|---|---|
| ① | 判定部分の sha256 が、二度走って同じか |
| ② | 2 表の行順を入れ替えても(3 通り)同じ出力になるか |
| ③ | 区分 + 別枠 = 台帳の行数、日ごとの回数の合計が 2 列とも区分に入った行数に等しいか |
| ④ | 行に書かれている時差そのものを換算先にすると、その行がみな (A) になり、2 列の回数が一致するか |
| ⑤ | (A) の 1 行を日付の境目の手前の 1 秒に置いた写しでは (A) のまま、境目の向こうへ 1 秒動かした写しではその 1 行だけが動き、ほかの行が変わらないか |

写しはメモリの中だけで、入力には 1 文字も書かない。

## 止まる理由(`STOPS`)

時刻の台帳の見出しが違う / 時刻の台帳に列の数が違う行がある / 時刻の台帳に行の番号が空の行がある /
換算先の登録表の見出しが違う / 換算先の登録表に列の数が違う行がある / 換算先の登録表が空 /
換算先の登録表に同じ名前が 2 回以上ある / 換算先の登録表に読めない時差がある /
換算先の登録表が 2 行以上あるのに、使う 1 行の指定が無い / 指定した名前が換算先の登録表に無い。

## テストと fixture

```
python -m pytest tools/stamp_day -q        # 16 passed
```

fixture は全て合成データで、時刻も出典も架空(年は 2031 年にしてある)。`fixtures/stamps_a.csv` は 20 行で、
3 つの区分と 4 つの別枠と `Z` の印が、少なくとも 1 行ずつ出るように作ってある。`fixtures/zones_a.csv` は 3 行。
`test_measure_*` が記事に載せた数を `assert` で固定している。

## できないこと

- **どちらの日付を採るかは返さない。** 2 列を並べるだけで、採る側は人が決める
- **時差の印が無い時刻は読まない。** 時差を当てる経路が無いので、別枠に出るだけになる
- **地名や時間帯の名前(`JST` など)は受け取らない。** 夏時間の表を持たないので、時差は固定の `+HH:MM` / `-HH:MM` だけ。夏時間の在る地域の記録を 1 つの時差で通すと、切り替えの前後で読みがずれる
- **端末の時間帯も時計も読まない。** 換算先は登録表の 1 行だけで決まる
- **文書に書かれた日付と結び付けない。** 文書の日付がどの時差で書かれたかは、この部品では分からない
- **日付だけの欄は扱わない。** 時刻が無い値は「形が読めない時刻」に出る
- 読める形は 1 つだけ(区切りは `T`、時差の印は `Z` か `±HH:MM`)。`+0900` のような書き方や、秒の無い時刻は読まない
- 換算先の時差が妥当かどうかは見ていない。人が登録したとおりに換算する
