# input_chain — 計算に要るものは引数の欄を見ても分からないので、入力の出どころを下まで辿って一覧にする

**呼んだ後には使った行の出典が付くが、呼ぶ前に何を手元へ置けばよいかは誰も返さない。式の入力が
また式で、その式の入力が表の行で、その行を引くのにまた日付と区分が要る。最後に残る「人しか
出せないもの」は、一段見ただけでは見えない。だから呼ぶ前に入力の出どころを下まで辿って、葉だけ
を一覧にする。**

[handoff_edge](../handoff_edge) の回は、値が返った**後**に呼び出し側へ残る一手を数える道具だった。
向きが逆で、ここは呼ぶ**前**に手元へ置くものを数える。しかも向こうは宣言を 1 段突き合わせる
だけだったが、ここは**辿ること自体が仕事**で、段数と輪を持つ。[basis_map](../basis_map) は
手元の日付がどの種別かという 1 段目の欄の話で、2 段目から下は見ていない。
[formula_table](../formula_table) は式を data として置く話で、式が食う入力の出どころは扱わない。

この部品は、式の宣言表・行の宣言表・問いの一覧の 3 枚から、問い(= 求める値)1 つごとに依存を
下まで辿り、葉 1 枚ごとに 5 値(**手元に在る / 人が用意する / 導出すると宣言 / 宣言が無い /
辿れない**)を付ける。段数つきの依存の一覧と、呼ぶ前に集めるものの名前と出典も返す。
**値を計算しない。式を評価しない。行を引かない。数えるだけだ。**

持たせていないものが規律になっている。

- **宣言に無い入力の種別を推測しない**(`case の欄` を既定として当てる経路が無い。5 値目の
  別枠「宣言が無い」に出す)
- **`導出すると宣言` と `case の欄` を同じに数えない**(導出すると書いてある入力と、呼び口で
  人が渡している入力は、どちらが正しいかを決めずに別の列で数える。足して 1 つにする欄が無い)
- **循環を黙って切らない**(経路に同じ式が 2 回出る枝と、段数の上限に当たった枝は `辿れない` に
  出す。打ち切った枝の名前と段を返す。無限にも指数にも降りない)
- **足りない入力を埋めない・代わりの式を出さない**(既定値を入れる経路も、似た名前に寄せる
  経路も無い)
- **出典の欄が空の行は使わずに止まる**
- **値を計算しない・式を評価しない・行を実際に引かない**(式は [formula_table](../formula_table)、
  値の比較は [compare_pick](../compare_pick)、返った後に残る一手は
  [handoff_edge](../handoff_edge) の仕事で、役割が重ならない)
- **引けるかどうかは見ない**(節の状態の欄も、年の在庫の欄も持たない。年の側は
  [cover_stock](../cover_stock))
- **完成度の割合を出さない**(件数と 3 つの分母の内訳だけを返す。率を返す呼び方も option も無い)
- **この部品自身の「読めない」を、測っている相手の「宣言が無い」と同じ欄に入れない**(宣言表が
  1 行でも壊れていたら 1 枚も辿らず、理由コードだけを返す。5 値は全て 0 になる)
- **入力表を書き換えず、式も行も生成しない**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない。行順にも依らない)
- **数は整数だけ**(float を使う経路が無い)

## 入力 — 式の宣言表と行の宣言表と問いの一覧

式の宣言表は 4 列。**1 つの式の 1 つの入力が 1 行**で、その入力をどこから調達するのかをここだけ
に書く。

| 列 | 意味 |
|---|---|
| `formula_id` | 式 id(空欄と、区切り文字を含む id は「表として読めない」) |
| `input_id` | 入力 id(別の式 id / rule id / case の欄の名前。同上) |
| `kind` | 調達先種別。登録の 4 種(`別の式` / `表の行` / `case の欄` / `導出すると宣言`)。空欄も登録外も**止まる** |
| `source` | 出典(空欄は**止まる**) |

同じ式に同じ入力 id が 2 行あると**止まる**。入力が 1 つも無い式は、行が 1 本も無いので
「宣言が無い」に出る(定数だけの式はこの 3 枚では宣言できない)。

行の宣言表は 4 列。**1 つの rule が 1 行**で、その行を引くのに何が要るかを書く。

| 列 | 意味 |
|---|---|
| `rule_id` | rule id(空欄と、同じ id が 2 行あるのは「表として読めない」) |
| `basis` | 引くのに要る基準日の欄。ちょうど 1 つ(空欄も 2 つ以上も**止まる**) |
| `dims` | 区分の次元を `\|` でつなぐ(空欄は次元なし = 止まらない。同じ欄を 2 回書くと**止まる**) |
| `source` | 出典(空欄は**止まる**) |

問いの一覧は 4 列。**1 つの問いが 1 行**で、訊く求める値と、そのとき手元に在る欄を書く。

| 列 | 意味 |
|---|---|
| `value_id` | 訊く求める値 id(= 式 id。空欄と、同じ問いの 2 行は「表として読めない」) |
| `at_hand` | 手元に在る case の欄を `\|` でつなぐ(空欄可。同じ名前を 2 つ書くと**止まる**) |
| `source` | 出典(空欄は**止まる**) |
| `swap` | 入れ替え方(`逆順` / `両端入れ替え` / `1 つずらす`)。`verify` が 3 枚の行順を入れ替えるときの宣言 |

求める値を `at_hand` にも書くと**止まる**(求める値そのものが手元に在るという宣言は、宣言として
矛盾している)。式 id と rule id に同じ名前があるときも**止まる**(どちらを指すか決まらない)。

## 辿り方 — 葉に付く 5 値

求める値の式から始めて、入力を 1 段ずつ降りる。降りるのは `別の式` と `表の行` の 2 種だけで、
残りの 2 種はその場で葉になる。

| 入力の種別 | どうするか | 葉 |
|---|---|---|
| `case の欄` | 降りない | 手元に在る / 人が用意する(`at_hand` に在るかで決まる) |
| `導出すると宣言` | 降りない | 導出すると宣言(**人が用意する には混ぜない**) |
| `表の行` | 行の宣言表を引き、要る欄を 1 段下の葉にする | 手元に在る / 人が用意する / 宣言が無い |
| `別の式` | その式の入力へ降りる | 宣言が無い / 辿れない(降りられないとき) |

降りられないのは 3 つ。参照先が宣言表に無い(`宣言が無い`)、**経路に同じ式が 2 回出る**
(`辿れない`)、**段数の上限 6 段に当たった**(`辿れない`)。どれも黙って切らず、枝の名前と段と
理由を一覧で返す。葉が付きうるいちばん深い段は 上限 + 2 = 8 段になる。

求める値そのものが式の宣言表に無いときは、段 0 の葉 1 枚(`宣言が無い`)だけを返す。
**残りを推測して埋めない。**

## 件数の検算 — 分母は 3 つある

- **5 値の件数の合計 = 葉の数(延べ)**
- **問いごとの内訳の合計 = 全体の 5 値の合計**
- **調達先種別別の件数の合計 = 式の宣言表の行数**

3 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
分母は 問いの数 / 葉の数 / 段数の最大 の 3 つを必ず付ける。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- 問い 1 つごとに葉が 0 枚以上付き、**5 値の合計が葉の数**に等しく、**問いごとの内訳の合計が
  全体**に等しく、**宣言に無い参照は 宣言が無い に出て**(`case の欄` を既定として当てない)、
  **`導出すると宣言` の葉は 人が用意する に混ざらず**、**経路に同じ式が 2 回出る枝と段数の
  上限に当たった枝は 辿れない に出て**段数が 上限 + 2 を超えず、判定部分に時刻・ホスト名・
  絶対パスが 1 つも入らず、**3 枚の行順を入れ替えても同じバイト列**になる
- または、1 枚も辿らずに理由コードが返る(辿った葉や指紋を取りに行くと例外になる)

どちらの場合も、この部品は式の宣言表も行の宣言表も問いの一覧も 1 文字も書き換えない。

この 1 文を `tests/test_input_chain_property.py` の `@given` テストが確かめている(式を 1〜3 つ
作って入力を 1〜3 つ、種別は登録の 4 種から引く。rule を 1〜2 本、問いを 1〜2 件。入力 id は
式 id・rule id・case の欄・宣言表に無い id から引くので、輪も宣言の穴も混ざる。3 割くらいの
確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。**葉の辿り方と 5 値はテストの側で
別に実装している**(部品の `walk` / `counts` を呼ばない)。同じファイルの 2 本目は「宣言に無い
参照に `case の欄` を当てない」ことを見ている(組み合わせは 16 通りしかないので、上限 300 の
下で全部を尽くす)。

## 出力 — 完成度の割合は返らない

`check` と `chain` が返るのは、3 枚それぞれの行数、3 つの分母、5 値の件数、段別と調達先種別別の
件数、分母の内訳と検算、それに 8 つの固定行だ。**割合だけを返す呼び方も、option も無い。**

```
"分母(問いの数)": 10,
"分母(葉の数)": 39,
"分母(段数の最大)": 4,
"5 値": {"手元に在る": 8, "人が用意する": 23, "導出すると宣言": 3, "宣言が無い": 3,
         "辿れない": 2},
"段別の葉の数": {"0 段": 1, "1 段": 10, "2 段": 18, "3 段": 7, "4 段": 3},
"調達先種別別(宣言表の行数)": {"別の式": 7, "表の行": 4, "case の欄": 8,
                               "導出すると宣言": 1},
"件数の合計の検算": "5 値の合計 39 / 葉の数 39(問いごとの内訳の合計 39 も同じ、…)",
"完成度の割合を出さない": "…",
"種別に既定を当てない": "…",
"導出すると宣言 と case の欄 を同じに数えない": "…",
"循環を黙って切らない": "…",
"足りない入力を埋めない・提案しない": "…",
"値を計算しない・式を評価しない・行を引かない": "…",
"入力を書き換えない": "…"
```

`chain` にすると、問いごとの依存の一覧(段数つき)に加えて、**呼ぶ前に集めるもの**と
**辿れない の一覧**が出る。前者は 1 行 1 名前で、名前 / 延べ数 / 要る問い / 段 / 出典 の 5 列だ。
**名前は宣言に書かれたものがそのまま出る**(道具が書き足すことはしない)。

## 止まる理由コード(13 個)

1 枚も辿らずに止まるものが 10 個。

`出典の欄が空` / `調達先種別が空` / `登録されていない調達先種別` /
`同じ式に同じ入力 id が 2 行ある` / `基準日の欄が空` / `基準日の欄に 2 つ以上書いてある` /
`同じ区分の欄を 2 回要求している` / `式 id と rule id に同じ名前がある` /
`手元に在る欄に同じ名前が 2 つある` / `求める値を手元に在ると宣言している`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄や区切り文字入り・同じ rule id が 2 行・同じ問いが 2 行・
登録外の入れ替え方、は**「表として読めない」**(終了コード 2)で、理由コードには混ぜない。

## 使い方

```
python input_chain.py init ひな型/
python input_chain.py check  式の宣言表.csv 行の宣言表.csv 問いの一覧.csv
python input_chain.py chain  式の宣言表.csv 行の宣言表.csv 問いの一覧.csv
python input_chain.py verify 式の宣言表.csv 行の宣言表.csv 問いの一覧.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、宣言された入れ替え方で 3 枚の
行順を入れ替えても同じ出力になるか、件数の合計が合うか、そして 2 つの写しだ。**入力の種別を
`case の欄` から `別の式` に替えた写し**では、その葉が消えて替えた式の入力がちょうど 1 段下に
出ること(替えた葉を持たない問いは 1 枚も動かないこと)を見る。**式が自分自身を入力にしている
写し**では、増えるのが `辿れない` の葉だけで、ほかの葉が 1 枚も動かないことを見る。写しはメモリ
の中だけで、入力の表には 1 文字も書かない。

終了コードは、葉が全部「手元に在る」ときだけ 0、呼ぶ前に集めるものか別枠が在るときは 3、表と
して読めなければ 2。**何割そろっているかはこの終了コードにも出力にも出さない。**

関数でも呼べる。

```python
import input_chain as H

t = H.input_chain(H.Formulas.load("式の宣言表.csv"), H.Rows.load("行の宣言表.csv"),
                  H.Questions.load("問いの一覧.csv"))
if t.report.ok:
    print(t.counts()["5 値"], t.collect())
```

## テストと fixture

```
python -m pytest tools/input_chain -q
python fixtures/make_fixtures.py     # 合成の 5 枚と、崩した表 28 枚を書き直す
```

`fixtures/` に入っているのは合成した 3 枚(入力 20 / rule 4 / 問い 10)と、段数の上限に当たる
深い鎖の 2 枚、それに理由コードを出すために 1 か所だけ崩した表 28 枚だ。**実在の料率・金額・
取引先名は 1 つも入っていない。** 式 id も rule id も欄の名前も架空で、値も日付も 1 つも入って
いない。

## できないこと

- 判定したことは「呼ぶ前に手元へ置くものがどれか」までで、**足りない入力を道具側では埋めない**。
  既定値を入れる引数も、代わりの式を選ぶ経路も無い
- **集める順も、誰に頼むかも出さない。** 件数と名前の一覧が残るだけだ
- **何割そろっているかを出さない。** 言えるのは宣言に書かれた範囲までで、率を返す経路が無い
- **宣言が本当かどうかは判定しない。** 「導出すると宣言」と書けばそう数える。宣言とソースを
  突き合わせるのは [scope_ledger](../scope_ledger) の仕事で、ここは宣言を読む側に立つ
- **値も日付も持たない。** 実在の料率や金額がいくらかも、その欄がいつの日付かも言わない
- **引けるかどうかを見ない**(節の状態は [handoff_edge](../handoff_edge)、年の在庫は
  [cover_stock](../cover_stock))
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
