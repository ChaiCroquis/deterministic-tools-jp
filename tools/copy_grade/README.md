# copy_grade — 同じ処理が散った箇所も同じ写しとは限らないので、まとめる前に文字の一致で段に分ける

「同じ処理が N か所に散っている」と数えた箇所も、**同じだと言える根拠は箇所ごとに別**だ。指紋が一致すると注記された組・人が見て同型だと注記された組・行数が 3 通りある派生・「散在」としか書かれていない組が、1 つの箇所数の中に入っている。**まとめる前にその段を分けないと、写しを消すだけで済む箇所と、読んで判断しないと挙動が変わる箇所が、同じ工程に乗る。**

この部品は、3 枚の表と写しの置き場から、同じ部品の **2 箇所の組**を 4 段 + 別枠 4 へ分ける。**まとめてよいかは決めない。取りに行かない。走らせない。**

```
python copy_grade.py check 部品の台帳.csv 箇所の台帳.csv 注記記号の登録表.csv 写しの置き場/
```

## 持たせていないもの

- **まとめてよいかを決めない**。統合の可否・順序・優先度・どの箇所が正本かを出す列が無い。終了コード 0 も「まとめてよい」ではなく「渡された写しが全部そのままで同一だった」の意味
- **写しの中身を出力に出さない**。出るのは段・行番号・件数・箇所 id だけで、入力の文字を出力へ貼る経路が無い(= 読んだコードそのものが公開物へ流れない物理形)
- **名前を出力に出さない**。ファイル名・パス・道具名の列を持たず、箇所 id だけで返す
- **振る舞いが同じかを見ない**。実行しない・import しない・構文解析しない・テストを走らせない。段は文字の一致で、同じ結果を返すかは出力に出ない
- **似ている度合いを出さない**。類似度・距離・一致率・割合を出す列が無く、段はちょうど一致の階段 4 つだけ
- **注記を段の代わりに使わない**。`指紋一致と注記` が在っても写しが一致しなければ (A) に入れる経路が無い。注記と段は別の列で並ぶ
- **宣言されている箇所数を整数に直さない**。`8+` や `18 ファイル` を生の文字列のまま持ち、写しが渡された箇所の件数とは別の列に並べる
- **テストの有無を段に混ぜない**(走らせた結果を台帳に残すのは別の部品の領分)。**写しを取りに行かない**(通信の経路が無く、置き場の外は読まない)
- **正規化は 3 つだけ**。**時計を読まない**。**入力を書き換えない**。**float を使わない**(行数と行番号は整数、ほかは文字列)

## 入力 — 3 枚 + 写しの置き場

**登録の側(部品の台帳 / 注記記号の登録表)の行に出典が無ければ、1 組も数えずに止まる。**

### 部品の台帳(6 列)

| 列 | 中身 |
|---|---|
| `part_id` | 部品 id(同じ id が 2 行あると止まる) |
| `what` | 部品の内容を表す説明 |
| `declared` | **宣言されている箇所数の文字列**(`17` / `8+` / `18 ファイル` / `4 + 5` のような生の文字列)。**整数に直す経路が無い** |
| `industry` | 業種依存の記号(`なし` / `あり`) |
| `unified` | 統一の宣言記号(`統一済みと宣言` / `モジュール化は 1 本だけと宣言` / `宣言なし`) |
| `source` | 出典(ファイル名 + 行番号)。空欄は止まる |

```csv
part_id,what,declared,industry,unified,source
P1,CSV の文字コードの判定,17,なし,宣言なし,合成の棚卸しのメモ(架空)L1
P4,和暦の処理,18 ファイル,なし,モジュール化は 1 本だけと宣言,合成の棚卸しのメモ(架空)L4
P8,外部サービスの API 呼び出し,8+,あり,統一済みと宣言,合成の棚卸しのメモ(架空)L8
```

### 箇所の台帳(6 列)

| 列 | 中身 |
|---|---|
| `site_id` | 箇所 id(同じ id が 2 行あると止まる) |
| `part_id` | 部品 id(部品の台帳に無いと止まる) |
| `copy` | **その箇所のテキストの写しを置いたファイル**(置き場からの相対パス)。空欄のとき、その箇所の組は別枠「写しが渡されていない」へ |
| `note` | 注記記号(登録表に在る記号だけ。無ければ別枠へ) |
| `declared_lines` | 注記に書かれている行数の記載(**生の文字列**。要求されない注記では `—`) |
| `source` | 出典。空欄のとき、その箇所の組は別枠「出典が空」へ |

```csv
site_id,part_id,copy,note,declared_lines,source
S01,P1,S01.txt,注記なし,—,合成の箇所のメモ(架空)L1
S12,P5,S12.txt,派生と注記,451,合成の箇所のメモ(架空)L12
S15,P6,S15.txt,指紋一致と注記,—,合成の箇所のメモ(架空)L15
```

### 注記記号の登録表(4 列)

**「その注記が何を要求するか」はここに在る。** 記号の綴りから当てる経路は無い。

| 列 | 中身 |
|---|---|
| `note` | 記号(`指紋一致と注記` / `同型と注記` / `派生と注記` / `散在と注記のみ` / `注記なし` …) |
| `means` | 意味(1 行) |
| `requires` | その注記が要求する欄(`—` / `写し` / `行数`) |
| `source` | 出典。空欄は止まる |

### 写しの置き場

箇所の台帳の `copy` が指すテキストを置くフォルダ。**絶対パスと `..` を含む行は読まずに止まる**(置き場の外を読む経路が無い)。写しは utf-8 で、読めなければ止まる。

## 分け方 — 組 1 つに付く 4 段と別枠 4

上から順に見る。どちらかの出典が空なら別枠。注記記号が登録表に無ければ別枠。その注記が要求する欄が空なら別枠。写しが渡されていなければ別枠。**そこを抜けてから、はじめて写しの文字だけを比べる。**

| 段 | 意味 |
|---|---|
| (A) そのままで同一 | 正規化の前の sha256 が一致(そのまま消せる形) |
| (B) 空白と改行だけの差 | 決めた 3 つの正規化の後で sha256 が一致(正規化前は不一致) |
| (C) 行数が同じで中身が違う | 行数一致・正規化後も不一致。**違う行の番号だけ**を出す |
| (D) 行数が違う | 2 つの行数をそのまま出す |

別枠 4 = 出典が空 / 注記記号が登録表に無い / その注記が要求する欄が空 / 写しが渡されていない。

正規化は 3 つに固定する。**行末の空白を落とす / 改行を LF に揃える / 末尾の空行を落とす。それ以外は何もしない**(字下げを揃えない・コメントを外さない・識別子を揃えない・引用符を揃えない。増やす引数も無い)。

合わせて部品ごとに **「宣言されている箇所数の文字列」と「写しが渡された箇所の件数」を並べて返す。** 一方をもう一方の代わりに使わせないためで、`8+` を整数に直す経路は無い。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- **組を作った**: 同じ部品の **2 箇所の組 1 つごとに 4 段か別枠 4 のどれか 1 つ**が付き、**その合計 = 部品ごとの「箇所の件数から 2 つ選ぶ組み合わせ」の総和**、**部品ごとの内訳の合計も注記の組ごとの内訳の合計も同じ数**になる。**違う行の番号が出るのは (C) の組だけ**で、**行数が違うのは (D) の組だけ**、**注記が何と書いてあっても段は写しの文字で決まり**(`指紋一致と注記` を (A) に読み替える経路が無い)、**宣言されている箇所数の文字列は生の文字列のまま**。出力に「まとめてよいか」「正本」「類似度」の欄が無く、判定部分に絶対パスも写しのファイル名も入らず、3 枚の行順を 3 通りに入れ替えても同じバイト列になる
- **1 組も数えずに理由コードが返る**: 作った組や sha256 を取りに行くと例外

どちらの場合も、この部品は 3 枚の表と置き場の写しを 1 文字も書き換えない。

この 1 文を検査にしたのが `tests/test_copy_grade_property.py`(hypothesis、`derandomize=True`)。段の分け方はテストの中に別に書いてあり、部品の `grade` / `four` を呼ばない。正規化もテストの側に別に実装してある。

## 件数の検算 — 3 通りの数え方が合う

- 4 段 + 別枠 4 の合計 = 同じ部品の 2 箇所の組の件数
- 部品ごとの内訳の合計 = 同じ数 / 注記の組ごとの内訳の合計 = 同じ数

`verify` はこれに加えて、判定部分の sha256 の二度走り、3 枚の行順の 3 通りの入れ替え、そして 2 つの写しを見る。

- **1 件の写しの行末に空白を 1 つ足した写し**: その組だけが (A) から (B) へ移り、**別枠の件数も (C)(D) の件数も動かない**(正規化が行末の空白を落とすことの物理形)
- **1 件の写しに空行でない 1 行を足した写し**: その写しを含む組が (D) へ移って行数の組が出て、**ほかの組は動かない**(行数が段の下の 2 つだけを決めることの物理形)

写しはメモリの中だけで作る。置き場のファイルにも 3 枚の CSV にも 1 文字も書かない。

## 出力 — まとめてよいかも似ている度合いも返らない

`check` は件数と分母の内訳、`pairs` はそれに一覧を足す。返るのは次のものだけ。

- 3 枚の行数と写しの本数、分母(部品の件数 / 箇所の件数 / 写しが渡された箇所の件数 / 組の件数)
- 4 段、別枠 4、決めた正規化の 3 つ
- 部品ごと / 注記の組ごとの内訳、宣言されている箇所数の文字列と写しの件数、注記記号の登録表の写し
- 箇所が 1 行も無い部品、どの箇所も使っていない注記記号の登録、理由別の止まった件数

`pairs` で足されるのは、段ごとの一覧((C) は違う行の番号つき、(D) は行数の組つき)、上の 2 つの一覧、判定部分の sha256、読んだ条件。

**「まとめてよいか」「正本」「優先度」「類似度」「一致率」の欄は無い。** 出力の最後に並ぶ 12 行の「持たせていないもの」は消せない。

## 止まる理由コード(9 個)

表の側は 6 個。**どれか 1 つでも在れば、1 組も数えない**(4 段は全て 0)。

- 宣言の出典が空
- 部品 id の重複
- 箇所 id の重複
- 箇所が指す部品 id が部品の台帳に無い
- 同じ注記記号が登録表に 2 行ある
- 同じ部品の 2 箇所が同じ写しのファイルを指している

`verify` が見つけるのが 3 個 = 件数の合計が合わない / 2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる。

表として読めない形(列が無い / 行が無い / 登録の外の記号 / id が空か区切り文字を含む / 写しが置き場に無い / 置き場の外を指す / 写しが utf-8 として読めない)は終了コード 2 で、組は 1 つも数えない。

## 使い方

ひな型を出す。

```
python copy_grade.py init ひな型/
```

段に分ける。

```
python copy_grade.py check 部品の台帳.csv 箇所の台帳.csv 注記記号の登録表.csv 写しの置き場/
```

一覧つきで出す(違う行の番号と行数の組が付く)。

```
python copy_grade.py pairs 部品の台帳.csv 箇所の台帳.csv 注記記号の登録表.csv 写しの置き場/
```

この手続き自体が決定論かを実測する。

```
python copy_grade.py verify 部品の台帳.csv 箇所の台帳.csv 注記記号の登録表.csv 写しの置き場/
```

終了コードは、別枠と止まった行と (A) 以外の段が 0 件のときだけ 0、在れば 3、読めなければ 2。**0 は「まとめてよい」ではなく「渡された写しが全部そのままで同一だった」の意味。**


## できないこと

- **まとめてよいかは分からない。** 段を分けるところまでで、どの箇所をどう寄せるかは読む人が決める。(A) でも「消してよい」とは言っていない(呼んでいる側が在るかは見ていない)
- **振る舞いが同じかは分からない。** 実行も import も構文解析もしないので、(A) 以外の段がどれだけ挙動を変えるかは出力に出ない。逆に (A) でも、外側の文脈が違えば同じに動くとは言えない
- **どれくらい似ているかは分からない。** 段はちょうど一致の階段 4 つで、類似度も一致率も返さない。(C) で返るのは違う行の番号だけ
- **宣言されている箇所数が正しいかは分からない。** 渡された写しの件数と並べるだけで、`8+` が実際に何か所かは数えられない。写しを取りに行く経路が無い
- **注記が正しいかは分からない。** 3 枚は人が書くもので、この部品は注記と段を並べるだけだ。`指紋一致と注記` と書いてあって (B) に入っても、どちらが間違っているかは言わない
- **BOM や字下げの違いは「空白と改行だけの差」に入らない。** 正規化は行末の空白・改行・末尾の空行の 3 つだけで、先頭の BOM や字下げの差は (C) か (D) として出る
- 上の件数は合成した 3 枚と写し 18 本に対する測定で、ほかの人の環境で同じ数字になるとは限らない
