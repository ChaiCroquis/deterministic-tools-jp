# part_sum — 総数の宣言と、内訳の数を足した数を横に置く

解説記事: [総数の下に内訳が並んでいても足して総数になるとは限らないので、数の付いた項目と付いていない項目を分けてから足す](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post_23.html)(2026-11-24 公開)
<!-- article-links:end -->

資料の頭に総数が 1 つ書かれ、その下に内訳が並んでいるとき、内訳を足して総数になるとは限らない。
数の付いていない項目が混じり、「各 4」のように掛けて読む項目が混じり、単位の字が違う項目が混じる。
この部品は、**人が文書から写した 3 表**を読み、総数ごとに「足した数・総数の宣言・差・数の付いていない項目の名前」を
横に置くところで止まる。**差の理由は当てない。数を文書から自動で拾わない。掛け算で補わない。**
stdlib のみ(csv / argparse / json / re)、依存なし。

## 入力(3 表、UTF-8 の CSV)

| 表 | 列 |
|---|---|
| 総数の台帳 | 総数id / 数 / 単位 / 出典 |
| 内訳の台帳 | 項目id / 総数id / 項目の名前 / 数(空でもよい)/ 単位(空でもよい)/ 読みの種類 / 出典 |
| 読みの種類の登録表 | 読みの種類 / 足す側(`入れる` `入れない` `数が無い` のどれか) |

- 出典はどの行にも要る(ファイル名 + 行番号のように、元の場所へ戻れる字)
- 数は半角の整数だけ(`1,079` のような 3 桁ごとのカンマは読む)。`各 4` `4×4` `3 種` は整数でないので別枠に出る
- 読みの種類の字は自分で決めて登録表に書く。置き場の例は `そのまま写した`(入れる)/ `掛けて読んだ`(入れない)/ `記載なし`(数が無い)
- 単位は、数の横に書かれていた字をそのまま写す。書かれていなければ空にする

## 出力(総数ごと)

| 欄 | 意味 |
|---|---|
| 足した数(2 列) | `入れる` の項目だけの和 / `入れない` の項目も入れた場合の和 |
| 総数の宣言 | 総数の台帳に書かれた数 |
| 差(2 列) | 総数の宣言 − 足した数。負の数は、足した数が総数を超えたという意味 |
| 数の付いていない項目 | 件数と、名前と出典の一覧。足す側には入らない |
| 区分(2 列) | A 数の付いていない項目が 0 で差が 0 / B 数の付いていない項目が 0 で差が 0 でない / C 数の付いていない項目が在り、足した数が総数以下 / D 数の付いていない項目が在り、足した数が総数を超える |
| 出典の行ごとの小計 | 出典の字ごとに、`入れる` の項目数と小計 / `入れない` の項目数と小計 / 数の付いていない項目数 / 単位の字が違う項目数 |
| 印(区分に入れない) | 単位の字が総数と違う項目 / 同じ項目の名前が 2 回在る |

全体では、区分ごとの件数、読みの種類ごとの項目数、別枠の件数を返す。並びは総数の台帳の順 → 内訳の台帳の順で固定している。

別枠(どの和にも入れずに、行番号と理由を返す)は 6 つ。

| 理由 | 意味 |
|---|---|
| 登録表に無い読みの種類 | 読みの種類の字が登録表に無い |
| 属する総数idが台帳に無い | 総数の台帳に無い総数id を指している |
| 出典が空 | 元の場所へ戻れない |
| 同じ項目idが2回 | どちらを足すかを決めないので、両方とも別枠 |
| 数が整数でない | 掛け算の字・小数・全角数字など |
| 読みの種類と数の有無が合わない | `数が無い` の種類なのに数が入っている、またはその逆 |

総数の台帳と読みの種類の登録表が読めないとき(列が無い / 総数の数が整数でない / 総数の出典が空 / 同じ総数id が 2 回 /
足す側の字が 3 つに無い)は、1 件も足さずに止まる。

## いつも成り立つこと

内訳の台帳の 1 行は「`入れる` で足された / `入れない` で 2 列目にだけ足された / 数の付いていない項目として名前だけ出た / 別枠に出た」のどれか 1 つにだけ入り、**足した数は `入れる`(2 列目は `入れない` も)の項目の数の和と等しく、差は総数の宣言 − 足した数で、数の付いていない項目と別枠の行はどの和も 1 も動かさない**。

この 1 文は `tests/test_part_sum_property.py` が性質テスト(hypothesis)で確かめている。総数 1〜3 個と内訳 0〜12 行を乱数で作り
(数の字は整数・桁区切りつき・空・掛け算の字・小数、読みの種類は登録の 3 つと登録に無い字、出典は時々空、項目id はわざと重複させる)、
毎回この 1 文が成り立つかを見る(乱数は固定で、毎回同じ 300 通り)。足し算と行の仕分けは道具の関数を使わず、テストの中で別に書いている。
テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python part_sum.py --totals fixtures/shuuroku/totals.csv --parts fixtures/shuuroku/parts.csv --kinds fixtures/shuuroku/kinds.csv
python part_sum.py --totals <総数の台帳.csv> --parts <内訳の台帳.csv> --kinds <読みの種類の登録表.csv> --json
```

終了コードは 0 = 全ての総数が 2 列とも区分 A で別枠も 0 / 3 = それ以外(人が見る行がある)/ 2 = 表が読めない。
0 は「写した数を足すと総数の宣言と同じになった」であって、総数が正しいという意味ではない。

```python
import part_sum as P

r = P.tally(P.read_table("totals.csv", P.TOTAL_COLS),
            P.read_table("parts.csv", P.PART_COLS),
            P.read_table("kinds.csv", P.KIND_COLS))
for t in r["総数ごと"]:
    print(t["総数id"], t["総数の宣言"], t["足した数_入れるだけ"], t["差_入れるだけ"], t["区分_入れるだけ"])
    for u in t["数の付いていない項目"]:
        print("  数なし:", u["項目の名前"], u["出典"])
```


| `fixtures/kowashita/` | 合成を崩した内訳 9 行。別枠の理由 6 つに 1 行以上ずつ当たる |
| `fixtures/shuuroku/` | 私の収録範囲のメモ 1 文書の、見出し 1 行と内訳 4 行から私が写した登録表(総数 1 つ・内訳 36 行) |

`shuuroku` に入っているのは項目の名前と行数だけで、料率・金額・人の情報は 1 つも入っていない。出典はファイル名を伏せた行番号にしてある。

## できないこと

- 差の理由は返さない。数の付いていない項目が在っても、差がその項目の分だとは言えない(文書にそう書かれていない限り)
- 数は人が写す。写し間違いはこの部品では見つからない(出典の欄から元の行へ戻って人が確かめる)
- 「各 4」を 16 と読むかどうかは人が決めて、読みの種類で分けて書く。部品は掛け算をしない
- 単位の字が違う項目は印を付けるだけで、足す側から外しも換算もしない。外すなら人が読みの種類を変える
- 総数と内訳のどちらが正しいかは決めない。割合にも直さない
- 項目をいくつと数えるか(「健保/厚年」を 1 つと読むか 2 つと読むか)は台帳を書く人の読みに依る。同じ名前が 2 回在る印はその跡を見せるだけ
