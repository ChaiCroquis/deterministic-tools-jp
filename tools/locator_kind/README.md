# locator_kind — 原本の置き場が年度ごとにどう決まるかを、出どころごとに層で並べる

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [自動で差し替えると書いた数表も来年の原本の場所は別の話なので、置き場の決まり方を下の層まで並べる](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post_12.html)(2026-11-13 公開)
<!-- article-links:end -->

外から毎年配られる表を自動で取っている線は、取りに行く場所が取得先の台帳に在る間だけ動く。年度が替わったときに
次の原本の場所がどう決まるかは 1 つ下の層の話で、出どころごとに決まり方が別になる。この部品は、その決まり方を
**型から作る / 人が足す / 上流が運ぶ** の記号で宣言した台帳を読み、出どころごとに
rule → 出どころ → 置き場 → 決まり方 → 足す人と機会 → 版の記録の在り所 を 1 行に並べる。

**読むのは渡された 5 枚の表だけ。** ネットワークに出ない、ディスクを歩かない、場所の文字列を URL として読まない、
置き場が在るか・取れるかを確かめない。**来年の置き場を当てない。** 年度の記号は文字列のまま写し、数として読まない
(1 足さない、和暦と西暦を換算しない)。型を既存の場所から推し当てない。足し忘れの危なさに点数も順位も付けない。
時計を読まない。標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 5 枚(どの行にも出典の欄が要る)

| 表 | 列 |
|---|---|
| 置き場の台帳 | 置き場 id / 出どころ id / 年度の記号 / 場所 / 出典 |
| 出どころの台帳 | 出どころ id / 領域 / 決まり方の記号 / 型 id / 足す人と機会 / 版の記録の在り所 / 出典 |
| 決まり方の登録表 | 記号 / 意味 / 出典 |
| 型の台帳 | 型 id / 型 / 印に入れる欄名 / 出典 |
| 依存の台帳 | rule id / 出どころ id / 出典(1 行 = rule 1 つと出どころ 1 つ) |

年度の記号と場所は、渡された文字をそのまま写す(場所は空でもよい)。型は、置き換える印 `{N}` を 1 つ以上含む
文字列で、「印に入れる欄名」は置き場の台帳の `年度の記号` か `置き場 id`。決まり方の記号が空の出どころは
`決まり方の記載なし`、足す人と機会が空なら `足す人の記載なし`、版の記録の在り所が空なら `版の記録の記載なし` と出す
(補わない)。出典が空の行は、出どころの台帳なら別枠に出し、ほかの 4 枚なら使わずに「使わなかった行」に理由つきで返す。

## 区分(出どころ 1 件に 1 つ)

| 区分 | 条件 |
|---|---|
| (A) 型が宣言され、台帳の場所がすべて型と一致する | 記号が `型から作る` で、台帳に在る場所(1 行以上)がすべて、型の印に年度の記号を当てた文字列と 1 文字も違わない |
| (B) 型が宣言されているが、一致しない場所が在る | 同じ条件で、一致しない場所が 1 行以上在る(出典つきで並べる。どちらが正しいかは決めない) |
| (C) 人が足す | 記号が `人が足す` で、型 id が空 |
| (D) 上流が運ぶ | 記号が `上流が運ぶ` で、置き場の台帳に行が無く、型 id も空 |
| (E) A〜D に当たらない | 内訳 5 つ = 決まり方の記載なし / 型から作る なのに比べる場所が無い / 人が足す なのに型 id が在る / 上流が運ぶ なのに場所の行か型 id が在る / 登録表に在るその他の記号 |

別枠の理由は 6 つで、手前が勝つ: 出典が空 / 決まり方の記号が登録表に無い / 置き場 id が重複 / 型 id が型の台帳に無い /
`型から作る` なのに型 id が空 / 依存の台帳の出どころ id が出どころの台帳に無い。最後の 1 つは、依存の台帳にだけ出てくる
出どころ id を 1 件として数える(分母 = 出どころの台帳の行数 + 依存の台帳にだけ出る出どころ id の数)。

ほかに返すもの: rule ごとの、依存する出どころの数と決まり方の記号ごとの内訳(2 通り以上なら `決まり方が混ざる` の印だけ。
まとめるべきだとは言わない)。`--kigou` で年度の記号を 1 つ渡すと、(A) の出どころに限って、型の印をその記号で置き換えた
文字列を `型に当てた文字列` として返す。**その場所に何かが在るかは見ていない。** (B)(C)(D)(E) と別枠には返さない。
次の記号を道具が作る経路は無い。

## いつも成り立つこと

出どころ 1 件には、区分 5 つか別枠の理由 6 つのうち 1 つだけが付き、その合計は出どころの件数に等しく、表の行順を入れ替えても答えは変わらず、型に当てた文字列は (A) の出どころにだけ返り、渡した表は 1 文字も書き換わらない。

この 1 文は `tests/test_locator_kind_property.py` が性質テスト(hypothesis)で確かめている。5 枚の表を乱数で作り
(空の出典、登録に無い記号、台帳に無い型 id、重複した置き場 id、台帳に無い出どころ id、型と合わない場所を含む)、
区分はテストの中で別の書き方で引き直して比べる(道具の判定は呼ばない)。乱数は固定で、毎回同じ 300 通り。

## 使い方

```
python locator_kind.py check  places.csv origins.csv kinds.csv patterns.csv deps.csv [--kigou 記号]
python locator_kind.py rows   places.csv origins.csv kinds.csv patterns.csv deps.csv   # 出どころ 1 件 1 行の CSV
python locator_kind.py verify places.csv origins.csv kinds.csv patterns.csv deps.csv   # 5 つの検算
```

終了コードは 0 = 判定した / 3 = verify のどれかが合わない / 2 = 表の形の誤り(1 件も判定しない)。
表の形の誤り = 列が無い、出どころ id・記号・型 id の重複や空、型に印 `{N}` が無い、印に入れる欄名が上の 2 つでない。

`verify` が見る 5 つ: 二度走って同じ指紋(sha256)か / 5 枚の行順を入れ替えても同じ出力か /
区分 + 別枠 = 出どころの件数か / (A) の出どころの場所を 1 行だけ 1 文字替えると、その出どころだけ (B) に動くか /
出どころ 1 つの記号を `型から作る` から `人が足す` に替えて型 id を空にすると、その出どころと、そこに依存する rule の
内訳だけが変わるか。写しはメモリの中だけで作る。

```python
import locator_kind as L
tables = L.read_all(["places.csv", "origins.csv", "kinds.csv", "patterns.csv", "deps.csv"])
result = L.judge(tables, kigou=None)   # 区分 / 別枠 / 出どころごと(層の 1 行つき)/ rule ごと
```

  試験では最後の 1 本でだけ通す

## できないこと

- 来年の置き場を当てない。`型に当てた文字列` は文字の置き換えの結果で、そこに何かが置かれるとは言っていない
- 置き場が在るか、取れるかを確かめない(取りに行かない)
- 型が正しいかは確かめない。(A) が言うのは「台帳の中で、型と場所の文字列が食い違っていない」まで
- 決まり方の記号が正しいかは確かめない。宣言された記号を登録表に当てるだけ
- 人が足す層で、足されたかどうかは見ない。足し忘れの危なさの点数も順位も持たない
- 年度の記号の次を作らない。`6` と `R6` が同じ年度かどうかも知らない
- 一致しない場所が在っても、型と場所のどちらが正しいとも言わない
