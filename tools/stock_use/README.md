# stock_use — 置き場に取ってきた原本の本数と、後の文書で使われたと書かれた記載を並べる

公式の原本やファイルを取ってきて置き場に置いた本数と、後の文書の出典の欄にそれが使われたと書かれた数は、別の数になる。
置き場の本数を「使った数」「収録の根拠の数」と読むと、もっともらしく違う数が生まれる。この部品は、**人が台帳に書いた分だけ**を使って、
置き場の種類ごとに、取得の本数と、使われた記載 / 未抽出や次の作業の欄にだけ在る記載 / 読んだ範囲に記載なし、を 5 つに分けて並べる。
差は、両側に数が literal に在るときだけ整数で出す。

**フォルダを数えない。** ディレクトリを読む経路は無く、本数は人が台帳に書いた数だけを使う。
**ファイル名から使い道を当てない。** どの記載をどの置き場の種類に当てるかは、人が対の登録表に書く。
差がどのファイルかを推し当てない。消してよいか・要らないかを決めない。滞留の理由を当てない(理由の欄が無い)。
置き場を「使っている / いない」の 1 値に丸めない。利用率・合計の 1 値を出さない。「多い」「少ない」と書かない(出力は件数だけ)。
ネットワークに出ない、渡されたファイルの外を読まない、時計を読まない、入力を書き換えない、float を使わない。
標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 4 枚(どの行にも出典の欄が要る)

| 表 | 列 |
|---|---|
| 置き場の台帳 | 置き場 id / 種類(`PDF` `HTML` `page` `xlsx` などを verbatim)/ 取得の本数 / 出典 |
| 記載の台帳 | 記載 id / 記号 / 名指された数 / 後の側の文字列(verbatim)/ 出典 |
| 記号の登録表 | 記号 / 意味 / 要求する欄(記載の台帳の欄の名前を `/` で区切る)/ 出典 |
| 対の登録表 | 記載 id / 置き場 id / 種類 / 出典 |

取得の本数は、文書に数字が在るときだけ整数で書く。`×` の無い 1 件書き(「press PDF」)は 1、数字が無ければ空にする。
名指された数は、後の側の記載が名指している数(年度の記号の数、題の数など)を人が数えて整数で書く。数えられなければ空にする。

記号は 6 つ: `出典の欄に在る` / `検証の欄に在る` / `未抽出の欄に在る` / `次の作業の欄に在る` / `読んだ範囲に記載なし` /
`置き場と書き手の言い方が違う`。どの行がどの記号かは**台帳を書く人が決める**。道具は文字を読んで記号を当てない。

## 5 値(置き場の種類の行 1 つに 1 つ)

| 5 値 | 条件 |
|---|---|
| (A) 使われた記載が在り、本数と名指された数が一致 | `出典の欄に在る` か `検証の欄に在る` の記載が在り、取得の本数と名指された数が literal に一致 |
| (B) 使われた記載が在り、本数と名指された数が一致しない | 同じく両側に数が在って一致しない。差(取得の本数 − 名指された数)を整数で返す。どのファイルが差かは返さない |
| (C) 使われた記載は在るが、比べる数が片側に無い | 取得の本数が空、名指された数がどの記載にも無い、または記載ごとに名指された数が違う(比べない訳を返す) |
| (D) 未抽出か次の作業の欄にだけ記載が在る | 使われた記載が無く、`未抽出の欄に在る` か `次の作業の欄に在る` の記載が在る |
| (E) 読んだ範囲に記載なし | 上のどれも無い。「使っていない」「要らない」とは言わない |

`置き場と書き手の言い方が違う` は区分に効かせず、別の列に並べる。

別枠の理由は 6 つで、手前が勝つ: 出典が空 / 取得の本数が整数でない / 台帳に無い id を指す対 / 登録表に無い記号 / id の重複 /
同じ種類に (A)(B) と (E) が同時に書かれた。id の重複には、置き場の種類の行の重複、記載 id の重複、1 つの記載を 2 つの種類に当てた対を含む。
記号が要求する欄が空のときも「出典が空」に入れる。

ほかに返すもの:

- 置き場ごとに 1 行 = 種類の数と、5 値 + 別枠の内訳。**置き場を 1 値に丸めない**
- どの種類にも当てていない記載(対の登録表に出てこない記載)の id と記号
- 台帳に無い置き場を指す対の数

補助として `words` が、指定した語が後の文書の指定した行の範囲に何回出るかを literal 一致で数える。この件数は判定に使わない。
0 件でも (E) に自動では入れない(人が台帳に書いた分だけが判定に使われる)。

## いつも成り立つこと

置き場の種類の行 1 つには 5 値か別枠の理由 6 つのうち 1 つだけが付き、その合計は置き場の種類の行数に、置き場ごとの内訳の合計はその置き場の種類の数に等しく、差は (B) の行にだけ 0 でない整数で付き、記載の台帳の行順を入れ替えても答えは変わらず、渡した表は 1 文字も書き換わらない。

この 1 文は `tests/test_stock_use_property.py` が性質テスト(hypothesis)で確かめている。4 枚の表を乱数で作り
(空の出典、整数でない本数、空の本数、台帳に無い記載 id と置き場、登録表に無い記号、重複した種類と記載 id、
1 つの記載を 2 つの種類に当てた対、使われた記載と記載なしの同居、言い方の違いを混ぜる)、
5 値と別枠と差はテストの中で別の書き方で引き直して比べる(道具の判定は呼ばない)。乱数は固定で、毎回同じ 300 通り。

## 使い方

```
python stock_use.py check  okiba.csv kisai.csv kigou.csv tsui.csv
python stock_use.py rows   okiba.csv kisai.csv kigou.csv tsui.csv   # 置き場の種類 1 行の CSV
python stock_use.py verify okiba.csv kisai.csv kigou.csv tsui.csv   # 5 つの検算
python stock_use.py words  later.md HTML page hirei --lines 1-150     # 補助の語数え(判定に使わない)
```

終了コードは 0 = 判定した / 3 = verify のどれかが合わない / 2 = 表の形の誤り(1 件も判定しない)。
表の形の誤り = 列が無い、記号の登録表の空・重複、道具が意味を持たない記号の登録、要求する欄に記載の台帳以外の欄の名前、
置き場 id・種類・記載 id の空、名指された数に整数以外、`--lines` が `1-150` の形でない。

`verify` が見る 5 つ: 二度走って同じ指紋(sha256)か / 記載の台帳の行順を入れ替えても同じ出力か /
5 値 + 別枠 = 置き場の種類の件数で、置き場ごとの内訳の合計 = その置き場の種類の数か /
記載がちょうど 1 行の種類からその 1 行を消すと、その種類だけが動き他は変わらないか /
(A) の種類の取得の本数を 1 増やすと、その種類だけが (B) へ動き差が 1 になるか。写しはメモリの中だけで作る。

```python
import stock_use as M
tables = M.read_all(["okiba.csv", "kisai.csv", "kigou.csv", "tsui.csv"])
result = M.judge(tables)   # 5 値 / 別枠 / 置き場の種類ごと / 置き場ごと / 当てていない記載 / 判定部分の sha256
```

`fixtures/gousei/` は合成した 4 枚(架空の店の、取引先から取ってきたファイルの置き場と月次の作業記録)。
`examples/temoto/` は、私の手元の作業状況の記録 1 枚から、置き場 3 つ・種類 7 つの本数と、私が読んで書いた記載 11 行を写した 4 枚。

テストの実行には別に pytest と hypothesis が要る。ライセンスは MIT。
