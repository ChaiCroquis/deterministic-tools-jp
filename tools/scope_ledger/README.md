記事や README の「できないこと」の節には、**その引数が無い / その経路が無い** と書いてある。
それは宣言であって、宣言は文章だ。**文章は読み手の側では確かめられない。**

この部品は、宣言のうち機械で見られる形のものだけを、名指しされた経路が対象のソースに静的に現れるかで
突き合わせ、**宣言どおり / 一致しない / 宣言が無い / 機械では読めない** の 4 値を、分母の内訳つきで
台帳に残す。対象は **実行しない。import もしない**(読むのは構文木だけ)。走らせる側は
[check_census](../check_census) で、こちらは走らせずに「無いと書いたものが無いか」を見る側になる。

持たせていないものが規律になっている。

- **対象を実行しない。import もしない**(読むのは構文木だけ。`subprocess` も `importlib` も持たない)
- **ネットワークを持たない**(取りに行く経路が無い。読むのは宣言表と、名指しされたソースだけ)
- **宣言の文から種類を推測しない**(種類の欄が空なら「機械では読めない」に落ちる。自然文を解釈して
  判定する経路が無い)
- **一致しない行をそれ以上の言葉にしない**(嘘・違反・不正と書く経路が無く、理由も推定しない。出すのは
  宣言の verbatim と現れた行番号だけ。[cross_route](../cross_route) / [intake_triage](../intake_triage) と同じ規律)
- **遵守率を単独で返さない**(4 値の件数と分母の内訳を必ず併記する。[check_census](../check_census) と同じ)
- **ソースも宣言表も書き換えない**(直す・生成する・宣言を書き戻す経路が無い)
- **出典の欄が空の行は判定せずに止まる**(誰の宣言かを辿れない行を台帳に入れない)
- **同じ道具名と線の名前の行が 2 件以上あれば止まる**(近い行で埋めない)
- **追えない形を黙って「宣言どおり」にしない**(別名での取り込み・再公開・動的な属性参照は追わず、
  「機械では読めない」に落とす。見えなかったことを守られていることの代わりにしない)

## 流れ(固定)

```
宣言表を読む → 出典が埋まっているか → 道具名 + 線の名前が 1 件か → 種類が 5 種のどれか
  → 対象ソースを構文木として読む → 名指しの経路が現れるかを見て 4 値に分ける
  → 件数と分母の内訳を出す → verify で 2 回目の判定部分と sha256 を突き合わせる
```

前の段で止まったら **1 行も判定しない**。止まったときは台帳が 1 行も返らず、理由コード 6 個のどれかだけが返る。

## いつも成り立つこと

台帳の結果は 2 通りしかない。

- 宣言表の行のひとつひとつがちょうど 1 つの判定(宣言どおり / 一致しない / 宣言が無い / 機械では読めない)に
  入り、その合計が宣言表の行数に等しく、宣言の欄が空の行は必ず「宣言が無い」、種類の欄が空で宣言がある行は
  必ず「機械では読めない」、「一致しない」の行には現れた行番号が 1 つ以上あって他の 3 値には 1 つも無く、
  どの行にも出典が残り、判定部分のバイト列に時刻・ホスト名・絶対パスが 1 つも入らない
- または、判定が 1 件も返らず理由コードが返る(台帳を取りに行くと例外になる)

どちらの場合も、この部品は対象のソースも宣言表も 1 文字も書き換えない。

この 1 文を `tests/test_scope_ledger_property.py` の `@given` テストが確かめている(宣言表を毎回乱数で
作り直し、1 行ごとに 13 とおりの在り方から引き、3 割くらいの確率で表のどこか 1 か所を崩す。乱数は固定で
毎回同じ 60 通り)。**期待する判定は部品の判定を呼ばずにテストの側で持っている。**

## 入力 — 宣言表 1 枚だけ

| 欄 | 何を宣言するか |
|---|---|
| `tool` | 道具名 |
| `line` | 線の名前(「外向きの通信を持たない」など) |
| `declaration` | 宣言の verbatim。**空欄はこの線について宣言が無いことを意味する** |
| `source` | その宣言の出典(ファイル名 + 行番号)。空欄は止まる |
| `kind` | 機械判定の種類。`import` / `call` / `kwarg` / `option` / `write` の 5 種か空欄 |
| `target` | 名指しの対象(`urllib` / `eval` / `shell=True` / `resolve:fallback` / `open` など) |
| `path` | 対象ソースのパス(宣言表のある場所からの相対、または絶対) |

`kind` が空欄の行は「機械では読めない」に落ちる。**宣言の文から種類を埋める経路は無い。**

## 機械判定の種類(5 種)

| 種類 | 見るもの | 名指しの書き方 |
|---|---|---|
| `import` | 名指しのモジュールを取り込んでいないか | `urllib`(`import urllib.request` も `from urllib import request` も当たる) |
| `call` | 名指しの呼び出しが無いか | `eval`(`Name` か属性の末尾が一致) |
| `kwarg` | 名指しのキーワード引数が無いか | `shell` か `shell=True`(値まで名指しできる) |
| `option` | 引数定義に名指しの文字列が無いか | `prefer` / `resolve:fallback`(`関数名:引数名` でその関数の定義だけを見る) |
| `write` | 名指しの書き込み経路が無いか | `open`(モードの literal に `w` / `a` / `x` / `+` を含む呼び出しだけ数える) |

`option` を関数名で絞らない書き方にすると、関数の引数定義と `add_argument` の文字列の両方を見る。

## 判定は 4 値

| 判定 | 入る行 |
|---|---|
| 宣言どおり | 名指しの経路がソースに現れない |
| 一致しない | 現れた(**現れた行番号つき**。言葉は足さない) |
| 宣言が無い | その線について宣言表の `declaration` が空(出典にはどこを見たかが残る) |
| 機械では読めない | 理由コード 4 個のどれか(下記) |

「機械では読めない」の理由コードは 4 個だけ。

```
種類の欄が無い / 対象が Python でない / 構文解析できない / 名前が動的に組み立てられている
```

最後の 1 つが肝になる。`getattr` に変数の名前を渡す形、`open` のモードを変数で渡す形、キーワードを
`**` で展開する形、取り込みの名前を `import_module` に変数で渡す形は、構文では追えない。
**そこを黙って「宣言どおり」に寄せない。**

同じソースに「現れた行」と「追えない形」が両方あるときは、**一致しない側に入れる**(確かに現れた事実が
先に立つ)。

## 遵守率は分子分母だけでは返らない

`rate()` が返すのは 4 値の件数、分母の内訳(宣言表の行数 / 機械で読めた数 / 読めなかった数 /
宣言が無い数)、2 つの遵守率、そして「機械では読めない行を宣言どおりに寄せていない」の 1 行だ。
**遵守率だけを返す呼び方も、option も無い。**

```
"遵守率_機械で読めた行のみ": "0.7500", "遵守率_宣言表の行すべて": "0.3529"
```

同じ台帳から 2 つ出る。読めなかった行と宣言が無い行を分母から落とすと上振れするので、
片方だけを引用できない形にしてある。

## 台帳の判定部分は決定論

判定部分に入るのは 7 欄だけで、この順に固定されている。

```
道具名 / 線の名前 / 判定 / 理由コード / 現れた行 / 宣言 / 出典
```

**絶対パス・読んだ時刻・ホスト名は判定部分に入れない**(別の欄「読んだ条件」に出し、sha256 の対象から
外す)。`verify` は 2 回判定して判定部分のバイト列の sha256 を突き合わせ、一致しなければ
**どの行のどの欄が違ったかを観測としてそのまま返す**(平均も多数決もしない)。

## 止まる理由コード(6 個)

```
出典の欄が空 / 対象ソースのパスが無い / 機械判定の種類が 5 種の外 /
名指しの対象の欄が空 / 同じ道具名と線の名前の行が 2 件以上 /
2 回目の判定部分がバイト列として不一致
```

列そのものが足りない宣言表は理由コードにせず、「宣言表として読めない」として終了コード 2 で返す
(宣言表を書く側の話なので、台帳の理由コードに混ぜない)。

## 使い方

```bash
python scope_ledger.py init 宣言表.csv        # ひな型を書く
python scope_ledger.py ledger 宣言表.csv      # 台帳にする(一致しない行があれば終了コード 3)
python scope_ledger.py verify 宣言表.csv      # 2 回判定して判定部分の sha256 を突き合わせる
```

関数としても同じ形で呼べる。

```python
from scope_ledger import Declaration, ledger

lg = ledger(Declaration.load("宣言表.csv"))
print(lg.rate() if lg.report.ok else [x.reason for x in lg.report.pending])
```

CLI の option は `-h` 以外に 1 つも無く、そのこともテストで固定してある。

## 読み替えた範囲(「線の上を歩いている当事者」の型)

- 主体 = 公開済みの道具 1 本ずつ(17 本)
- 触れている線 = 機械が決めてよいところと人が決めるところの境目
- 当事者の説明 = 記事の「できないこと」節と README に書いた宣言の verbatim(一次出典が手元にある)
- 規制側の反応 = 静的な突合の結果

主体が人でないので意図の推定が構造的に起きない代わりに、**見えるのは構文の形までで、振る舞いは見えない**。
一致しない行には行番号と verbatim だけを置き、言葉を足していない。

## できないこと

- 判定したことは「名指しされた経路が静的に現れないか」までで、**道具が宣言どおり振る舞うことは判定しない**
- **宣言が十分かも判定しない**。書かれていない線の良し悪しも、線の引き方の妥当性も見ない
- **現れた行がその宣言の対象の経路かどうかは分からない**。名指しは関数を特定しないので、同じ名前が別の
  経路で現れても当たる。そこを確かめるのは人の側になる
- 別名での取り込み・再公開・動的な属性参照は追わない。追えない形は「機械では読めない」に落ちるだけで、
  **そこに何が在るかは分からない**
- Python でない対象は読めない。他の言語のソースも、設定ファイルも、ドキュメントも対象の外
- 文章だけの宣言(「推定しない」「解釈しない」のような、経路として名指しできないもの)は原理的に
  この部品の外になる。**それが読めないことは、守られていないことではない**
- 宣言表の正しさは判定しない。宣言の verbatim が原文と一致しているか、種類と名指しの対象がその宣言の
  意味に合っているかは、宣言表を書く人の側になる
- 上の件数は、合成の対象とこの repo の 17 本に対する測定で、他の人の手元で同じ数字になるとは限らない
