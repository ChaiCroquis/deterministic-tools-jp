# intake_csv — 取込用 CSV を書いたら、読み戻して元データと突き合わせる

取込側が要求する形(cp932 / CRLF / クォート無し)で CSV を書くと、書いた瞬間には気づけない壊れ方をする。
値の中のカンマで列がずれ、cp932 に無い文字が置換文字に化け、cp932 に書けても読み戻すと別の字になる文字がある。
この部品は書き出しを「書いて終わり」にせず、**出力ファイルを取込側と同じ読み方で読み戻し、元データから数えた
件数・指定列の合計・全セルの文字列と突き合わせる**。合わなければ作業ファイルを消して止まる。
**差の原因は推定しない。どちらが正しいとも決めない。** stdlib のみ(csv / decimal / argparse)、依存なし。

## 流れ(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | 列仕様の表を読む(列の順・見出し・型・桁・ゼロ埋め・空を許すか・合計を取るか) | 型が表に無い / 見出しが重複 |
| 2 | 元データと列仕様を突き合わせる | 列が足りない(空欄で埋めない)。仕様に無い列は書かないで列名を返す |
| 3 | 値を検査する | 判断待ちの理由コード 8 種(下の表)。1 件でもあれば出力を作らない |
| 4 | 作業ファイル(`<出力先>.tmp`)に cp932 / CRLF / クォート無しで書く | cp932 で書けない字は例外(置換文字で書き進めない) |
| 5 | 作業ファイルを読み戻して、見出し・件数・合計・全セルを突き合わせる | 1 つでも差があれば作業ファイルを消す |
| 6 | 通ったものだけ本来の名前にする(`os.replace`) | — |

判断待ちが残っているあいだ、取込側に渡るファイルは作られない。半端な出力を渡さないための順番になっている。

## 判断待ちの理由コード(`REASONS`)

| 理由コード | 意味 |
|---|---|
| 必要な値が空 | 空を許さない列が空。空欄で埋めると取込側では別の意味になる |
| 数字でない | 整数・金額・コードの列に、符号と数字以外が入っている(全角数字・桁区切りのカンマ・U+2010 のハイフンを含む) |
| 桁あふれ | 列仕様の桁を超えている。切り詰めると別の値になる |
| 改行が値の中にある | 1 行 1 レコードの形と両立しない |
| 引用符が値の中にある | クォート無しの要求と両立しない |
| 区切り文字が値の中にある | クォート無しで書くと列がずれる。クォートで逃がすと取込側が読めない |
| cp932 に無い文字 | cp932 で表せない。置換文字で書き進めると元の字が失われる |
| 書いて読むと別の文字になる | cp932 に書けるが、読み戻すと別の符号位置の字になる(多対一の対応) |

理由コードは「機械では決まらない理由」の名前になっている。どう直すかは人が決める。

## cp932 に無い文字は、思っているものと違う

`髙`(U+9AD9)`﨑`(U+FA11)`㈱`(U+3231)`①`(U+2460)は cp932 にある(NEC / IBM の拡張)。半角カナもある。
書けないのは `😀` `𠮷`(サロゲートペア)`½` `€` `✓` `♬` `—`(U+2014 のダッシュ)などで、外から貼られた文字に多い。

さらにややこしいのが、**書けるのに読み戻すと別の字になる**組み合わせだ。

| 元の字 | cp932 | 読み戻すと |
|---|---|---|
| `〜` 波ダッシュ U+301C | 0x8160 | `～` 全角チルダ U+FF5E |
| `−` 負符号 U+2212 | 0x817C | `－` 全角ハイフンマイナス U+FF0D |

cp932 側の 1 つの符号に Unicode 側の 2 つの字が対応しているので、往復しても元に戻らない。
`errors="strict"` でも例外にならないので、書いた側では気づけない。この部品はこれを検査でも読み戻しでも拾う。

## 使い方

```
python intake_csv.py <元データ.csv> <出力先.csv> --spec <列仕様.csv>
python intake_csv.py <元データ.csv> --spec <列仕様.csv> --check      # 検査だけ(書かない)
python intake_csv.py <元データ.csv> <出力先.csv> --spec <列仕様.csv> --naive   # 比較用(検査も読み戻しもしない)
```

終了コードは 0 = 書いて読み戻しも一致 / 3 = 判断待ちか突合の差で書かなかった / 2 = 列仕様か読み書きの誤り。
バッチの中に置いて、3 で止められる。

```python
from intake_csv import Spec, write, read_back, verify, check_rows

spec = Spec.from_csv("retsu_shiyou.csv")
r = write("torikomi.csv", spec, rows)        # rows = list[dict[str, str]]
if not r.ok:
    for p in r.pending:
        print(p.row, p.column, p.reason, p.value)      # 判断待ち(この時点で出力ファイルは無い)
    for d in r.diffs:
        print(d.row, d.column, d.original, d.readback)  # 突合の差
else:
    print(r.count, r.totals)                 # 書いた件数と、合計を取る列の合計
```

## 列仕様の表

`fixtures/retsu_shiyou.csv` が例。列は 6 つで、`○` / `1` / `はい` を書けば有効になる。

| 欄 | 意味 |
|---|---|
| 見出し | 出力の見出し。並び順が出力の列順になる |
| 型 | 文字列 / 整数 / 金額 / コード |
| 桁 | 文字数の上限(0 = 制限なし)。超えたら切り詰めずに判断待ち |
| ゼロ埋め | コードの先頭ゼロを桁までそろえる |
| 空を許す | 空欄を許す列に印を付ける(既定は許さない) |
| 合計 | 読み戻しで合計を突き合わせる列(整数と金額だけ) |

自分の取込仕様に合わせるときは、この CSV を差し替える。部品のコードは触らない。


fixture は全て合成データで、氏名・部署・金額はすべて架空。`shikyu_koujo.csv` は 17 行で、1 行につき 1 か所だけ
問題を仕込み、期待する結果を「期待」列に書いてある(「備考」「期待」は列仕様に無いので出力には書かれない)。
`test_measure_*` は合成 1,000 行で、検査も読み戻しもしない書き出しとこの部品を比べる。固定 seed(20260926)で
決定論的に再現し、記事に載せた数値はこのテストが `assert` で固定している。

## できないこと

- 桁は**文字数**で数える。取込側がバイト数で桁を決めている仕様には合わない(列仕様に持たせていない)
- 区切り文字・文字コード・改行は cp932 / CRLF / カンマ固定。TSV や UTF-8 の取込仕様には使えない
- 差の原因は推定しない。元データと読み戻しのどちらが正しいかも決めない
- 読み戻しは自分が書いたファイルを読むだけで、取込側が実際にどう解釈するかは確かめていない
- 数値は文字列のまま出す(丸めない)。丸めが要る仕様なら、渡す前に人が決める
- 判断待ちの行を自動で直す機能は無い(直し方が業務の判断になるため)
