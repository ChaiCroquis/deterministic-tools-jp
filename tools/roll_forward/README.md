# roll_forward — いまの総行数が合っていても途中の増減は消えるので、期首と増減を回ごとに歩いて総数に当てる

文書に書いた総数は、ある時点の残高の写しで、どの作業で何件増えて何件減ったかは総数からは読めない。この部品は、増減の台帳を期首から 1 回ずつ歩き(前の回の累計 + 増えた件数 − 減った件数 = その回の累計)、文書に書かれた総数がどの回の累計に当たるかを返す。**行の中身は読まない。台帳と文書のどちらが正しいかも決めない。**

```
python roll_forward.py check 増減の台帳.csv 状態の記号の登録表.csv 総数の宣言の台帳.csv
```

## 持たせていないもの

- **行の中身を読まない**。入るのは件数と記号と出典だけで、増えた行・減った行が何であったかは見ない
- **指紋を比べない**。出力の指紋の列を持たない(差分の件数と指紋の 2 経路を並べるのは `diff_tally` の仕事)
- **足りない回を補わない**。台帳に行として無い回は歩かない
- **空を 0 にしない**。増減の欄が空の回は `欄が無い` のまま前の回の累計を引き継ぐ。3 欄の一部だけが空の行は読めない件数として止まる
- **正しい側の列が無い**。当たる回が在るか無いかだけを返す
- **一致率を出さない**。当たる回が在る宣言の件数と宣言の総件数を必ず並べる
- **原因を言い当てない**。当たる回なしのときに出すのは、最も近い累計との差(符号つきの整数)だけ
- **どの回が「その宣言の時点」かを選ばない**。累計が一致した回を全部返す。時計も読まない(時刻は渡された文字列を写すだけで、並べる鍵は回 id)
- **入力を書き換えない**。**float を使わない**。**通信しない**

## 入力 — 3 表

**どの行にも出典の欄が要る。** 空の行が 1 つでも在れば、1 回も歩かずに止まる。文字コードは UTF-8。

### 増減の台帳(9 列)

| 列 | 中身 |
|---|---|
| `run_id` | 回 id。**並べる鍵はこの文字列の順**(`R01` `R02` のように桁をそろえる)。同じ id が 2 行あると読めない |
| `run_at` | 時刻。渡された文字列をそのまま写す(読まない) |
| `status` | 状態の記号(登録表に無ければ止まる) |
| `added` | 増えた件数。0 以上の整数か、空(= 欄が無い) |
| `removed` | 減った件数。同じ |
| `changed` | 中身が替わった件数。同じ。**累計の式には入れず、隣の列に写すだけ** |
| `opening` | 期首の印。最初の回に `期首`、ほかは空。1 件でなければ止まる |
| `unit` | 単位の名前(`行` など)。台帳の中で 1 つにそろえる |
| `source` | 出典(ファイル名 + 行番号) |

```csv
run_id,run_at,status,added,removed,changed,opening,unit,source
R01,T01,S1,1301,0,0,期首,行,合成の実行履歴のメモ(架空)L1
R03,T03,S2,,,,,行,合成の実行履歴のメモ(架空)L3
R08,T08,S1,341,141,1,,行,合成の実行履歴のメモ(架空)L8
```

### 状態の記号の登録表(4 列)

| 列 | 中身 |
|---|---|
| `status` | 記号 |
| `meaning` | `通った` か `落ちた` |
| `needs_delta` | 増減の欄が要るか。`要る` か `要らない` |
| `source` | 出典 |

登録と欄の有無が食い違う回(要るのに無い / 要らないのに在る)は、止めずに別の一覧へ出す。

### 総数の宣言の台帳(5 列)

| 列 | 中身 |
|---|---|
| `claim_id` | 宣言 id |
| `total` | 総数(0 以上の整数。桁区切りのカンマは入れない) |
| `unit` | 単位の名前。**台帳と違えば、比べずに止まる** |
| `quote` | その総数を書いた文の写し |
| `source` | 出典 |

## 出力

- **回ごとに 1 行**: 回 id / 前の回の累計 / 増 / 減 / その回の累計 / 替わった件数 / 区分 / 印 / 出典
- **区分は 4 値**: (A) 増か減の片方だけが在り累計が動いた / (B) 増減が 0 で累計が動かない / (C) 増と減が両方在る(純増減と総増減を並べる)/ (D) 増減の欄が無い(累計は前の回のまま。0 とは書かない)
- **宣言ごとに 1 行**: 総数 / 累計が一致した回の一覧(在るだけ全部)/ 引き継ぎで同じ値になっている (D) の回(別の欄)/ 一致した回が無ければ `当たる回なし` と最も近い累計との差
- **文書に現れない累計**: どの宣言にも当たらない累計の値と、その回
- `check` は件数だけ、`rows` は回と宣言の一覧つき、`verify` は 5 つの検査

## 止まる理由(6 つ)

どれか 1 つでも在れば、1 回も歩かない(区分は全て 0、回の件数はそのまま別枠に入る)。

| コード | 理由 |
|---|---|
| E1 | 出典が空 |
| E2 | 状態の記号が登録表に無い |
| E3 | 期首の印が 1 件でない、先頭の回に無い、または期首の回に増減の欄が無い |
| E4 | 件数が負か整数でない(3 欄の一部だけが空の行も含む) |
| E5 | 累計が負になる(在る以上に減った) |
| E6 | 単位の名前が空か、台帳と宣言で違う |

列が無い・行が無い・id の重複・登録表の値が決めた語でない、は「表として読めない」で、理由コードの前に止まる。

## verify が見る 5 つ

- 二度走って、判定部分の sha256 が同じか
- 宣言の台帳の行順を入れ替えても同じ出力か
- 区分 4 値 + 別枠の合計が回の件数に等しいか
- 1 回の増えた件数を 1 増やした写しで、その回以降の累計がすべて 1 増え、それより前は変わらないか
- 1 回の増減を空にした写しで、その回だけ (D) へ移り、前の回の累計を引き継ぐか

写しはメモリの中だけで、入力の表には書かない。

## いつも成り立つこと

読んだ結果は 2 通りしかない。回ごとに区分が 1 つ付いて 4 値の合計が回の件数に等しく、どの回の累計も「前の回の累計 + 増 − 減」(増減の欄が無い回は前の回の累計のまま)に等しくて負にならず、当たる回が在る宣言はその回の累計が総数に等しく、当たる回なしの宣言の総数はどの累計とも違い、替わった件数をいくつ増やしても累計は動かないか、1 回も歩かずに理由コードが 1 つ以上返って区分が全て 0 になるか、のどちらかで、どちらの場合も入力は 1 文字も書き換わらない。

`tests/test_roll_forward_property.py` がこの 1 文を確かめる。累計の足し直しと宣言の突き合わせは、道具の関数を使わずテストの中で別に書いてある。

## 試験

```
python -m pytest tools/roll_forward -q
```

`fixtures/` の 3 表は合成で、実在の記録の写しではない(回 id・状態は記号、時刻は `T01` のような記号、出典は「合成の…(架空)」)。

## 終了コード

- 0: 全ての宣言に当たる回が在る(**総数が台帳と合うという意味で、行の中身が正しいという意味ではない**)
- 1: 当たる回なしの宣言が在る
- 2: 1 回も歩かずに止まった、または表として読めない
