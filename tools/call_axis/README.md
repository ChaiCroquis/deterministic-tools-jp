# call_axis — 式が呼べる語の一覧を、登録した働きの記号の軸で並べ直し、式の側と検証の側の記載を横に置く

計算の仕方を式として data に持つと、「式の中で呼んでよい語はこれだけ」という閉じた一覧ができる。
ただし一覧は書かれた順に名前が並んでいるだけで、どの語が表を引き、どの語が端数を落とし、どの語が大小で選ぶのか、
その語の境目を確かめた記載が在るのかは、一覧からは読めない。
この部品は、**同じ一覧を人が登録した「働きの記号」の軸で並べ直し、式の一覧の側の記載と検証の表の側の記載を、
人が対の登録表に書いた分だけ横に置く**。
**式を読まない・評価しない・走らせない。語の名前から働きを当てない。名前の似かたで記載と結び付けない。
記載が無い語を「未検証」「危険」と評価しない。**
標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 4 表(どの行にも出典の欄が要る)

| 表 | 列 | 書くこと |
|---|---|---|
| 語の台帳 | `word_id, word, order, role, source` | 呼べる語を原文のまま `word` に写す。`order` は旧軸(一覧に書かれた順)の整数。`role` は働きの記号 |
| 働きの登録表 | `role, edge, source` | 働きの記号を人が登録する。境目を持つ働きだけ `edge` に `境目` と書く |
| 記載の台帳 | `note_id, side, text, result, source` | `side` は `式の一覧` か `検証の表`。`text` は記載を原文のまま、`result` は結果の文字列(在る分だけ) |
| 対の登録表 | `word_id, note_id, source` | 語と記載の対応。人が書いた分だけ |

`source` を `<文書の名前> L<行番号>` の形にしておくと、`--doc` で文書の行の写しと突き合わせられる。

## 出力

語ごとに、旧軸の順 / 働きの記号 / 式の側の記載と出典 / 検証の側の記載・結果と出典 / 区分 / 印 が返る。
並びは 働きの記号 → 旧軸の順 で固定(働きの記号は文字コードの順)。別枠の語はその後ろに並ぶ。

| 区分 | 意味 |
|---|---|
| (A) 式の側にも検証の側にも記載が在る | 両方の側に対が 1 つ以上在る |
| (B) 検証の側だけに記載が在る | 検証の表の側の対だけが在る |
| (C) 式の側だけに記載が在る | 式の一覧の側の対だけが在る |
| (D) 読んだ範囲に記載なし | 対が 1 行も無い(試験が無いという意味ではない) |
| 別枠(6 つ) | 登録表に無い働きの記号 / 働きの記号が空 / 出典が空 / 同じ語 id が 2 回 / 対の登録表が台帳に無い記載を指す / 旧軸の順が重なる |

印は 2 つで、区分には使わない。

- 境目を持つ働きなのに検証の側の記載が無い
- 語の文字列を literal に含まない記載と対になっている(例: `cut0` と `cut(` は含まれない側)

ほかに、働きの記号ごとの語の件数、区分ごとの件数、どの語の横にも置かれなかった記載の件数、
台帳に無い語 id を指す対の行数(語の行数には入らない)を返す。

登録の側が崩れているとき(働きの登録表で同じ記号が 2 回、記載の側が 2 語以外、対の出典が空、旧軸の順が整数でない など)は、
区分を 1 行も返さずに理由コード(4 個)で止まる。

## いつも成り立つこと

結果は 2 通りしかない。**語 1 行ごとに、区分 4 値か別枠のどれか 1 つだけが付き、その合計が語の台帳の行数に等しく、横に置かれる記載は対の登録表に書かれた行だけで、別枠でない語は働きの記号 → 旧軸の順に並び、4 表の行順を入れ替えても判定部分が同じバイト列になる**か、**1 行も数えずに理由コードが 1 つ返る**か。どちらの場合も 4 表は書き換わらない。

この 1 文は `tests/test_call_axis_property.py` が性質テスト(hypothesis)で確かめている。4 表を小さな語彙から乱数で作り
(id の重複・空の出典・空の働き・登録表に無い働き・重なる旧軸の順・台帳に無い記載や語を指す対が、どれも出る)、
毎回この 1 文が成り立つかを見る(乱数は固定で、毎回同じ 300 通り)。区分の決め方は道具の関数を使わず、テストの中で別に書いている。
テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python call_axis.py init ひな型/
python call_axis.py check 語.csv 働き.csv 記載.csv 対.csv
python call_axis.py check 語.csv 働き.csv 記載.csv 対.csv --doc 文書.md --label 文書の名前
python call_axis.py verify 語.csv 働き.csv 記載.csv 対.csv
```

終了コードは 0 = 並べた / 3 = 理由コードで止まった / 2 = 表として読めない。`init` は既に在るファイルを書き換えない。

`--doc` を付けると、出典が `<文書の名前> L<行番号>` の行について、語の文字列・記載の文字列・結果の文字列が
その行にそのまま在るかを見る(写し間違いの検出)。

`verify` は 5 つ見る。二度走らせて sha256 が同じか / 4 表の行順を逆にしても同じか / 区分 + 別枠の合計が語の台帳の行数に戻るか /
1 語の働きの記号を別の登録済みの記号に替えると、その語の段だけが動き区分は変わらないか / 対を 1 行抜くと、その語だけが動き他は変わらないか。

```python
import call_axis as M

tables = [M.read_table(p, k) for p, k in (("語.csv", "words"), ("働き.csv", "roles"),
                                           ("記載.csv", "notes"), ("対.csv", "pairs"))]
out = M.check(*tables)
for row in out["語"]:
    print(row["働きの記号"], row["旧軸の順"], row["語"], row["区分"], row["印"])
```

## 持たせていないもの

- 語の名前から働きを当てる経路(働きの記号は人が登録した分だけ)
- 式の文字列を読んで、どの語を呼んでいるかを拾う経路。式を評価する経路・走らせる経路
- 名前の似かたで記載と結び付ける経路(対の登録表に書かれた行だけを使う)
- 記載が無い語を「未検証」「危険」と評価する経路、検証の結果の数が正しいかを返す経路
- 語を足す・減らす提案、通信、現在時刻、浮動小数点、入力を書き換える経路

## 試験

```
python -m pytest tools/call_axis -q -s
```

`fixtures/` は合成した 4 表と合成の文書で、実在の制度・名前は入っていない。
