# halt_depth — エラーの欄を行に割り、登録した印がどこまで出てから止まったかを回ごとに並べる

解説記事: [失敗と書かれた回も止まった場所が同じとは限らないので、エラーの欄に残った印を下の層まで並べる](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post_22.html)(2026-11-23 公開)
<!-- article-links:end -->

実行の履歴で「failed」と 1 語で書かれた回は、同じ段の名前で止まっていても、止まるまでに出した印が同じとは限らない。
エラーの欄の中には、その段の中の検査が出した行が順に残っていることがある。
この部品は、**エラーの欄を改行で割り、人が登録した印(行頭の字)が在るか無いか・何行目か・印の後ろの文字列を、
回ごとに原文のまま並べる**。
**止まった理由を当てない。印の後ろの文字列を数に直さない。状態の文字列を読まない・直さない。印を字面から見つけない。
伏せる行の登録表の字を含む行は、出力のどの欄にも写さず、件数だけ返す。**
標準ライブラリのみ(csv / json / hashlib / argparse)、依存なし。

## 入力の 4 表(どの行にも出典の欄が要る)

| 表 | 列 | 書くこと |
|---|---|---|
| 回の台帳 | `run_id, status, error, source` | `status` は状態の文字列を原文のまま。`error` はエラーの欄を改行ごと原文のまま(空でもよい) |
| 印の登録表 | `mark_id, text, stage, order, kind, source` | `text` は行頭に literal で当てる字(前の空白も字のうち)。`order` は並び順の整数。`kind` は `通過の印` か `止まった印` |
| 段の登録表 | `stage, name, source` | 段の記号と、上の層の段の名前。人が登録した分だけ |
| 伏せる行の登録表 | `text, source` | この字を含む行は、出力のどの欄にも写さない(実行した場所のパスなど) |

回の台帳は `.jsonl`(1 行 1 回の JSON。`status` と `error` の欄を読む)でも渡せる。そのとき回 id は `L<行番号>`、
出典は `<--label の名前> L<行番号>` になり、`error` が `null` の回は空として扱う。

## 出力

回 × 印ごとに、在る・無い / エラーの欄の中での行番号(複数なら全部)/ 印の後ろの文字列(原文のまま。伏せた行なら空)が返る。
並びは 回の台帳の順 → 印の並び順 で固定。

回ごとに、行数 / 印に当たった行・伏せた行・空の行・どの印にも当たらなかった行の件数(4 つの合計は行数に戻る)/
在った通過の印のうち並び順が最後のもの / 止まった印の有無 / 無かった通過の印 / 印が在った段の名前 / 区分 が返る。

| 区分 | 意味 |
|---|---|
| (A) 止まった印が在り、登録した通過の印が全部在る | 登録した印は全部出てから止まっている |
| (B) 止まった印が在り、通過の印の一部が無い | 出ていない通過の印が在る |
| (C) エラーの文字列は在るが、登録した印が 1 つも無い | 印の登録が足りないか、別の形のエラー |
| (D) エラーの文字列が空 | エラーの欄が空(`null` を含む) |
| (E) 通過の印は在るが、止まった印が無い | 止まった印として登録した字が出ていない |
| 別枠の回(2 つ) | 同じ回 id が 2 回 / 出典が空 |
| 別枠の印(5 つ) | 印の文字列が空 / 出典が空 / 登録表に無い段の記号 / 並び順が重なる / 伏せる行の字が印の文字列を含む |

別枠の印は当てるのに使わない。別枠の種類は、回と印で重なる「出典が空」を 1 つに数えると 6 つになる。

補助の印は 2 つで、区分には使わない。

- 同じ印が 1 回の中に 2 行以上在る(行数は「表示された行の数」で、件数ではない)
- 同じ印の後ろの文字列が回によって違う(文字列として比べる。`120` と `120.0` は違う字)

ほかに、区分ごとの回数、印ごとの在る回数、行の内訳の合計を返す。

登録の側が崩れているとき(同じ印 id が 2 回、種類が 2 語以外、並び順が整数でない、段の登録表で同じ記号が 2 回、
伏せる行の字が空 など)は、1 回も並べずに理由コード(5 個)で止まる。

## いつも成り立つこと

結果は 2 通りしかない。**回 1 行ごとに、区分 5 値か別枠のどれか 1 つだけが付き、その合計が回の台帳の行数に等しく、印が「在る」と返るのは登録した字が行頭にそのまま在る行だけで、行の内訳の合計がエラーの欄の行数に戻り、伏せる字を含む行の中身はどの欄にも出ず、登録表の行順を入れ替えても判定部分が同じバイト列になる**か、**1 回も並べずに理由コードが 1 つ返る**か。どちらの場合も 4 表は書き換わらない。

この 1 文は `tests/test_halt_depth_property.py` が性質テスト(hypothesis)で確かめている。4 表を小さな語彙から乱数で作り
(回 id の重複・空の出典・空の印・登録表に無い段・重なる並び順・伏せる字に含まれる印・2 語以外の種類・整数でない並び順が、どれも出る)、
毎回この 1 文が成り立つかを見る(乱数は固定で、毎回同じ 300 通り)。区分と在る・無いの決め方は道具の関数を使わず、テストの中で別に書いている。
テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 使い方

```
python halt_depth.py init ひな型/
python halt_depth.py check 回.csv 印.csv 段.csv 伏せる行.csv
python halt_depth.py check 回.csv 印.csv 段.csv 伏せる行.csv --text
python halt_depth.py check 履歴.jsonl 印.csv 段.csv 伏せる行.csv --label 実行の履歴
python halt_depth.py verify 回.csv 印.csv 段.csv 伏せる行.csv
```

終了コードは 0 = 並べた / 3 = 理由コードで止まった / 2 = 表として読めない。`init` は既に在るファイルを書き換えない。
`--text` を付けると、回 × 印を 1 行ずつの文字で出す。

`verify` は 5 つ見る。二度走らせて sha256 が同じか / 登録表 3 つの行順を逆にしても同じで、回の台帳を逆にしても回ごとの結果が同じか /
区分 + 別枠の合計が回の台帳の行数に戻り、行の内訳の合計が行数に戻るか /
印を 1 つ抜いても、残りの印の在る・無い・行番号・後ろの文字列が変わらないか / 後ろの文字列のどれにも伏せる字が無いか。

```python
import halt_depth as M

runs = M.read_runs("履歴.jsonl", "実行の履歴")
marks, stages, hides = (M.read_table(p, k) for p, k in (("印.csv", "marks"), ("段.csv", "stages"), ("伏せる行.csv", "hides")))
out = M.check(runs, marks, stages, hides)
for r in out["回"]:
    print(r["回"], r["状態"], r["区分"], r["無かった通過の印"])
```

## 持たせていないもの

- 止まった理由を分類する経路(返すのは、どの印が在ったか・無かったかまで)
- 印の後ろの文字列を数に直して比べる経路、2 つの値のどちらが期待でどちらが実際かを当てる経路
- 上流の変化か実装の不具合かを分ける経路
- 状態の文字列を書き換える経路・語の意味を読む経路
- 伏せた行の中身を返す経路(返すのは件数だけ。どの印にも当たらなかった行も、返すのは件数と行番号だけ)
- 印を字面から自動で見つける経路、正規表現、通信、現在時刻、浮動小数点、入力を書き換える経路

## 試験

```
python -m pytest tools/halt_depth -q -s
```

`fixtures/` は合成した 4 表で、段の名前も印も架空のもの。実在の記録・名前は入っていない。
