# quiet_slots — 数表を貼るのをやめても渡す欄を決める推論は残るので、空でも止まらない欄を先に数える

「AI は推論せず、これを呼ぶ」と宣言しても、**推論がやむのは数表の値の側だけ**だ。呼ぶときにどの欄を埋めるかの判断は宣言の外に残る。しかも残った欄は一様でない。**空なら例外で止まる欄と、空でも宣言どおり通って広い行に当たる欄と、既定がどこにも宣言されていない欄が混ざっている。**

この部品は、4 枚の表から、問い × 欄 の組ごとに 4 値のどれか 1 つを付け、**空でも止まらない欄**を数える。**値は入れない。引かない。省略の正否も決めない。**

```
python quiet_slots.py check 問いの宣言表.csv 欄の登録表.csv 行の在り方の表.csv 出口の登録表.csv
```

## 持たせていないもの

- **CLI を呼ばない・引かない・走らせない**。外部プロセスを起こす経路が無いので、「空にして呼んだら何が返るか」は出力に出ない。出るのは宣言の上での空きだけ
- **欄に値を入れない**。入力に値の列が 1 つも無い。入るのは欄名・記号・行数・出典だけで、実在の料率・金額・日付が入る欄そのものを持たない
- **空白を推測で埋めない**。`宣言なし` を `できる` 側へ寄せる引数も、既定を当てる辞書も無い。宣言が無い欄は `どちらの宣言も無い` のまま出る
- **トークン数・文字数・削減量を出さない**。数え方が手元に無いので列に持たない
- **省略の正否を決めない**。4 値と印を並べるところまでで、どの欄を埋めるかは呼ぶ人が決める。「正しい埋め方」「推奨」「既定値」の欄が無い
- **どの問いを道具に回すべきか決めない**。問いの宣言表に書いた問いだけを数える
- **入力を下へ辿らない**(見るのは 1 段目だけ)。**返り値の側に残る一手を見ない**(数えるのは呼ぶ前の欄だけ)。**日付の種別そのものの台帳を作らない**
- **行の中身の値を読まない**。**時計を読まない**。**入力を書き換えない**。**float を使わない**(行数は整数、ほかは文字列)

## 入力 — 4 枚

**どの行にも出典の欄が要る。** 登録の側(欄 / 行の在り方 / 出口)に空欄が 1 つでも在れば、1 組も数えずに止まる。

### 問いの宣言表(5 列)

1 つの問いが 1 行。**手元に在る欄の名前だけを書き、値は書かない。**

| 列 | 中身 |
|---|---|
| `ask_id` | 問い id(同じ id が 2 行あると止まる) |
| `command` | 呼ぶコマンド名 |
| `target` | 求める rule or 式の id(求めないなら `—`) |
| `slots` | **手元に在る欄名の一覧**(`|` 区切り。空欄 = 0 本)。**値を書く列が無い** |
| `source` | 出典(ファイル名 + 行番号)。空欄のとき、その問いの組は別枠「出典が空」へ入る |

```csv
ask_id,command,target,slots,source
Q1,status,—,,合成の呼び出しのメモ(架空)L1
Q2,resolve,R1,K1|K3,合成の呼び出しのメモ(架空)L2
Q4,compute,R3,K2|K4|K5|K10,合成の呼び出しのメモ(架空)L4
```

### 欄の登録表(6 列)

この道具のいちばん大事な表。**同じ欄名を 2 行書いてよい**(2 通りの宣言が在ることを写すため)。

| 列 | 中身 |
|---|---|
| `slot` | 欄名 |
| `kind` | 欄の種別記号(`基準日` / `選択の次元` / `知識時点` / `式の入力` / `判断の結果`) |
| `emptiable` | **空にできるか記号**(`できない` / `できる` / `宣言なし`) |
| `filler` | **誰が埋めてよいか記号**(`表から引く` / `人` / `人かLLM` / `宣言なし`) |
| `exit` | `できない` の欄が止まる出口記号(ほかは `—`)。**出口の登録表に在る記号だけ** |
| `source` | 宣言の出典。空欄は止まる |

```csv
slot,kind,emptiable,filler,exit,source
K1,基準日,できない,表から引く,例外,合成の宣言のメモ(架空)L1
K3,選択の次元,できる,表から引く,—,合成の宣言のメモ(架空)L3
K6,判断の結果,できる,人かLLM,—,合成の宣言のメモ(架空)L6
K7,知識時点,宣言なし,宣言なし,—,合成の宣言のメモ(架空)L7
```

### 行の在り方の表(4 列)

| 列 | 中身 |
|---|---|
| `target` | rule or 式の id |
| `dimension` | 次元名(= 欄名) |
| `rows` | **その次元を空にしたとき当たる行数**(1 以上の整数) |
| `source` | 出典。空欄は止まる |

同じ `target` と `dimension` の組が 2 行あると止まる。どの問いも求めていない `target` を指す行は、止めずに「どの問いも求めていない行の在り方の宣言」の一覧へ出す(黙って落とさない)。

### 出口の登録表(3 列)

**「止まる」の定義はここに在る。** `できない` と宣言した欄は、この表の `止まる` 側の記号を指していないと止まる。

| 列 | 中身 |
|---|---|
| `exit` | 出口記号(`例外` / `終了コード2` / `終了コード3` / `通る`) |
| `stops` | 止まるか記号(`止まる` / `止まらない`) |
| `source` | 宣言の出典。空欄は止まる |

## 分け方 — 組 1 つに付く 4 値と別枠 3

| 値 | 意味 |
|---|---|
| 空にできない | 空なら止まる出口が宣言されている |
| 空でよいと宣言されている | 未指定でも通ると宣言されている(= ワイルドカード) |
| 埋めるのは人か LLM だと宣言されている | 誰が埋めてよいかが `人かLLM` |
| どちらの宣言も無い | 空にできるかも誰が埋めてよいかも `宣言なし` |

上から順に見る。問いの行の出典が空なら別枠。欄名が登録表に無ければ別枠。同じ欄に 2 通りの宣言が在れば別枠。問いが手元に在ると宣言した欄も、空にする欄ではないので別に数える。そこを抜けてから、**空にできるか記号で 3 つへ振り分け、`誰が埋めてよいか` が `人かLLM` の欄だけを 3 番目へ移す**。

別枠は 3 つ = 同じ欄に 2 通りの宣言が在る / 欄名が登録表に無い / 出典が空。

**空でよいと宣言されている組にだけ印が付く。**

| 印 | 意味 |
|---|---|
| 1 行に決まる | その次元を空にしても当たる行は 1 本と宣言されている |
| 2 行以上が当たる(行数つき) | 同じ有効期間に複数の行が並ぶと宣言されている |
| 行数の宣言が無い | 行の在り方の表に行が無い(**0 とも 1 とも読まない**) |

**空でも止まらない欄** = 「空でよいと宣言されている」+「埋めるのは人か LLM だと宣言されている」。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- **組を作った**: 問い × 欄 の組 1 つごとに **4 値か別枠 3 か「手元に在ると宣言されている」のどれか 1 つ**が付き、**その合計 = 問いの件数 × 欄の件数**、**問いごとの内訳の合計も欄の種別ごとの内訳の合計も同じ数**になる。印が付くのは「空でよいと宣言されている」組だけで(**印の合計 = その件数**)、**`宣言なし` と宣言された欄が「空でよい」側へ移る経路は無く**、**`人かLLM` と宣言された欄は必ず「埋めるのは人か LLM」**、**問いが手元に在ると宣言した欄は空にする欄に数えず**、**出典が空の問いの組は 4 値に 1 つも入らない**。出力に「正しい埋め方」「推奨」「割合」の欄が無く、判定部分に絶対パスが入らず、4 枚の行順を 3 通りに入れ替えても同じバイト列になる
- **1 組も数えずに理由コードが返る**: 作った組や sha256 を取りに行くと例外

どちらの場合も、この部品は 4 枚の表を 1 文字も書き換えない。

この 1 文を検査にしたのが `tests/test_quiet_slots_property.py`(hypothesis、`derandomize=True`)。判定の分け方はテストの中に別に書いてあり、部品の `judge` / `four` を呼ばない。

## 件数の検算 — 3 通りの数え方が合う

- 4 値 + 別枠 3 + 手元に在る の合計 = 問い × 欄 の組の件数
- 問いごとの内訳の合計 = 同じ数 / 欄の種別ごとの内訳の合計 = 同じ数
- 印の合計 = 「空でよいと宣言されている」の件数

`verify` はこれに加えて、判定部分の sha256 の二度走り、4 枚の行順の 3 通りの入れ替え、そして 2 つの写しを見る。

- **空にできるかを `できる` → `宣言なし` に替えた写し**: その欄の組だけが「空でよい」から「どちらの宣言も無い」へ移り、**別枠の件数も手元に在るの件数も動かない**(`宣言なし` を `できる` 側へ寄せる経路が無いことの物理形)
- **行の在り方の行数を 1 → 2 に替えた写し**: その組の印だけが `1 行に決まる` → `2 行以上が当たる` へ移り、**4 値の件数は 1 つも動かない**(行数が印の側だけに効くことの物理形)

## 出力 — 正しい埋め方も削減量も返らない

`check` は件数と分母の内訳、`cells` はそれに一覧を足す。返るのは次のものだけ。

- 4 枚の行数、分母(問いの件数 / 欄の件数 / 組の件数)
- 4 値、別枠 3、手元に在ると宣言されている、印の内訳
- **空でも止まらない欄の件数と、そのうち `2 行以上が当たる` の件数**
- 問いごと / 欄の種別ごと / 欄ごとの内訳、「止まる」の定義(出口の登録表の写し)
- どの問いも求めていない行の在り方の宣言、どの欄も指していない出口の登録、理由別の止まった件数

`cells` で足されるのは、判定ごとの一覧、空でも止まらない欄の一覧、別枠の一覧、欄ごとの一覧、上の 2 つの一覧、判定部分の sha256、読んだ条件。

**「正しい埋め方」「推奨」「既定値」「割合」「削減量」の欄は無い。** 出力の最後に並ぶ 12 行の「持たせていないもの」は消せない。

## 止まる理由コード(10 個)

表の側は 7 個。**どれか 1 つでも在れば、1 組も数えない**(4 値は全て 0)。

- 宣言の出典が空
- 問い id の重複
- 同じ問いに同じ欄名が 2 回
- 空にできない欄の出口記号が出口の登録表に無い
- 空にできない欄の出口が止まらないと宣言されている
- 同じ rule と次元の組が行の在り方の表に 2 行ある
- 同じ出口記号が出口の登録表で止まるかが食い違う

`verify` が見つけるのが 3 個 = 件数の合計が合わない / 2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる。

表として読めない形(列が無い / 行が無い / 登録の外の記号 / id が空か区切り文字を含む / 行数が整数でない)は終了コード 2 で、組は 1 つも数えない。

## 使い方

ひな型を出す。

```
python quiet_slots.py init ひな型/
```

数える。

```
python quiet_slots.py check 問いの宣言表.csv 欄の登録表.csv 行の在り方の表.csv 出口の登録表.csv
```

一覧つきで出す。

```
python quiet_slots.py cells 問いの宣言表.csv 欄の登録表.csv 行の在り方の表.csv 出口の登録表.csv
```

この手続き自体が決定論かを実測する。

```
python quiet_slots.py verify 問いの宣言表.csv 欄の登録表.csv 行の在り方の表.csv 出口の登録表.csv
```

終了コードは、空でも止まらない欄と別枠と止まった行とどの問いも求めていない宣言が 0 件のときだけ 0、在れば 3、表として読めなければ 2。**0 は「呼び出しが正しい」ではなく「全ての組が、空にできないか手元に在ると宣言されている」の意味。**

python -m pytest tools/quiet_slots -q
```

fixture は合成した 4 枚(問い 5 行 / 欄の登録 10 行 / 行の在り方 6 行 / 出口 4 行)と、崩した表 30 枚。**実データ・実在の料率・実在の金額・実在の日付は 1 つも入っていない。** 問い id は記号、欄名は記号、rule or 式の id は記号、出典は「合成の…(架空)」で、行数の桁だけ手元の棚卸しと同じ形にそろえてある。

python fixtures/make_fixtures.py
```

## できないこと

- **空にして呼んだら何が返るかは分からない。** この部品は CLI を呼ばない。`2 行以上が当たる` は宣言表の行数の写しで、実際に引くと 1 行に決まるか同順位競合で止まるかは出力に出ない
- **実際にどの欄を空にして呼んだかは分からない。** 数えるのは宣言の上での空きだけで、呼び出しの記録を読む経路が無い
- **トークンがどれだけ減るかは分からない。** 数え方を持っていない
- **どの欄を埋めるべきかは分からない。** 4 値と印を並べるだけで、省略の正否は読む人が決める
- **問いごとに要る欄は分からない。** 道具は問いと欄の全組を数えるので、`status` のように欄が 0 本の問いでも登録された欄すべてが組になる。これは「宣言の上での空き」を数える定義の帰結で、要る欄を決めるのは人
- **宣言が正しいかは分からない。** 4 枚は人が書くもので、この部品は宣言どおりに分けるだけ
- 上の件数は合成した 4 枚の表に対する測定で、ほかの人の環境で同じ数字になるとは限らない
