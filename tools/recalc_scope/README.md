# recalc_scope — 差し替えた後にどれを出し直すかは、引いた版の指紋を結果に残してから決める

解説記事: [差し替えた後にどれを出し直すかは、引いた版の指紋を結果に残してから決める](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_16.html)(2026-10-17 公開)
<!-- article-links:end -->

**数表を差し替えた後、過去に出した結果のどれを出し直すかは「最終実行の日付」では決まらない。
結果の側に「引いた版の指紋」と「引いた行のキー」を残していないと、全部出し直すか何も出し
直さないかの二択になる。**
[asof_table](../asof_table) の回で基準日と公表時点で版を選ぶところ、
[update_ledger](../update_ledger) の回で数表の側の更新台帳、
[context_pack](../context_pack) の回で AI へ渡す行に版を焼くところまでは決めた。けれど
**過去に出した結果と新しい版の差分を突き合わせて、出し直す範囲を出す段** は、どの回でも
手つかずだった。

この部品は、結果の台帳・版の台帳・版間の差分の台帳の 3 枚から、結果 1 行ごとに 4 値
(**影響あり / 影響なし / 決まらない / 止まった**)を付ける。決まらないものは理由別
(**見本だけ / キー無し / 鎖が切れている**)に分けて数え、分母(結果台帳の行数)と内訳を
併記して返す。**再計算はしない。範囲を出すだけだ。**

持たせていないものが規律になっている。

- **版は指紋で指し、日付で指さない**(同じ内容に戻った版があるので日付順では一意にならない。
  日付の列は表示にだけ使い、鎖の辿り方にも判定部分にも入れない)
- **差分台帳が「見本だけ」と宣言している区間は「決まらない」に落ちる**(見本から全件を
  推定しない。この部品の骨をそのまま入力の形にしたところ)
- **結果の行に引いたキーが無ければ「決まらない」**(キーが空の結果を「影響なし」に寄せない)
- **指紋が空の版(検証に落ちた回)は版として使わずに止まる**
- **版の鎖が辿れない区間は「決まらない」**(区間の差分が台帳に無いとき、間を推定で繋がない)
- **再計算しない**(値を計算し直す経路も、他の道具を呼ぶ経路も持たない。引くのは
  [asof_table](../asof_table)、走らせるのは [check_census](../check_census)、渡すのは
  [context_pack](../context_pack) の仕事で、役割が重ならない)
- **出し直すべきだと勧めない / 順番も付けない**(返るのは件数と内訳だけ。出し直す対象の
  一覧も結果 id の順で返る)
- **影響の判定は「結果が引いたキー ∩ 区間で変わったキー ≠ 空」までで、値がどう変わるかは
  判定しない**
- **件数は理由別に、分母(結果台帳の行数)と内訳つきで出す**(率を単独で返さない。
  [check_census](../check_census) 以降と同じ)
- **4 つを混ぜない**([answer_check](../answer_check) / [span_split](../span_split) /
  [band_edge](../band_edge) / [blank_kind](../blank_kind) と同じ)
- **入力表を書き換えず、キーも指紋も生成しない**([intake_triage](../intake_triage)
  以降と同じ)
- **出典の欄が空の行は使わずに止まる**([source_pin](../source_pin) /
  [reader_registry](../reader_registry) と同じ)
- **float を使わない**(件数は整数。値は 1 つも持たない)

## 入力 — 結果の台帳と版の台帳と差分の台帳の 3 つ

結果の台帳は 8 列。過去に出した結果 1 件が 1 行になる。

| 列 | 意味 |
|---|---|
| `result_id` | 結果 id(空欄は「表として読めない」。2 行あると**止まる**) |
| `target` | 対象(空欄は「表として読めない」) |
| `item` | 項目(空欄は「表として読めない」) |
| `version` | 引いた版の指紋。**空欄は止まる。版台帳に無い指紋も止まる** |
| `keys` | 引いた行のキー(縦棒で区切る。0 件以上)。**空欄なら決まらない** |
| `issued` | 出した日。**表示だけに使い、判定部分には入れない** |
| `source` | その行の出典。**空欄は止まる** |
| `swap` | 入れ替え方。`verify` が結果の台帳の行順を入れ替えるときの宣言 |

版の台帳は 4 列。業種の語彙を 1 つも持たない。

| 列 | 意味 |
|---|---|
| `version` | 版の指紋(空欄は「表として読めない」) |
| `date` | 版の日付。**表示だけに使い、鎖の辿り方にも判定部分にも入れない** |
| `parent` | 前の版の指紋(空欄 = 鎖の始まり。台帳に無い指紋でもよい) |
| `source` | その行の出典。**空欄は止まる** |

版間の差分の台帳は 6 列。**1 区間 × 1 変更種別で 1 行** になる(追加と削除と変更を 1 行に
丸めない)。

| 列 | 意味 |
|---|---|
| `from_version` | 前の版の指紋 |
| `to_version` | 後の版の指紋 |
| `keys` | 変わった行のキー(縦棒で区切る。0 件でもよい) |
| `change` | 変更種別。登録の 3 種(`追加` / `削除` / `変更`)。**外は止まる** |
| `coverage` | キーの一覧が `全件` か `見本だけ` かの宣言。**空欄は止まる** |
| `source` | その行の出典。**空欄は止まる** |

```csv
from_version,to_version,keys,change,coverage,source
b3c8d1e6f2a9b4c7,c5d2e9f4a1b8c3d6,合成のキーE(架空),追加,見本だけ,私の棚卸し記録(非公開)
c5d2e9f4a1b8c3d6,d9e4f1a8b3c6d2e7,合成のキーA(架空)|合成のキーB(架空),変更,全件,協会けんぽ / 私の棚卸し記録(非公開)
```

## 鎖 — 日付では並べず、指紋の親子だけで辿る

版の鎖は `parent` だけで組む。鎖を組む関数は `date` の欄に 1 度も触らない(そのことも
テストで固定してある)。鎖が 1 本に決まらない表は、**値を 1 つも読む前に「表として読めない」
で返る**。

| 版の台帳の形 | どうなるか |
|---|---|
| 1 本の鎖(先頭が 1 つ、輪が無い) | 鎖として使う |
| 枝が 2 つ出ている | 新しい版が 1 つに決まらない → **読めない表** |
| 全部が誰かの前の版(輪) | 鎖の先頭が 0 個 → **読めない表** |
| 鎖から外れた版がある | 推定で繋がない → **読めない表** |
| 同じ指紋に別の日付が 2 行 | **止まる**(日付で版を指せない) |

## 4 値 — 「影響なし」と「決まらない」を混ぜない

| 値 | いつ入るか |
|---|---|
| `影響あり` | 引いたキーと、区間で変わったキーが 1 件以上重なった |
| `影響なし` | 区間の全ての段が全件で宣言されていて、重なったキーが 0 件 |
| `決まらない` | 見本だけ / キー無し / 鎖が切れている のどれか |
| `止まった` | 理由コードが返った行(指紋が空、版台帳に無い指紋 など) |

判定の順は **キー無し → 鎖が切れている → 見本だけ → キーの突き合わせ** だ。だから区間が
0 段(引いた版がいちばん新しい版)でも、引いたキーが空なら `決まらない` に入る。
**キーが空の結果を「影響なし」に寄せない** ほうを採った。

## 件数の検算 — 分母は結果台帳の行数

- **4 値の件数の合計 = 結果の台帳の行数**
- **決まらない理由別の件数の合計 = 決まらないの件数**

2 つは別の経路で数えているので、片方だけ数え方を差し替えると、この検算が自分で見つけて
止まる。同じ結果 id が 2 行あると件数を結果 1 件ずつに割り当てられないので、そこでも止まる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- 結果ごとに 4 値が 1 つだけ付き、**4 値の合計が結果台帳の行数** に等しく、**決まらない
  理由別の合計が決まらないの件数** に等しく、`影響あり` には当たったキーが 1 件以上あり
  (`影響なし` は 0 件)、判定部分に時刻・ホスト名・絶対パス・**日付** が 1 つも入らず、
  **結果台帳の行順を入れ替えても同じバイト列** になる
- または、1 行も読まずに理由コードが返る(結果や指紋を取りに行くと例外になる)

どちらの場合も、この部品は結果の台帳も版の台帳も差分の台帳も 1 文字も書き換えない。

この 1 文を `tests/test_recalc_scope_property.py` の `@given` テストが確かめている(版を
2〜4 段の鎖にし、区間ごとに差分の宣言の在無と全件 / 見本だけを振り、結果を 1〜4 行作り、
3 割くらいの確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 150 通り)。**4 値は部品の判定を
呼ばず、台帳の行と鎖からテスト側の別実装で組み立てている。** 同じファイルの 2 本目は 300 通りで、
「版の日付と出した日を振り直しても判定部分のバイト列が 1 バイトも変わらない」ことを見ている。

## 出力 — 出し直す率は単独では返らない

`check` と `scope` が返るのは、結果の台帳・版の台帳・差分の台帳それぞれの行数、版の鎖の段数、
新しい版の指紋(先頭 8 桁)、4 値の件数、決まらない理由別の件数、出し直す対象の件数、それに
分母の内訳と検算と 3 つの固定行だ。**率だけを返す呼び方も、option も無い。**

```
"4 値": {"影響あり": 3, "影響なし": 4, "決まらない": 5, "止まった": 0},
"決まらない理由別": {"見本だけ": 2, "キー無し": 2, "鎖が切れている": 1},
"出し直す対象": 3
```

固定行は 3 つとも消せない。「版は指紋で指す」(日付を突き合わせに使っていないこと)、
「見本から全件を推定しない」、「再計算しない」(値も順番も出さないこと)だ。
`scope` はさらに結果ごとの内訳(引いた版・引いたキーの件数・結果・決まらない理由・区間の
段数・突き合わせたキーの件数・当たったキー・出した日・出典)と、`影響あり` だけを並べた
一覧を出す。

`verify` は 3 つ見る。2 回読んで判定部分のバイト列の sha256 を突き合わせること、**宣言された
入れ替え方で結果の台帳の行順を入れ替えても同じ出力になるか**、そして **4 値の件数の合計が
結果台帳の行数に合うか** だ。合わなければ観測としてそのまま返す。

## 止まる理由コード(9 個)

```
出典の欄が空 / 版の指紋が版台帳に無い / 指紋が空の版を参照 / 同じ指紋に別の日付が 2 つ /
全件か見本かの宣言が空 / 変更種別が宣言外 / 件数の合計が合わない /
2 回目の判定部分が不一致 / 行順を入れ替えた表で出力が変わる
```

次のものは理由コードにせず、**「表として読めない」として終了コード 2 で返す**。全件か見本かの
宣言・入れ替え方が登録の外の語だったとき、列そのものが足りないとき、結果 id・対象・項目・
出した日・版の指紋・版の日付・区間の指紋が空欄のとき、キーの一覧に同じキーを 2 つ書いたとき、
同じ版または同じ区間 × 同じ変更種別の宣言が 2 行あるとき、前の版が自分と同じ指紋のとき、
区間の前と後が同じ指紋のとき、入れ替え方の宣言が 2 通りあるとき、そして鎖が 1 本に決まらない
とき(枝が 2 つ / 先頭が 0 個 / 鎖から外れた版)。

## 使い方

```bash
python recalc_scope.py init ひな型/                                   # 3 枚の表のひな型を書く
python recalc_scope.py check  結果の台帳.csv 版の台帳.csv 差分の台帳.csv   # 件数と分母の内訳
python recalc_scope.py scope  結果の台帳.csv 版の台帳.csv 差分の台帳.csv   # 上 + 結果ごとと指紋
python recalc_scope.py verify 結果の台帳.csv 版の台帳.csv 差分の台帳.csv   # 2 回 + 行順 + 検算
```

終了コードは、**決まらない行が 1 行も無いときだけ 0**(影響ありが何件あっても 0)、決まらない
行があるときや止まったときは 3、表として読めなければ 2。まとめて走らせる仕組みの中に置いて、
3 で止められる。

関数としても同じ形で呼べる。

```python
from recalc_scope import Ledger, Versions, Diffs, scope

t = scope(Ledger.load("結果の台帳.csv"), Versions.load("版の台帳.csv"),
          Diffs.load("差分の台帳.csv"))
print(t.counts() if t.report.ok else [p.reason for p in t.report.pending])
```

CLI は `scope` / `check` / `verify` / `init` の 4 つで、option は `-h` 以外に 1 つも無い。
そのこともテストで固定してある。

```bash
python -m pytest tools/recalc_scope -q      # 31 passed(2026-10-17 実走)
```

`fixtures/` に結果の台帳 2 枚・版の台帳 2 枚・差分の台帳 2 枚と、崩した表 36 枚が入っている。

実在の料率や金額や取引先名は 1 つも無い。写したのは形だけ、つまり「同じ内容に戻った版が
ある」「差分のキーが見本だけの区間がある」「検証に落ちた回は指紋が無い」という 3 つで、これは
私の更新の実行記録に残っている形だ。出典のうち 5 件はこの repo 内の実在の行
(`articles/07_asof_table.md` L13 / L16、`articles/09_update_ledger.md` L13 / L15、
`articles/15_context_pack.md` L15)を指し、テストがその行を開いて語が在ることまで確かめている。

## できないこと

- 判定したことは「出し直す対象が台帳から 1 つに決まるか」までで、**どれを実際に出し直すべき
  かは判定しない**
- **値がどう変わるかも言わない。** 影響の判定はキーが重なるかどうかまでで、重なった結果の
  値が動くかどうかは見ていない
- **差分台帳が足りているかも判定しない。** 見本だけと宣言された区間は、見本のキーで当て直さず
  決まらないに落ちるだけで、足すべきキーを提案する経路が無い
- **再計算しない。** 値を計算し直す経路も、他の道具を呼ぶ経路も持たない
- **順番を付けない。** 出し直す対象の一覧は結果 id の順で、どれから手を付けるかは人の側に返る
- 版の鎖が 1 本に決まらない表は、推定で繋がずに読めない表として返る
- 対象と項目は結果に添えるだけで、判定には使わない
- キーは文字列として突き合わせる。表記が揺れているキー(全角と半角など)は別のキーになる
- 上の件数は、合成した台帳に対する測定で、他の人の環境で同じ数字になるとは限らない
