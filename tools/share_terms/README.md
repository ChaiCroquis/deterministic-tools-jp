# share_terms — 手元で引ける行がそのまま配れる行とは限らないので、許諾の名前と要る欄を行に書いてから出す

**手元で引ける行と、外に出して配れる行は別で、配れる形かどうかは行の欄に書かれた許諾の宣言から
しか決まらない。**

[source_pin](../source_pin) の回は、原本の場所と生の文字に値を突き合わせる道具だった。あちらは
**その値が原本どおりか**の話で、こちらは**その原本を外に出してよいと誰が書いたか**を数える。
[recalc_scope](../recalc_scope) は版の指紋で出し直す対象を出す道具、[backing_axis](../backing_axis)
は裏付けの由来の軸で行を並べ直す道具、[idle_rows](../idle_rows) はどの問いからも参照されない行を
数える道具で、どれも**手元で使う側**の話になる。こちらは **外に出す側** で、同じ「照合専用」の行が
idle_rows では別枠、ここでは「出さないと宣言された」側に入る(軸が違う)。

この部品は、行の台帳・許諾の登録表・出典元の台帳・配布物の目録の 4 枚から、rule 1 件ごとに
5 値(**宣言が揃っている / 出すと宣言されたが欄が空 / 出さないと宣言された / 出す宣言が無い**
の 4 値 + 別枠 **登録表に無い許諾の名前**)を付け、空の欄を名前つきで並べる。
**配ってよいかを判定しない。許諾の名前を推測しない。規約の原文を取りに行かない。数えるだけだ。**

持たせていないものが規律になっている。

- **許諾の名前を推測しない**(出典元の名前・URL の形・ファイル拡張子から名前を当てる経路が無い。
  登録表に無い名前は別枠に出し、「公式の公開情報だから大丈夫」の既定を持たない)
- **配ってよいかを判定しない**(出力に可否の欄も注意の欄も無い。配布の是非を指す語を、この部品は
  実装にも出力にも 1 つも持たない)
- **規約の原文を取りに行かない・解釈しない**(ネットワーク経路も本文を読む経路も無い。要求される
  欄は許諾の登録表に宣言として渡される側で、この部品は規約の中身を知らない)
- **帰属の文字列を生成しない**(verbatim の写しだけを扱い、出典元の名前から文面を組む経路が無い。
  空なら空のまま「足りない欄」へ入る)
- **足りないのと決めていないのを同じ列に潰さない**(出すと宣言されたが欄が空の行と、出す宣言
  そのものが無い行を、**別の値と別の行数で返す**。これが骨の物理形)
- **出さないと宣言された行を足りない側に数えない**(外に出す宣言が `出さない` の行は別の値に出て、
  空の欄の一覧にも、欄が空の件数にも入らない)
- **判断がつかない行は誰の宣言に由来するかを必ず併記する**(別枠の各行に出典が付き、出典の欄が
  空の行は入口で止まる)
- **出典元や上流の意図を推定しない**(なぜ名前が書かれていないか、なぜ出さないと宣言したかの理由欄
  が無い)
- **件数を割合にしない**(件数と行数と分母の内訳だけを返す)
- **順位も勧めも出さない**(どの出典元から埋めるべきかの順位欄が無い。埋める順は表を持つ人が決める)
- **取得日は記録するだけ**(出典元の台帳の取得日を全部書き換えても、5 値も行数も判定部分の指紋も
  動かない。現在時刻を読む呼び出しも 1 つも無い)
- **出典の欄が空の行は使わずに止まる**
- **行を引かない・値を計算しない・式を評価しない・ファイルを配らない**(評価器も転送経路も持たない。
  原本の接地は [source_pin](../source_pin)、版の指紋での出し直しは [recalc_scope](../recalc_scope)
  の仕事で、ここに寄せない)
- **この部品自身の「読めない」を、測っている相手の「欄が空」と同じ欄に入れない**(4 枚のどれかが
  1 行でも壊れていたら 1 件も数えず、理由コードだけを返す。5 値は全て 0 になり、空の欄も 0 件になる)
- **入力表を書き換えず、行も宣言も生成しない**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない。行順にも依らない)
- **数は整数だけ**(行数も件数も整数で、float を使う経路が無い)

## 入力 — 4 枚の表

行の台帳は 10 列。**1 つの rule が 1 行**で、ここが「手元で引ける行」の側になる。

| 列 | 意味 |
|---|---|
| `table_id` | 数表 id(空欄・区切り文字入りは「表として読めない」) |
| `rule_id` | rule id(同じ id が 2 行あると**止まる**。2 つの数表に跨っても**止まる**) |
| `rows` | 行数(0 以上の整数)。小数は読めない |
| `origin_id` | 出典元 id(出典元の台帳に無い id は**別枠の一覧**へ。止めない) |
| `license_name` | 許諾の名前(空欄可)。登録表に無ければ**別枠** |
| `attribution` | 帰属の文字列(空欄可)。**verbatim の写しだけ** |
| `source_url` | 原文の URL(空欄可) |
| `fingerprint` | 版の指紋(空欄可)。出典元の台帳の指紋と食い違えば**止まる** |
| `share` | 外に出す宣言(`出す` / `出さない` / 空欄)。登録外は「表として読めない」 |
| `source` | 出典(ファイル名 + 行番号)。空欄は**止まる** |

許諾の登録表は 5 列。**1 つの許諾の名前が 1 行**で、ここが「その許諾が何を要求すると宣言されて
いるか」の側になる。**ヘッダだけでも読める**(= 1 つも登録していない状態は正常で、そのとき出すと
宣言された行が全部別枠へ出る)。

| 列 | 意味 |
|---|---|
| `license_name` | 許諾の名前(空欄・区切り文字入りは「表として読めない」) |
| `needs_attribution` | 帰属の文字列を要求すると宣言されているか(`要る` / `要らない`) |
| `needs_source_url` | 原文の URL を要求すると宣言されているか(同上) |
| `needs_fingerprint` | 版の指紋を要求すると宣言されているか(同上) |
| `declared_in` | その宣言の出典(空欄は**止まる**) |

要求される欄は `帰属の文字列` / `原文の URL` / `版の指紋` の 3 つだけで、**ここを増やす経路は入力
側に無い**。規約の本文から欄を起こす変換を持たないので、3 つで足りない許諾はこの部品では扱えない。

出典元の台帳は 4 列。**1 つの出典元が 1 行**。

| 列 | 意味 |
|---|---|
| `origin_id` | 出典元 id(同じ id が 2 行あると「表として読めない」) |
| `fingerprint` | 取得した版の指紋(行の指紋と食い違えば**止まる**) |
| `got_on` | 取得日(`YYYY-MM-DD`)。**記録するだけで判定に使わない** |
| `license_written_at` | 許諾の名前が書かれている場所(ファイル名 + 行番号。空欄可) |

`license_written_at` と行の `license_name` は、**在る / 無いを食い違わせない**。場所が無いのに名前が
書かれていれば止まり(名前の出どころが無い)、場所が在るのに名前が空でも止まる(書かれているものを
行に写していない)。どちらも、名前を推測で埋める前に出す食い違いになる。

配布物の目録は 5 列。**1 つの (出す先, rule) の組が 1 行**。

| 列 | 意味 |
|---|---|
| `bundle_id` | 出す先 id(同じ id に 2 通りのファイル名があると**止まる**) |
| `file_name` | 出すファイル名(空欄は「表として読めない」) |
| `rule_id` | 含む rule id(台帳に無い id は**別枠の一覧**へ。止めない) |
| `swap` | 入れ替え方(`逆順` / `両端入れ替え` / `1 つずらす`)。`verify` が使う宣言。**1 行だけ埋める** |
| `source` | 出典(空欄は**止まる**) |

## 分け方 — rule 1 件に付く 5 値

| 行の形 | どうするか | 5 値 |
|---|---|---|
| 外に出す宣言が `出さない` | 配らないと宣言された行なので、要求される欄を見に行かない | 出さないと宣言された |
| 外に出す宣言が空 | まだ誰も決めていない。埋める欄も決まらない | 出す宣言が無い |
| 出すと宣言、名前が登録表に無い(空欄を含む) | 要求される欄が分からないので足りない欄を数えない | 登録表に無い許諾の名前 |
| 出すと宣言、要求された欄が 1 つでも空 | 埋める欄が決まっている | 出すと宣言されたが欄が空 |
| 出すと宣言、要求された欄が全部埋まっている | — | 宣言が揃っている |

上から順に見るので、**「出す宣言が無い」と「出すと宣言されたが欄が空」は別の値になる**。前者は
配るかどうかの宣言そのものが無い話で、後者は宣言した上で欄が足りない話だ。やることも違う。前者は
出すか出さないかを決める番で、後者は決まっている欄を埋める番になる。

**要求すると宣言された欄が 0 個の許諾では、3 欄が全部空でも「揃っている」になる**。この部品は
「普通こうする」の既定を持たず、登録表に書かれた宣言だけを見るからだ。

## 足りないのと、決めていないのを潰さない

| 値 | 許諾の名前 | 要求される欄 | 読み方 |
|---|---|---|---|
| 出すと宣言されたが欄が空 | 登録表に在る | 分かる(1 つ以上空) | 埋める欄の名前が出る。埋めれば揃う |
| 出す宣言が無い | 何でもよい | 見に行かない | 出すか出さないかを先に決める番 |
| 登録表に無い許諾の名前 | 空欄か、登録に無い名前 | 分からない | どの許諾が当たるかを人が決める番 |

この 3 つを「ライセンス未整理」の 1 つに潰すと、配る前に何をすればよいかが分からなくなる。
埋める欄が決まっている状態と、宣言していない状態と、そもそも誰も許諾を決めていない状態が、同じ列に
並ぶからだ。

## 件数の検算 — 5 通りの数え方が合う

- **5 値の件数の合計 = rule の数**
- **4 値の合計 = 許諾の名前が登録表に在る rule の数**(別枠は分母の外)
- **出典元ごとの内訳の合計 = rule の数**、かつ **数表ごとの内訳の合計 = rule の数**
- **出典元ごとの行数の合計 = 全体の行数**(**出典元の台帳に無い id も 1 行として並べる**。外すと
  合計が合わなくなるので、欠けを黙って落とせない)
- **5 値ごとの行数の合計 = 全体の行数**

5 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。
分母は rule の数 / 名前が登録表に在る rule の数 / 別枠の数 / 台帳に出てくる出典元の数 / 出す先の数
の 5 つを必ず付ける。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- rule 1 件ごとに、5 値のどれか 1 つが付き、**5 値の合計が rule の数**に等しく、**4 値の合計が
  許諾の名前が登録表に在る rule の数**に等しく、**出典元ごとと数表ごとの内訳の合計も rule の数**に
  等しく、**出典元ごとの行数の合計と 5 値ごとの行数の合計がどちらも全体の行数**に等しく、
  **「宣言が揃っている」行はその許諾が要求すると宣言した欄が 1 つも空でなく**、**「出すと宣言された
  が欄が空」の行は空の欄が 1 つ以上あって名前つきの一覧に出て**、**出さないと宣言された行・出す宣言
  が無い行・別枠の行は空の欄を 1 件も持たず**、**配布物ごとに要る帰属の文字列は入力に書かれた文字列
  だけ**で、判定部分に時刻・ホスト名・絶対パス・取得日が 1 つも入らず、**4 枚の行順を入れ替えても
  同じバイト列**になる
- または、1 件も数えずに理由コードが返る(数えた rule や指紋を取りに行くと例外になる)

どちらの場合も、この部品は 4 枚の表を 1 文字も書き換えない。

この 1 文を `tests/test_share_terms_property.py` の `@given` テストが確かめている(出典元を
1〜3 つ、許諾の名前が書かれている場所の在る / 無いを引き、数表を 1〜2 つ、その中の rule を
1〜2 件ずつ、許諾の名前を 3 通り、3 つの欄をそれぞれ 空 / 埋まっている から、外に出す宣言を
3 通りから引く。3 割くらいの確率でどこか 1 か所を崩し、崩し方 10 通りが「1 件も数えずに止まる
理由コード」10 個に 1 対 1 で対応している。乱数は固定で毎回同じ 200 通り)。**5 値の分け方は
テストの側で別に実装している**(部品の `judge` / `five` を呼ばない)。同じファイルの 2 本目は
「出さないと宣言された行と出す宣言が無い行は空の欄を持たない」ことだけを、外に出す宣言 × 許諾の
名前 × 3 欄の埋まり方 の総当たりで見ている(上限 300)。

書いている途中で 1 つ捕まえたのは、性質テストではなく `verify` の側だ(合成した 4 枚に対して
`verify` を 1 回走らせたら、許諾を 1 件外した写しの「合うか」が false で返った)。**最初は
「許諾を 1 件外すと、その名前を指す行が別枠へ移る」の動く行を、名前だけで選んでいた**。同じ名前を
持つ「出さない」と宣言された行まで動く側に数えてしまい、件数が 1 件ずれた。実際にはその行は動かない
(宣言を先に見ているので、許諾が登録表から消えても「出さないと宣言された」のままになる)。動く行を
「出すと宣言されている行」に絞り、**同じ名前だが動かない行**を別の欄で数えてから測り直した。
**宣言を先に見る道具を、宣言を見ずに試そうとして詰まった形**になる。

## 止まる理由コード(13 個)

4 枚の表の側。1 件も数えずに止まるものが 10 個。

`出典の欄が空` / `同じ rule id が台帳に 2 行ある` / `同じ rule id が 2 つの数表に跨っている` /
`同じ出す先 id と rule id の組が目録に 2 行ある` / `同じ出す先 id に 2 通りのファイル名が書かれている` /
`出さないと宣言された行が配布物の目録に載っている` / `出す宣言の無い行が配布物の目録に載っている` /
`行の版の指紋が出典元の台帳の指紋と食い違う` /
`許諾の名前が書かれているのに出典元の台帳にその場所が無い` /
`許諾の名前が空なのに出典元の台帳に場所が書かれている`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄や区切り文字入り・同じ id が 2 行・行数が 0 以上の整数でない・
外に出す宣言が登録外・要求するかが登録外・出すファイル名が空欄・取得日の形が違う・その月に無い
日付・登録外の入れ替え方・入れ替え方の宣言が 2 通り、は**「表として読めない」**(終了コード 2)で、
理由コードには混ぜない。

## 使い方

```
python share_terms.py init ひな型/
python share_terms.py check 行の台帳.csv 許諾の登録表.csv 出典元の台帳.csv 配布物の目録.csv
python share_terms.py terms 行の台帳.csv 許諾の登録表.csv 出典元の台帳.csv 配布物の目録.csv
python share_terms.py verify 行の台帳.csv 許諾の登録表.csv 出典元の台帳.csv 配布物の目録.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、宣言された入れ替え方で 4 枚の
行順を入れ替えても同じ出力になるか、件数の合計が 5 通りとも合うか、そして 2 つの写しだ。
**1 欄を空にした写し**では、「宣言が揃っている」が 1 減って「出すと宣言されたが欄が空」が 1 増え、
**空の欄の一覧にその欄名が 1 件現れ、行数の合計がその rule の行数ちょうどだけ移る**こと。
**許諾を 1 件外した写し**では、その名前を指す「出す」の行だけが別枠へ移り、**同じ名前を持つ
「出さない」の行と「出す宣言が無い」の行は動かない**こと。1 件の許諾は複数の rule に効くので、
**動く rule と動かない rule を入力から先に数えておき、外した後の件数が両方合うか**を見る。写しは
メモリの中だけで、入力の表には 1 文字も書かない。

終了コードは、別枠・空の欄・逆向きの欠け・止まった行が 0 件のときだけ 0、在れば 3、表として読め
なければ 2。**0 は「配ってよい」ではなく「手元の 4 枚に欠けが無い」の意味で、配ってよいかどうかは
この終了コードにも出力にも出ない。**

関数でも呼べる。

```python
import share_terms as S

t = S.share_terms(S.Ledger.load("行の台帳.csv"), S.Registry.load("許諾の登録表.csv"),
                  S.Origins.load("出典元の台帳.csv"), S.Bundles.load("配布物の目録.csv"))
if t.report.ok:
    print(t.counts()["5 値"], t.empty_fields(), t.attributions())
```

## テストと fixture

```
python -m pytest tools/share_terms -q
python fixtures/make_fixtures.py     # 合成の 4 枚と、崩した表 35 枚を書き直す
```

`fixtures/` に入っているのは合成した 4 枚(台帳 15 行 = 867 行 / 登録表 3 行 / 出典元 7 行 /
目録 8 行)と、理由コードと「表として読めない」を出すために 1 か所だけ崩した表 35 枚だ。
**実在の料率・金額・取引先名は 1 つも入っていない。** 数表 id も rule id も出典元 id も出す先 id も
架空で、`H1` `K11` `G1` `B1` のような記号にしてある。許諾の名前だけは、名前の形が分からないと
読めないので `MIT` と `公共データ利用規約` を置き、3 つ目は架空の名前にした。
**rule の数と行数の桁(15 rule / 867 行、うち出すと宣言されたのが 12 rule / 769 行)だけは手元の
記録と同じ形にそろえてある**(値は架空)。

## できないこと

- **配ってよいかは分からない。** この部品が返すのは宣言が揃っているかだけで、どの規約が当たるか、
  その規約の下で配れるかは人が決める。終了コード 0 も「欠けが無い」であって、配布の許可ではない
- **許諾が要求する欄を、この部品は知らない。** 登録表に書かれた宣言を読むだけなので、宣言そのものが
  間違っていれば結果も間違う。宣言の出典(`declared_in`)を必ず書くのはそのためで、**この部品は
  出典が在ることまでしか見ない**(その行に本当にそう書いてあるかは人が読む)
- **要求される欄は 3 つに固定。** 帰属の文字列・原文の URL・版の指紋の外を要求する許諾は、この部品
  では表せない。増やす経路を入力側に持たせていない
- **帰属の文字列の中身は見ない。** 空かどうかだけを見るので、書いてある文面が許諾の求める形かは
  分からない。文面を作る経路も持たない
- **名前が書かれていない理由は分からない。** 未調査なのか、調べた上で名前が無いのかを分けないので、
  理由は読む人が書くことになる
- **順位も勧めも出さない。** どの出典元から埋めるかは表を持つ人が決める
- **取得日より後に規約が変わっても気づかない。** この部品は規約の原文を取りに行かないので、
  登録表の宣言が古いままなら古いまま数える
- 上の件数は、合成した 4 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
