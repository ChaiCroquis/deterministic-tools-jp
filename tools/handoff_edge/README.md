# handoff_edge — 返ってきた値で計算が終わるとは限らないので、残る一手を境界の表に書く

**値が返ってきたことと、その値で計算が終わっていることは別。行が無ければ例外で止まるが、式の
節が未実装のときは値がそのまま返り、仕上げの一手だけが呼び出し側に残る。設計上そもそも表の外に
置いたもの(人の判断・主体ごとの値・履歴の走査)も返り値には現れない。だから引く前に、求める値
ごとに「道具の中で済む」「返るが一手残る」「外から渡す前提」「止まる」の 4 つを境界の表 1 枚に
して、線の外に何が在るかを数える。**

[scope_ledger](../scope_ledger) の回は、自分の道具が書いた「できないこと」の宣言と、ソースの側に
その経路が無いかを突き合わせる道具だった。向きが逆で、あれは**できないと書いたこと**を確かめる。
ここは**できると答える値の側に残っている一手**を数える。[source_pin](../source_pin) は取りに行く
前の取得の地図で線の位置が取得の側にあり、[cover_stock](../cover_stock) は年の側の在庫で、端が
仮置きかどうかはあちらの別枠に譲る。

この部品は、守備範囲の宣言表・計算のレシピ表・問いの一覧の 3 枚から、問い(= 求める値)1 つごとに
5 値(**道具の中で済む / 返るが一手残る / 外から渡す前提 / 止まる / 宣言が無い**)を付ける。
最後の 1 つが別枠で、宣言表に無い節を参照していた問いがここに出る。節ごとの内訳と、残る一手の
一覧(名前と出典)も返す。**値を計算しない。式を評価しない。行を引かない。数えるだけだ。**

持たせていないものが規律になっている。

- **宣言表に無い節は判定しない**(収録済を既定として当てる経路が無い。別枠の 5 値目に出す)
- **「止まる」と「値が返る」を同じ出口に潰さない**(終了コード 1 つに写す経路を持たない = この
  部品の骨の物理形)
- **`未実装` と `設計上の外` を同じに数えない**(線の内側の未完成と、線の外に置いた設計判断は
  やることが別なので、別の列で数える。足して 1 つにする欄が無い)
- **残る一手を道具側で埋めない・提案しない**(上限を当てる引数も、代わりの式を選ぶ経路も、
  足すべき節を出す経路も無い)
- **残る一手の名前が空の行は止まる**(状態だけ書いて、何が残るかを書かない行を通さない)
- **値を計算しない・式を評価しない・行を実際に引かない**(式は [formula_table](../formula_table)、
  値の比較は [compare_pick](../compare_pick)、年の在庫は [cover_stock](../cover_stock) の仕事で、
  役割が重ならない)
- **端が仮置きかどうかは扱わない**(確度の欄も日付の欄も持たない。日付を読む呼び出しが 0 件)
- **完成度の割合を出さない**(件数と 2 つの分母の内訳だけを返す。率を返す呼び方も option も無い)
- **この部品自身の「読めない」を、測っている相手の「止まる」と同じ欄に入れない**(宣言表が 1 行
  でも壊れていたら 1 件も判定せず、理由コードだけを返す。5 値は全て 0 になる)
- **入力表を書き換えず、節も宣言も生成しない**
- **出典の欄が空の行は使わずに止まる**
- **同じ入力には同じバイト列**(判定部分に時刻・絶対パス・ホスト名を入れない)
- **数は整数だけ**(float を使う経路が無い)

## 入力 — 守備範囲の宣言表と計算のレシピ表と問いの一覧

守備範囲の宣言表は 6 列。**1 節が 1 行**で、その節が道具の中で済むのか、外に一手が残るのかを
ここだけに書く。「節」は 1 つの rule か 1 つの式のことで、求める値より細かい単位になる。

| 列 | 意味 |
|---|---|
| `node_id` | 節 id(空欄と、英数字 `-` `_` 以外は「表として読めない」。2 行あると**止まる**) |
| `belongs_to` | その節が属する rule または式 id(空欄は**止まる**) |
| `state` | 節の状態。登録の 4 種(`収録済` / `未実装` / `未対応` / `設計上の外`)。空欄も登録外も**止まる** |
| `exit` | 出口。登録の 2 種(`値が返る` / `止まる`)。空欄も登録外も**止まる** |
| `remaining_step` | 呼び出し側に残る一手の名前。`収録済` 以外は要る。`収録済` に書いてあると**止まる** |
| `source` | 出典(空欄は**止まる**) |

`収録済` で出口が `止まる` の行も**止まる**。収録してあるのに引けないという宣言は、宣言として
矛盾しているからだ。逆に `未実装` で `値が返る` の行は矛盾ではない。それがこの部品の主題で、
**式の節が未実装でも、式そのものは呼べて値が返る**ことは実際に起きる。

計算のレシピ表は 3 列。**1 つの求める値が 1 行**で、その値に要る節を並べる。

| 列 | 意味 |
|---|---|
| `value_id` | 求める値 id(空欄も、同じ id が 2 行あるのも「表として読めない」) |
| `node_ids` | その値に要る節 id を `|` でつなぐ(空欄は**止まる**。同じ id を 2 回書くと「表として読めない」) |
| `source` | 出典(空欄は**止まる**) |

問いの一覧は 3 列。**1 つの問いが 1 行**で、訊く求める値を並べる。

| 列 | 意味 |
|---|---|
| `value_id` | 訊く求める値 id(レシピ表に無い id と、同じ問いの 2 行は「表として読めない」) |
| `source` | 出典(空欄は**止まる**) |
| `swap` | 入れ替え方(`逆順` / `両端入れ替え` / `1 つずらす`)。`verify` が 3 枚の行順を入れ替えるときの宣言 |

## 判定 — 節を集めて 1 値にする順番が仕様

節 1 つの判定は、状態と出口の 2 列だけで決まる。

| 状態 | 出口 | 節の判定 |
|---|---|---|
| `収録済` | `値が返る` | 道具の中で済む |
| 何でも | `止まる` | 止まる |
| `設計上の外` | `値が返る` | 外から渡す前提 |
| `未実装` / `未対応` | `値が返る` | 返るが一手残る |

問い 1 つの 5 値は、要る節の判定を集めて、**手前の関門が勝つ順**でいちばん手前の 1 つを返す。

```
宣言が無い → 止まる → 外から渡す前提 → 返るが一手残る → 道具の中で済む
```

**この順番そのものが仕様で、入れ替えない。** 宣言が無いのは、そもそも判定できないから先頭に
置く。止まるは値が 1 つも返らないので、いちばん強い言い方として次に置く。外から渡す前提は、
呼ぶ前に外から渡しておく一手なので、返ってから残る一手より時間の順で手前になる。順を入れ替える
と、同じ宣言から別の答えが出る(`fixtures/` の `V07` で実際に別の値になる)。

節ごとの内訳は 5 値とは別に全部残るので、**どの節がどの理由で外に出たかは潰れない**。

## 件数の検算 — 分母は 2 つある

- **5 値の件数の合計 = 問いの数**
- **節の判定別の件数の合計 = 判定した節の延べ数**(別枠の問いの節は数えない。問いが要る節の
  延べ数は別に出す)
- **節の状態別の件数の合計 = 宣言表の行数**

3 つは別の経路で数えているので、片方だけ数え方を差し替えるとこの検算が自分で見つけて止まる。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- 問い 1 つごとに 5 値が 1 つだけ付き、**5 値の合計が問いの数**に等しく、**節の判定別の合計が
  判定した節の延べ数**に等しく(延べ数を超えず)、**別枠の問いは節を 1 つも判定せず**、
  **状態を `未実装` から `収録済` に替えると「返るが一手残る → 道具の中で済む」の 1 本しか
  動かず**、**節を宣言表から外すと別枠へしか動かず**、判定部分に時刻・ホスト名・絶対パスが
  1 つも入らず、**3 枚の行順を入れ替えても同じバイト列**になる
- または、1 件も判定せずに理由コードが返る(判定した問いや指紋を取りに行くと例外になる)

どちらの場合も、この部品は宣言表もレシピ表も問いの一覧も 1 文字も書き換えない。

この 1 文を `tests/test_handoff_edge_property.py` の `@given` テストが確かめている(節を 1〜3 つ
作って状態・出口・残る一手の 3 つ組を整合するものから引き、レシピを 1〜3 本、要る節を 1〜3 つ
引く。問いを 1〜2 件。3 割くらいの確率でどこか 1 か所を崩す。乱数は固定で毎回同じ 200 通り)。
**節の判定と問いの 5 値はテストの側で別に実装している**(部品の `verdict` / `judge` を呼ばない)。
同じファイルの 2 本目は 300 通りで、「宣言表に無い節に収録済を当てない」ことを見ている。

## 出力 — 完成度の割合は返らない

`check` と `edge` が返るのは、3 枚それぞれの行数、分母(問いの数)、5 値の件数、節の判定別と
状態別の件数、分母の内訳と検算、それに 7 つの固定行だ。**割合だけを返す呼び方も、option も無い。**

```
"分母(問いの数)": 12,
"5 値": {"道具の中で済む": 2, "返るが一手残る": 3, "外から渡す前提": 3, "止まる": 3,
         "宣言が無い": 1},
"節の判定別(延べ数)": {"道具の中で済む": 6, "返るが一手残る": 6, "外から渡す前提": 5,
                       "止まる": 3},
"節の状態別(宣言表の行数)": {"収録済": 2, "未実装": 3, "未対応": 3, "設計上の外": 3},
"件数の合計の検算": "5 値の合計 12 / 分母 12(節の判定別の合計 20 = 判定した節 20、…)",
"完成度の割合を出さない": "…",
"状態に既定を当てない": "…",
"未実装と設計上の外を同じに数えない": "…",
"残る一手を埋めない・提案しない": "…",
"出口を終了コードに潰さない": "…",
"値を計算しない・式を評価しない・行を引かない": "…",
"入力を書き換えない": "…"
```

`edge` にすると、問いごとの内訳に加えて**残る一手の一覧**が出る。1 行 1 件で、求める値 / 節 /
状態 / 残る一手の名前 / 出典 の 5 列だ。**一手の中身を道具が書き足すことはしない**(名前は
宣言表に書かれたものがそのまま出る)。

## 止まる理由コード(14 個)

1 件も判定せずに止まるものが 11 個。

`出典の欄が空` / `節 id の重複` / `レシピに節 id が 1 つも無い` / `節の状態が空` /
`登録されていない節の状態` / `出口が空` / `登録されていない出口` / `残る一手の名前が空` /
`収録済なのに残る一手が書いてある` / `収録済なのに出口が止まる` / `属する rule も式 id も空`

`verify` が見つけるものが 3 個。

`件数の合計が合わない` / `2 回目の判定部分が不一致` / `行順を入れ替えた表で出力が変わる`

列が足りない・行が無い・id が空欄・同じ節 id を 2 回参照・レシピ表に無い求める値を訊く・登録外の
入れ替え方、は**「表として読めない」**(終了コード 2)で、理由コードには混ぜない。

## 使い方

```
python handoff_edge.py init ひな型/
python handoff_edge.py check  守備範囲の宣言表.csv 計算のレシピ表.csv 問いの一覧.csv
python handoff_edge.py edge   守備範囲の宣言表.csv 計算のレシピ表.csv 問いの一覧.csv
python handoff_edge.py verify 守備範囲の宣言表.csv 計算のレシピ表.csv 問いの一覧.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、宣言された入れ替え方で 3 枚の
行順を入れ替えても同じ出力になるか、件数の合計が合うか、そして 2 つの写しだ。**状態を `未実装`
から `収録済` に替えた写し**では、「返るが一手残る → 道具の中で済む」の 1 本しか動かず、減った
分だけ増えることを見る。**節を 1 つ宣言表から外した写し**では、別枠が増えた分だけほかの 4 値が
減ることを見る。写しはメモリの中だけで、入力の表には 1 文字も書かない。

終了コードは、全部の問いが道具の中で済むときだけ 0、一手が残る問いか別枠があるときは 3、表として
読めなければ 2。**測っている相手の出口をこの終了コードに写さない。**

関数でも呼べる。

```python
import handoff_edge as H

t = H.handoff_edge(H.Boundary.load("守備範囲の宣言表.csv"),
                   H.Recipes.load("計算のレシピ表.csv"),
                   H.Questions.load("問いの一覧.csv"))
if t.report.ok:
    print(t.counts()["5 値"], t.remaining())
```

## テストと fixture

```
python -m pytest tools/handoff_edge -q
python fixtures/make_fixtures.py     # 合成の 3 枚と、崩した表 30 枚を書き直す
```

`fixtures/` に入っているのは合成した 3 枚(節 11 / 求める値 12 / 問い 12)と、理由コードを出す
ために 1 か所だけ崩した表 30 枚だ。**実在の料率・金額・取引先名は 1 つも入っていない。** 節 id も
rule の名前も架空で、値も日付も 1 つも入っていない。

## できないこと

- 判定したことは「道具の中で済む節と、外に残る一手がどれか」までで、**残る一手を道具側では
  埋めない**。上限を当てる引数も、代わりの式を選ぶ経路も無い
- **足すべき節も、着手の順も提案しない。** 件数と一覧が残るだけだ
- **完成度の割合を出さない。** 言えるのは宣言表に書かれた節の範囲までで、率を返す経路が無い
- **実在の料率や金額がいくらかも言わない。** 値の欄そのものを持っていない
- **宣言が本当かどうかは判定しない。** 宣言表に「収録済」と書けばそう数える。宣言とソースを
  突き合わせるのは [scope_ledger](../scope_ledger) の仕事で、ここは宣言を読む側に立つ
- **端が仮置きかどうかも、引ける年も見ない**(年の側は [cover_stock](../cover_stock))
- 上の件数は、合成した 3 枚の表に対する測定で、他の人の環境で同じ数字になるとは限らない
