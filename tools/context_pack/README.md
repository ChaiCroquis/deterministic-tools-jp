# context_pack — 数表は AI に思い出させず、引いた行に版を焼いて渡す

<!-- article-links:begin (publish/readme_links.py が台帳から生成。手で直さない) -->
解説記事: [数表は AI に思い出させず、引いた行に版を焼いて渡す](https://chronicles-of-solo-parenting.blogspot.com/2026/10/ai.html)(2026-10-06 公開)
<!-- article-links:end -->

引いた行 1 件を AI のプロンプトへ貼る場面を扱う。人は表を開けば版が見え、機械は引数で版を指定できるが、
**AI は渡された塊の中にしか版を持てない**。だから値・対象・有効期間・公表時点・出典・原本の指紋が
塊に焼かれていないと、もっともらしく古い値が通る。

この部品は、宣言された列を欠けなく焼いた塊を 1 つ作るか、作らずに理由コードで止まるかの 2 通りしか
しない。要点は塊の書式そのものより、**同じ行を「誰が読むか」の軸で並べ直すと、版の辿り方だけが
読み手ごとに違う** ところにある。

持たせていないものが規律になっている。

- **モデル名・API・ネットワークを持たない**(推論は部品の外。塊を作るだけで、投げない)
- **要約・言い換え・切り詰めの経路を持たない**(`max_chars` を超えたら黙って truncate せず止まる)
- **表全体を貼る経路を持たない**(「全部渡して AI に選ばせる」引数が無い)
- **近い行で埋める経路を持たない**(該当 0 件でも 2 件以上でも止まる。順位で勝ち負けを決め直さない)
- **依頼文・判断の指示文を作らない**(「この値で計算して」等の文面は人が書く)
- **トークン数を返さない**(分割器は部品の外にあり、出典にしてよいファイルにも無い。返すのは文字数と
  バイト数で、それが token 数の代わりにならないことを出力自体に書く)
- **仮置きの公表時点を黙って確定値の顔で渡さない**(塊の中に仮置きと書く)

stdlib のみ(csv / json / decimal / hashlib / datetime / unicodedata / argparse)、依存なし。

## 流れ(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | 宣言を検査する(field の重複・pin の列名・必ず焼く列・max_chars・要求された field) | 宣言に無い field を要求 |
| 2 | 問いと行を突き合わせる(rule と selector が一致する行はちょうど 1 行か) | 該当 0 件 / 該当 2 件以上 |
| 3 | 焼く列が行に在るか、必ず焼く列が埋まっているかを見る | pin の列が行に無い / 出典・sha256・有効期間・公表時点が空欄 |
| 4 | 宣言された字数の上限に入るかを見る | max_chars 超過(切り詰めない) |
| 5 | 2 回組み立てて、バイト列が一致するかを見る | 2 回目の組み立てでバイト列が不一致 |

前の段で止まったら次の段には進まない。止まったときは塊が 1 つも作られず、理由コードだけが返る。

## いつも成り立つこと

組み立ての結果は 2 通りしかない。**必ず焼く 8 つの列が欠けなく入った塊が 1 つ返り、同じ問いから
2 回目を組み立てても同じバイト列になる**か、**塊は 1 つも作られず、理由コードが返る**か。どちらの
場合も、この部品は入力の行を 1 つも書き換えず、要約も切り詰めもせず、ファイルを 1 つも開かない。

この 1 文は `tests/test_context_pack_property.py` が性質テスト(hypothesis)で確かめている。宣言どおりの
行を乱数で 1〜4 行作り、9 通りから 1 つ引いて 1 か所だけ崩し(「崩さない」も同じ確率で引く)、さらに
宣言表の側の `max_chars` と任意 field と「行に無い列を焼く宣言」を乱数で動かして、毎回この 1 文が
成り立つかを見る。乱数は固定で、毎回同じ 300 通り。判定は道具の関数を使わず、テストの中に別に書いて
いる(どの段でどの理由コードが返るか、field ごとに何の文字が焼かれるか)。テストの実行には pytest と
hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 引いた行(入力その 1)

`ROW_COLUMNS` の 13 列だけ。前の工程(基準日と公表時点で引く部品)が返す形で、CSV でも 1 行 JSON でもよい。

| 列 | 意味 |
|---|---|
| `rule` | 何を求めたか |
| `selector` | 対象セグメント |
| `valid_from` / `valid_to` | 有効期間(半開区間。`valid_to` が空なら開いたまま) |
| `known_from` / `known_to` | 知識の期間(公表側) |
| `known_quality` | `実値` / `仮置き`。**空欄は許さない** |
| `priority` | 0 本則 / 10 経過措置 / 20 特例 |
| `payload` | 値 |
| `source` | 出典 |
| `source_file` / `source_row` / `source_sha256` | 原本のファイル名・行番号・指紋 |

`rule` / `selector` / `payload` が空の行、日付として読めない `valid_*` / `known_*`、`実値` / `仮置き` 以外の
`known_quality`、64 桁の 16 進でない `source_sha256` は、理由コードにせず終了コード 2 で返す
(引いた行として読めない = 引く側の話)。

## 貼り先の宣言表(入力その 2)

1 field = 1 行で、欄は 4 つ。`fixtures/sengen.csv` が例、`init` でひな型が出る。

| 欄 | 意味 |
|---|---|
| `field` | 塊に出す行の名前。そのまま `名前: 値` の行になる(`:` と改行は書けない) |
| `required` | 印が付いていれば必ず出す。空欄なら `--field` で要求された時だけ出す |
| `max_chars` | その行の値の字数の上限(空欄 = 制限なし)。超えたら止まる |
| `pin` | 版として焼く列の名前。`\|` で複数書ける(並び順がそのまま塊に出る) |

**必ず焼く 8 列**(`CORE_PINS` = `payload` / `selector` / `valid_from` / `known_from` / `source` /
`source_file` / `source_row` / `source_sha256`)のどれかを `required` の field が pin していなければ、
宣言の不備として終了コード 2 で返す。塊に何を出すかは宣言表の側で決まるが、**この 8 列を外す自由は
無い**。

## 塊の書式(固定)

```
値: 9.70
対象: 保険料率_甲 / 地域=地域A
有効期間: 2026-03-01 / (なし)
公表時点: 2026-02-10 / 実値
出典: 合成の料率表 2026 年度版(架空)
原本: moto_ryouritsu.csv / 2 / 995a9e72d1…(64 桁)
```

- 行の順は宣言表の順、区切りは `: ` と ` / `、改行は `\n`、最後の行の後ろにも改行が 1 つ付く
- 空欄の列は `(なし)` と書く(「以降」のような言い換えをしない)
- 数の列(`payload` / `priority`)は Decimal の文字列で出す(`9.70` の末尾の 0 を落とさない)
- `known_quality` が `仮置き` の行には、最後に `注記: 公表時点は仮置き(確定値ではない)` が 1 行増える

## 止まる理由コード(`REASONS`)

| 理由コード | 意味 |
|---|---|
| 出典が空欄 | 出典・原本のファイル名・原本の行番号のどれかが空欄。どこの何行目から来たかが塊から辿れない |
| sha256 が無い | 原本の指紋が空欄。原本が差し替わったかを塊から確かめられない |
| 有効期間が空欄 | 有効期間の始まりが空欄。いつからの値かが塊から辿れない |
| 公表時点が空欄 | 公表時点か、その品質(実値 / 仮置き)が空欄 |
| 該当 0 件 | 問いに当たる行が無い。近い行で埋めない |
| 該当 2 件以上 | 問いに当たる行が 2 行以上ある。順位で決め直すのは引く側の仕事 |
| 宣言に無い field を要求 | 塊に出す行は宣言表の側で決まる |
| max_chars 超過 | 宣言された字数の上限を超えた。要約も切り詰めもしないので止まる |
| 2 回目の組み立てでバイト列が不一致 | 同じ問いから 2 回組み立てて、バイト列が違った |
| pin に指定された列が行に無い | 宣言表が焼くと言っている列が、渡された行に無い |

## 使い方

```
python context_pack.py pack   <引いた行.csv|json> --decl <宣言表.csv> --rule <名> --select <対象> [--field 順位]
python context_pack.py verify <引いた行.csv|json> --decl <宣言表.csv> --rule <名> --select <対象>
python context_pack.py init   <宣言表.csv>
```

終了コードは 0 = 塊ができた / 3 = 理由コードで止まった / 2 = 宣言表・行・引数の不備。バッチの中に
置いて 3 で止められる。`--rule` と `--select` に既定は無い。

```python
from context_pack import Declaration, load_rows, pack, verify

p = pack(load_rows("引いた行.csv"), Declaration.load("宣言表.csv"),
         {"rule": "保険料率_甲", "selector": "地域=地域A"})
if p.report.ok:
    print(p.text())          # プロンプトへ貼る塊
    print(p.sha256())        # 同じ問いなら同じバイト列
    print(p.sizes())         # 文字数とバイト数(トークン数は返らない)
else:
    for x in p.report.pending:
        print(x.reason, x.detail)
```

`sizes()` は塊の大きさと、比べた相手(表全体をそのまま貼る / 機械が引数で引く 1 行 / 値だけを貼る)の
大きさを返す。**表全体は大きさを測るために内部で並べ直すだけで、その文字列を返す経路は無い。**

## 前後の工程

前の工程(基準日と公表時点で引く部品 → 値 1 件をピン 1 行で持つ部品)が返した行をそのまま受け取る。
後ろには工程が無い。塊を貼ったプロンプトを AI に投げるのは人で、この部品はモデルを呼ばない。

## テストと fixture

```
python -m pytest tools/context_pack -q      # 70 passed
python fixtures/make_fixtures.py            # 合成 fixture を作り直す
```

fixture は全て合成データで、地域名・料率・限度額・出典名はすべて架空。原本 2 枚(`moto_*.csv`)を先に
書き、その **本物の sha256** と行番号を `hiita.csv` の行に焼いてある(原本を 1 文字変えれば一致しなく
なる)。`hiita.csv` は 12 行で、5 行は宣言どおりに焼ける行、6 行は必ず焼く列のどれかを 1 か所だけ空に
した行、1 行は同じ問いに当たる 2 行目。`test_measure_*` が記事に載せた数値の出どころで、固定の
fixture から決定論的に出る値を `assert` で固定している。

## できないこと

- 塊を作ったことは「宣言された列を欠けなく焼いた」までで、**AI がその塊を使うとは言えない**。貼った
  塊を無視して記憶から答える経路は、こちら側からは閉じられない
- **トークン数は測れない**。返しているのは文字数とバイト数で、分割器はモデル側にある。文字数が減れば
  token も減るとは限らない(proxy の限界を出力自体に書いてある)
- 値が制度として正しいかは判定しない。見ているのは行の列が埋まっているかだけ
- 宣言表の正しさは判定しない。`max_chars` が雑なら止まりすぎるし、`pin` に要らない列を並べれば塊が
  太る。**宣言を書く人が線を動かす**
- 1 つの問いに 1 つの塊しか作らない。複数の値を 1 つのプロンプトに入れたい場合は、問いの数だけ呼んで
  人が並べる(並べ方を部品の中に入れると、順序と区切りが塊の外で決まってしまう)
- 公表時点が仮置きかどうかは行の `known_quality` を見ているだけで、本当の公表日を調べはしない
- 上の数字は合成データでの測定で、他の人の表で同じ字数になるとは限らない
