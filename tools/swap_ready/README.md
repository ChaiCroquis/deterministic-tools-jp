# swap_ready — 入れ替えてよい経路も入れ替えられるとは限らないので、受け入れ検査の所属を先に分ける

「ここは後で入れ替えられるように作った」と書いた経路が在っても、**入れ替えられる状態かどうかは別**だ。受け入れ検査が入れ替える側と同じ束に入っている(内蔵)うちは、宣言は使われないまま残る。しかも **「入れ替わっていない」と「入れ替わった跡を数える欄が無い」は別の事実**で、台帳に欄が無い経路はどちらとも言えない。

この部品は、3 枚の台帳と記号の登録表 2 枚から、入れ替えの経路 1 件ごとに 4 値 + 別枠 6 を付ける。**入れ替えるべきかは決めない。自分では何も入れ替えない。走らせない。**

```
python swap_ready.py check 経路.csv 検査.csv 跡.csv 許す宣言.csv 検査の所属.csv 2026-09-20
```

## 持たせていないもの

- **入れ替えるべきかを決めない**。推奨・順位・点数・割合・合計の 1 値を出す列が無い。終了コード 0 も「入れ替えてよい」ではなく「使われていない許可が台帳に無い」の意味
- **滞留の理由を推定しない**。理由は入力の注記を出典ごと写すだけで、空の行には `理由の記載なし` を入れる。理由を言い当てる辞書も分類器も持たない
- **自分では何も入れ替えない**。実行しない・import しない・構文解析しない・通信の経路が無い・入力フォルダの外を読まない
- **検査の中身を見ない**。検査が十分かは判定しない。見るのは所属(どちらの束に在るか)と、その宣言が要求する欄が埋まっているかまで
- **0 件と欄が無いを同じ値にしない**。跡の欄そのものが無い経路は別枠へ出し、件数の欄は `数えられない` を返す
- **範囲つきの許可を `許す` に寄せない**。`照合専用` のような限定の文字列を整数や真偽に直す経路が無い。範囲の判定は人が別の欄に書いた種別記号の列だけで行い、注記の文字は読まない
- **独立と書いただけでは独立にしない**。検査が在る束の名前を要求し、入れ替える側の束と同じ名前なら矛盾する宣言として別枠へ出す
- **時計を読まない**(基準日は呼び出し側が渡す)。**入力を書き換えない**。**float を使わない**(件数と日数は整数、ほかは文字列)

## 入力 — 3 枚 + 記号の登録表 2 枚

**登録表 2 枚の行に出典が無ければ、1 経路も数えずに止まる。**

### 経路の台帳(8 列)

| 列 | 中身 |
|---|---|
| `route_id` | 経路 id(同じ id が 2 行あると止まる) |
| `kind` | 入れ替える対象の種別記号(`版` / `実装` / `data` / `行`) |
| `bundle` | 入れ替える側の束の名前 |
| `permission` | 許す宣言の記号(登録表に在る記号だけ。無ければ別枠へ) |
| `scope_note` | 許可の範囲の注記(`照合専用` のような限定の文字列を**生のまま**。無ければ `—`) |
| `scope_kinds` | 範囲に含める対象の種別記号を `/` で区切った列(無ければ `—`) |
| `declared_on` | 宣言された日(`YYYY-MM-DD`。記載が無ければ `—`) |
| `source` | 出典(ファイル名 + 行番号)。空欄のとき、その経路は別枠「出典が空」へ入る |

`scope_note` と `scope_kinds` を分けたのは、**範囲の判定を注記の文字から当てないため**だ。`照合専用` が何を許しているかは人が読んで `scope_kinds` に記号で書く。道具は記号の列だけを見る。

### 受け入れ検査の台帳(5 列、1 経路に 0〜N 行)

| 列 | 中身 |
|---|---|
| `check_id` | 検査 id |
| `route_id` | 経路 id(経路の台帳に無いと読めない) |
| `placement` | 検査の所属記号(`独立` = 入れ替える側と別の束 / `内蔵` = 同じ束 / `無い`) |
| `bundle` | 検査が在る束の名前(`独立` の宣言が要求する欄) |
| `source` | 出典。空欄のとき、その経路は別枠「出典が空」へ入る |

**`独立` と書いて `bundle` が入れ替える側と同じ名前なら、矛盾する宣言として別枠へ出る。** 同じ経路に `独立` と `内蔵` の 2 行が在る場合も同じ。

### 跡の台帳(6 列、1 経路に 0〜N 行)

| 列 | 中身 |
|---|---|
| `route_id` | 経路 id |
| `field` | 跡を残す欄の名前(`—` = 欄が無い) |
| `observed` | その欄で入れ替わりが観測された件数(整数。`—` = 数えない) |
| `range` | 観測した行の範囲(例 `11 行`) |
| `reason` | 理由の注記(**入力の文字をそのまま写す**。空欄なら `理由の記載なし`) |
| `source` | 出典。空欄のとき、その経路は別枠「出典が空」へ入る |

理由だけを書きたい行は `field` を `—` にする。**跡を数える行にはならないが、理由と出典は残る。**

### 記号の登録表 2 枚(各 4 列)

| 表 | 記号 | `requires` に書ける値 |
|---|---|---|
| 許す宣言の登録表 | `許す` / `範囲つきで許す` / `許さない` / `宣言なし` | `—` / `宣言された日` / `許可の範囲` |
| 検査の所属の登録表 | `独立` / `内蔵` / `無い` | `—` / `束の名前` |

**「その記号が何を要求するか」はここに在る。** 記号の綴りから当てる経路は無い。4 つ / 3 つの記号が揃っていないと止まる。

## 分け方 — 経路 1 件に付く 4 値(欄は 5 つ)と別枠 6

| 値 | 意味 |
|---|---|
| (A) | 許す宣言が在り、検査が独立で、跡が 1 件以上 = 使われている |
| (B) | 許す宣言は在るが、検査が内蔵か無い = 入れ替えてよいが入れ替えられない |
| (C) | 許す宣言が在り検査も独立だが、跡が 0 件 = 入れ替えられるが入れ替えていない |
| (D) | 許さないと宣言(線の外) |
| (D) | 宣言なし(未規定) |

別枠 6 は上から順に当たり、**4 値より先に当たる**。出典が空 / 記号が登録の外 / その記号が要求する欄が空 / 矛盾する宣言 / 許可の範囲の外 / 跡を残す欄そのものが無い。

**跡の欄が無いことで別枠へ出るのは、許す宣言が在って検査も独立な経路だけ**だ((A) か (C) に分かれるはずの経路が分かれないから)。(B) と (D) の経路では、跡の欄の有無は列に出るだけで 4 値は変わらない。

## いつも成り立つこと

読んだ範囲は 2 通りしかない。

- **4 値を付けた**: **経路 1 件ごとに 4 値の 5 欄か別枠 6 のどれか 1 つ**が付き、**その合計 = 経路の件数**、**種別ごとの内訳の合計も束ごとの内訳の合計も同じ数**になる。**許す側の宣言が無い経路は (A)(B)(C) に入らず**、**検査が独立でない経路は (A)(C) に入らず**、**跡の欄が無い経路は件数に `数えられない` を返して 0 件と同じ値にならない**。**範囲つきで許す経路は、通す対象の種別が範囲の記号の列に在るときだけ 4 値へ進む**(注記の文字は読まない)。理由は入力の注記のままで、判定部分に絶対パスもファイル名も注記の文字も入らず、5 枚の行順を 3 通りに入れ替えても同じバイト列になる
- **1 経路も数えずに理由コードが返る**: 4 値や sha256 を取りに行くと例外

どちらの場合も、この部品は 5 枚の表を 1 文字も書き換えない。

この 1 文を検査にしたのが `tests/test_swap_ready_property.py`(hypothesis、`derandomize=True`)。4 値の決め方はテストの中に別に書いてあり、部品の `judge` / `five` / `extras` を呼ばない。

## 件数の検算 — 3 通りの数え方が合う

`check` の出力の `件数の合計の検算` が、同じ件数を 3 通りに数えて並べる。

- 4 値 + 別枠 の合計
- 対象の種別(版 / 実装 / data / 行)ごとの合計
- 入れ替える側の束ごとの合計

**3 つが経路の件数に戻らなければ、どこかの数え方が壊れている。**

## 滞留の量 — 3 つだけ

- (B) + (C) の件数
- 経路ごとの跡の件数(**0 を含む**。欄が無い経路は `数えられない`)
- 経路ごとの「宣言された日 → 呼び出し側が渡した基準日」の日数(記載が無ければ `宣言された日の記載なし`)

**順位も割合も合計の 1 値も返さない。**

## 止まる理由コード(7 個)

登録の行の出典が空 / 経路 id の重複 / 登録表に無い記号が在る / 要求する欄が決めた欄の外 / 基準日が渡されていない / 宣言された日が基準日より後 / 跡の件数が整数でない。

**止まった表は 4 値を 1 件も返さない**(4 値も別枠も全て 0 で、理由コードだけが返る)。表として読めないとき(列が無い / 行が無い / 記号が決めた外 / id が空 / 参照が台帳に無い)は終了コード 2。

## 使い方

```
python swap_ready.py init ひな型/
python swap_ready.py check  経路.csv 検査.csv 跡.csv 許す宣言.csv 検査の所属.csv 2026-09-20
python swap_ready.py report 経路.csv 検査.csv 跡.csv 許す宣言.csv 検査の所属.csv 2026-09-20
python swap_ready.py verify 経路.csv 検査.csv 跡.csv 許す宣言.csv 検査の所属.csv 2026-09-20
```

`report` は経路ごとの一覧と、種別ごと・束ごとの内訳と、理由と、判定部分の sha256 を足す。`verify` は 5 つ見る。

- 2 回読んで判定部分の指紋が同じか
- 5 枚の行順を 3 通りに入れ替えても同じ出力になるか
- 3 通りの数え方の合計が合うか
- 1 件の跡の件数に 1 足すと、**その経路だけ**が (C) → (A) へ移るか
- 1 件の検査の所属を 内蔵 → 独立 にすると、**その経路だけ**が (B) から動くか

終了コードは、止まらず・別枠 0 件・(B) と (C) と「(D) 宣言なし」が 0 件のときだけ 0、在れば 3、表として読めなければ 2。

## テストと fixture

```
python -m pytest tools/swap_ready -q
```

`fixtures/` の 5 枚は合成で、**実データ・実在の名前・実在のパスは 1 つも入っていない**(経路 id は記号、束の名前は「借り物の束 / 自前の束 / 本番の束 / 照合用の束」、出典は「合成の…(架空)」)。`fixtures/kowashita/` に、止まる理由コード 7 個と表として読めない 7 通りへ道を付けた崩した表が入っている。`fixtures/make_fixtures.py` で作り直せる。

## できないこと

- **入れ替えるべきかは分からない。** 4 値を付けるところまでで、どの経路をどう入れ替えるかは読む人が決める。(A) でも「入れ替えてよい」とは言っていない
- **検査が十分かは分からない。** 見るのは所属だけで、検査の中身は読まない。独立な検査が 1 件在っても、それが入れ替えを受け止められるかは出力に出ない
- **滞留の理由は分からない。** 返るのは入力の注記の写しだけで、注記が無い経路は `理由の記載なし` になる。理由を言い当てない
- **跡の件数が正しいかは分からない。** 台帳に人が書いた件数をそのまま使う。欄が無い経路は `数えられない` で、0 回なのか記録されていないのかは言えない
- **許可の範囲が正しく記号に落ちているかは分からない。** `照合専用` が何を許すかは人が `scope_kinds` に書く。注記と記号の列がずれていても道具は気づかない
- 上の件数は合成した 5 枚に対する測定で、ほかの人の環境で同じ数字になるとは限らない
