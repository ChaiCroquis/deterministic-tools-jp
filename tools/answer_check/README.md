# answer_check — AI が返した数値は、渡した行に在るかどうかだけで突き合わせる

解説記事: [AI が返した数値は、渡した行に在るかどうかだけで突き合わせる](https://chronicles-of-solo-parenting.blogspot.com/2026/10/ai_082792725.html)(2026-10-07 公開)
<!-- article-links:end -->

前の工程([context_pack](../context_pack))で、引いた行を AI のプロンプトへ貼る塊にするところまでは
機械で固められる。固められないのは、**返ってきた文章のほう** だ。文章に現れた数値が、渡した行の値
なのか、塊の外から出てきた値なのかは、文章を読んだだけでは区別できない。

この部品は **文章に現れた数値が塊の行に在るかどうか** だけを判定し、4 値の件数と分母の内訳を返して
人に戻す。AI を採点しない。どちらが正しいとも決めない。

要点は突き合わせそのものより、**同じ数値について経路が 2 本あるときに、比べる前に単位・期間・丸めの
宣言を揃え、揃っていない組み合わせは比べずに残す** ところにある。

持たせていないものが規律になっている。

- **モデル名・API・ネットワークを持たない**(推論は関所の外。文章は人が貼る)
- **どちらが正しいとも返さない**(正とする側を選ぶ引数が無い。[cross_route](../cross_route) と同じ規律)
- **許容誤差の引数を持たない**(差額を丸めて吸収する経路が無い。丸めは名前で宣言し、両側に同じ名前の
  丸めを当てる。[tally_gate](../tally_gate) と同じ)
- **文章を書き換えない**(訂正文・指摘文・再依頼文を作る経路が無い。[intake_triage](../intake_triage) と同じ)
- **接地率を単独で返さない**(4 値の件数と分母の内訳を必ず併記する)
- **塊の外へ値を取りに行かない**(足りない行を表から引き直す経路が無い。原本のファイルを 1 つも開かない)
- **近い行で埋めない**(同じ対象の行が塊に 2 件以上あれば比べずに止まる)
- **推測で単位を補わない**(宣言に無い単位は正規化せず「比べられない」に落とす)

stdlib のみ(csv / json / re / decimal / hashlib / datetime / unicodedata / argparse)、依存なし。

## 流れ(固定)

| 段 | すること | 止まる条件 |
|---|---|---|
| 1 | 塊を検査する(必ず在る 8 列が埋まっているか、同じ対象の行が 1 件か) | 出典 / sha256 / 有効期間 / 公表時点が無い、同じ対象が 2 件以上 |
| 2 | 宣言を検査する(単位が書かれているか、正規化の名前が登録済みか) | 単位の宣言が無い、宣言に無い正規化 |
| 3 | 文章を読む | 文章が空 |
| 4 | 基準日を見る(塊の有効期間が宣言された基準日を含むか) | 有効期間が基準日を含まない |
| 5 | 取り出して 4 値に分ける(件数と分母の内訳を返す) | — |
| 6 | 2 回判定してバイト列を突き合わせる | 2 回目の判定でバイト列が不一致 |

前の段で止まったら次の段には進まない。止まったときは判定が 1 件も返らず、理由コードだけが返る。

## いつも成り立つこと

判定の結果は 2 通りしかない。**文章から見つけた表記のひとつひとつがちょうど 1 つの箱に入り(接地 /
食い違い / 塊に無い / 比べられない、または読めなかった表記)、その合計が見つけた表記の総数に等しく、
同じ入力から 2 回判定すれば同じバイト列になる**か、**判定は 1 件も返らず、理由コードが返る**か。
どちらの場合も、この部品は文章を 1 文字も書き換えず、塊の行を 1 つも書き換えず、原本のファイルを
1 つも開かず、どちらが正しいとも返さない。

この 1 文は `tests/test_answer_check_property.py` が性質テスト(hypothesis)で確かめている。塊を乱数で
0〜3 件、文章を 0〜5 文作り(1 文に 1 つの表記)、表記は 10 とおり・単位は 4 とおり(宣言にある 2 つ /
宣言に無い 1 つ / 単位なし)・呼び方は 4 とおり(宣言の 3 つ / 呼び方の無い文)から引く。さらに 3 割
くらいの確率で 1 か所だけ崩す(塊の出典・指紋・有効期間・公表時点を空にする、同じ対象の行を 2 件に
する、宣言の単位を空にする、登録に無い丸めの名前を呼ぶ、文章を空にする)。乱数は固定で、毎回同じ
300 通り。**判定は道具の関数を使わず、テストの中に別に書いている**(表記を数として読むところ、倍率と
丸めを当てるところ、4 値に分けるところを別実装で持つ)。同じファイルの 2 本目は **分母の恒等式** を
見る(4 値の合計が取り出せた数値に等しく、照合できていない数値を分母から外した接地率は、取り出せた
数値すべてを分母にした接地率を下回らない = 狭い分母だけを引用すると必ず上振れする側に出る)。
テストの実行には pytest と hypothesis が要る(道具そのものは標準ライブラリだけで動く)。

## 入力その 1 — 塊(AI へ渡したもの)

[context_pack](../context_pack) が組んだ塊(text)をそのまま読める。空行で区切って複数並べてよい。

```
値: 9.70
対象: 保険料率_甲 / 地域=地域A
有効期間: 2026-03-01 / (なし)
公表時点: 2026-02-10 / 実値
出典: 合成の料率表 2026 年度版(架空)
原本: moto_ryouritsu.csv / 2 / d8d3d4…(64 桁)
```

同じ列を持つ CSV / 1 行 JSON でもよい(`fixtures/kata.csv` / `fixtures/kata_1ken.json`)。列は 11。

| 列 | 意味 |
|---|---|
| `selector` | 対象(塊の「対象」の行そのまま。突き合わせはこの文字列で行う) |
| `payload` | 値 |
| `valid_from` / `valid_to` | 有効期間(半開区間) |
| `known_from` / `known_quality` | 公表時点と、その品質(`実値` / `仮置き`) |
| `source` / `source_file` / `source_row` / `source_sha256` | 出典・原本のファイル名・行番号・指紋 |
| `priority` | 持ち越すだけ(突き合わせには使わない) |

`selector` が空の行、日付として読めない `valid_*` / `known_from`、`実値` / `仮置き` 以外の
`known_quality`、64 桁の 16 進でない `source_sha256` は、理由コードにせず終了コード 2 で返す
(塊として読めない = 組む側の話)。

## 入力その 2 — 文章(AI が返したもの)

plain text。ファイルでも標準入力(`-`)でもよい。**この部品は文章を書き換えない。** 読むのは数の
表記だけで、文の意味は見ない。

## 宣言表(比べる対象ごとに 1 行)

`fixtures/sengen.csv` が例、`init` でひな型が出る。

| 欄 | 意味 |
|---|---|
| `selector` | 塊の「対象」とそのまま一致する文字列 |
| `alias` | 文章の中でその対象を指す呼び方。`\|` で複数。**2 つの対象に同じ呼び方は書けない** |
| `unit` | 文章に出てよい単位。`\|` で複数。**1 つめが塊の値の単位** |
| `scale` | `unit` と同じ数だけ `\|` で並べる倍率の名前。**1 つめは「そのまま」** |
| `period` | 照合の基準日(YYYY-MM-DD)。塊の有効期間がこの日を含まなければ止まる |
| `rounding` | 比べる前に両側へ当てる丸めの名前 |

倍率の名前: `そのまま` / `10分の1` / `100分の1` / `1000分の1` / `百倍` / `千倍` / `万倍`。
丸めの名前: `しない` / `整数` / `小数1桁` 〜 `小数4桁`。**どちらも既定を持たない。**

丸めは **両側に同じ名前の丸めを当てる** だけで、差額の大きさで通す / 通さないを決める引数は無い
(`tolerance` に相当するものがソースのどこにも無いことをテストで固定してある)。ただし雑な丸めを
宣言すれば食い違いは隠れる。**線を動かすのは宣言を書く人のほう。**

## 数の取り出し(緩く拾って、厳しく読む)

- 拾うのは半角 / 全角の数字の連なりと、宣言された単位が直後に付く漢数字
- 読むときは NFKC で正規化し、`1,234` のような 3 桁区切りだけを落として `Decimal` にする
- 読めなかった表記(漢数字 `九・七`、範囲 `9.70〜9.82`、3 桁でない区切り `3,57,000`)は
  **4 値には入れず、分母の内訳に「取り出せなかった表記」として必ず出す**
- 単位は宣言されたものしか読み取らない。宣言に無い単位が付いていれば「単位なし」と同じ扱いになり、
  `比べられない` に落ちる(推測で単位を補わない)
- その数値がどの対象かは、**同じ文の中で数値より左にある、いちばん近い呼び方** で決める。左に
  呼び方が無ければ `塊に無い` になる

## 判定は 4 値

| 判定 | 何が起きたか |
|---|---|
| `接地` | 宣言どおりに正規化した文章の数値が、塊の行の値と一致した |
| `食い違い` | 同じ対象の行は塊にあるが、値が違った(前の版の値が混ざった場合など) |
| `塊に無い` | どの行にも対応しない数値(対象が決まらない / その対象の行が塊に無い) |
| `比べられない` | 単位・期間・丸めの宣言が足りず、比べる前に止まった |

**`食い違い` のときにどちらかを正として返す経路を持たない。** AI を採点せず、文章も直さない。返すのは
数値ごとの 4 値と、塊のどの行と比べたかの対応表だけで、訂正文の欄は無い。

## 接地率は分子分母だけでは返らない

`rate()` は接地率を出すが、**`接地 ÷ (接地 + 食い違い)` だけを単独で返す呼び方を持たない。** 4 値の
件数と、分母に何を含めたかの文字列を必ず同時に返す。

```
{"接地": 5, "食い違い": 1, "塊に無い": 2, "比べられない": 1,
 "文章から取り出せた数値": 9, "取り出せなかった表記": 3, "見つけた表記の総数": 12,
 "比べられた数値": 6,
 "接地率_比べられた数値のみ": "0.8333", "接地率_取り出せた数値すべて": "0.5556",
 "分母に含めたもの": "比べられた数値のみ = 接地 5 + 食い違い 1 = 6(塊に無い 2 + 比べられない 1 を
                   除いた分母) / 取り出せた数値すべて = 9(取り出せなかった表記 3 件はどちらの分母
                   にも入らない)"}
```

照合できていない数値を分母から落とすと、同じ入力で `0.5556` が `0.8333` になる。だから片方だけを
引用できない形にしてある。

## 止まる理由コード(10 個)

| 理由コード | 何が起きたか |
|---|---|
| 塊に出典が無い | 出典・原本のファイル名・原本の行番号のどれかが空欄。どこの何行目から来たかが辿れない |
| 塊に sha256 が無い | 原本の指紋が無い。原本が差し替わったかを確かめられない |
| 塊に有効期間が無い | 有効期間の始まりが無い。いつからの値かが辿れない |
| 塊に公表時点が無い | 公表時点か、その品質(実値 / 仮置き)が無い |
| 塊の有効期間が照合の基準日を含まない | 別の版の行と文章を突き合わせることになるので止まる |
| 単位の宣言が無い列を要求 | 宣言表の対象に `unit` が無い。単位を推測で補わない |
| 同じ selector の行が 2 件以上 | どちらと比べるかは文章の側では決まらない。近い行で埋めない |
| 文章が空 | 取り出せた数値 0 件を「全部接地」として返さない |
| 宣言に無い正規化を要求 | 登録されていない倍率 / 丸めの名前を呼んでいる |
| 2 回目の判定でバイト列が不一致 | 同じ入力から 2 回判定して、返したバイト列が違った |

## 使い方

```
python answer_check.py check  <塊> <文章> --decl <宣言表.csv>
python answer_check.py verify <塊> <文章> --decl <宣言表.csv>
python answer_check.py init   <宣言表.csv>
```

終了コードは 0 = 取り出せた数値が 1 件以上あり、その全部が接地し、読めない表記も無い / 3 = 接地しない
数値があった、または理由コードで止まった(どちらかは出力の `ok` で分かる)/ 2 = 塊・宣言表・文章の
不備。バッチの中に置いて 3 で止められる。option は `--decl` だけで、ほかに引数は無い。

```python
from answer_check import Declaration, load_pack, check

c = check(load_pack("kata.txt"), Declaration.load("sengen.csv"),
          open("bunshou.txt", encoding="utf-8").read())
if c.report.ok:
    print(c.rate())          # 4 値 + 分母の内訳 + 2 つの接地率
    print(c.table())         # 表記ごとの判定と、塊のどの行と比べたか
    print(c.sha256())        # 同じ入力なら同じバイト列
else:
    for x in c.report.pending:
        print(x.reason, x.detail)
```

## 読み替えた範囲(2 経路の独立性)

2 経路で突き合わせる型を、ここでは **経路A = 塊に焼いた行(出典 + sha256 + 有効期間つき)/ 経路B =
返ってきた文章から取り出した数値** と読み替えている。**経路B が塊そのものに由来する場合、2 経路は
独立ではない** ので、見えるのは転記の壊れ(桁・単位・版の取り違え)までだ。この 1 行は出力の
`読み替えた範囲` にも入っていて、報告から外せない。制度として正しいかを見たいなら、経路B を別の
公表物から取る必要があり、それは [cross_route](../cross_route) の仕事になる。

## 前後の工程

前は [context_pack](../context_pack)(引いた行を塊に組む)。その前は
[asof_table](../asof_table)(基準日と公表時点で引く)と [source_pin](../source_pin)(出典を焼く)。
後ろには工程が無い。4 値の件数は人に戻る。

## テストと fixture

```
python -m pytest tools/answer_check -q      # 49 passed
python fixtures/make_fixtures.py            # 合成 fixture を作り直す
```

fixture は全て合成データで、地域名・料率・限度額・出典名・文章はすべて架空。原本 2 枚(`moto_*.csv`)を
先に書き、その **本物の sha256** と行番号を塊に焼いてある(原本を 1 文字変えれば一致しなくなる)。
`bunshou.txt` は 12 文で、数の現れ方を 7 とおり仕込んである(同じ桁・単位 / 丸めだけ違う / 単位が違う /
全角と桁区切り / 前の版の値 / 塊に無い数値 / 単位の宣言が無い表記)。`test_measure_*` が記事に載せた
数値の出どころで、固定の fixture から決定論的に出る値を `assert` で固定している。

## できないこと

- 判定したことは「文章に現れた数値が塊の行に在るか」までで、**文章の主張が妥当かは判定しない**。
  数値が全部接地していても、その数値を使った結論が合っているとは言えない
- **値が制度として正しいかも判定しない**。見ているのは塊の行と一致するかだけで、塊の行が間違っていれば
  間違ったまま接地する
- **モデルがなぜその数値を出したかは分からない**。プロンプトの書き方との関係も測っていない
- 経路B が塊に由来する場合、2 経路は独立でない。**見えるのは転記の壊れまで**(上の「読み替えた範囲」)
- 数値と対象の結び付けは「同じ文の中で左にある、いちばん近い呼び方」という 1 つの規則だけで決めている。
  文をまたいで指している場合や、表の形で返ってきた場合は結び付かず、`塊に無い` に落ちる
- **暦の日付も数の表記として拾う**。`2026-03-01` は年・月・日の 3 件になり、単位が無いので
  `比べられない` に入る。日付を除く経路は持たせていない(除く規則を入れると、年号のように見える
  数値を黙って落としてしまう)
- 丸めを雑に宣言すれば食い違いは隠れる。`整数` と書けば `9.70` と `9.80` はどちらも `10` になる。
  宣言の正しさは判定しない
- 上の件数は合成の塊と文章での測定で、他の人の文章で同じ数字になるとは限らない
