前回、引いた行を AI のプロンプトへ貼る塊にした。値・対象・有効期間・公表時点・出典・原本の指紋を焼いた塊で、どれか 1 つでも欠ければ塊を作らずに止まる形にしてある。渡すところまでは、これで機械の側に寄せられた。残っているのは返ってきたほうだ。この記事で作るのは、返ってきた文章に現れた数値が、渡した行に在るかどうかだけを判定する関所になる。AI を採点する部品ではない。

**なぜ重要か**: 塊を渡したあと、返ってきた文章を読んで「合っていそうだ」と思う。その瞬間に何が起きているかというと、文章の中の数値が、渡した行から来たのか、それとも塊の外から出てきたのかを、見分けないまま通している。どちらも同じ見た目の数字で、桁も単位も文章の中では自然に見える。[2 つの経路で同じ数字を取る回](https://chronicles-of-solo-parenting.blogspot.com/2026/10/2.html)で書いたとおり、私の記録に残っている食い違いは、値の優劣ではなく「そもそも同じものを指していなかった」ことのほうだった。だからこの関所も、どちらが正しいかを決めにいかない。やるのは、**比べる前に単位・期間・丸めの宣言を揃え、揃っていない組み合わせは比べずに残す**ことで、最後に残るのは件数と、その件数をどの分母で数えたかの内訳になる。

**要点**:
- 判定は 4 値にする。接地・食い違い・塊に無い・比べられない。食い違ったときにどちらかを正として返す経路を持たない
- 比べる前に単位と丸めを名前で宣言させ、宣言に無い単位は正規化せずに「比べられない」へ落とす。推測で単位を補わない
- 許容誤差の引数を持たない。丸めは名前で呼び、両側に同じ名前の丸めを当てるだけで、差額の大きさで通す経路は無い
- 接地率は単独では返らない。4 値の件数と、分母に何を含めたかの文字列が必ず一緒に付く

**数字で見る**: 合成の塊 4 件と、AI の答えに見立てた合成の文章 12 文を突き合わせると、見つけた表記 12 のうち取り出せたのが 9、残り 3 は読めない表記だった。取り出せた 9 の内訳は接地 5・食い違い 1・塊に無い 2・比べられない 1 で、比べられた 6 だけを分母にした接地率と、取り出せた 9 すべてを分母にした接地率は、同じ突き合わせから別々の数字になる。

## 何を解決するのか

前提から書く。私の数表は、いま 1,681 行、45 種類のルールが入っている。引く側は基準日と公表時点を引数に取り、返ってくる行には出典と有効開始日が必ず付く。前回はその行をプロンプトへ貼る塊にした。塊には値だけでなく、対象・有効期間・公表時点・出典・原本のファイル名と行番号と指紋が焼いてある。

ここまでで、渡す側は機械で止められるようになった。欠けていれば塊ができない。

止められないのは、返ってきた文章のほうだ。塊を貼って質問を書き、返ってきた文章を読む。文章には数字が並んでいる。渡した値と同じものもあれば、違うものもある。違っていても、文章としては自然に読める。私がやっていたのは、目で追って「だいたい合っている」と判断することだった。これは検算ではない。

### 読むだけでは、出どころが分からない

文章に現れた数値には、少なくとも 3 つの出どころがありうる。渡した塊の値をそのまま書いたもの。渡した塊の値を書き写すときに桁や単位がずれたもの。そして、塊を見ずに記憶から出てきたものだ。

この 3 つは、文章の上では区別が付かない。付けたければ、渡した行と突き合わせるしかない。

突き合わせると決めた途端に、別の問題が出てくる。**同じ数値でも、書き方は 1 とおりではない。** 塊に `9.70` と書いて渡しても、返ってくる文章は `9.7%` かもしれないし、`97‰` かもしれないし、全角の数字かもしれない。桁区切りが入ることもある。文字として比べれば全部違う値になり、全部「食い違い」になる。それでは使えない。

かといって、形の違いを吸収する仕組みを足していくと、今度は逆の事故が起きる。`9.70` と `9.80` を「近いから同じ」と扱う経路を 1 本でも作れば、前の版の値が静かに通る。

### 揃えるのは値ではなく、宣言のほう

直し方は、吸収する仕組みを足さないことだ。足すのは、比べる前に揃っているべき宣言になる。

| 宣言する欄 | その対象について言えるようになること |
|---|---|
| `alias` | 文章の中でその対象をどう呼ぶか。ここに無い呼び方は結び付けない |
| `unit` | 文章に出てよい単位。1 つめが塊の値の単位になる |
| `scale` | 単位ごとの倍率の名前。2 つめ以降の単位を 1 つめに揃える |
| `period` | 照合の基準日。塊の有効期間がこの日を含まなければ止まる |
| `rounding` | 比べる前に両側へ当てる丸めの名前 |

この 5 つが揃っている組だけを比べる。揃っていなければ、値が一致していても比べない。一致していても比べない、という扱いにするところが肝で、**たまたま数字が合っている組を「接地できた」に数えないため**にこうしてある。

倍率も丸めも、名前で呼ばせている。既定を持たせていない。「よしなに揃える」経路を作ると、どこで揃えたのかが出力に残らず、後から「この数字はどの正規化を通ったのか」が決まらなくなる。

## 図 1 文章での数値の現れ方と、どの箱に入ったか

![数値の現れ方 7 とおりを行に、接地・食い違い・塊に無い・比べられない を列にした対応表](figures/answer_check_cases.png)

行が文章での現れ方、列が 4 値だ。藍が実走でその箱に入ったところ、橙が同じく入ったうえで人に戻す必要があるところ、無彩色がその現れ方ではその箱に入らなかったところになる。各セルの件数は合成の塊と文章に対してその場で動かした判定の出力で、テストが固定している。

読みどころは 3 つある。

1 つめは、上の 4 行が**どれも接地に入っている**ことだ。丸めだけ違う書き方、`‰` や千円のような別の単位、全角と桁区切り。これらは宣言どおりに正規化すれば同じ値に揃う。揃えてよい理由は「近いから」ではなく、宣言表にその名前が書いてあるからで、どの名前を通ったかは対応表に残る。

2 つめは、5 行目が**接地ではなく食い違いに入っている**ことだ。前の版の値が文章に出た場合がこれにあたる。ここは丸めでも単位でも揃わない。揃わないので食い違いとして出すのだが、**どちらが正しいとは返さない。** 塊の行が正しいと決めてしまうと、塊の側の間違いに気づけなくなる。関所が返すのは「文章の数値と塊の値が違った」という事実と、どの行と比べたかだけになる。

3 つめは、下の 2 行が**比べられていない**ことだ。塊にどの行も無い数値と、単位の宣言が無い表記は、照合できていない側に入る。ここを 0 件にする方法はいくらでもある。宣言に無い単位を推測で補えばいいし、呼び方が見つからない数値を近い対象に当てればいい。そうすると接地率は上がるが、上がったぶんは全部、機械が推測した分になる。

## 手順

入力は 2 つ、それに宣言表が 1 枚だ。1 つめの入力は前の工程が組んだ塊で、そのまま読める。

```
値: 9.70
対象: 保険料率_甲 / 地域=地域A
有効期間: 2026-03-01 / (なし)
公表時点: 2026-02-10 / 実値
出典: 合成の料率表 2026 年度版(架空)
原本: moto_ryouritsu.csv / 2 / d8d3d48c3f2894ef2f63b9d8ce7994df8b6b1f4c1ad9cafaa87db74a5680de0c
```

空行で区切れば何件並べてもよい。同じ列を持つ CSV や 1 行 JSON でも受け取る。どの入り口から入れても、判定の結果のバイト列は同じになる。

2 つめの入力が、返ってきた文章だ。ファイルでも標準入力でもよく、**この関所は文章を 1 文字も書き換えない。**

3 枚目が宣言表になる。1 つの対象が 1 行だ。

```
selector,alias,unit,scale,period,rounding
保険料率_甲 / 地域=地域A,保険料率_甲|甲の料率,%|‰,そのまま|10分の1,2026-06-01,小数2桁
限度額_丁 / 区分=区分1,限度額_丁,円|千円,そのまま|千倍,2026-06-01,整数
```

突き合わせるときは 3 つとも渡す。

```
python answer_check.py check 塊.txt 文章.txt --decl 宣言表.csv
```

返るのは 4 値の件数と、分母の内訳と、表記ごとの対応表だ。

```
{"ok": true, "stage": "判定した", "塊の行": 4,
 "接地": 5, "食い違い": 1, "塊に無い": 2, "比べられない": 1,
 "文章から取り出せた数値": 9, "取り出せなかった表記": 3, "見つけた表記の総数": 12,
 "比べられた数値": 6,
 "接地率_比べられた数値のみ": "0.8333", "接地率_取り出せた数値すべて": "0.5556",
 "分母に含めたもの": "比べられた数値のみ = 接地 5 + 食い違い 1 = 6(塊に無い 2 + 比べられない 1 を
                   除いた分母) / 取り出せた数値すべて = 9(取り出せなかった表記 3 件はどちらの
                   分母にも入らない)"}
```

同じ突き合わせから 2 つの接地率が出る。照合できていない数値を分母から落とすと `0.5556` が `0.8333` になるので、片方だけを引用できない形にしてある。これは[2 経路で突き合わせる回](https://chronicles-of-solo-parenting.blogspot.com/2026/10/2.html)で作った一致率と同じ作りだ。

対応表は 1 表記 1 行で、欄は固定されている。

```
{"表記": "97", "文": 2, "単位": "‰", "読めた": true,
 "対象": "保険料率_甲 / 地域=地域A", "判定": "接地", "正規化": "9.70",
 "塊の行": 1, "塊の値": "9.70"}
```

何を正規化に通したか、塊のどの行と比べたか、その行の値は何だったかまでが出る。出ないものもある。**訂正文の欄が無い。** 「ここが違うので直してください」という文面を関所が作ると、その文面の正しさを誰も検査しないまま下流へ流れる。文面を書くのは人の仕事にしてある。

数の取り出しは、緩く拾って厳しく読む形にした。

```
拾う:   半角と全角の数字の連なり、宣言された単位が直後に付く漢数字
読む:   NFKC で正規化し、3 桁の区切りだけを落として Decimal にする
落ちる: 漢数字、範囲の表記、3 桁でない区切り → 「取り出せなかった表記」として数える
```

読めなかった表記を捨てないところが、ここでの線引きになる。捨てると分母が小さくなり、接地率が静かに上がる。4 値には入れず、分母の内訳に別の箱として出す。

欠けている塊は、判定に入る前に止まる。

```
{"ok": false, "stage": "塊", "塊の行": 1,
 "pending": [{"reason": "塊に sha256 が無い", "detail": "塊 1 の source_sha256 が空欄"}]}
```

止まる理由コードは 10 個で、これ以上増やしていない。

```
塊に出典が無い / 塊に sha256 が無い / 塊に有効期間が無い / 塊に公表時点が無い /
塊の有効期間が照合の基準日を含まない / 単位の宣言が無い列を要求 /
同じ selector の行が 2 件以上 / 文章が空 / 宣言に無い正規化を要求 /
2 回目の判定でバイト列が不一致
```

同じ対象の行が塊に 2 件あるときは、比べずに止まる。片方を選んで比べることはできるのだが、選んだ記録は文章の側に残らない。どちらと比べるかが決まらないまま接地と言うほうが、止まるより悪いと考えている。

「文章が空」を理由コードにしてあるのは、取り出せた数値 0 件を「全部接地」として返さないためだ。分母が 0 のときに 1.0000 を返す関所は、何も見ていないときに最高点を出すことになる。

関数として呼ぶ形も同じになる。

```python
from answer_check import Declaration, load_pack, check

c = check(load_pack("塊.txt"), Declaration.load("宣言表.csv"),
          open("文章.txt", encoding="utf-8").read())
print(c.rate() if c.report.ok else [x.reason for x in c.report.pending])
```

引数は塊・宣言表・文章の 3 つだけで、「許容誤差」「正とする経路」「足りない行を表から引き直す」に相当する引数は 1 つも無い。これはテストでも固定してある。

## 検証

テストは 49 件で、fixture は全て合成データだ。地域名も料率も限度額も出典名も、AI の答えに見立てた文章も架空で、実在のものは入れていない。原本にあたる CSV を 2 枚先に書き出し、その**本物の sha256** と行番号を塊に焼いてあるので、原本を 1 文字でも変えれば塊の中の指紋と合わなくなる。

```
$ python -m pytest tools/answer_check -q
........................................
[measure] 塊 4 件と文章 12 文を突き合わせる: 見つけた表記 12 / 取り出せた 9 / 取り出せなかった 3

.

[measure] 止まった(宣言の段): 単位の宣言が無い列を要求
[measure] 止まった(宣言の段): 宣言に無い正規化を要求

          = 理由コード 10 個すべてに道がある
```

4 値の内訳を補う。接地した 5 件は、同じ書き方が 1 件、丸めだけ違う書き方が 1 件、別の単位で書かれたものが 2 件、全角と桁区切りが 1 件だ。食い違いの 1 件は、前の版の値が文章に出たものになる。塊に無いの 2 件は毛色が違っていて、片方は宣言表に名前があるのに塊に行が無い対象、もう片方は文の中に呼び方がまったく無い数値だ。どちらも「どの行とも対応しない」という意味では同じ箱に入る。比べられないの 1 件は、単位を付けずに数字だけが書かれたものになる。

読めなかった 3 件は、漢数字の表記、範囲の表記、3 桁でない区切りの表記だ。これらは数として読めないので 4 値に入れず、分母の内訳に別の箱として出す。読めないことを「無かった」ことにしないためで、ここを隠すと接地率が上がる側にだけ動く。

理由コード 10 個のうち 9 個は、崩した fixture を通して止まることを見ている。残る 1 つの「2 回目の判定でバイト列が不一致」は普通は起きないので、判定を 1 か所だけ差し替えて、その経路が本当に止まるかを確かめた。

暦の日付の扱いも測った。文章に `2026-03-01` のような日付が入っていると、年・月・日の 3 件が数の表記として拾われる。単位が付いていないので全部「比べられない」に落ちる。日付だけを除く規則を入れると、年号のように見える数値まで黙って落としてしまうので、除く経路は持たせていない。かわりに、落ちた件数が分母の内訳に出る。

残りのテストは、生の表記と位置が文章そのままであること(= 文章を書き換えていないこと)、入力の塊の行が 1 つも書き換わらないこと、判定のあいだに原本のファイルを 1 つも開かないこと、止まったときに結果を取りに行くと例外になること、接地率を単独で取り出す呼び方が無いこと、`tolerance` や `prefer` にあたる名前がコードのどこにも出てこないこと、CLI の option が `--decl` 1 つだけであることを見ている。

いつも成り立つことは 1 文にして、性質テストで確かめている。判定の結果は 2 通りしかない。文章から見つけた表記のひとつひとつがちょうど 1 つの箱に入り、その合計が見つけた表記の総数に等しく、同じ入力から 2 回判定すれば同じバイト列になるか、判定は 1 件も返らず理由コードが返るか、だ。どちらの場合も、文章は 1 文字も書き換わらず、塊の行も書き換わらず、どちらが正しいとも返らない。塊と文章と宣言表を毎回乱数で作り直し、3 割くらいの確率で 1 か所だけ崩して、毎回この 1 文が成り立つかを見る。乱数は固定で、毎回同じ 300 通りを試す。**どの箱に入るかの判定は、道具の関数を使わず、テストの中に別に書いてある。** 同じファイルの 2 本目は分母の恒等式を見ていて、照合できていない数値を分母から外した接地率が、取り出せた数値すべてを分母にした接地率を下回らないこと、つまり狭い分母だけを引用すると必ず上振れする側に出ることを確かめている。

## 図 2 突き合わせの流れと、止まる場所

![塊を検査し、宣言を検査し、基準日を見て、取り出して 4 値に分け、2 回判定して返すまでの流れ図](figures/answer_check_flow.png)

段は 6 つで、橙のピルが関所だ。前の 4 段は文章を 1 文字も読む前の検査で、塊と宣言の噛み合わせだけを見ている。

この図でも見てほしいのは、描かれていない経路のほうになる。4 値に分ける段から「正しいほうを選ぶ」へ出る矢印がどこにも無い。「差が小さいので通す」へ出る矢印も無い。「足りない行を表から引き直す」へ戻る矢印も無い。文章の段から「訂正文を作る」へ進む矢印も無い。実装でも同じで、そういう引数を持たせていないから、落ちる先が無く、落ちる経路も書けない。

基準日を見る段を、文章を読むより前に置いてあるのが今回の並びの肝になる。塊の有効期間が照合の基準日を含んでいなければ、そもそも別の版の行と文章を突き合わせることになる。ここを後ろに置くと、比べ終わってから「違う版だった」と分かることになり、それまでに出た件数は全部意味を失う。

最後の段は前回と同じで、判定を 2 回行って自分の出力を突き合わせている。同じ入力から 2 回判定して違うバイト列が出てきたら、それは決定論ではないということなので、そこで止める。

## 道具

道具は [GitHub](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/answer_check) にある。ライセンスは MIT で、自由に使える。標準ライブラリだけで動く(テストの実行には pytest と hypothesis が要る)。宣言表のひな型は `init` で出る。

```
python answer_check.py init 宣言表.csv
```

自分の文章に合わせるときは、この CSV を書き換える。呼び方を足し、文章に出てよい単位とその倍率の名前を並べ、基準日と丸めを書く。部品のコードは触らない。終了コードは、取り出せた数値が全部接地したときだけ 0 で、それ以外は 3 になる。バッチの中に置いて 3 で止められる。

## 別の業種なら

この関所が持っているのは `selector` と `alias` と `unit` と `scale` と `period` と `rounding` という 6 つの欄だけで、給与や社会保険の語彙は 1 つも入っていない。税率と勘定科目、送料と手数料、歩掛、点数と加算。どれも「AI に文章で答えさせると、もっともらしく桁や版の違う数値が混じる」場面で、同じ構図だと考えている。私が実測したのは上の合成データの範囲だけなので、他の分野は「同じ詰まり方になりそうな例」であって実測ではない。変わるのは塊の中身と、宣言表に書く呼び方・単位・倍率の名前だけで、関所のコードはそのまま使える。

## できないこと

- 判定したことは「文章に現れた数値が塊の行に在るか」までで、**文章の主張が妥当かは判定しない**。数値が全部接地していても、その数値を使った結論が合っているとは言えない
- 値が制度として正しいかも判定しない。見ているのは塊の行と一致するかだけで、塊の行が間違っていれば間違ったまま接地する
- モデルがなぜその数値を出したかは分からない。プロンプトの書き方との関係も測っていない
- **2 つの経路が独立しているとは言えない。** ここでの経路 A は塊に焼いた行、経路 B は文章から取り出した数値だが、経路 B が塊そのものを写したものであれば、見えるのは転記の壊れ(桁・単位・版の取り違え)までになる。この 1 行は出力の中にも入れてあって、報告から外せないようにした
- 数値と対象の結び付けは「同じ文の中で左にある、いちばん近い呼び方」という 1 つの規則だけで決めている。文をまたいで指している場合や、表の形で返ってきた場合は結び付かず、塊に無いに落ちる
- 暦の日付も数の表記として拾う。単位が無いので比べられないに入る。日付を除く規則は入れていない
- 丸めを雑に宣言すれば食い違いは隠れる。`整数` と書けば `9.70` と `9.80` はどちらも同じ値になる。宣言の正しさは判定しないので、線を動かすのは宣言を書く人のほうだ
- 上の件数は合成の塊と文章での測定で、他の人の文章で同じ数字になるとは限らない
