差分の記録に「替わった 1 件」と出ていると、値が 1 つ替わったと読みたくなる。今回はその読みを、記録に残っている見本で確かめる。骨は 1 行で言える。**替わったと数えられた行の見本を前(old)と後(new)で欄ごとに見比べると、写っている欄がすべて同じものと、文言の欄だけが違うものがあり、数値の欄が違う見本は私が読んだ範囲に 1 件も無かった。**

**なぜ重要か**: 私の記録には自動更新の実行履歴が 1 ファイルあり、1 行が 1 回の実行で、差分の欄に増えた・減った・替わった行の件数が入っている。この連載でも以前の回で、3 つめの欄を「中身が替わった行数」と呼んできた。件数だけを報告に写すと、それは値が動いた数として伝わる。ところが同じ行には見本が残っていて、見本のほうは別のことを言っている。**件数と見本は同じ行に在るのに、外に出るのは件数だけになりやすい。**

**要点**:
- 替わったと数えられた行の見本を、old と new で欄ごとに文字列として比べる。数として近いかは見ない
- 違った欄を、人が登録した記号(数値の欄 / 文言の欄 / 種別の欄 / 識別子の欄)に当てて区分する。登録表に無い欄が違っていたら、当てずにそこで止める
- 写っている欄がすべて同じ見本は「変更なし」とは書かない。**見本に写っていない所で何が違ったかは、見本からは決められないので残差として残す**
- 見本は全件ではない。回ごとに件数の合計と見本の本数を横に並べ、区分ごとの件数を 1 値に丸めない

**数字で見る**: 私の実行履歴の記録 11 行を 3 表に写して 1 回通すと、替わったと数えられた 3 件の見本は、写っている欄がすべて同じ 2 件 / 文言の欄だけ違う 1 件 / 数値の欄が違う 0 件に分かれた。合成した 3 表(回 9 行 / 見本 19 行 / 欄 6 行)では、替わったの見本 14 本が区分 6 本と別枠 8 本に分かれる。

---

## 何を解決するのか

### 前提は、この連載自身の言い方に在る

先に前提を置く。相手は誰かの誤読ではなく、私の記録と、この連載が自分で書いてきた言い方だ。

構成を書いた記録の 15 行目は、実行履歴のファイルを「全実行の履歴 (status・差分・sha256・上流 commit)」と呼んでいる。全体像を書いた記録の 50 行目は、自動更新の流れの中に `diff` という段を置いている。そして以前の回で私は、差分の 3 つの欄を「増えた / 減った / 中身が替わった行数」と書いた。**どれも「替わったの件数 = 中身が替わった行の数」と読める書き方になっている。**

この読みは、件数の欄だけを見ているかぎり確かめようがない。確かめる材料は、同じ行の見本のほうに在る。

### 替わったが 0 でない回は 3 回で、見本は 1 件ずつ在る

実行履歴の記録は 11 行で、替わったの件数が 0 でない回は 5 行目・6 行目・8 行目の 3 回になる。どれも 1 件で、見本が 1 本ずつ残っている。見本は key と old と new の 3 つでできていて、key は規則の名前・絞り込みの条件・有効開始日・順位の 4 つ、old と new は値の側の欄だけを持つ。

5 行目の見本の key は `地域別最低賃金 / 都道府県 Tokyo / 2025-10-03 / 0` で、old は `kind: param / value: 1226 / unit: 円/時`、new も `kind: param / value: 1226 / unit: 円/時` だ。**old と new が、写っている 3 つの欄とも同じになっている。**

6 行目の見本も同じ key で、old と new がやはり同じだ。

8 行目の見本は `保険料_端数処理` で、`kind` と `id` は old と new で同じ、`text` が違い、new にだけ `text_cash` という欄が在る。こちらは文言が差し替わった見本で、以前の回でも「文言が替わった例」として 1 回引いた。

つまり、替わったと数えられた 3 件のうち、見本の上で値の数字が動いているものは無い。2 件は写っている欄が全部同じで、1 件は文言だけが違う。

### 同じ記録に在る記載を、結び付けずに並べる

ここで「では 5 行目と 6 行目は何が替わったのか」を当てたくなる。同じ記録に、関係がありそうな記載はいくつか在る。

- 5 行目は、増えた 1 件・替わった 1 件の回で、増えた行の見本は同じ規則・同じ絞り込みの条件で、有効開始日が 2026-10-03 の行になっている
- 6 行目は、減った 1 件・替わった 1 件の回で、出力の指紋が 1 行目・2 行目・7 行目と同じ文字列に戻っている
- 全体像を書いた記録の 109 行目には「行を足したら前の行を閉じる規律は人が忘れる (未来有効行の追加で実際に validator に止められた)」と書いてある

3 つめは、行を足すと前の行にも手が入ることを書いている。けれど **5 行目と 6 行目の「替わった」がそれだとは、どの記録にも書かれていない。** だから私は、この 3 つを並べるだけにして、結び付けていない。道具にも、結び付ける経路を置いていない。

### 残るのは、見本に写っていない所

残差ははっきりしている。5 行目と 6 行目で old と new の何が違ったかは、見本には写っていない。見本の old と new が持っているのは `kind` `value` `unit` の 3 欄だけで、表の行がそれ以外の欄を持っているかどうかも、見本からは読めない。だから「何も替わっていない」とも「どこかが替わった」とも、見本からは言えない。**言えるのは「見本に写っている欄は同じ」までだ。**

もうひとつ、見本は全件ではない。件数の合計と見本の本数を並べると、5 行目は 2 件に 2 本、6 行目は 2 件に 1 本(減った 1 行は見本に無い)、8 行目は 483 件に 6 本、9 行目は 180 件に 5 本になる。8 行目で減った 141 行は、見本に 1 本も無い。区分は見本の比較であって、表そのものの行を比べた結果ではない。

いちばん下の段は観測のまとめで、4 つを別の枠に分けた。差の大きさ(区分ごとの件数)、同じ記録に在る記載、残差、見本が全件でないこと。**理由の列も、正しい読みの列も、「実質の変更は何件」の 1 値も置いていない。** 同じ記録に在る記載の枠には「並べるだけで、結び付けない」と書いてある。

欄の記号は私が登録した分で、`value` を数値の欄、`text` と `text_cash` を文言の欄、`kind` と `unit` を種別の欄、`id` を識別子の欄にした。登録を変えれば区分は動く。

## 手順

入力は 3 表になる。回の台帳、見本の台帳、欄の登録表だ。

回の台帳には、実行 1 回を 1 行で書く。

```csv
run_id,added,removed,changed,source
R01,40,0,0,合成の実行履歴のメモ(架空)L1
R03,,,,合成の実行履歴のメモ(架空)L3
R06,12,5,4,合成の実行履歴のメモ(架空)L6
```

件数が記録されていない回(失敗の回など)は、3 欄を空にする。0 とは書かない。空の回を指す見本は区分に入れず、別枠へ出す。

見本の台帳は、1 行に見本 1 本を書く。old と new が欄と値の対になるので、ここだけ CSV ではなく 1 行 1 本の JSON にしてある。

```
{"run_id": "R04", "kind": "changed", "key": "合成の規則A / 区分 甲 / 期 P1 / 0", "old": {"kind": "param", "value": 5000, "unit": "点"}, "new": {"kind": "param", "value": 5000, "unit": "点"}, "source": "合成の実行履歴のメモ(架空)L4"}
{"run_id": "R04", "kind": "added", "key": "合成の規則A / 区分 甲 / 期 P2 / 0", "old": null, "new": {"kind": "param", "value": 5000, "unit": "点"}, "source": "合成の実行履歴のメモ(架空)L4"}
```

`kind` は `added` `removed` `changed` の 3 つで、比べるのは `changed` だけになる。`added` と `removed` の見本は、回ごとの本数に数えるだけで中身は読まない。

欄の登録表が、区分を決める表になる。

```csv
field,symbol,source
kind,種別の欄,合成の登録のメモ(架空)L1
id,識別子の欄,合成の登録のメモ(架空)L2
value,数値の欄,合成の登録のメモ(架空)L3
text,文言の欄,合成の登録のメモ(架空)L5
```

記号は `数値の欄` `文言の欄` `種別の欄` `識別子の欄` の 4 つしか受け取らない。**欄の名前から記号を当てる経路は無い。** `value` という名前だから数値、とは道具は考えない。登録表に無い欄が違っていたら、その見本は「違う欄に登録表に無い欄が含まれる」で止まり、人が登録表に足すのを待つ。

返るのは区分ごとの件数で、足し合わせた 1 値は無い。`rows` にすると、回ごとの一覧(件数の合計・見本の本数・見本の範囲・件数は在るのに見本が 1 本も無い種別)と、見本ごとの一覧(区分か別枠・違った欄の名前と記号・片側だけの印・同じだった欄の名前)が出る。

比べ方は 1 つだけで、**値が書かれた文字列として等しいか**を見る。`5000` と `5000.0` は等しくない。数の `1226` と文字列の `"1226"` も等しくない。数として近いかを見る経路は置いていないし、float も使っていない。丸めて比べると、「同じ」と言ってよい範囲を道具が勝手に決めることになるからだ。

見る順は決めてある。違った欄が 1 つも無ければ (A)。違った欄に登録表に無い欄が 1 つでも在れば (D)。そうでなく数値の欄が在れば (C)。違った欄が全部文言の欄なら (B)。残りが (E) で、数値の欄は同じだが種別か識別子の欄が違う見本になる。片側にだけ在る欄は違った欄に入れ、「old にだけ」「new にだけ」の印を別の列に付けて、その欄の記号で区分する。

表として読めないとき(見出しが違う、回の id が重複、出典が空、件数が整数でない、記号が登録の外、見本の行が読めない、など)は、1 本も区分せずに理由を返す。

私の実行履歴の記録は、次の写しで 3 表にした。入力のファイルは読むだけで、書き出すのは別の置き場になる。

```python
import csv, json, sys

src, out = sys.argv[1], sys.argv[2]
runs, samples = [], []
for n, line in enumerate(open(src, encoding="utf-8"), 1):
    rec, rid, where = json.loads(line), f"L{n}", f"実行履歴の記録 {n} 行目"
    d = rec["diff"] or {}
    runs.append([rid] + [d.get(k, "") for k in ("added", "removed", "changed")] + [where])
    for s in d.get("samples", []):
        kind = "changed" if "old" in s else "added" if "added" in s else "removed"
        samples.append({"run_id": rid, "kind": kind, "key": " / ".join(str(x) for x in s["key"]),
                        "old": s.get("old", s.get("removed")), "new": s.get("new", s.get("added")),
                        "source": where})
with open(out + "/runs.csv", "w", encoding="utf-8", newline="") as f:
    csv.writer(f).writerows([["run_id", "added", "removed", "changed", "source"]] + runs)
with open(out + "/samples.jsonl", "w", encoding="utf-8") as f:
    f.writelines(json.dumps(s, ensure_ascii=False) + "\n" for s in samples)
```

この写しでは見本の台帳が 14 行になり、うち替わったの見本が 3 本だった。別枠は 0 本で、終了コードは 0 になる。**終了コードの 0 は「読めて別枠が無い」という意味で、「値は替わっていない」という意味ではない。**

最後に、この手続き自体が決定論かどうかを見る。

```
python change_kind.py verify fixtures/runs_a.csv fixtures/samples_a.jsonl fixtures/fields_a.csv
```

`verify` は 5 つ見る。判定部分の sha256 が二度走って同じか。3 表の行順と、old と new の中の欄の順を入れ替えても同じ出力になるか。区分と別枠の合計が替わったの見本の本数に戻り、回ごとの見本の本数の合計が見本の台帳の行数に戻るか。**(A) の見本の new の数値の欄を 1 文字だけ変えた写し**では、その 1 本だけが (C) へ動いて、ほかの見本が 1 本も動かないか。**欄の登録表から 1 欄を消した写し**では、その欄が違っている見本だけが (D) になるか。写しはメモリの中だけで、入力には 1 文字も書かない。

```
[measure] 出力の末尾の「持たせていないもの」は 10 行。それ以外の出力に
          ['実質', '変更なし', '割合', '率', '理由', '推計'] のどの語も現れない(0 件)
[measure] 部品が import している module は 7 個。時計・通信・float・round・乱数の呼び出しは 0 件。
          hashlib を呼ぶのは 1 か所
13 passed
```

(紙面に収めるために、長い行は途中で折り返し、verify の行は中身を短く書き直してある。数は実走の出力のままだ。)

読みどころは 3 つある。

ひとつめが、合成した表の (A) の 2 本だ。R04 と R05 は私の記録の 5 行目・6 行目と同じ形にしてあり、同じ key の見本が 2 回続けて「替わった」と数えられ、どちらも写っている 3 欄が同じになる。R05 は減った 1 件の見本が無い回で、`件数は在るのに見本が 1 本も無い種別` に `removed` が出る。**(A) は区分の 1 つであって、「変更なし」の別名ではない。** 出力のどこにも「変更なし」という語が現れないことは、テストで見ている。

ふたつめが、別枠の 8 本になる。出典が空、回の台帳に無い回を指す、件数の欄が空の回を指す、見本の本数が件数を超える回に属する、同じ回に同じ key が 2 本在る、old か new が無い。どれも「比べてよいか」が先に怪しい見本で、比べた結果と混ぜると区分の件数が濁る。合成の表では、替わったの見本 14 本のうち比べたのは 6 本だけだ。

みっつめが、2 つの写しの動き方だ。(A) の見本の数値を 1 文字変えると、その 1 本だけが (C) へ動く。欄の登録表から 1 欄を消すと、その欄が違っている見本だけが (D) になり、延べ 4 本が動く。**登録表が区分を決めていて、道具が欄の名前から何かを読み取っていない**ことを、この形で確かめた。

いつも成り立つことは 1 文にして、性質テストで確かめている。読んだ結果は 2 通りしかない。種別が changed の見本 1 本ごとに 5 つの区分か 6 つの別枠のどれか 1 つだけが付き、その合計が changed の見本の本数に等しく、(A) が付くのは old と new で欄の名前の集まりが同じで全部の欄の値が書かれたとおりに等しい見本だけで、(C) が付く見本には数値の欄の違いが必ず在り、3 表の行順と欄の順を入れ替えても同じバイト列になるか、1 本も区分せず、止まった理由が 1 つ返るか、だ。どちらの場合も入力の 3 表は 1 文字も書き換わらない。3 表は乱数で作り、区分と別枠の照合は道具の関数を使わずにテストの中で別に書いた。乱数は固定で、毎回同じ 200 通りになる。

書いている途中で直したことが 2 つある。1 つは区分の数だ。最初は 4 つ(同じ / 文言だけ / 数値が違う / 登録表に無い欄)で設計していたが、合成の表に「識別子だけが違う見本」を入れたところ、4 つのどれにも当たらなかった。文言だけでも数値でもなく、登録表にも在る。そこで (E) を足して 5 つにした。もう 1 つは `verify` で、最初は見本を「回・種別・key」の組で見分けていた。これだと同じ回に同じ key が 2 本在る見本(別枠の 1 つ)が 1 本に潰れて、写しの前後を比べられない。見本の台帳の行順で見分ける形に直した。

私の記録を写した 3 表のほうは、置き場に入れていないので、テストには入っていない。上の「2 件 / 1 件 / 0 件」は、手順の節に載せた写しを 1 回通した出力になる。

## 図 2 区分するまでの流れと、止まる場所

![3 表を読み、回と見本を当て、changed の見本を取り出し、old と new を欄ごとに比べ、違った欄を登録表に当てて区分し、件数の合計と見本の本数を並べ、検算と verify をするまでの流れ図](figures/change_kind_flow.png)

段は 7 つで、橙のピルが関所になる。前の 3 段は比べる前の検査で、表として読めるか、見本が指す回が在るか、比べる相手が在るかを見ている。別枠の 6 つはここで分かれる。

この図で見てほしいのは、描かれていない経路のほうだ。**見本の外を読む矢印が無い。** 同じ回に足された行と結び付ける矢印も、替わった理由を当てる矢印も、見本から全件の内訳へ推計する矢印も、「変更なし」と言い換える矢印も無い。実装でも同じで、そういう引数を持たせていない。

4 段目と 5 段目が本体になる。4 段目で old と new を欄ごとに文字列として比べ、違った欄の名前を写す。5 段目でその欄を登録表に当てる。登録表に無い欄が違っていたら、当てずに (D) で止める。

6 段目で、回ごとに件数の合計と見本の本数を並べる。7 段目で、2 通りの数え方が合うかを見る。

件数と出力の指紋の 2 経路を並べること、増減の累計、値の出どころの入れ替え、再計算の範囲は、以前の回の別の部品で扱っている。この部品が読むのは見本の old と new だけで、役割は重ならない。

## 道具

道具は [GitHub](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/change_kind) にある。ライセンスは MIT で、自由に使える。標準ライブラリだけで動く(テストの実行には pytest と hypothesis が要る)。

手元で書くのは 3 表で、回の台帳と見本の台帳は、多くの環境では更新の仕組みがすでに書いている記録から写すだけになると考えている。人が決めるのは欄の登録表で、「この欄は数値か、文言か」を 1 欄ずつ登録する。登録していない欄が違っていれば (D) に出てくるので、登録の漏れはそこで見える。

合成した 3 表が置き場に入っているので、同じ数字が手元で出るかを確かめられる。規則の名前も値も出典も架空で、実在の料率や金額は入っていない。5 つの区分と 6 つの別枠が、少なくとも 1 本ずつ出るように作ってある。

使い方として想定しているのは、「今回の更新で何件替わったか」を人に伝える前に 1 回通すことだ。出てきた区分ごとの件数と、回ごとの「件数の合計と見本の本数」を、そのまま並べて伝える。

## 別の業種なら

この部品が持っている欄は、回の番号・key・欄の名前と値・記号・出典だけで、給与や社会保険の言葉は入っていない。どの業種でも「差分 N 件」の記録は値が替わった件数として読まれやすい、と私は考えている。会計なら、仕訳の同期の記録で「更新 N 件」と出ても、金額が同じで摘要や更新時刻だけが違う行が混ざる。買い物の仕組みなら、商品マスタの同期で「変更あり」と出た行のうち、価格が同じで説明文だけが違うものがある。人事なら、社員マスタの差分で所属も等級も同じなのに替わったと数えられる行がある。どれも件数だけを報告に写すと、値が動いた数として伝わる。私が測ったのは上の 3 表と私の記録 1 ファイルの範囲だけなので、ほかの業種は同じ詰まり方になりそうな例であって実測ではない。変わるのは表に書く語と、欄の登録表の中身になると考えている。

## できないこと

- **(A) の行で何が違ったかは分からない。** 見本に写っている欄が同じだと言えるだけで、写っていない欄は比べていない。私の記録の 5 行目と 6 行目で何が替わったと数えられたのかは、この部品では決まらない(決めるには、その回の前後の表そのものを読む別の手続きが要る)
- **見本に無い行のことは分からない。** 見本が一部の回では、区分は見本の本数ぶんだけになる。全件の内訳へ割合を掛けて広げる経路は持っていない
- **欄の記号が正しいかは分からない。** 記号は人が登録したもので、道具は登録どおりに当てるだけだ。同じ見本でも、登録を変えれば区分は動く
- **数として同じかは見ていない。** 書き方が違うだけの数(末尾の 0 の有無など)も「違う」になる。同じと言ってよい範囲は、道具の外で人が決める
- **替わった理由は出ない。** 同じ回に足された行や減った行と結び付ける経路も無い。結び付けたいときは、出典の在る記載を別に並べて、人が判断する
- 私の記録についての「2 件 / 1 件 / 0 件」は、記録 1 ファイルの 11 行を 1 回通した結果で、私の環境での話になる。その 3 表は置き場に入れていないので、読む人が同じ数を出すことはできない
- 合成した 3 表の件数は合成の表に対する測定で、ほかの人の環境で同じ数字になるとは限らない
