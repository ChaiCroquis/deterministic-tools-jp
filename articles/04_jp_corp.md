取引先の台帳を 2 つ突き合わせるとき、会社名は「法人格を取ってから似ている順に寄せる」のが定石になっている。私の記録では、会社名を正規化しているコードが 7 か所あって、その 7 か所すべてがこのやり方だった。だがこれは、別の法人を 1 件に畳む道を最初から開けている。この記事では、法人格を除去ではなく分離して照合キーに残し、13 桁の法人番号があれば名前より先にそれで突き合わせ、決まらない行は理由コードを付けて人に返す部品を 1 か所にまとめる。

**なぜ重要か**: 会社名には、氏名には無いものが 1 つある。誰でも使える一意の番号が公表されていることだ。にもかかわらず、私が書いてきた突合は全部、名前を削って似ている順に並べるところから始まっていた。番号の列は台帳にあるのに、突合には使っていなかった。しかも削り方が悪い。法人格を除去すると「山田商事株式会社」と「山田商事有限会社」はどちらも「山田商事」になり、完全一致で当たってしまう。別法人なのに、出力の上では「きれいに一致した行」として見える。名寄せの間違いが音を立てないのは氏名と同じだが、会社名の場合は、音を立てずに済ませなくてよい手がかりが最初から手元にあったという点が違う。

**要点**:
- 法人格は除去せず分離して照合キーに残す。捨てると「A 株式会社」と「A 有限会社」が同じキーになる
- 番号の列があるなら、名前より先に番号で突き合わせる。検査数字が通れば、名前の表記が違っても同じ法人として扱える
- 検査に落ちた番号は名前で救わない。壊れた番号のまま下流へ流さないための関所にする
- 決まらない行は 7 つの理由コードで人に返す。類似度のしきい値は 1 つも持たない

**数字で見る**: 合成した 1,000 行の台帳 2 つで、法人格を除去して寄せる素朴な突合は 907 件を決め、そのうち 37 件が別法人だった。この道具は 885 件を突合し(うち 300 件は法人番号で)、別法人への結合は 0 件、残り 115 件を理由コード付きで判断待ちにした。

---

## 何を解決するのか

会社名は、同じ 1 社でも台帳ごとに書き方が揃わない。給与や社会保険の側は「株式会社山田商事」と前株で書く。請求の側は「山田商事(株)」と後株の丸括弧で、表計算から出てきた列には合字の「㈱」が入っている。営業の一覧には「山田商事株式会社 大阪支店」と事業所名が付いていて、古い台帳には全角英字の「ＡＢＣ物産株式会社」が残っている。

この表記の揺れを均すこと自体は、決定論でできる。NFKC で合字と全角英数を寄せ、空白と区切りを落とせば、上の表記はほとんど同じ形になる。問題はその次だ。多くの道具は、揃えた文字列から法人格を「除去」してしまう。株式会社・有限会社・合同会社といった語を消してから、残りを比べる。私の 7 か所も全部そうしていた。

法人格を消すと、比較が楽になる。前株と後株の違いが消え、合字の違いも消える。だが同時に、法人格が持っていた情報も消える。「山田商事株式会社」と「山田商事有限会社」は、消したあとはどちらも「山田商事」で、完全一致する。この 2 つは別の法人だ。同じ屋号を使う株式会社と有限会社は珍しくない。そして畳まれた結果は、出力の上では「完全一致で決まった行」に見える。類似度を使ったかどうかに関係なく、除去した時点で間違いは決まっている。

合成データで試すと、法人格を除去してから突き合わせる素朴なやり方は 1,000 行のうち 907 件を決め、そのうち 37 件が別法人に当たった。一方、素朴でも何でもない「文字列をそのまま完全一致」では 178 件しか決まらず、それでも 3 件は別法人だった。決まる件数は 5 倍近く増えるが、増えた分に間違いが混ざっていて、出力を見ても区別が付かない。

ここで、氏名の名寄せには無かった手がかりが使える。法人には 13 桁の番号が公表されていて、誰でも参照できる。番号が両方の台帳にあるなら、名前をどう寄せるかという議論そのものが要らない。番号が一致すれば同じ法人で、番号が違えば別の法人だ。私がやっていなかったのは、この列を見ることだった。

だからこの道具は、順番を入れ替えた。番号がある行は番号で突き合わせる。番号が無い行だけを名前の経路に回し、その名前の経路では法人格を捨てない。どちらでも決まらない行は、理由を付けて人に返す。

## 手順

最初に決めるのは会社名の分け方で、これが正本になる。分けるのは 3 つ、法人格の種類と、屋号と、事業所の印だ。

表記の正規化では、NFKC で合字と全角英数を寄せ、空白と区切りを落とす。これで「㈱山田商事」「山田商事(株)」「山田商事　株式会社」が同じ土俵に乗る。ローマ字の大文字小文字は畳む。カナと漢字は畳まない。読みを持っていないので、同じ会社かどうかを決められないからだ。

法人格の分離では、表にある法人格を探して種類として取り出す。取り出すだけで、捨てない。前にあっても(前株)、後ろにあっても(後株)、途中にあっても同じ種類として扱う。表は 24 種類ある。

| 分類 | 表にある法人格 |
|---|---|
| 会社 | 株式会社 / 有限会社 / 合同会社 / 合資会社 / 合名会社 |
| 法人(一般・公益) | 一般社団法人 / 一般財団法人 / 公益社団法人 / 公益財団法人 |
| 医療・福祉・教育 | 医療法人社団 / 医療法人財団 / 医療法人 / 社会福祉法人 / 学校法人 / 宗教法人 |
| 士業・行政 | 社会保険労務士法人 / 税理士法人 / 弁護士法人 / 司法書士法人 / 行政書士法人 / 独立行政法人 |
| その他 | 特定非営利活動法人 / 事業協同組合 / 協同組合 |

長い表記から先に当てるので、「医療法人社団みどり会」は医療法人社団として取れて、医療法人には食われない。表に無い法人格は、種類が空のまま屋号に残る。畳まれるのではなく、別のキーになる。

事業所の印は、支店・支社・営業所・事業所・出張所・支部の 6 語で終わる行に立てる。ここで大事なのは、支店名を屋号から切り離さないことだ。「山田商事(株)大阪支店」には区切りが無いので、「大阪」がどこから始まるかを機械は決められない。切り離そうとすれば推測が入る。だから屋号は「山田商事大阪支店」のまま持ち、別の欄に「支店」という印だけを立てる。結果として本社の行と支店の行は別のキーになる。これは取りこぼしではなく、別の事業所として扱うという判断だ。

```python
LEGAL_FORMS = (
    ("株式会社", ("株式会社", "(株)")),
    ("有限会社", ("有限会社", "(有)")),
    ("特定非営利活動法人", ("特定非営利活動法人", "NPO法人")),
    ("医療法人社団", ("医療法人社団",)),
    ("医療法人", ("医療法人", "(医)")),      # 長い表記から先に当てるので食われない
    ...
)

def parse(text):
    """会社名を 法人格の種類 / 屋号 / 事業所の印 に分ける。除去ではなく分離する。"""
    s = normalize(text)                       # NFKC + 空白と区切りを除く
    m = _FORM_RE.search(s)
    kind = _ALIAS_TO_KIND[m.group(0)] if m else ""
    rest = s[:m.start()] + s[m.end():] if m else s
    branch = next((x for x in BRANCH_SUFFIXES if rest.endswith(x) and len(rest) > len(x)), "")
    return Corp(text, kind, rest.casefold(), branch, position)
```

照合キーは、この 3 つをつないだものだ。法人格の種類が入っているので、「山田商事株式会社」と「山田商事有限会社」は別のキーになる。

次が番号の経路だ。13 桁の法人番号は、先頭 1 桁が検査数字で、残り 12 桁から算式で作れる。だから機械で確かめられる。

```python
def check_digit(base12):
    """9 -(下 12 桁を右から数え、奇数番目は 1 倍・偶数番目は 2 倍して合計した値)を 9 で割った余り。"""
    total = sum(int(c) * (1 if i % 2 == 0 else 2) for i, c in enumerate(reversed(base12)))
    return 9 - total % 9
```

この算式について、正直に書いておくことがある。私が確かめたのは「この算式で作った番号が、この実装で必ず通る」ことと「1 桁書き換えた番号が落ちる」ことだけで、算式そのものが公表されている仕様と一致するかは確かめていない。テストは同じ算式で作った合成番号でしか通っていない。実際の番号に使う前に、算式が公表値と合うかは自分で確かめてほしい。もう 1 つ、この算式には見えない誤りがある。ある桁を 9 と 0 で取り違えても検査に通る。9 の倍数ぶんのずれは余りに出ないからで、これはテストで固定して、限界として残してある。

突合の本体は、番号の経路を先に見て、次に名前の経路に回すだけだ。判断は入れない。入るのは検査と件数の判定だけで、それで決まらないものは全部人に返す。

```python
def match(row, index, self_index=None):
    c = parse(row.name)
    if not c.key:
        return Decision(row, "", PENDING, "", "空の会社名", ())
    nr = number_reason(row.number)
    if nr not in ("", "空"):
        return Decision(row, c.key, PENDING, "", nr, ())      # 壊れた番号は名前で救わない
    if nr == "":
        hits = index.by_number.get(_clean_number(row.number), ())
        if len(hits) == 1:
            return Decision(row, c.key, OK, BY_NUMBER, "", hits)   # 名前が違っても突合する
    ...
    hits = index.by_key.get(c.key, ())
    if not hits:
        near = index.by_plain.get(c.plain_key, ())            # 法人格を無視したキー
        return Decision(row, c.key, PENDING, "", "法人格が違う" if near else "相手なし", near)
```

判断待ちの理由は 7 つある。どれも「機械では決まらない理由」の名前になっている。

| 理由コード | 意味 |
|---|---|
| 空の会社名 | 法人格を分離すると屋号が残らない(法人格だけ、記号だけ) |
| 番号の検査に落ちる | 13 桁でない、または検査数字が合わない。壊れた番号を名前で救わない |
| 番号が食い違う | 照合キーは一致するが、双方の番号が別の番号になっている |
| 法人格が違う | 屋号と事業所の印は同じだが、法人格の種類が違う |
| 相手なし | 同じ照合キーの相手がいない。別表記・未登録・別法人のどれかは機械では決まらない |
| 相手が複数 | 同じ照合キーの相手が 2 件以上ある |
| 自分側が重複 | 同じ照合キーの行が自分側にも 2 件以上ある。キーが 1 社を指さない |

このうち「法人格が違う」が、今回いちばん書きたかった理由コードだ。法人格を捨てないので、「山田商事有限会社」は「山田商事株式会社」と別のキーになる。ただ、別のキーにして終わりだと「相手なし」に落ちるだけで、台帳を見た人は何が起きたか分からない。だから法人格を無視したキーでもう一度だけ引いて、屋号と事業所の印が同じ相手がいたら、それを候補として添えて返す。畳まないが、黙って捨てもしない。

「番号が食い違う」も同じ考え方だ。名前のキーは一致したのに、両側の番号が別の番号を指しているなら、そこには台帳の側の誤りがある。名前が合っているからと言って通してしまうと、番号の列を持っている意味が無くなる。

コマンドラインからも使える。判断待ちが 1 件でもあれば終了コード 3 になるので、バッチの中に置いて止められる。

```
python jp_corp.py --check 5835678256246                          # 番号 TAB OK / NG(理由)
python jp_corp.py A.csv B.csv --column 取引先名 --number-column 法人番号
```

```python
from jp_corp import Row, parse, to_key, match_all

to_key("㈱山田商事")          # '株式会社|山田商事|'
```

返ってくるのは「照合(番号 or 名前)」か「判断待ち + 理由コード + 候補」のどちらかで、確率もスコアも返さない。返さないことに意味がある。スコアを返せば、受け取った側はいつか必ずしきい値を書く。

1 行目が文字列の完全一致だけの突合で、決まったのは 178 件、そのうち 3 件は別法人に当たっている。表記を散らしてあるので、ほとんどの行は落ちる。

2 行目が、法人格を除去してから突き合わせ、外れたら類似度 0.8 以上を自動採用するやり方だ。907 件が決まり、そのうち 37 件が別法人だった。間違いの大半は、同じ屋号で法人格だけ違う 40 行と、同じ屋号で同じ法人格の別法人 30 行から出ている。どちらも除去したあとは同じ文字列になるので、台帳の並び順で先に見つかった方が採用される。採用された行は「一致した行」として下流へ流れる。

3 行目がこの道具だ。885 件を突合し、そのうち別法人に結合したものは 0 件だった。内訳は、名前の経路で決まったのが 585 件、番号の経路で決まったのが 300 件になる。この 300 件には、屋号をカナ表記に変えた 50 行が入っている。名前では当たらない行が、番号があるというだけで確実に決まる。判断待ちは 115 件で、その内訳は合成のときに仕込んだ数とそのまま一致する。右に載せなかった 40 行、右にだけ別法人を置いた 15 行、法人格を書き間違えた 10 行、番号を壊した 10 行、番号を食い違わせた 5 行、同じキーの別法人 30 行、屋号が残らない 5 行だ。言い換えると、この道具が人に返したのは「機械には決められない形にしてある行」だけで、それ以外は取りこぼしていない。

4 行目は、同じ屋号で法人格だけ違う 20 組(40 行)だけを取り出したもので、40 行とも照合され、取り違えは 0 件だった。法人格をキーに残しているので、この組が 1 件に畳まれる経路そのものが無い。

907 や 37 という数は、合成の仕方(表記の散らし方、同じ屋号を何組入れるか、番号をどれだけ埋めるか)で決まる値で、実際の台帳でこの割合になるという意味ではない。比べているのは割合ではなく、「決まらないものを決めてしまうか、理由を付けて返すか」「手元にある番号を使うか、使わないか」という性質の違いだと考えている。

## 図 2 突合の流れ

![会社名の突合の流れ — 番号がある行は番号で、無い行は法人格を捨てないキーで](figures/jp_corp_flow.png)

段は 5 つ。表記を正規化する、法人格を分離する、番号の経路を見る、照合キーで引く、人に返す。橙のピルが関所で、屋号が残らない行と番号の検査に落ちた行は前半で、キーで決まらない行は後半で、それぞれ判断待ちへ抜ける。抜けた行には理由コードと候補が付く。番号の経路が名前の経路より前にあることが、この図でいちばん言いたいところだ。名前を寄せる工夫をいくら足しても、番号の列を見ないかぎり、この経路は開かない。

## 道具

[jp_corp](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/jp_corp) に置いた。`jp_corp.py` 1 ファイルと、テスト、合成 fixture の生成スクリプトが入っている。依存は無く、標準ライブラリだけで動く。ライセンスは MIT。

使い方は上の手順のとおり。関数として呼ぶなら `parse(name)` / `to_key(name)` / `number_reason(number)` / `build_index(rows)` / `match_all(left, right)`、コマンドラインなら `--key` で分け方の確認、`--check` で番号の検査、CSV を 2 つ渡して突合。fixture を作り直したいときは `python fixtures/make_fixtures.py`。法人格の表を自分の台帳に合わせたいときは `LEGAL_FORMS` に行を足して、テストを 1 つ足す。

## 別の業種なら

この部品は、給与や社会保険の語彙を 1 つも持っていない。持っているのは法人格の表と、番号の検査と、件数の判定だけだ。会計の取引先マスタ、請求と入金の突合、EC の出店者一覧、建設の下請け台帳でも、同じ取引先が別表記で二重に並ぶ形は同じで、番号の列を持てる点も同じだと考えている。私が実測したのは給与まわりの事業所一覧と、上の合成データだけなので、他の分野は「同じ詰まり方になりそうな例」であって実測ではない。変わるのは CSV の列名だけで、部品そのものは書き換えずに持ち出せる。たとえば取引先マスタなら「取引先コード,取引先名,法人番号,締日」の取引先名と法人番号を `--column` と `--number-column` で指すところが、上の事業所一覧と同じ扱いになる。番号の列がまだ無い台帳でも、名前の経路だけで動く。番号の列を足す価値がどれくらいあるかは、判断待ちの件数がそのまま答えになる。

## できないこと

- 同じ法人かどうかは決めない。決めるのは「番号が一致するか」「照合キーが一致するか」だけで、判断待ちの行を人が見る前提の部品だ。人手を減らす道具ではなく、人が見る行を絞る道具になる
- 検査数字の算式が公表されている仕様と一致するかは確かめていない。同じ算式で作った合成番号でしか通していないので、実際の番号に使う前に自分で照合してほしい
- 9 と 0 の取り違えは検査で見えない。桁を 1 つ打ち間違えた番号は落ちるが、この 1 種類だけは通ってしまう
- 法人格の表は 24 種類しか持っていない。外国の法人格や組合の細かい種類は表に無く、種類が空のまま屋号に残る。足すことはできるが、足すこと自体が判断になる
- 支店名は屋号から切り離さないので、本社の行と支店の行は別のキーになる。事業所をまとめて 1 社として数えたい台帳では、別の扱いが要る
- 旧商号や合併後の名称は追えない。名前が変わっていて番号も無い行は「相手なし」として人に返る
- 屋号の中の表記ゆれ(「あおば」と「アオバ」)は畳まない。カナと漢字も畳まない。畳むこと自体が判断になる
- 上の数字は合成データと私の環境での実測で、他の人の環境で同じになるとは限らない。特に 907 と 37 と 885 は、合成の仕方で変わる
