差異の一覧を Excel で人に返すとき、差があったセルを塗るのがいちばん早い。私の記録でも、チェックの結果を色分けした Excel で返すコードが 4 本の道具に別々に置いてあって、どれも塗るところで終わっていた。ところがその Excel が次の工程に渡ると、色は落ちる。CSV にした瞬間、別のブックに値を書き写した瞬間、値だけを貼り付けた瞬間に、塗りは消えて何も残らない。この記事では、判定の結果を理由コードという値として表に持ち、色はその列から決定論で決まる従属表示として静的に焼き、書いたあとに読み戻してセル座標と件数と塗りを突き合わせる部品を 1 か所にまとめる。あわせて、ここまでの 5 本が返してきた判断待ちの理由を、部品ごとではなく理由の種類という軸で並べ直す。

**なぜ重要か**: ここまで作ってきた部品は、どれも「機械で決まらないものは理由コードを付けて人に返す」形にしてきた。文字コードも、和暦も、氏名も、会社名も、取込 CSV の書き出しもそうだ。決まらないものを無理に決めない、というところまでは揃っている。だが、返した理由が人に届くかどうかは、返す側の出力の形で決まる。色は人の目にはいちばん速い伝え方で、開いて見るぶんには足りている。足りていないのは、その Excel が誰かの手で次の工程に渡ったあとだ。色は文字ではないので、値だけを読む処理をひとつ通すと、理由は痕跡も残さずに消える。理由コードを丁寧に作っておいて、最後の 1 歩で捨てている状態になる。

**要点**:
- 理由は値として列に置く。色はその列から決まる従属表示にして、セルに静的に焼く
- 条件付き書式では塗らない。開いたときに Excel が評価する形だと、出力ファイル単体では色が確定しない
- 凡例のシートを書く。色だけで意味を運ばない(色覚の差・白黒の印刷・色を落とす工程で消えるため)
- 書いたら読み戻して、セル座標と理由コードの対応・件数・塗りを入力の判定と突き合わせ、合わなければ出力を消す

**数字で見る**: 合成した 1,000 行の差異一覧に 60 セルぶんの理由を付けて書き出し、値だけを読む工程をひとつ通したところ、色だけで示した出力から復元できた理由は 0 件、この部品の出力からは 60 件がセル座標つきで残った。塗りのほうはどちらも 0 件になった。

## 何を解決するのか

色分けした Excel は、作るのも読むのも速い。差のあるセルを塗って渡せば、受け取った人はすぐ見つけられる。ここまでは本当だ。問題はその次に起きる。

渡された Excel は、そのまま眺められて終わるわけではない。差のある行だけ抜いて一覧にする。並べ替える。別のブックにまとめる。取込用に CSV へ落とす。別の道具に食わせる。このうち、値だけを読む工程を通ると、塗りは付いてこない。Excel 本体の並べ替えなら塗りはセルと一緒に動くが、値をコピーして貼り付けたり、CSV にしたり、別のブックに書き写したりすると、残るのは文字だけになる。

そこで起きるのは「色が消えて見にくい」ではない。情報が無くなる。黄色いセルだった、という事実がどこにも書かれていないので、元のファイルを開き直すしかなくなる。開き直しても、その色が何を意味していたかは、作った人の頭の中にしか無いことが多い。

もうひとつ、色そのものの不確かさがある。条件付き書式で塗ると、ファイルの中に色は入らない。入るのは条件の式だけで、色は開いたときに Excel が評価して決める。つまり、出力ファイル単体では結果が確定していない。書いた側が「塗れているはずだ」と思っている色を、機械で確かめる手段が無くなる。

だから順番を変える。まず理由を値として列に置く。塗るのはそのあとで、色は理由コードから 1 方向に引いて決まるだけの従属表示にする。そして書いた Excel を読み戻し、セル座標と理由コードの対応、件数、理由ごとの件数、塗りの 4 つを入力の判定と突き合わせる。合わなければ出力ファイルを消す。

### 理由の種類という軸

ここまでの 5 本は、どれも「入力の種類」で並べてきた。半角カナはどうなる、値の中のカンマはどうなる、改元をまたぐ日付はどうなる、という軸だ。部品を説明するには、その軸が合っていた。

人に返すときに並ぶのは、部品ではなく理由のほうだ。差異一覧を受け取る人は、どの部品が止めたかではなく、自分が何を決めればいいかを見る。そこで軸を差し替える。行を「何が足りないから機械で決まらないか」にすると、5 本ぶんの判断待ちは 5 種類に収まった。

| 理由の種類 | 機械に足りないもの |
|---|---|
| 値が無い | 判定の材料そのもの。空欄を埋めると、埋めた側が値を作ってしまう |
| 表の外にある | 道具が持つ表(改元表・同値表・法人格の表・列仕様)に答えが無い。表を増やすこと自体が判断になる |
| 相手が決まらない | 突合の相手が 0 件か 2 件以上。どれを指すかは名簿の外の情報で決まる |
| 形が両立しない | 出力側や取込側が要求する形と、値の形が噛み合わない。逃がすと相手が読めなくなる |
| 往復で値が変わる | 書いて読み戻すと別の値になる。見た目が同じなので人の目では気づけない |

部品ごとの話は、[文字コードの判定](https://chronicles-of-solo-parenting.blogspot.com/2026/09/csv.html)、[和暦の変換](https://chronicles-of-solo-parenting.blogspot.com/2026/09/blog-post.html)、[氏名の照合](https://chronicles-of-solo-parenting.blogspot.com/2026/09/blog-post_22.html)、[会社名の照合](https://chronicles-of-solo-parenting.blogspot.com/2026/09/blog-post_23.html)、[取込 CSV の書き出し](https://chronicles-of-solo-parenting.blogspot.com/2026/09/csv_01431241508.html)にそれぞれ書いた。ここでは繰り返さない。この記事で使うのは、並べ直したあとの 5 種類のほうだ。

軸を差し替えて分かったのは、5 種類のうち 4 種類は、色だけでは区別のしようがないということだった。相手が 0 件なのか 2 件以上なのかは同じ 1 色になる。カンマなのか全角数字なのか桁あふれなのかも同じ 1 色になる。色を増やせば解けるように見えるが、増やした色の意味はどこかに文字で書くことになるので、結局は文字の話に戻ってくる。

## 図 1 理由の種類ごとに、出力のどこに置かれ、下流で残るか落ちるか

![軸を差し替えた一覧 — 行は「部品」ではなく「理由の種類」](figures/excel_report_reasons.png)

行が理由の種類、左の列が色だけで示した出力、右の列がこの部品の出力だ。左はどの行も「塗りは残るが、値だけを読む工程を通ると 0 件になる」で終わる。右は理由コードの列・判断待ちのシート・凡例の 3 か所に文字として置かれるので、同じ工程を通っても残る。左右の違いは情報量ではない。左のファイルにも情報は入っている。違うのは、その情報が値の側に入っているか、書式の側に入っているかだ。

## 手順

呼ぶ側が渡すのは 3 つで、部品はこの 3 つだけを見る。

| 渡すもの | 中身 | 部品の側の扱い |
|---|---|---|
| 値の表 | 列の順と各行の値 | 文字列のまま置く。型を推測しない |
| セルごとの判定 | 行番号 / 列名 / 理由コード | 判定はしない。受け取ったものを置くだけ |
| 理由コードの表 | 理由コード / 意味の 1 行説明 / 塗り | 語彙は呼ぶ側のもの。部品は業種も判定の意味も持たない |

理由コードの語彙を部品の中に持たないのは、持った瞬間に業種が入ってくるからだ。上の 5 種類は私がまとめたもので、別の現場では別のまとめ方になる。表を差し替えれば部品はそのまま動く。

表に無い理由コード、値の表に無い行や列、同じセルに理由が 2 つ。このどれかが来たら、色を決める前に止まる。同じセルに 2 つ来たときにどちらの色で塗るかは、機械では決まらない判断だからだ。

出力は 3 つのシートで、名前も順も固定にした。

| シート | 中身 |
|---|---|
| 明細 | 元の値をそのまま置き、右端に理由コードの列を併置する。理由のあるセルだけを塗る |
| 凡例 | 理由コード / 意味の 1 行説明 / 塗りの hex / 見本。色だけで意味を運ばないための欄 |
| 判断待ち | 1 セル 1 行で シート / セル座標 / 行番号 / 列名 / 値 / 理由コード |

理由コードの列は明細シートの右端に必ず置く。行の中に理由が 2 つあれば、列の順に並べて 1 つのセルに入れる。そして判断待ちのシートが、セル座標と理由コードの対応の正本になる。理由コードの列だけでは、1 行に 2 つ理由があったときにどちらの列の話か分からないからだ。

塗りは対応表から引いて、セルに静的に焼く。

```python
def _solid(fill):
    return PatternFill(start_color=f"FF{fill}", end_color=f"FF{fill}", fill_type="solid")

for j in judgments:
    ws[cell_of(table, j.row, j.column)].fill = _solid(reasons.fill_of(j.code))
```

`fill_of` は理由コードを受け取って塗りを返すだけの関数で、逆はない。色から理由を引く関数も、色をキーにした表も作っていない。作ると、読み戻しのときに「色を見て理由を決める」経路ができてしまう。それでは色が値になってしまい、この部品の前提が崩れる。

条件付き書式は使わない。使うとどうなるかは、比較用の書き出しを同じテストに入れて確かめてある。条件付き書式で塗った出力を読み戻すと、焼かれた塗りは 1 つも読めない。ファイルの中にあるのは条件の式だけで、色は開いたときに決まるからだ。

凡例のシートには、塗りの hex を文字としても書く。色の見本だけ置いても、白黒で印刷した人や色の見分けがつきにくい人には届かない。意味の 1 行説明を空にできないようにしてあるのは、空のまま出せる形にしておくと必ず空で出るからだ。

読み戻しは、書いたときの知識を使わずに読む。

```python
def recover_reasons(path):
    """出力から「セル座標 → 理由コード」を復元する。読むのは文字だけで、塗りは見ない。"""
    wb = load_workbook(path, data_only=True)
    if SHEET_PENDING not in wb.sheetnames:
        return {}
    got, head = {}, None
    for row in wb[SHEET_PENDING].iter_rows(values_only=True):
        if head is None:
            head = [str(c) for c in row]
            continue
        r = dict(zip(head, ["" if c is None else str(c) for c in row]))
        got[r["セル座標"]] = r["理由コード"]
    return got
```

突き合わせるのは、見出しの並び、全セルの値、理由コードの列、セル座標と理由コードの対応、理由ごとの件数、塗り、凡例の行の 7 つだ。塗りも突き合わせる。塗りから理由は引かないが、理由から決まるはずの色が本当にそうなっているかは確かめられる。差が 1 つでもあれば作業ファイルを消して、シート名・セル座標・何の差・入力・読み戻しの 5 つを並べて返す。どちらが正しいかは書かない。

もうひとつ、読み戻しを openpyxl だけでやると、同じ道具で書いたものを同じ道具で確かめる形になる。そこで標準ライブラリの zipfile でも中を見る。xlsx は zip なので、どの部品にどの文字列が入っているかを openpyxl を通さずに数えられる。

```python
def where_it_lives(path, needle):
    with zipfile.ZipFile(path) as z:
        return [n for n in sorted(z.namelist()) if needle in _plain(z.read(n))]
```

コマンドラインからも使える。

```

python excel_report.py 値の表.csv --judgments 判定.csv --reasons 理由コードの表.csv --check
```

合成した 12 行の差異一覧を `--check` に通すと、こう返る。

```

相手が決まらない	3
形が両立しない	3
往復で値が変わる	2

```

関数として呼ぶと、返ってくるのは「書けた(件数と内訳)」か「突合の差」のどちらかだ。

```python
from excel_report import Table, ReasonTable, Judgment, write, recover_reasons

table = Table.from_csv("sai_ichiran.csv")
reasons = ReasonTable.from_csv("riyu_hyou.csv")

if not r.ok:
    for d in r.diffs:

```

1 行目がこの部品だ。60 セルを塗って書き、読み戻すと 60 件のセル座標と理由コードの対応がそのまま復元できて、差は 0 件だった。

2 行目と 3 行目が比較になる。どちらの出力も塗られたセルは 60 で、開いて見るぶんには同じに見える。違いは、CSV にしたときに理由を運んでいる行の数だ。色だけの出力は 0 行、この部品の出力は 55 行あった。55 は理由を付けた行の数で、1 行に 2 つある行もひとつの行として数えている。そして値だけを別のブックに書き写すと、塗りはどちらも 0 件になる。色だけの出力はこの時点で判定の痕跡がひとつも無い表になり(値は残るが、どのセルが判断待ちだったかは書かれていない)、この部品の出力は理由コードの列がそのまま残る。

4 行目が条件付き書式との比較だ。同じ判定を条件付き書式で塗ると、ファイルから読める塗りは 0 件になる。入っているのは 5 本の条件の式だけで、色はファイルの外(Excel の評価)で決まる。静的に焼いたほうは 60 件そのまま読める。開いて見る人にはどちらも同じ色に見えるので、この差は目では分からない。

5 行目が、値と色が別の場所に入っていることを標準ライブラリの側から見たものだ。理由コードの文字列は 3 つのシートの XML に入っていて、styles.xml には入っていない。塗りの色は styles.xml に入っていて、明細シートの XML には入っていない(凡例シートの XML に出てくるのは、hex を文字としても書いているからだ)。値と色は、ファイルの中で物理的に別の場所に置かれている。「色は値ではない」というのは比喩ではなく、こういう形をしているという話だった。

なお、60 や 55 という数は合成の仕方で変わる値で、実際のデータでこの割合になるという意味ではない。比べているのは割合ではなく、「値だけを読む工程を通ったあとに理由が残るか消えるか」という性質の違いだと考えている。

## 図 2 書き出しの流れ

![色分け Excel の書き出しの流れ — 理由を値として置いてから、色はその列から決める](figures/excel_report_flow.png)

段は 5 つ。判定を受け取る、置き場所を決める、作業ファイルに書く、読み戻して突き合わせる、渡す。橙のピルが関所で、前半では表に無い理由コードや行・列が来た時点で色を決める前に止まり、後半では座標・件数・塗りに差が出た時点で作業ファイルを消す。2 段目が「置き場所を決める」になっていて、塗る前に理由コードの列と凡例と判断待ちのシートを組むところがこの図の要点になる。色を決めるのは、置き場所が全部決まったあとだ。

## 道具

[excel_report](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/excel_report) に置いた。`excel_report.py` 1 ファイルと、テスト、合成 fixture の生成スクリプトが入っている。依存は openpyxl だけで、この環境にある 3.1.5 で動かしている。ライセンスは MIT。

使い方は上の手順のとおり。関数として呼ぶなら `Table.from_csv(path)` / `ReasonTable.from_csv(path)` / `write(path, table, reasons, judgments)` / `recover_reasons(path)` / `verify(path, table, reasons, judgments)` / `where_it_lives(path, needle)`、コマンドラインなら `--check` で受け取ったものを見るだけ、CSV を 3 つ渡して書き出し。理由コードの語彙を自分の現場に合わせたいときは `fixtures/riyu_hyou.csv` を差し替える。部品のコードは触らない。比較用に `naive_write`(色だけで示す)と `conditional_write`(条件付き書式で塗る)も入れてあるので、自分の環境で同じ比較ができる。

## 別の業種なら

この部品は、給与や社会保険の語彙をひとつも持っていない。持っているのは値の表と、理由コードの表と、置き場所と、読み戻しの突合だけだ。会計の残高突合の差異一覧、EC の在庫差分、医療や介護の請求返戻の一覧、建設の出来高の差異でも、差異を色だけで示した Excel が人手で回され、次の工程で色が落ちる形は同じだと考えている。私が実測したのは給与まわりの差異一覧と、上の合成データだけなので、他の分野は「同じ詰まり方になりそうな例」であって実測ではない。変わるのは理由コードの表だけで、部品そのものは書き換えずに持ち出せる。たとえば残高の突合なら「証憑が無い / 勘定科目の表に無い / 相手勘定が決まらない / 金額の形が両立しない」を理由コードの表にして、意味の 1 行説明と塗りを添える。在庫の差分なら理由の並びが変わるだけだ。部品の側からは、給与も残高も在庫も同じことになる。

## できないこと

- Excel 本体で開いたときの見え方は確かめていない。読み戻しは openpyxl と zipfile が読んだ値の話で、Excel が同じように描くかは見ていない
- 色の落ち方を試したのは「値だけを読む工程」(CSV 化 / 別のブックへ値で書き写す / 値の貼り付け)までだ。Excel 本体の並べ替えでは塗りはセルと一緒に動くので、そこでは落ちない。私の手元で試した工程の範囲の話で、他の人の環境や他の版の Excel は見ていない
- 淡い色を 2 つの理由コードに割り当てても止めない。色の見分けやすさは機械では決められないので、凡例のほうを正本にしてある
- 判定はしない。どのセルが判断待ちかを決めるのは呼ぶ側で、この部品は置き場所と突合だけを引き受ける
- 差の原因は推定しない。入力と読み戻しのどちらが正しいかも決めない
- 依存は openpyxl ひとつで、この環境の版でしか実行していない。文字を共有文字列の表ではなくシートの XML に直接書くのはこの版の挙動なので、版が変われば zipfile で見た結果も変わる
- 1 つのセルに理由を 2 つ付けることはできない。どちらを塗るかが機械では決まらないので止まる
- シート名と理由コードの列名は固定にした。値の表に同じ名前の列があると止まる
- 上の数字は合成データと私の環境での実測で、他の人の環境で同じになるとは限らない。特に 60 と 55 は合成の仕方で変わる
- 理由の種類を 5 つに束ねたのは、ここまでの 5 本を並べ直した私のまとめ方であって、これで足りるという話ではない。別の部品を足せば種類は増えると考えている
