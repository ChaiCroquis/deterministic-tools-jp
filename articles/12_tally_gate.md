支給控除の一覧は「人 × 項目」の表だ。人ごとに横へ足した差引の額と、項目ごとに縦へ足した集計行と、総計の 3 つは、同じ数字集合から出てくる。だから「3 つが全部一致するまで取込用の出力を作らない」という関所が作れる。この記事で作るのはその関所だが、見たいのは検算そのものではなく、同じ数字を人の軸で足すか項目の軸で足すかで、見える壊れ方がどう変わるかのほうだ。

**なぜ重要か**: 縦と横が合ったことを「数字が正しい」と読み替えてしまうと、検算を置いた分だけ安心して先へ進んでしまう。合計は、同じ数字集合を 2 つの並べ方で足して同じになったという話でしかない。しかも 3 つの検査は壊れ方に対して等しく敏感ではない。符号や所属の宣言を取り違えた形は人の軸にだけ出て項目の軸には出ないし、人が 1 行抜けた形はその逆で、残った人の計算は全部そのまま成り立ってしまう。どの軸に出たかまで見ないと、関所を通った後に「何は確かめられて、何は確かめられていないのか」が手元に残らない。

**要点**:
- 検査は 3 つで順序を固定する。人ごと、項目ごと、総計の順に足し、全部一致するまで取込用の出力を作らない。差を吸収する許容誤差の引数は持たせない
- 符号や所属の宣言を取り違えた形は、人ごとの合計にだけ出る。項目ごとの合計は印字されたままの値を足すので、宣言そのものを使わないからだ
- 人が 1 行抜けた形は逆で、人ごとの合計には 1 件も出ない。項目ごとの合計と総計にだけ出る
- 行と列の両方に出た時だけ交点が絞れる。ただし差が打ち消し合う形では候補が増えてしまい、総計からは消える

**数字で見る**: 合成した 8 人 + 集計行 1 行の表に壊れ方を 6 通り仕込むと、人ごとの合計に出た件数は 0 件から 7 件、項目ごとの合計に出た件数は 0 件から 6 件まで散らばった。6 通りのうち 3 通りは総計では消え、交点が 1 組に決まったのは 1 通りだけだった。

---

## 何を解決するのか

ここまでの 5 本で、数表から行を引く、式を表に置いて計算する、更新を台帳に残して差し替える、原本から値を取り出す、2 つの経路で突き合わせる、という形がそろった。どれも「渡す数字をどう作るか」の話だった。今回はその数字を使う側へ降りる。

私の棚卸しの記録では、手元の道具 39 本が何らかの突合を持っていて、そのうち配布して使っている検査の道具は 14 本ある。記録に残っている中でいちばん手数が少なく、いちばん止めてくれたのが、支給控除の一覧に対する縦横の検算だった。人ごとに横へ足した額が差引の列と合い、項目ごとに縦へ足した額が集計行と合い、総計も合う。この 3 つが全部一致しない限り取込用のファイルを作らない、という形だ。

これを部品として書き出そうとして、気づいたことがある。縦横の検算は「3 回確かめている」ように見えるが、3 回とも同じ数字集合を足し直しているだけで、独立した 3 つの証拠ではない。たとえば項目ごとの合計が全部集計行と一致していれば、それを並べ直した総計も必ず一致する。総計の検査は、項目ごとの検査が落ちた時にだけ新しいことを言う。

だとすると、この関所の価値は「3 回合った」ことではなく、**落ちた時にどの軸まで届いたか**のほうにある。そこで部品は、3 つの検査を途中で止めずに全部走らせ、差が出た軸の組み合わせを分類して返す形にした。

もう 1 つ、前回までと同じ規律を持ち込んでいる。丸めの名前は項目の宣言表から取り、既定を持たない。合計の突き合わせは、足す前に位をそろえないと成り立たないからだ。合成した表では、保険料の欄に銭を残してある。8 人のうち 2 人は端数がちょうど 50 銭に当たるので、丸めの名前を切り捨てから四捨五入に変えるだけで、合っていた表が落ちる。

## 図 1 同じ壊れ方でも、どの軸で足すかで見える件数が変わる

![壊れ方 6 通りと、人ごと・項目ごと・総計の各軸で見えた件数、交点が特定できるかの対応表](figures/tally_gate_visibility.png)

行が仕込んだ壊れ方、列が見る軸だ。各セルの件数は、合成の表に壊れ方を 1 つずつ仕込んでその場で実走した出力で、テストが `assert` で固定している。

読みどころは 2 つある。1 つは、**0 件のセルが 2 種類ある**ことだ。符号の所属を取り違えた行と、項目を別の所属に入れた行は、項目ごとの合計では 0 件になる。これは「たまたま出なかった」のではなく、項目ごとの合計が印字されたままの値を足していて、符号も所属も使っていないからだ。仕組みの上で見えない。一方、人が 1 行抜けた形と集計行だけが古い形は、人ごとの合計で 0 件になる。残った人の計算はどれも成り立っているので、人の軸から見ると何も壊れていない。

もう 1 つは、交点の列だ。1 か所の値がずれた時は、人の軸に 1 件、項目の軸に 1 件出るので、交点は 1 組に決まる。どのセルを直せばいいかが表から出る。ところが差が打ち消し合う形では、人の軸に 2 件、項目の軸に 2 件出るので、交点の候補は 4 組に増える。実際に壊れているのは 2 組なのに、表からは区別できない。そして総計では消える。

## 手順

入力は 2 枚だ。1 枚は明細で、行が人、列が項目、値が金額。1 行だけ集計行が入る。

```
識別子,基本給,役職手当,通勤手当,保険料甲,保険料乙,源泉税,保険料の戻し,差引支給額
10001,182000,25000,4200,8472.10,5614.70,8298,,188815
10002,190000,,4500,8844.50,5861.50,7569,1200,173426
10003,200000,,,9310.00,6170.00,7768,,176752
合計,1710000,75000,37200,79600,52753,71139,4600,1623308
```

もう 1 枚は項目の宣言表で、1 項目が 1 行になる。

```
item,group,sign,rounding,source
基本給,支給,+,円未満四捨五入,合成の支給控除一覧(架空)
通勤手当,支給,+,1円未満切捨て,合成の支給控除一覧(架空)
保険料甲,控除,+,50銭以下切捨て,合成の端数処理メモ(架空)
保険料の戻し,控除,-,円未満四捨五入,控除の中で引く側(印字は符号なし)
差引支給額,差引,+,丸めない,合成の支給控除一覧(架空)
```

| 列 | 意味 |
|---|---|
| `item` | 項目の名前。明細の列の見出しと一致する |
| `group` | その項目がどこに属するか。名前は呼び出し側が決める |
| `sign` | その所属の中で足す時の符号。印字が符号なしの項目に `-` を付ける |
| `rounding` | 丸めの名前。**空欄は許さない** |
| `source` | 出典。差の報告に載る |

部品は給与の語彙を持っていない。`支給` も `控除` も、ただの文字列として宣言から受け取る。どう足すかは恒等式で渡す。

```
python tally_gate.py check 明細.csv --spec 宣言表.csv --identity "支給 - 控除 = 差引" --id-column 識別子 --total-row 合計
```

恒等式は所属の名前だけで書き、左辺が符号つきの並び、右辺が 1 つという形に限っている。項目の名前も業種の言葉も、ここには出てこない。全部一致した時の出力はこうなる。

```
{"ok": true, "visibility": "all_agree", "axes": [], "people": 8, "items": 8,
 "row_total": "1623308", "column_total": "1623308", "pending": [], "diffs": []}
```

`row_total` が人ごとの左辺を全員ぶん足した値、`column_total` が集計行から同じ左辺を作った値で、この 2 つが総計の 2 経路になる。1 人の基本給を 1,000 円だけ動かすと、3 つの軸に出る。

```
$ python tally_gate.py check 明細.csv --spec 宣言表.csv --identity "支給 - 控除 = 差引" --id-column 識別子 --total-row 合計
{"ok": false, "visibility": "row_and_column", "axes": ["row", "column", "total"],
 "row_total": "1624308", "column_total": "1623308",
 "diffs": [{"axis": "row", "who": "10003", "expected": "176752", "actual": "177752", "delta": "1000"},
           {"axis": "column", "item": "基本給", "expected": "1710000", "actual": "1711000", "delta": "1000"},
           {"axis": "total", "expected": "1623308", "actual": "1624308", "delta": "1000"}]}
```

別の人の別の項目で打ち消し合う形にすると、総計だけが通る。

```
{"ok": false, "visibility": "invisible_in_total", "axes": ["row", "column"],
 "row_total": "1623308", "column_total": "1623308",
 "diffs": [{"axis": "row", "who": "10001", "delta": "1000"},
           {"axis": "row", "who": "10004", "delta": "-1000"},
           {"axis": "column", "item": "役職手当", "delta": "1000"},
           {"axis": "column", "item": "通勤手当", "delta": "-1000"}]}
```

丸めの名前が空欄の項目があると、足す前に止まる。理由コードで止まった時は、3 つの検査そのものに進まない。

```
{"ok": false, "visibility": "not_checked",
 "pending": [{"reason": "rounding 空欄", "detail": "項目『保険料甲』に丸めの名前が無い(既定は持たない)"}]}
```

止まる理由コードは 7 つで、これ以上増やしていない。丸めの名前が空欄、所属が空欄、明細に宣言表へ無い列がある、同じ識別子の行が 2 行ある、集計行が無い、金額が数として読めない、検査を通る前に出力を要求した、の 7 つだ。表そのものの不備(恒等式が読めない、符号が `+` でも `-` でもない、登録していない丸めの名前)は理由コードにせず、表を直す話として終了コード 2 で返す。

終了コードは、全部一致したら 0、理由コードか差で止まったら 3、表や引数が壊れていたら 2 になる。バッチの中に置いて 3 で止められる。

```python
from tally_gate import Declaration, Spec, Table, check

decl = Declaration.of("支給 - 控除 = 差引", id_column="識別子", total_row="合計")
gate = check(Table.load("明細.csv", decl.id_column), Spec.load("宣言表.csv"), decl)
rows = gate.handoff() if gate.report.ok else None     # 通らなければ例外で止まる
```

`handoff` が返すのは行だけで、ファイルは書かない。取込用の CSV を書くのは別の部品の仕事で、その列仕様へそのまま渡せる形にしてある。関所の側に書き出しを持たせないのは、「検査には落ちたが出力はもうできている」という状態を作らないためだ。差を吸収する引数も持たせていない。差が 1 円でも不一致として扱う。

## 検証

テストは 64 件で、fixture は全て合成データだ。率も金額も人も架空で、実在の保険料率や税率は 1 つも入れていない。

```
$ python -m pytest tools/tally_gate -q
...............................................
[measure] 1 か所の値のずれ: row_and_column(人ごと 1 件 / 項目ごと 1 件 / 総計 1 件)
[measure] 符号の所属の取り違え: row_only(人ごと 2 件 / 項目ごと 0 件 / 総計 0 件)
[measure] 項目を別の group に入れた: row_only(人ごと 7 件 / 項目ごと 0 件 / 総計 0 件)
[measure] 別の人の別の項目で差が打ち消し合う: invisible_in_total(人ごと 2 件 / 項目ごと 2 件 / 総計 0 件)
[measure] 人が 1 行抜けた: column_and_total(人ごと 0 件 / 項目ごと 6 件 / 総計 1 件)
[measure] 集計行だけ古い: column_and_total(人ごと 0 件 / 項目ごと 1 件 / 総計 1 件)
........
[measure] 端数ちょうど 50 銭の欄 4 件: 丸めの名前を『50銭以下切捨て』から『円未満四捨五入』に変えると、人ごとの検査が 2 件 / 項目ごとの検査が 2 件 / 総計が 1 件 落ちる(人ごとの差は -2 円)
.........         [100%]
64 passed in 1.50s
```

測定の中身を少しだけ補う。符号の所属を取り違えた時に人ごとの合計へ出たのは 2 件で、差は 2,400 円と 6,800 円だった。8 人全員ではなく 2 人なのは、その項目に値が入っている人が 2 人しかいないからだ。値が 0 の人の行は、符号を取り違えても動かない。所属を取り違えた時に 7 件なのも同じ理由で、その欄が空欄の 1 人だけ出ていない。

人が 1 行抜けた時の総計の差は 197,833 円で、これは抜けた人の差引支給額そのものだった。人ごとの合計には 1 件も出ていない。

残りのテストは、7 つの理由コードが全部通る道を持つこと、丸めの名前ごとに境界の値が固定値どおりになること、全角の数字が素通りしないこと、交点が 1 組に決まる場合と 4 組に増える場合、項目ごとの合計が全部一致したら総計も必ず一致すること、関所の側に書き出しの経路が無いこと(CLI を通してもファイルが 1 つも増えないこと)、差を吸収する引数が関数にも CLI にも無いことを見ている。合成 fixture が生成器から決定論的に出ることも、ディスク上の CSV と突き合わせて確かめてある。

いつも成り立つことは 1 文にして、性質テストで確かめている。結果は 2 通りしかない。3 つの検査が全部一致して次の工程へ渡す行が返るか、行は返らず理由コードか分類と差の一覧が返るか、だ。どちらの場合も、この部品からファイルは 1 つも開かれない。人ごとの差引と集計行をテストの中の計算でそろえた表を乱数で作り、半分の確率で 1 か所だけ壊して、毎回この 1 文が成り立つかを見る。乱数は固定で、毎回同じ 300 通りを試す。足し直しは道具の関数を使わず、丸めも含めてテストの中で別に書いてある。

## 図 2 検査の流れと、止まる場所

![2 つの表を読み、丸めを確かめ、人ごとに足し、項目ごとに足し、総計を 2 経路で比べて渡すまでの流れ図](figures/tally_gate_flow.png)

段は 6 つで、橙のピルが関所だ。2 段目が丸めの確認で、どの軸で足すよりも前に置いてある。3 段目と 4 段目の関所には「差は残して先へ」と書いてある。差が出ても止めずに次の軸へ進むのは、どの軸まで届いたかが分類の中身だからだ。

この図でも見てほしいのは描かれていない経路のほうになる。どこから出ても行き先は理由コードか分類で、「差が小さいので通す」や「不一致のまま出力を作る」に戻る矢印がどこにも無い。実装でも同じで、関数にも CLI にも許容誤差の引数を持たせていない。落ちる先が無ければ、落ちる経路も書けない。

## 道具

[tally_gate](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/tally_gate) に置いた。`tally_gate.py` 1 ファイルと、テスト、合成 fixture の生成スクリプトが入っている。依存は無く、標準ライブラリだけで動く。ライセンスは MIT。

丸めの名前は 4 つで、前回までの部品と同じものをそろえてある。足りなければ登録を増やす。増やす場所は 1 か所で、恒等式の側には書けない。自分の現場に合わせる時に触るのは宣言表と恒等式のほうで、部品のコードは触らない。

## 別の業種なら

この部品が持っているのは、人 × 項目の表と、所属と符号と丸めの名前の宣言、それに恒等式 1 本だけだ。会計の試算表を科目の軸と貸借の軸から足す形、EC の在庫を商品の軸と倉庫の軸から足す形、建設の数量を工種の軸と工区の軸から足す形、医療や介護の請求を利用者の軸と項目の軸から足す形は、どれも同じ構図だと考えている。特に貸借の一致は、打ち消し合う誤りが総計で消えるところまで同じになるはずだ。私が実測したのは上の合成データの範囲だけなので、他の分野は「同じ詰まり方になりそうな例」であって実測ではない。変わるのは所属の名前と恒等式の形だけで、入力の例を試算表や在庫表に差し替えれば部品はそのまま使える。

## できないこと

- 合計が一致したことは「同じ数字集合を 2 つの軸から足して同じになった」までで、値そのものが正しいとは言えない。項目の所属が妥当かどうかも判定しない
- 打ち消し合う差は総計の検査を通る。行と列には出るので交点の候補は出るが、1 組には決まらない
- 元の数字集合そのものが同じ誤りから作られていれば、どの軸から足しても同じ答えになる。軸を増やしてもこの形は捕まらない
- 項目ごとの合計が全部一致すれば総計も必ず一致するので、総計だけに出る壊れ方は作れない。3 つめの検査は独立した 3 つめの証拠ではない
- 丸めは足す前に位をそろえるためだけに使う。その値が宣言どおりの丸めで計算されたかは確かめない
- 空欄は 0 として足す。空欄と 0 を区別したい仕様には合わない
- 軸は人と項目の 2 つだけで、3 つ以上の軸での突き合わせは持たない。恒等式も符号の並び 1 本だけで、掛け算や条件分岐は書けない
- 上の件数は合成データでの測定で、他の人の表で同じ内訳になるとは限らない。特に 0 件になった軸は、仕込んだ壊れ方の選び方で変わる
