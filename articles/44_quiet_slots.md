前回は、更新の記録を 2 経路で並べた。今回は向きを変えて、数表を引く呼び出しの入口に立つ。骨は 1 行で言える。**「AI は推論せず、これを呼ぶ」と宣言しても、推論がやむのは数表の値の側だけで、呼ぶときにどの欄を埋めるかの判断は宣言の外に残る。しかも残った欄は一様でなく、空なら例外で止まる欄と、空でも宣言どおり通って広い行に当たる欄と、既定がどこにも宣言されていない欄が混ざっている。**

**なぜ重要か**: 私の記録には、料率や計算式を行として持つ仕組みがある。その README の見出しには「使い方 (AI は推論せず、これを呼ぶ)」と書いてある。料率を思い出させるのをやめて、コマンドで引く形にした、という宣言だ。この宣言のとおりにすると、数表の値を思い出す推論は確かにやむ。**ところが、呼ぶときにどの欄を埋めるかは、その宣言のどこにも書かれていない。** そして空にした欄の行き先は一様ではない。基準日を空にすれば例外で止まるが、都道府県を空にしても止まらず、宣言どおりに広い行へ当たる。`as_of` に至っては、機能は書いてあるのに既定を書いた行がどこにも無い。貼るのをやめて減らした分だけ、呼び出しの側で静かに広い行へ当たっていても、出口には何も出ない。

**要点**:
- 呼ぶ前に、欄ごとに「空にできない」「空でよいと宣言されている」「埋めるのは人か LLM だと宣言されている」「どちらの宣言も無い」の 4 つを 1 枚の境界表にする。値は入れない、引かない
- **4 つのうち後ろの 2 つが「空でも止まらない欄」になる。** 止まる欄だけを気にしていると、ここが見えない
- 「空でよい」と宣言された欄でも、当たる行が 1 本に決まるか複数になるかは行の側で決まる。だから道具は**行数を数えるところまで**にして、同順位競合に化けるとは書かない
- **宣言が無い欄を「空でよい」側へ寄せる経路を道具に置かない。** 宣言なしは宣言なしのまま出す

**数字で見る**: 合成した 4 枚(問いの宣言 5 行 / 欄の登録 10 行 / 行の在り方 6 行 / 出口の登録 4 行)を通すと、**問い 5 × 欄 10 = 組 50 件が 4 値と別枠 3 と「手元に在る」に分かれ、空でも止まらない欄が 9 組、そのうち `2 行以上が当たる` 印の付いた組が 2 件**になる。

## 何を解決するのか

### 宣言されているのは「呼べ」までだった

私の記録の README は、20 行目の見出しで「使い方 (AI は推論せず、これを呼ぶ)」と書いている。13 行目の表には、引く側のコマンドについて「resolve / compute / status / list / formulas。1 行 JSON 出力」とあり、実行者の欄が「AI・人・他ツール」になっている。収録範囲をまとめたほうの記録でも、52 行目に「[AI が使う層] rules_cli.py resolve / compute / status / list / formulas → 1 行 JSON (出典・依存行つき)」と書いてあり、53 行目に呼び出しの入口そのものが登録されている。

三層に分けた設計としては、これで筋が通っている。取得と変換と検証は人も AI も触らない層へ寄せ、引く層だけを外に出した。**書かれているのは「呼べ」までで、呼ぶときの欄の埋め方は、どの行にも書かれていない。**

### 4 本の例のどれにも as_of が現れない

欄の実例は、同じ README の 23〜26 行目に 4 本ある。`status` は欄が 0 本、健保の料率を引く `resolve` は 2 本、健保と介護の控除額を計算する `compute` は 4 本、雇用保険料を計算する `compute` は 3 本だ。

ここで気づくのが、**4 本のどれにも `as_of` が現れない**ことになる。収録範囲の記録の 33 行目には、行の列として「`known_from` / `known_to` | 知識時間 (公表側)。`as_of` で「当時の知識」を再現」と書いてある。当時の知識で引き直す機能は在る。**在るのに、例のどれにも書かれておらず、既定を書いた行もどこにも無い。** しかも同じ記録の 122 行目には「known_from (公表日) | 年金 press 由来の行のみ実値。他は valid_from で仮置き」とあり、同じ `as_of` を渡しても効き方が行ごとに違う。

### 空にすると止まる欄と、通る欄が混ざっている

止まる側は、はっきり書いてある。収録範囲の記録の 39 行目に「引き方 `resolve(rule, case, as_of)`: rule → 知識時間 → 有効時間 (case[basis]) → selector → 最高 priority 1 行。同順位競合・基準日欠落・収録範囲外は 例外 (黙って現行値を返さない)」とあり、README の 29 行目に「終了コード: 0 成功 / 2 該当なし・入力不足 / 3 表の不備 (競合)」とある。基準日が空なら止まる。

ただし、**2 は「該当なし」と「入力不足」が同じ記号**になる。止まった理由が欄の空きなのか、それとも収録範囲の外なのかは、出口の数字からは分からない。

通る側も、はっきり書いてある。同じ記録の 34 行目に「`selector` | 対象セグメント (都道府県 / 事業の種類 / 生年月日帯 / 離職時年齢 …)。未指定次元 = ワイルドカード」とあり、棚卸しの記録の 115 行目にも「selector 未指定 = wildcard」と、次元を後から足しても既存の行を直さずに済む仕掛けとして登録してある。**これは拡張性のために入れた設計であって、欠陥ではない。** 欠陥でないまま、呼ぶ側には「この欄を省いた」と書く場所が無い。

### 同じ「空でよい」が、行の在り方で 2 つに割れる

ここが、この回でいちばん書きたかったところになる。「空でよい」と宣言された欄でも、空にしたときに当たる行が 1 本に決まるか複数になるかは、**欄の側ではなく行の側で決まる**。

棚卸しの記録の 18 行目には、厚生年金の保険料率について「対象月初日 | — | param | 2017-09 以降固定」とあり、備考に「行は 1 本」と書いてある。次元が無いので空にしようもなく、当たるのは 1 行だ。

同じ表の 16 行目は、健康保険の料率について「対象月初日 | 都道府県 | param | 年度 (3月分〜)」としている。こちらは収録範囲の記録の 64 行目で「健保料率 (141)」、84 行目で「協会けんぽ 折半額 再計算 (3 年 × 47 支部 × 50 等級)」とあり、**都道府県を空にすると同じ有効期間に 47 行が並ぶ**。70 行目の「地域別最低賃金 (1,079、47 都道府県 × 2002-2025)」「労災保険率 (55 業種、R6〜)」も同じ形で、「消費税率 標準/軽減 (4/1、1989〜)」は次元が無い。

つまり、同じ「ワイルドカードで通る」でも、片方は 1 行に決まり、もう片方は 47 行が並ぶ。並んだ先で 39 行目の同順位競合に化けるのかどうかは、実際に引かないと分からない。**だから道具は、行数を数えるところまでにしてある。** 化けるとは書かない。

### 推論で埋めてよいと宣言された欄もある

棚卸しの記録の 129 行目には、表に入らないものの 1 つめとして「要件該当性の判断 | 労働者性、常用的使用関係、生計維持、業務起因性・通勤災害、障害等級の認定 (診断書)、同一労働同一賃金の「不合理」」があり、扱い方の欄に「判断結果を case の属性として受け取る (人間 or LLM が起票)。表は属性が確定した後だけ動く」と書いてある。137 行目の判定のコツも「同じ入力に対して行政が誰でも同じ答えを出すか」で表と表の外を分けている。

**推論を禁じた宣言と、推論で埋めてよいと宣言した欄が、同じ記録に並んで在る。** どちらも設計としては正しい。正しいまま、呼び出しの欄を 1 語で「引数」と呼んでしまうと、この 2 つが同じ列に入る。

### 実際にどの欄を空にして呼んだかは、数えられない

正直に書いておくと、事後に数える手も今は無い。収録範囲の記録の 129 行目に「CLI 実行時の event 追記 (work-tools 規約 4) | 未実装 | AI が呼ぶ時に手動追記の運用」とあり、128 行目には「独立 golden (registry の acceptance) | pipeline 内蔵検証のみ、別 golden 未作成」とある。呼んだ記録が残らないので、実際にどの欄を空にして呼んだかは後から数えられない。

**だから道具が数えるのは、宣言の上での空きだけになる。** 実測の代わりではない。

## 図 1 呼び出しの欄を、空にしたときの出口で 4 つに分けた境界表

![呼び出しの欄を行、空にしたときの出口(空にできない / 空でよいと宣言されている / 埋めるのは人か LLM / どちらの宣言も無い)を列にして、各セルに出典のファイル名と行番号を置いた境界表](figures/quiet_slots_map.png)

この図は論評ではなく、README の 4 本の呼び出しから取った欄に、`as_of` と登録表に無い欄名を足して、宣言の在りかで 4 列に割り直したものだ。行が欄 1 つ、列が空にしたときの出口になる。各セルに出典をファイル名と行番号で置いた。

**正しい埋め方の列は置いていない。** 推奨の列も、合計の行も、割合の行も無い。この図が答えるのは「どこに宣言が在るか」までで、「どう埋めるべきか」ではないからだ。

淡い藍の 4 行が、空なら止まると宣言されている欄になる。対象月初日と賃金締切日が基準日で、空なら例外。報酬月額と賃金総額は計算式の入力で、空なら終了コード 2 になる。

淡い橙が、空でも止まらない欄と、宣言が無い欄と、別枠だ。都道府県と事業の種類は、ワイルドカードで通ると宣言されている側になる。**同じ 1 つのセルの中で、健保の料率なら 47 行が当たり、厚生年金の保険料率なら 1 行に決まる**と分かれているのが、この図でいちばん見てほしいところになる。障害等級の認定は、人か LLM が起票してよいと宣言された欄だ。`as_of` は機能が在るのに既定が無い欄、資格取得日は欄名そのものが登録表に無い欄になる。

介護該当のセルには別枠の印だけを付けた。棚卸しの記録の 117 行目は「depends_on による 2 段引き | 「介護該当区分」「年齢区分」のような導出属性を case 側に要求しない」としているのに、README の 25 行目はそれを欄として渡している。**同じ欄について 2 通りの宣言が在る**。この食い違い自体は前に別の回で扱ったので、今回は印を付けるところで止めて、訂正の回にはしない。

## 手順

ひな型を出す。問いの宣言表・欄の登録表・行の在り方の表・出口の登録表の 4 枚が出る。

```
python quiet_slots.py init ひな型/
```

問いの宣言表には、呼びたい問いを 1 行で書く。

```csv
ask_id,command,target,slots,source
Q1,status,—,,合成の呼び出しのメモ(架空)L1
Q2,resolve,R1,K1|K3,合成の呼び出しのメモ(架空)L2
Q4,compute,R3,K2|K4|K5|K10,合成の呼び出しのメモ(架空)L4
```

`slots` が「手元に在る欄名の一覧」で、縦棒で区切る。**値を書く列が無い。** 名前だけを書く。実在の料率も金額も日付も入る場所が無いので、この表を人に見せても中身は出ない。`target` は求める行や式の id で、`status` のように何も求めないなら横棒を書く。

欄の登録表が、この道具のいちばん大事な表になる。

```csv
slot,kind,emptiable,filler,exit,source
K1,基準日,できない,表から引く,例外,合成の宣言のメモ(架空)L1
K3,選択の次元,できる,表から引く,—,合成の宣言のメモ(架空)L3
K6,判断の結果,できる,人かLLM,—,合成の宣言のメモ(架空)L6
K7,知識時点,宣言なし,宣言なし,—,合成の宣言のメモ(架空)L7
```

`emptiable` が「空にできるか」で、`できない` / `できる` / `宣言なし` の 3 つしか受け取らない。**3 つめが大事で、ここから `できる` 側へ寄せる引数が道具に無い。** 既定を当てる辞書も持っていない。`filler` が「誰が埋めてよいか」で、`人かLLM` と宣言された欄だけが 3 番目の値へ移る。`exit` は、空にできない欄が止まる出口を書く場所になる。

**同じ欄名を 2 行書いてよい。** 2 通りの宣言が在ることを写すためだ。空にできるかか誰が埋めてよいかが食い違っていれば、その欄の組は 4 値に入らず、出典を 2 本とも付けて別枠へ出る。

行の在り方の表には、その次元を空にしたとき当たる行数を書く。

```csv
target,dimension,rows,source
R1,K3,47,合成の行数のメモ(架空)L1
R1,K4,1,合成の行数のメモ(架空)L2
R3,K3,55,合成の行数のメモ(架空)L5
```

**ここに入るのは行数だけで、行の中身は入らない。** 同じ行や式の id と次元名の組が 2 行あると止まる。どの問いも求めていない id を指す行は、止めずに別の一覧へ出す。黙って落とすと、書いたのに使われていない宣言に気づけなくなるからだ。

出口の登録表で、「止まる」の定義を宣言する。

```csv
exit,stops,source
例外,止まる,合成の宣言のメモ(架空)L11
終了コード2,止まる,合成の宣言のメモ(架空)L12
通る,止まらない,合成の宣言のメモ(架空)L14
```

**この表を別に持たせたのは、「止まる」が欄の性質ではなく出口の性質だからだ。** 空にできないと宣言した欄が、止まらない出口を指していたら、そこで止める。宣言が自分で矛盾している形を、黙って通さないためになる。

数える。

```
python quiet_slots.py check 問いの宣言表.csv 欄の登録表.csv 行の在り方の表.csv 出口の登録表.csv
```


削減量を返す呼び方は無い。返るのは件数と分母だけで、**最後に並ぶ 12 行は消せない**。`cells` にすると、判定ごとの一覧、**空でも止まらない欄の一覧**、別枠の一覧、欄ごとの一覧、どの問いも求めていない宣言の一覧、どの欄も指していない出口の一覧が出る。

上から順にどう見ているかも書いておく。問いの行の出典が空なら、その問いの組は別枠で終わり。欄名が登録表に無ければ別枠。同じ欄に 2 通りの宣言が在れば別枠。問いが手元に在ると宣言した欄は、空にする欄ではないので別に数える。そこを抜けてから、はじめて空にできるかで 3 つへ振り分け、**誰が埋めてよいかが `人かLLM` の欄だけを 4 番目へ移す**。印が付くのは「空でよい」の組だけだ。

最後に、この手続き自体が決定論かどうかを実測する。

```
python quiet_slots.py verify 問いの宣言表.csv 欄の登録表.csv 行の在り方の表.csv 出口の登録表.csv
```

`verify` は 5 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、3 通りの入れ替え方で 4 枚の行順を入れ替えても同じ出力になるか、3 通りの数え方の合計が合うか、そして 2 つの写しだ。**空にできるかを `できる` から `宣言なし` に替えた写し**では、その欄の組だけが「空でよい」から「どちらの宣言も無い」へ移り、別枠の件数が 1 つも動かないこと。**行の在り方の行数を 1 から 2 に替えた写し**では、その組の印だけが移り、4 値の件数が動かないこと。写しはメモリの中だけで、入力の表には 1 文字も書かない。

## 検証

テストは 27 件で、測っているものは 8 つある。組 50 件が 4 値と別枠と手元に在るに分かれる側、**空でも止まらない欄が 9 組でそのうち 2 組に `2 行以上が当たる` の印が付く**側(これが骨)、宣言が無い欄が 8 組ある側、同じ欄に 2 通りの宣言が在る欄が別枠へ出る側、出典が空の問いの組が 4 値に入らない側、宣言を替えると 1 つの欄の組だけが移る側、行数を替えると印だけが移る側、出力の末尾の「持たせていないもの」が 12 行そろっている側だ。4 値の分け方は、テストの側でも 4 枚の表の行から直に分類し直して確かめている。

ひとつめが、空でも止まらない欄の 9 組になる。合成した表では、問い 4 件(出典が空の 1 件を除く)に対して、空でよいと宣言された欄が 6 組、人か LLM が埋めてよいと宣言された欄が 3 組ある。**どちらも、空にして呼んでも宣言のうえでは止まらない。** 止まる側の 7 組と足しても 16 組で、組全体の一部にしかならないところが、この道具のいちばん地味な結論になる。

ふたつめが、印の 3 つの分かれ方だ。同じ「空でよい」でも、`1 行に決まる` が 2 組、`2 行以上が当たる` が 2 組、`行数の宣言が無い` が 2 組になる。**3 つめを 0 とも 1 とも読まないところが大事**で、行数の宣言が無いことと、行数が 1 だと分かっていることは、同じ列に置けない。テストの側では、この 3 つが行の在り方の表の宣言だけで決まることを総当たりで確かめている。

みっつめが、宣言が無い 8 組になる。欄で言えば 2 つで、知識時点の欄と、次元のうち 1 つだ。**どちらも印が空のまま出る。** 宣言なしを「たぶん空でよい」と読み替える経路を道具に置いていないからで、これが型の禁則(空白を自分の推測で埋めない)を物理の形にしたところになる。

よっつめが、2 つの写しの分かれ方だ。空にできるかの宣言を替えると判定だけが動いて別枠は動かない。行数を替えると印だけが動いて判定は動かない。**2 つとも「片方だけが動く」ことを見ている。** 宣言の層と行の層が本当に別の層なら、こうなるはずだという形を、写しで確かめた。

いつも成り立つことは 1 文にして、性質テストで確かめている。読んだ範囲は 2 通りしかない。問い × 欄 の組 1 つごとに 4 値か別枠 3 か「手元に在ると宣言されている」のどれか 1 つが付き、その合計が問いの件数と欄の件数の積に等しく、問いごとの内訳の合計も欄の種別ごとの内訳の合計も同じ数になり、印が付くのは「空でよい」の組だけで印の合計がその件数に等しく、宣言なしと宣言された欄が「空でよい」側へ移る経路が無く、人か LLM と宣言された欄は必ず 3 番目の値になり、問いが手元に在ると宣言した欄は空にする欄に数えず、出典が空の問いの組は 4 値に 1 つも入らず、4 枚の行順を 3 通りに入れ替えても同じバイト列になるか、1 組も数えずに理由コードが返るか、だ。どちらの場合も入力は 1 文字も書き換わらない。問いを 1 件から 4 件、欄の登録を 5 欄、同じ欄の 2 本目の宣言を 0 件から 1 件、行の在り方を 0 件から 3 件まで引く。乱数は固定で、毎回同じ 250 通りになる。崩し方は 7 通りで、1 組も数えずに止まる理由コード 7 個すべてに道を付ける。2 本目は「空にできるか・誰が埋めてよいか・行数の宣言の 3 つだけが判定と印を決める」ことを総当たりで見ていて、上限は 300 にしてある。

書いている途中で 1 つ捕まえたのは、問いが手元に在ると宣言した欄の扱いだった。**最初は、手元に在る欄も 4 値のどれかに入れていた。** そうすると「空にできない欄」の件数に、実際には埋めてある欄が混ざる。性質テストが、同じ欄をある問いは渡していて別の問いは渡していない、という形を作ってきて落ちた。そこで手元に在る欄を 4 値の外へ出し、組の合計だけが戻る形に変えた。埋めてある欄と、空にしても止まらない欄は、同じ列に置けない。

## 図 2 境界表ができるまでの流れと、止まる場所

![4 枚の表を読み、出典と形を見て、登録表に当て、出口を結び、在る欄と無い欄に分け、空にできるかで振り分け、人か LLM の欄を移し、印を付けて検算するまでの流れ図](figures/quiet_slots_flow.png)

段は 9 つで、橙のピルが関所になる。前の 4 段は分ける前の検査で、表の形と出典、欄名が登録表に在るか、空にできない欄の出口が「止まる」側に結べるかを見ている。

この図で見てほしいのは、描かれていない経路のほうだ。**CLI を呼ぶ矢印が無い。** 欄に値を入れる矢印も、宣言なしを「できる」へ寄せる矢印も、トークン数や削減量へ出る矢印も、省略の正否を決める矢印も、入力を下へ辿る矢印も、行の中身の値を読む矢印も、現在時刻を読む矢印も、入力を書き換える矢印も無い。実装でも同じで、そういう引数を持たせていないから、落ちる先が無く、落ちる経路も書けない。

5 段目から 8 段目が本体になる。5 段目で、手元に在ると宣言した欄を外し、出典が空の問いと 2 通りの宣言が在る欄を別枠へ出す。6 段目で、残りを空にできるかの記号で 3 つに振り分ける。7 段目で、人か LLM が埋めてよいと宣言された欄を移す。8 段目で、空でよい欄にだけ行数から印を付ける。

9 段目で 3 通りの合計を検算する。4 値と別枠と手元に在るの合計が組の件数に戻り、問いごとの内訳の合計も、欄の種別ごとの内訳の合計も同じ数に戻る。**この 3 つは数えている切り口が違う**ので、どれか 1 つを差し替えると合わなくなる。

## 道具

道具は [GitHub](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/quiet_slots) にある。ライセンスは MIT で、自由に使える。標準ライブラリだけで動く(テストの実行には pytest と hypothesis が要る)。値の列も、日付の列も、時刻の列も持たない。入るのは欄名と記号と行数と出典だけだ。

手元で書くのは 4 枚で、いちばん軽いのが問いの宣言表になる。呼びたいコマンドを並べて、手元に在る欄の名前を書くだけで、値は書かない。重いのは欄の登録表で、「この欄は空にできるのか」「空にできないなら、どの出口で止まるのか」「誰が埋めてよいのか」を人が決めるところになる。道具が見るのは、その欄が埋まっているかと、出口が「止まる」側に結べるかまでだ。

合成した表が置き場に入っているので、同じ数字が手元で出るかを確かめられる。**実在の料率も実在の金額も実在の日付も 1 つも入っていない。** 問い id は記号、欄名は記号、求める id も記号、出典は「合成の…(架空)」で、行数の桁だけ手元の棚卸しと同じ形にそろえてある。

使い方として想定しているのは、引く仕組みを人や AI に渡す前に 1 回通すことになる。出てきた「空でも止まらない欄」の件数が、そのまま「この呼び出しについて、宣言はどこまで書けているか」を測る材料になる。**削減量は出ない。出るのは組ごとの 4 値と、印と、別枠だけだ。**

## 別の業種なら

この部品が持っている欄は、問い id・コマンド名・求める id・欄名・種別記号・空にできるか記号・誰が埋めてよいか記号・出口記号・止まるか記号・行数・出典だけで、給与や社会保険の言葉は 1 つも入っていない。どの分野でも「表は引けるようにしたのに、引くための欄をどう埋めるかは書いていない」形は同じで、分けるのは空にしたときの出口になると考えている。会計なら、税率や勘定科目を引く道具に対して、どの日付(発生日 / 支払日 / 決算期)で引くかと、事業区分を空にしたとき全区分の行が当たるかが宣言されていない。買い物の仕組みなら、送料や手数料の表を引くときの地域区分と会員区分が空だと広い行へ当たり、キャンペーンの適用判断は人が起票する欄になる。運送なら、運賃表を引く距離帯と車種区分、待機の認定は人の欄。医療や介護なら、単価を引く算定月と施設区分、算定要件の該当性は人の欄。建設なら、労務単価を引く職種と地域、現場ごとの補正は人の欄。製造なら、部品表を引く型番と有効日になる。私が測ったのは上の合成した 4 枚の範囲だけなので、ほかの分野は同じ詰まり方になりそうな例であって実測ではない。変わるのは表に書く語だけになると考えている。

## できないこと

- **空にして呼んだら何が返るかは分からない。** この部品は引く側のコマンドを呼ばない。`2 行以上が当たる` は宣言表の行数の写しで、実際に空にして引くと 1 行に決まるのか同順位競合で止まるのかは、出力に出ない
- **実際にどの欄を空にして呼んだかは分からない。** 数えるのは宣言の上での空きだけになる。呼んだ記録を残す仕組みが手元ではまだ動いていないので、事後に数える手が無い
- **トークンがどれだけ減るかは分からない。** 数え方を持っていないので、文字数もトークン数も削減量も列に無い
- **どの欄を埋めるべきかは分からない。** 4 値と印を並べるだけで、省略してよいかは読む人が決める。終了コード 0 も「全ての組が、空にできないか手元に在ると宣言されている」であって、呼び出しが正しいという意味ではない
- **問いごとに要る欄は分からない。** 道具は問いと欄の全組を数えるので、`status` のように欄が 0 本の問いでも、登録された欄すべてが組になる。これは「宣言の上での空き」を数えるという定義の帰結で、要る欄を決めるのは人になる
- **宣言が正しいかは分からない。** 4 枚は人が書くもので、この部品は宣言どおりに分けるだけだ。宣言そのものが間違っていれば、間違ったまま 4 つに分かれる
- 図 1 の割り当ては、私の記録の 3 つのファイルを読んだもので、私の環境での話になる。ほかの人の引く仕組みが同じ形だとは言えない
- 上の件数は合成した 4 枚の表に対する測定で、ほかの人の環境で同じ数字になるとは限らない
