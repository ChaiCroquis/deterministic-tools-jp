前回までで、数表を引くときの日付の軸と値の軸は宣言の形が決まった。残っているのはもう 1 つの軸、値そのものが入っていないマスだ。骨は 1 行で言える。**同じ空欄が、列によって「全部に当たる」とも「まだ取っていない」とも「制度として該当なし」とも読める。どれかを書いていないと、空欄は黙って 0 か現行値になる。**

**なぜ重要か**: ここまでの回で、行を選ぶ条件はだいぶ宣言の形になった。基準日と公表時点を書き、期間が境界をまたぐなら先に切り、帯には以上と未満を書く。どれも「どの行が当たるか」を 1 つに決めるための宣言だった。けれど当たった行のマスが空だったとき、その空が何を意味するかは、どの回でも書かせていない。そして空欄は、書かれていなくても何かに化ける。合計するときは 0 になり、前の行を引き継ぐ処理では現行値になり、絞り込みの列では「全部に当たる」になる。化け方はコードの 1 行で決まり、決まったことは出力のどこにも残らない。入力は壊れていない、エラーも出ない、数字だけが静かに違う。この形がいちばん見つけにくいと私は考えている。

**要点**:
- 空欄の意味は値の表の理由コードから取る。理由コードの無い空欄は 1 マスも読まずに止まる
- 同じ空欄記号を列ごとに別の意味で読む。その列が「全部に当たる」列かどうかの宣言が無ければ止まる
- 0 と空欄をどちらにも寄せない。空欄を 0 にせず、0 を空欄として落とさない
- 欠けている件数は理由コード別に数え、分母(対象 × 項目の総数)と内訳を併記する

**数字で見る**: 合成した対象 3 × 項目 4 = 12 マスを通すと、値が在る 4 マスと、意味の付いた空欄 8 マスに分かれた。理由コードは 7 種で合計 8 件、そのうち 1 件は値を持ったままの仮置きだった。値の列のマス 1 つに「全部に当たる」の理由コードを書くと、そのマスだけが決まらなくなり、残る 11 マスの結果は変わらなかった。

## 何を解決するのか

表に空のマスがある。これだけでは、何も分からない。

分からないのに、処理は進む。それが問題の形だ。空欄を読む側は、必ず何かに決めている。決めていないつもりでも決めている。合計の式に入れれば 0 として足され、条件に入れれば偽として扱われ、絞り込みの列なら「指定なし = 全件」として扱われる。どれも、空欄そのものに意味があったわけではなく、**読む側の既定が意味を与えた** 結果だ。

私の記録を見返すと、同じ 1 つの空白記号に、少なくとも 9 通りの意味が並んでいた。まだ値を取っていない。値はあるが出典の照合が済んでいない。確認できた範囲の先頭を仮に置いた。制度として当たらない。行そのものを入れていない。数式の一部を作っていないので呼び出し側で補う。公布はされたが施行日が決まらないので登録だけしてある。自動で見つける手だてが無いので手で足している。そして、絞り込みを書いていないので全部に当たる。

最後の 1 つだけが、ほかの 8 つと向きが逆になる。ほかの 8 つは「値が無い」だが、これは「全部に当たる」だ。**同じ空白なのに、片方は何も返さず、もう片方は全部を返す。**

### 空欄を直すのと、空欄に名前を付けるのは別の話

ここで手を出したくなるのは「空欄を埋める」ほうだ。けれど埋めるには値が要るし、値を取ってくるのは別の作業になる。今日できることではない。

できるのは、**空欄のままで、それが何の空欄かを書く** ことだ。書けば、同じ空白を列ごとに別の経路に流せる。書かなければ、読む側の既定が黙って決める。この 2 つの差は、値を 1 つも取ってこなくても今日のうちに作れる。

だからこの部品は、埋める経路を持たない。空欄に名前を付けて数えるところまでで止まる。

### 0 は、空欄のいちばん近くにある罠だと思う

0 と空欄は、見た目が近い。人数 0 人、日数 0 日、金額 0 円。どれも「無い」と読めてしまう。

けれど 0 が正規の値になりうる項目では、0 と空欄は別物だ。人数 0 人は測った結果で、空欄は測っていないことだ。逆に、0 が正規の値にならない項目に 0 が書いてあれば、それは誰かが空欄を 0 で埋めた跡かもしれない。

どちらも、項目の側に「0 が正規の値になりうるか」を書いていないと判別できない。だからこの部品は、その欄が空なら止まる。そして **空欄を 0 にする経路も、0 を空欄として落とす経路も持たない。**

## 図 1 線の内側に残っている空白 9 件

![空白の類型 9 件を行に、どこに在る空白か・線の内側である根拠・原文に残っている理由と量・この道具での返し方を列にした対応表](figures/blank_kind_cases.png)

行が、私の記録に残っている空白の類型で、列がその空白について記録に書いてあることだ。藍が「全部に当たる」として扱う行、橙が「該当なし」として別の出口に返す行になる。

断りを書いておく。ひとつめは読み替えだ。この型はもともと「許可されているのに滞っているもの」を並べるものだが、ここでは制度上の許可ではなく **表に入ると判定されたこと**、つまり線の内側に読み替えている。見ているのは手元の記録に書かれている文言までで、条文も実データも見ていない。ふたつめは、空のままである原因を推定していないことだ。記録に理由が書かれている行だけ理由を載せ、書かれていない行は空のままにした。みっつめは、原文から取れる数値だけを置き、取れない行には「数値は原文に無い」と書いたこと。よっつめは、値を出していないことだ。料率も金額も上限の数も図に入れていない。記録自身が冒頭で、値は未取得で、各行は照合前で、条文の照合も済んでいないと書いているからだ。いつつめは収集範囲で、その記録に書かれている範囲に限る。制度を網羅して読んだわけではない。むっつめは、件数を率にしていないこと。

読みどころは右端の列になる。9 件のうち 7 件は「値として返さない」に落ちる。1 件だけ「該当なしとして返す」で、1 件だけ「全部に当たるとして扱う」だ。**3 つの返し方は、表の上ではどれも同じ空白から始まっている。** 違いは、その空白にどの名前が付いているかだけで、名前が無ければ 3 つのどれにもなれる。

左から 2 列目は、その空白が線の内側にあることの根拠だ。行として並んでいる、出典の列がある、計算に使う行になっている、出口が終了コードで分けてある、収録範囲の表に名前がある、数式の行として登録されている。どれも「表に入ると決めた」痕跡で、だからこそ空のままでも気づきにくい。**外に出されたものは見えるが、内側に残った空白は表の一部として見える。**

## 手順

ひな型を出す。値の表と項目の宣言と理由コードの宣言の 3 枚が出る。

```
python blank_kind.py init ひな型/
```

値の表には、対象 × 項目 のマスを 1 行ずつ書く。

```csv
target,item,value,reason,source,swap
合成の区分A,合成の金額の列(架空),120000,,協会けんぽ / 私の棚卸し記録(非公開),逆順
合成の区分B,合成の金額の列(架空),,値が未取得,協会けんぽ / 私の棚卸し記録(非公開),
合成の区分C,合成の金額の列(架空),95000,仮置き,協会けんぽ / 私の棚卸し記録(非公開),
合成の区分A,合成の年齢の列(架空),,全部に当たる,articles/07_asof_table.md L15,
```

値が空で理由コードも空の行があれば、1 マスも読まずに止まる。3 行目のように、値が書いてあっても理由コードが付いていれば、その値は仮置きの欄に回る。出典の欄が空の行も止まる。

項目の宣言には、列ごとの読み方を書く。

```csv
item,kind,reasons,zero_ok,all_match,source
合成の金額の列(架空),金額,値が未取得|要照合|仮置き,はい,いいえ,協会けんぽ / 私の棚卸し記録(非公開)
合成の月数の列(架空),月数,未収録|呼び出し側で補う|施行日待ち,いいえ,いいえ,日本年金機構 / 私の棚卸し記録(非公開)
合成の年齢の列(架空),年数,全部に当たる,はい,はい,articles/07_asof_table.md L15
```

いちばん右から 2 つめが、この回の肝になる。その列の空欄が「全部に当たる」を意味するかどうかだ。はいなら、その列が許す理由コードは「全部に当たるとして扱う」のものだけになる。値扱いのコードも混ざっていれば、同じ空白に 2 つの意味が宣言されていることになるので、読む前に止まる。

理由コードの宣言には、名前と意味と返し方を書く。

```csv
code,meaning,how,source
値が未取得,行は在るが値をまだ取っていない,値として返さない,協会けんぽ / 私の棚卸し記録(非公開)
該当なし,制度として当たらない,該当なしとして返す,厚生労働省 / 私の棚卸し記録(非公開)
全部に当たる,絞り込みを指定していない,全部に当たるとして扱う,articles/07_asof_table.md L15
```

返し方は 3 つだけで、この外は読めない表として返る。**足すべき理由コードを部品が提案することはない。** 一覧に無い意味は、書かれていない以上そこに無いものとして扱われる。

まず数える。

```
python blank_kind.py check 値の表.csv 項目の宣言.csv 理由コードの宣言.csv
```


欠けている率を単独で返す呼び方は無い。件数には必ず分母の内訳が付くし、**最後の 3 行は消せない。** 前の回の「等号は宣言された欄だけ」「覆いの検算」と同じ作りで、ここでは「空欄の意味は宣言から取る」「0 と空欄を寄せない」「前の値で埋めない」が消せない行になっている。

`read` にすると、マスごとの内訳が付く。値・結果・理由コード・空欄の意味・返し方・仮置きの値・出典だ。理由コードの付いたマスだけを並べた表も別に出る。

最後に、読む手続き自体が決定論かどうかを実測する。

```
python blank_kind.py verify 値の表.csv 項目の宣言.csv 理由コードの宣言.csv
```

`verify` は 3 つ見る。2 回読んで判定部分のバイト列の指紋が同じか、**宣言された入れ替え方で値の表の行順を入れ替えても同じ出力になるか**、そして **理由コード別の件数の合計と理由コードの無い行の件数が、対象 × 項目 の総数に合うか** だ。3 つめが、この部品に自分で入れた検算になる。

終了コードは、全てのマスに値が在るときだけ 0、空欄や決まらないマスがあるときや止まったときは 3、表として読めなければ 2 になる。空欄が残っている表は 3 で返るので、まとめて走らせる仕組みの中に置けば、埋まるまで先に進まない形にもできる。

## 検証

読みどころは 3 つある。

ひとつめは、4 行目と 5 行目の対比だ。**同じ空白記号、同じ理由コード。** 片方は「全部に当たる」列に書かれていて、意味の付いた空欄として返る。もう片方は値の列に書かれていて、決まらないとして返る。変えたのはマス 1 つの理由コードだけで、それだけで結果が分かれた。そして残る 11 マスの結果は動いていない。

ここで部品は、どちらが正しいかを決めていない。**2 つの読みのどちらも返さず、意味の欄も返し方の欄も空のまま「決まらない」と書く。** 片方を選んで返すと、選んだことが出力から消える。消えると、次に読む人は選ばれた側しか見ない。

6 行目も対にして読むと分かりやすい。許す理由コードの一覧を広げただけでは、指紋は 1 桁も動かない。動くのは、マスの理由コードを書き換えたときと、0 を書いたときだ。**宣言を緩めることと、宣言を使うことは別の操作** で、前者だけでは結果は変わらない。

ふたつめは、止まり方の分かれ方になる。理由コードの無い空欄は止まる。宣言に無いコードも止まる。全部に当たる列に値扱いのコードを混ぜた宣言も、値を 1 つも読む前に止まる。一方、意味が食い違っているマスは止まらず、決まらないとして件数に残る。**宣言そのものが矛盾している場合と、宣言は揃っているが 1 マスの読みが決まらない場合を、分けてある。** 前者は表を直せば消えるもので、後者は人が決めるまで消えないものだからだ。

空欄であること自体も止まらない。意味の付いた空欄は 8 件あって、理由コードは 1 件も出ていない。読む手続きは成立しているからだ。**空欄は欠陥ではなく、名前の付いていない空欄が欠陥になる。** この区別ができると、埋まっていない表のまま先へ進める。

みっつめは、件数の検算だ。理由コード別の件数の合計と、理由コードの無い行の件数を足して、対象 × 項目 の総数に合うかを見ている。マスを 1 つ落とした表でも、同じマスを 2 行書いた表でも、値を読む前にここで止まる。**欠けているものを数えるとき、分母が揺れているといちばん困る** からで、分母は値を 1 つも見ないうちに確定させておきたかった。

いつも成り立つことは 1 文にして、性質テストで確かめている。読んだ結果は 2 通りしかない。マスごとに 4 値が 1 つだけ付き、4 値の合計が対象 × 項目 の総数に等しく、空欄の意味と返し方は宣言された理由コードからだけ付き、理由コード別の件数の合計と理由コードの無い行の件数の和が総数に等しく、判定部分に時刻もホスト名も絶対パスも入らず、値の表の行順を入れ替えても同じバイト列になるか、1 マスも読まずに理由コードが返るか、だ。どちらの場合も入力は 1 文字も書き換わらない。対象を 1 から 3、項目を 1 から 3、各マスを値か空欄で振り、3 割くらいの確率でどこか 1 か所を崩して、毎回この 1 文が成り立つかを見る。乱数は固定で、毎回同じ 150 通りだ。**4 値は部品の分類を呼ばず、行と宣言からテスト側の別実装で組み立てている。** 同じファイルの 2 本目は 300 通りで、列の種類の 1 欄を書き換えると同じ理由コードの空欄だけが入れ替わり、値の側のマスは動かないことを見ている。

## 図 2 読む流れと、止まる場所

![値の表と項目の宣言と理由コードの宣言を読み、宣言の欄を見て、列の意味を 1 つに絞り、マスを検算し、空欄の意味を付けて、件数を数えて返すまでの流れ図](figures/blank_kind_flow.png)

段は 6 つで、橙のピルが関所になる。前の 4 段はマスを 1 つも読む前の検査で、表の形と宣言の揃い方、それに対象 × 項目 の格子そのものだけを見ている。

この図で見てほしいのは、描かれていない経路のほうだ。空欄から「0 にする」へ出る矢印が無い。空欄から「前の行の値を引き継ぐ」へ出る矢印も無い。仮置きの値から「値として返す」へ出る矢印も無い。理由コードの無い空欄から「理由を推定して付ける」へ出る矢印も無い。件数から「率だけを返す」へ出る矢印も無い。実装でも同じで、そういう引数を持たせていないから、落ちる先が無く、落ちる経路も書けない。

4 段目だけは少し毛色が違う。ここはマスの中身を見ずに、格子が埋まっているかだけを見る段だ。値が 1 つも無くても、この段は走る。**何マス欠けているかを数えるには、何マスあるはずかが先に決まっていないといけない** からで、値を見ながら分母を数えると、落ちている行は分母からも落ちる。

5 段目が、この回の本体になる。ここでやっているのは判定というより、**同じ空白を列ごとに別の経路へ分ける** ことだけだ。「全部に当たる」列の空白は全部に当たるとして、値の列の空白は値が無いとして、該当なしのコードが付いた空白は別の出口として返る。どれになるかを決めるのは列の宣言とコードの宣言で、部品は組み合わせが 1 つに決まるかどうかしか見ていない。

ひとつ、この回で扱わないことをはっきりさせておく。この部品は日付を持たない。期間も切らない。値を帯にも当てない。版を選ぶのは基準日の列を足した回の道具で、期間を切るのはその次の回、帯で引くのは前回の道具だ。役割を重ねなかったのは、どの決めごとで答えが動いたのかを追えるようにしておきたいからだ。

## 道具

道具は [GitHub](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/blank_kind) にある。ライセンスは MIT で、自由に使える。標準ライブラリだけで動く(テストの実行には pytest と hypothesis が要る)。

手元で書くのは、値の表と項目の宣言と理由コードの宣言の 3 枚だけだ。合成した表が置き場に入っているので、同じ数字が手元で出るかを確かめられる。**値も対象も項目も全て架空で、実在の金額や率は 1 つも入っていない。** 空欄の類型の名前だけは、私の記録に文言として残っている区別を写してあるが、値そのものは写していない。

使い方として想定しているのは、空欄のある表を受け取ったときに 1 回通すことだ。止まったら、理由コードを足すか、列の種類を書くか、0 の扱いを決める。どれにするかは部品が決めない。理由コードの一覧は、はじめから揃っていなくてよいと思う。止まった分だけ足していけば、その表の空白が何種類あったかが、そのまま一覧になる。

## 別の業種なら

この部品が持っている欄は、対象・項目・値・理由コード・出典と、値の種類・許す理由コードの一覧・0 の扱い・列の種類だけで、給与や社会保険の言葉は 1 つも入っていない。会計なら、残高や勘定科目の空欄(未計上なのか 0 円なのか未取得なのかが同じ空白)。EC なら在庫数の空欄で、欠品の 0 と未登録と「在庫管理の対象外」が並ぶ。SaaS なら API が返す null で、未設定と無効と値が 0 の 3 つが同じ null になる。医療や介護なら測定値の空欄(未実施と正常と対象外)。建設なら数量の空欄で、数量ゼロと未積算が同じ空白になる。どれも「空白が 1 種類しか無いのに、意味が複数ある」という形で同じなので、同じ部品がそのまま使えると考えている。私が測ったのは上の合成した表の範囲だけなので、ほかの分野は同じ詰まり方になりそうな例であって実測ではない。変わるのは表に書く中身だけで、部品のコードはそのまま使える。入力例だけ業種を変えれば、料率の表のところが残高の表になり、在庫の表になる。

## できないこと

- 判定したことは「空欄の意味が宣言から 1 つに決まるか」までで、**どの意味が制度として正しいかは判定しない**
- **値がいくらかも言わない。** 値は入力の表から来るので、拾ってくるのは人の側になる
- **理由コードの一覧が足りているかも判定しない。** 宣言に無い意味は、書かれていない以上そこに無いものとして扱われる
- **空欄の理由を推定しない。足すべき理由コードも提案しない。** 理由コードの無い空欄は止まるだけで、埋める候補を出す経路が無い
- 仮置きを外す判断もしない。仮置きの値は仮置きの欄に出るだけで、採るか採らないかは人の側に返る
- 日付で表の版を選ばない。期間も切らない。値を帯にも当てない。それぞれ別の回の道具の仕事になる
- 対象の欄は結果に添えるだけで、意味の決め分けには使わない。対象ごとに空欄の意味が違う表は、項目を分けて渡すことになる
- 値は数として読む。文字で書かれた区分の列は、そのままでは渡せない
- 上の件数は、合成した表に対する測定で、他の人の環境で同じ数字になるとは限らない
