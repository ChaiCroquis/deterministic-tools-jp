前回は、宣言した「次の一歩」を約束に割り、翌日の 1 枚のどこに記載が在るかを並べた。今回は同じ作業状況の記録の、ファイルの置き場の行を見る。骨は 1 行で言える。**公式の原本を取ってきて置き場に置いた本数と、収録範囲の出典の欄に「この原本を使った」と書かれた数は別の数で、置き場の本数を「収録の根拠の数」と読むと、もっともらしく違う数が生まれる。だから置き場の種類ごとに、取ってきた本数と、使われた記載・未抽出や次の作業の欄にだけ在る記載・読んだ範囲に記載なし、を並べる。差は両側に数が在るときだけ整数で出し、滞留の理由は書かない。**

**なぜ重要か**: 原本の置き場に「PDF ×7」と書いてあれば、7 本の PDF から値を取った、と読みたくなる。私もそう読んでいた。けれど同じ記録の出典の欄が名指している PDF は 2 つの題の 3 年度分で、数えると 6 になる。**残りの 1 本が何なのかは、記録のどこにも書かれていない。** 置き場の本数だけを見ていると、この差は見えない。逆に、差を見つけたからといって「1 本は要らない」と決めると、今度は確かめていないことを書くことになる。

**要点**:
- 取ってきた本数は置き場の行から、名指された数は出典の欄から、どちらも人が台帳に書く。道具はフォルダを開かない
- 置き場の種類ごとに 5 値 = 一致 / 差が在る / 片側に数が無い / 未抽出か次の作業の欄にだけ在る / 読んだ範囲に記載なし。差は整数で返すが、どのファイルが差かは返さない
- 置き場は「使っている / いない」の 1 値に丸めない。置き場ごとに 5 値の内訳を返す
- 手元の記録では、置き場 3 つ・種類 7 つが、一致 2・差 1 が 2・片側に数なし 1・次の作業だけ 1・記載なし 1 に分かれた

**数字で見る**: 置き場の種類 7 → 5 値は 2 / 2 / 1 / 1 / 1、別枠 0 件。差は厚労省の PDF で 1、年金機構の PDF で 1。記載 11 行のうち、どの種類にも当てなかった行が 1。テストは 20 passed。

---

## 何を解決するのか

### 置き場の側: 3 つの置き場に、7 つの種類

材料は、私の手元の作業状況の記録 1 枚だ。社労士の仕事で引く料率や等級表、給付の上限額、年金額の数値を、日付で引ける数表に整える作業の記録で、2026-09-20 時点のもの、全部で 178 行ある。

ファイルの一覧の表の終わりに、公式の原本を取ってきて置いた場所が 3 行並んでいる。

```
| `sources/kyoukaikenpo/` | 公式 xlsx ×3 + extracted.json |
| `sources/mhlw/` | 厚労省 page ×3、PDF ×7、ハローワーク HTML ×2、extracted_koyou.json |
| `sources/nenkin/` | 年金機構 PDF ×5、press PDF、HTML ×3、extracted_nenkin.json |
```

164〜166 行目だ。`extracted` の付いた JSON は、原本から抽出した結果で、取ってきた原本ではないので台帳から外した。残りを種類ごとに 1 行にすると 7 行になる。協会けんぽの xlsx 3 本、厚労省の page 3 本、PDF 7 本、ハローワークの HTML 2 本、年金機構の PDF 5 本、press PDF、年金機構の HTML 3 本だ。press PDF には「×」が無いので、1 件書きとして 1 本と台帳に書いた。

### 使われた側: 出典の欄は何本を名指しているか

同じ記録の 64〜66 行目は、収録範囲の表だ。行ごとに「出典」の欄があり、どの原本から値を取ったかが書いてある。

- 64 行目「公式 xlsx `r{N}ippan3.xlsx` (R6/R7/R8)」
- 65 行目「厚労省「基本手当日額の計算式及び金額」「支給限度額の変更」PDF (R6/R7/R8) + ハローワーク HTML」
- 66 行目「年金機構 PDF (再評価率 R7/R8、従前額保障、定額単価) + 厚労省 令和 8 年度 年金額改定 press」

ほかに 90 行目、検証の表に「ハローワーク HTML の上限額 4 行 vs 厚労省 PDF」がある。抽出した値を別の原本と突き合わせた記録で、これも使われた側の記載になる。

**名指された数は、私が数えた。** 64 行目は年度の記号が 3 つなので 3。65 行目の PDF は 2 つの題が 3 年度ずつなので 6。66 行目の年金機構の PDF は、再評価率の R7 と R8、従前額保障、定額単価の 4 つ。press は 1 つ。ハローワークの HTML は、65 行目にも 90 行目にも本数の手がかりが無いので、空のままにした。数え方は人の読みで、道具は文字列から数を拾わない。

### 使われていない側の欄: 未抽出と次の作業

使われた記載が無い原本は、別の欄に名前が出ていることがある。

- 118 行目、できていないことの表「**報酬比例部分の乗率** (`hirei.pdf`) | 画像 PDF、未抽出」
- 140 行目、次の作業候補「4. 年金の残り (支給開始年齢 経過措置 / 繰上げ繰下げ / 加給年金) — 年金機構 HTML から」

108 行目の「分かったこと」の欄には、こうも書いてある。「公式 PDF はテキスト抽出できるものが多い (厚労省の計算式・限度額、年金機構の再評価率・定額単価・従前額、厚労省 press)。例外は報酬比例乗率 (画像 PDF)。」**この「多い」には件数が無い。** 道具の出力で言い換えると、PDF の種類 3 行のうち、両側の数が一致したのは press の 1 行で、残りの 2 行は差 1 だった。テキスト抽出ができたかどうかと、置いた本数が出典の欄に全部名指されているかどうかは、別の話になる。

### 7 つを並べてみた

**協会けんぽの xlsx は、3 本に対して名指しが 3 つで、両側が合う。** 置き場の本数と出典の欄の年度の記号が、literal に一致する対照の行になった。

**厚労省の PDF は、7 本に対して名指しが 6 つで、差が 1 になる。** その 1 本がどれかは、出典の欄の範囲では決められない。題の名前で 6 本を割り当てたとしても、残りの 1 本が別の題なのか、同じ題の古い版なのか、記録には書かれていない。道具は差を整数で返すだけで、どのファイルかは当てない。

**厚労省の page 3 本は、読んだ範囲に記載が無い。** 「page」という語は、記録の 178 行のうち 165 行目、置き場の行そのものにしか出てこない。出典の欄にも、検証の欄にも、次の作業の欄にも無い。私はこれを「読んだ範囲に記載なし」と台帳に書いた。ここで「使っていない」とは書かない。page を開いて PDF の場所を知った、という使い方なら、出典の欄に名前が出ないのは自然だからだ。

**ハローワークの HTML 2 本は、使われた記載が在るが、比べる数が無い。** 65 行目と 90 行目の 2 か所に名前が在るので使われた側に入るが、何本を名指しているかが書かれていないので、2 本と比べない。

**年金機構の PDF は、5 本に対して名指しが 4 つで、差が 1 になる。** ここで 118 行目の `hirei.pdf` が気になる。画像 PDF で未抽出の原本で、数の上では差の 1 本にぴったり見える。**けれど、`hirei.pdf` が nenkin の置き場の 5 本の 1 本だとは、記録のどこにも書かれていない。** だから私は 118 行目の記載を、どの種類にも当てなかった。道具はそれを「どの種類にも当てていない記載 1 行」として返す。当てたくなる対応を、書かれていないまま当てないための欄だ。

**press PDF は、1 本に対して名指しが 1 つで、両側が合う。** ただし置き場は年金機構の側(nenkin)なのに、66 行目の書き手は「厚労省 令和 8 年度 年金額改定 press」と書いている。置き場の名前と書き手の呼び方が違う。どちらが正しいという話ではないので、区分には効かせず、言い方の違いの列に並べるだけにした。

**年金機構の HTML 3 本は、次の作業の欄にだけ在る。** 66 行目の出典の欄に HTML の語は無く、140 行目の次の作業候補に「年金機構 HTML から」と在るだけだ。取ってきて置いたが、記録の上ではまだ抽出の出典になっていない、と読める。なぜそうなっているかは書かれていないので、道具も理由の欄を持たない。

連載の中での位置も書いておく。[走らせた結果だけを台帳に残す回](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_07.html)は、検証が在るかと走らせたかを分けた。[どの問いからも参照されない行を数える回](https://chronicles-of-solo-parenting.blogspot.com/2026/10/blog-post_28.html)は、引ける行と参照される行を分けた。[誰が書くかと作り直す元の軸で並べ直す回](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post_11.html)は、ファイルを書き手で分けた。[置き場の決まり方を下の層まで並べる回](https://chronicles-of-solo-parenting.blogspot.com/2026/11/blog-post_12.html)は、同じ 165 行目の置き場を引いて、来年の原本の場所がどう決まるかを見た。今回はどれとも重ならず、いま置き場に在る本数と、出典の欄の名指しの数だけを突き合わせる。

## 手順

入力は 4 枚の表になる。どの行にも出典の欄が要る。

置き場の台帳には、置き場と種類ごとに取ってきた本数を書く。種類の文字列は置き場の行から verbatim で写す。数字が無ければ本数は空にする。

```csv
置き場 id,種類,取得の本数,出典
kyoukaikenpo,xlsx,3,作業状況の記録 L164 公式 xlsx ×3
mhlw,page,3,作業状況の記録 L165 厚労省 page ×3
mhlw,PDF,7,作業状況の記録 L165 PDF ×7
nenkin,press PDF,1,作業状況の記録 L166 press PDF(× の無い 1 件書き)
```

記載の台帳には、私が読んで見つけた記載を 1 行ずつ書く。名指された数は私が数えた数で、数えられなければ空にする。読んだのに無かった種類には `読んだ範囲に記載なし` の行を書いて、どこまで読んだかを出典の欄に残す。

```csv
記載 id,記号,名指された数,後の側の文字列,出典
L64,出典の欄に在る,3,公式 xlsx `r{N}ippan3.xlsx` (R6/R7/R8),作業状況の記録 L64
L65-pdf,出典の欄に在る,6,厚労省「基本手当日額の計算式及び金額」「支給限度額の変更」PDF (R6/R7/R8),作業状況の記録 L65
L90-pdf,検証の欄に在る,,ハローワーク HTML の上限額 4 行 vs 厚労省 PDF,作業状況の記録 L90
L66-iikata,置き場と書き手の言い方が違う,,厚労省 令和 8 年度 年金額改定 press,作業状況の記録 L66
L118,未抽出の欄に在る,,**報酬比例部分の乗率** (`hirei.pdf`) | 画像 PDF、未抽出,作業状況の記録 L118
page-nashi,読んだ範囲に記載なし,,,作業状況の記録 L1〜L178 を読んだ(L165 の置き場の行を除く)
```

90 行目は HTML と PDF の 2 つの種類に触れているので、記載を 2 行に分けた。**1 つの記載を 2 つの種類に当てると、道具は別枠に出す。** 1 行がどちらの種類の数を名指しているのかが曖昧になるからだ。

記号の登録表には、使う記号を全部書き、その記号が要求する欄を書く。登録表に無い記号を使った行は別枠に出る。

```csv
記号,意味,要求する欄,出典
出典の欄に在る,収録範囲の表の出典の欄に、使ったと読める記載が在る,後の側の文字列/出典,私の決め
次の作業の欄に在る,次の作業候補の欄にだけ在る,後の側の文字列/出典,私の決め
読んだ範囲に記載なし,読んだ範囲に記載が無かったと人が書いた,出典,私の決め
```

対の登録表には、どの記載をどの置き場の種類に当てるかを書く。**ここが、ファイル名から使い道を当てない仕組みになる。** 118 行目の記載は、対を書いていない。

```csv
記載 id,置き場 id,種類,出典
L65-pdf,mhlw,PDF,私の対応付け
L90-pdf,mhlw,PDF,私の対応付け
L140,nenkin,HTML,私の対応付け
page-nashi,mhlw,page,私の対応付け
```

並べる。

```
python stock_use.py rows   okiba.csv kisai.csv kigou.csv tsui.csv
python stock_use.py check  okiba.csv kisai.csv kigou.csv tsui.csv
python stock_use.py verify okiba.csv kisai.csv kigou.csv tsui.csv
```

`rows` の出力はこうなった(5 値の文字列は先頭だけにした)。

```
置き場 id,種類,取得の本数,名指された数,5 値または別枠,差,使われた記載,未抽出・次の作業の記載,言い方の違い
kyoukaikenpo,xlsx,3,3,(A),,L64,,
mhlw,PDF,7,6,(B),1,L65-pdf / L90-pdf,,
mhlw,page,3,,(E),,,,
mhlw,ハローワーク HTML,2,,(C),,L65-html / L90-html,,
nenkin,HTML,3,,(D),,,L140,
nenkin,PDF,5,4,(B),1,L66-pdf,,
nenkin,press PDF,1,1,(A),,L66-press,,L66-iikata
```

`check` の出力のうち、当てていない記載の部分はこうなった。

```json
"どの種類にも当てていない記載": [{"記載 id": "L118", "記号": "未抽出の欄に在る"}],
"台帳に無い置き場を指す対": 0
```

補助の語数えは、判定とは別のコマンドにした。置き場の表が始まる前の 150 行目までを数える。

```
python stock_use.py words 作業状況の記録.md HTML page hirei --lines 1-150
```

私の手元では「page」0 件、「hirei」は 118 行目と 137 行目に 1 件ずつ、「HTML」は 6 行に 1 件ずつだった。**この件数は判定に入らない。** HTML の 6 行には、65 行目と 90 行目の使われた記載も、140 行目の次の作業も、120 行目の「HTML に日付なし」のような別の話も混ざっている。語が出たかどうかでは、どの欄のどの種類の話かは決まらない。語数えは台帳を書くときの読み落としの手がかりにだけ使い、5 値は台帳に書いた行だけで決まる。

別枠の理由は 6 つで、手前が勝つ。出典が空 / 取得の本数が整数でない / 台帳に無い id を指す対 / 登録表に無い記号 / id の重複 / 同じ種類に (A)(B) と (E) が同時に書かれた。**2 つ目は、本数の欄に「3本」や全角の数字を書いた場合だ。** 数として読めないものを読める形に直さず、別枠に出す。

## 検証

テストは 20 件で、全部通った。

```
python -m pytest tools/stock_use -q
20 passed
```

合成した 4 枚(架空の店の、取引先から取ってきたファイルの置き場と、月次の作業記録)では、置き場の種類 14 行が 5 値 7 件(A 2 / B 1 / C 2 / D 1 / E 1)と別枠 7 件に分かれ、合計は 14 に戻る。別枠は 6 つの理由が全部出る(id の重複だけ 2 行)。どの種類にも当てていない記載が 1 行、台帳に無い置き場を指す対が 1 行ある。どの数もテストの中で `assert 値 == …` として固定してあり、道具を直して数が変われば記事も直す。

`verify` の 5 つも、合成の 4 枚と手元の 4 枚の両方で通った。

- 二度走って、判定部分の sha256 が同じ
- 記載の台帳の行順を逆にしても、出力が同じ
- 5 値 + 別枠 = 置き場の種類の行数、置き場ごとの内訳の合計 = その置き場の種類の数
- 記載がちょうど 1 行の種類からその行を消すと、その種類だけが動く(手元の 4 枚では 64 行目の記載を消し、協会けんぽの xlsx だけが (A) から (E) に動いた)
- (A) の種類の取得の本数を 1 増やすと、その種類だけが (B) へ動き、差が 1 になる(手元の 4 枚では協会けんぽの xlsx を 4 本にした)

「いつも成り立つこと」は性質テストで確かめている。4 枚の表を乱数で 300 通り作り、空の出典・整数でない本数・空の本数・台帳に無い記載 id と置き場・登録表に無い記号・重複した種類と記載 id・2 つの種類に当てた記載・使われた記載と記載なしの同居を混ぜる。5 値と別枠と差は、テストの中で別の書き方で引き直して比べる。乱数は固定で、毎回同じ 300 通りになる。

**この性質テストは、作っている途中で 1 回落ちた。** 記載 id が重複した 2 行の行順を入れ替えると、どの種類にも当てていない記載の記号の欄が変わった。先に読んだ 1 行だけを見ていたからだ。重複した id の行を全部見るように直してから通っている。

## 図 2 並べるまでの流れと、止まる場所

![4 枚を読み、行の形を見て、置き場の種類ごとに振り分け、件数だけを数え、検算するまでの流れ図。関所は 3 つ](figures/stock_use_flow.png)

段は 5 つで、橙のピルが関所になる。

この図で見てほしいのは、描かれていない経路のほうだ。**フォルダを開いて数える矢印が無い。** ファイル名から使い道を当てる矢印も、差のファイルを当てる矢印も、消してよいかを決める矢印も、滞留の理由を当てる矢印も、利用率を出す矢印も、原本を取りに行く矢印も無い。実装でも同じで、そういう引数を持たせていない。テストの 1 本は、道具が import しているのが標準ライブラリの csv / json / hashlib / argparse だけで、ディレクトリを読む部品や通信の部品、時計の部品を使っていないことを確かめている。

3 段目の振り分けが本体になる。言い方の違いを先に別の列へ出し、使われた記載が在れば両側の数を見る。どちらかが空なら (C)、在れば literal に比べて一致なら (A)、違えば (B) で差を付ける。使われた記載が無ければ未抽出か次の作業の欄を見て (D)、それも無ければ (E) になる。(E) の語は「読んだ範囲に記載なし」で固定で、「使っていない」「要らない」とは言い換えない。

## 道具

道具は [GitHub](https://github.com/ChaiCroquis/deterministic-tools-jp/tree/main/tools/stock_use) にある。ライセンスは MIT で、自由に使える。標準ライブラリだけで動く(テストの実行には pytest と hypothesis が要る)。

手元で書くのは 4 枚で、いちばん重いのは名指された数を数える作業だ。出典の欄の 1 行を読み、年度の記号や題がいくつ並んでいるかを数える。**数え方に迷ったら空にしておく。** 空なら (C) に出て比べないだけで済むが、迷った数を書くと、もっともらしい差が生まれる。

合成した 4 枚が `fixtures/gousei/` に、手元の記録を写した 4 枚が `examples/temoto/` に入っているので、同じ数字が手元で出るかを確かめられる。

使い方として想定しているのは、原本を取ってきて抽出を進めた後に 1 回通すことだ。差の在る種類と、次の作業の欄にだけ在る種類と、記載の無い種類が、出典の行番号つきで並ぶ。**どのファイルを消すべきかは出ない。** 出るのは、置き場の本数のうち出典の欄に名指されていない部分の件数だけだ。

## 別の業種なら

どの業種でも「取ってきて置いた」と「使った」は別の台帳になりそうだと考えている。会計なら、取引先から受け取った請求書 PDF の本数と、仕訳の証憑の欄に名指された数が合わない月がある、という形が考えられる。EC なら、仕入先からダウンロードした商品マスタの CSV が置き場に 7 本あるのに、取り込みの記録が名指すのは 6 本、という形が考えられる。医療・介護なら、取り寄せた告示の PDF のうち、点数表の出典の欄に出てくるのは一部で、残りは「次に対応」のメモにだけ名前がある、という形が考えられる。道具が持つ欄は置き場 id・種類の文字列・本数・記号・出典だけで業種の語彙を持たないので、入力例の語を変えるだけで同じように通せる。ただし私が測ったのは合成の 4 枚と手元の 4 枚の範囲だけで、ほかの業種は同じ詰まり方になりそうな例であって実測ではない。

## できないこと

- **フォルダの実物を数えない。** 本数は記録に書かれた数で、置き場を開いて数えた結果ではない。記録と実物がずれていても、道具には分からない
- **名指された数を数えない。** 出典の欄の文字列から数を拾う経路は無く、人が数えて書く。65 行目を 6 と数えたのは私の読みで、数え方が変われば差も変わる
- **差がどのファイルかは言わない。** 厚労省の PDF の差 1 も、年金機構の PDF の差 1 も、どの 1 本かは出典の範囲では決まらない。`hirei.pdf` がその 1 本だとも言わない
- **消してよいか、要らないかは決めない。** 差の 1 本が古い版の控えなのか、次の作業で使う原本なのかは、記録に書かれていない
- **記載なしは、読んだ範囲の話だ。** 今回読んだのは手元の記録 1 ファイルだけで、抽出器のソースや取得の台帳は読んでいない。そこに page を使った記録が在る可能性は消せない
- **記号が正しいかは分からない。** 90 行目を「使われた側」と読むのも、140 行目を「次の作業の欄」と読むのも私の読みで、道具はその記号を受け取るだけだ
- 上の件数は、合成の 4 枚と私の手元の記録を写した 4 枚に対する測定で、私の環境での話になる。ほかの人の置き場で同じ数字になるとは限らない
